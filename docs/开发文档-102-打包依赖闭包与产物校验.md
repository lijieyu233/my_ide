# 打包依赖闭包与产物校验（RELEASE-01）

> 2026-10-01；实施前基线 `634990d`。沿用090-C、093的RELEASE-A/B合同，先修复实际包不能加载的缺口。

## 实施合同

1. 保留受控files清单，补git-native、git-ops、launch-ops、launch-service以及运行时图标，不把docs、测试、工作区数据和开发脚本带入包。
2. 构建后读取真实app.asar，检查生产入口/本地依赖、Worker、HTML静态引用、vendor、插件、sql.js WASM与生产npm入口；拒绝私人配置、临时目录、测试数据和开发依赖。检查必须在npm build的构建流程中执行，缺文件返回失败。
3. 检查器以明确生产资源和本地依赖扫描共同覆盖；动态资源需要显式声明。扫描不等于运行时证明。
4. 临时生成asar夹具，删除任一必需资源都应失败；注入禁止路径也应失败。生产文件清单不能成为测试的唯一来源。
5. 使用本机Electron发行目录构建隔离Windows目录包，不覆盖dist、不发布。真实打包可执行文件使用独立profile/home/临时项目，验证文本保存、Git Worker/面板、SQLite WASM读写重开、启动面板和Office vendor加载。清除开发模块查找环境，不从源码导入运行时模块。
6. 目录包通过后尝试portable构建/启动，分别记录结果；工具链失败须保留诊断，不能把目录包成功冒充portable成功。

## 验证与收尾

后台npm test，并运行新增产物夹具测试。实际构建、内容校验、包内加载、功能矩阵及portable分别记录证据。测试进程隐藏且只写本轮临时目录；清理路径需限定系统临时父目录与本轮前缀。完成后重启MyIDE，独立提交并推送，核对dev。
