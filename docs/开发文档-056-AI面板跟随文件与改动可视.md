## 一、背景：主入口是面板，问题也在面板

用户的原话：

> 「你这个能力可以有 但是主要还是通过ai面板描述」
> 「你先改吧 最好自己测试 **从人使用的角度而不是ai的角度评测**」

所以内联改写（选中 → 快捷键 → 就地改）只是补充，**主链路是"在面板里说一句话，AI 把事办了"**。而这条链路当时是断的，问题不在提示词、也不在按钮，在三处：

| # | 卡点 | 代码证据 |
|---|---|---|
| 1 | **它不知道你在看哪份文件** | `buildMessages()` 只发 system + 对话历史，`ctxFiles` 只有手动点 📎 / @ 才填。说"帮我整理这份文档"时，它不知道"这份"是哪份 |
| 2 | **改完你看不见改了哪** | `renderToolRow()` 只在聊天里留一行 `🔧 replace_edit 周报.md`，然后一句"改好了"。想知道改了啥，自己去翻文件 |
| 3 | **只能全要或全不要** | `applyWrite()` → `confirmDiff()` 弹模态框，底部只有「拒绝 / 应用修改」 |

## 二、改动一：面板跟着"你正在看的那份文件"走

### 实现

```js
let followPath = null;             // 正在跟随的文件
const followMuted = new Set();     // 用户明确说过「不跟随」的文件

async function followActive() {    // 读 Viewer.activeTab → 自动进上下文（标记 auto:true）
  const path = (tab && !tab.dir) ? tab.path : null;
  if (path === followPath) { renderFollow(); return; }
  followPath = path;
  ctxFiles = ctxFiles.filter((x) => !x.auto);
  if (path && !followMuted.has(path)) { /* 读内容 → push({ path, content, auto: true }) */ }
}
```

**同步时机**（漏一个就会出现"显示的和实际发出去的不一致"）：
- `Viewer.activate()` 末尾 —— 切标签、打开文件都汇聚在这里
- 输入框 `focus` —— 用户可能刚切过标签
- `send()` 之前 —— 保证发出去的上下文是对的
- 面板打开时（`setAiVisible`）

### 界面

输入栏上方一条「正在看 xxx.md」（眼睛图标 + 文件名 + ✕）：

- 一眼知道"我说的话是针对它"，不用再手动附
- 点 ✕ = **不再跟随这个文件**，切走再切回来也不会自动加（`followMuted` 是集合，不是单值；手动 📎 加回来会 `delete`）
- **自动跟随的文件不再占 chips** —— chips 只显示手动附加的，避免同一个文件出现两次

### 顺带修的

新对话（✚）以前 `ctxFiles = []` 全清 —— 连"我在看这份文档"也一起清掉，每开一次新对话就得重新附一次。改成只清手动附加的，保留 `auto` 项。

## 三、改动二：改完把改动摆在眼前（可展开、可单独撤销）

### 实现

`applyWrite()` 写盘成功后：

```js
const cp = { path, rel, oldText, existed, done: false, card: null };
checkpoints.push(cp);
cp.card = addEditCard(cp, content);   // 在消息流里落一张卡片
```

卡片长这样：

```
_ui_outline.md                    +1 -1     [看改动] [撤销]
  ↓ 点「看改动」懒渲染（长文档不占 DOM）
  - 二级 B
  + 二级 B（备注）
```

- `+N / -M` 分别是绿 / 红（**人眼复核过像素**：加绿减红，反了会误导）
- diff 渲染抽成 `diffRowsHtml()`，与原来的确认弹窗共用（长未改动段折叠为「⋯ N 行未改动 ⋯」）
- **撤销是按处回退**：`cp.oldText` 写回，卡片变灰 + 按钮变「已撤销」，其它改动不受影响
- `⟲` 按钮从"弹栈撤销"改成"撤销最近一处**未撤销**的"

### 顺带修的：空白气泡

`continueStream()` 无条件 `addMsg('assistant', '')` —— 模型这一轮只调工具、不返回文字时，聊天里就留下一个**空白气泡**（用户截图里一眼就能看到，很怪）。

```js
const hasCalls = !!(r && Array.isArray(r.toolCalls) && r.toolCalls.length);
if (!isErr && !String(text || '').trim()) {
  if (hasCalls) { curStream.remove(); }                        // 有工具行，气泡是多余的
  else { md.innerHTML = '<p class="ai-err">（模型这轮没有返回内容）</p>'; }
}
```

## 四、验证：从"人用起来顺不顺"出发

用户明确要求不要用"断言通过率"自证，所以做了两层：

### 4.1 端到端：把"人说完一句话之后发生的整件事"真跑一遍

自检环境没有真 API key，但**不能因此只断言 DOM 存在** —— 那测不出链路通不通。

做法：主进程把 `ai:chat` 这个 IPC 换成脚本化应答

```js
ipcMain.removeHandler('ai:chat');
ipcMain.handle('ai:chat', async (e, cfg, messages, tools) => {
  stubRound++;
  if (stubRound === 1) return { ok: true, text: '', toolCalls: [{ id: 'c1', name: 'replace_edit', args: {...} }] };
  /* 第二轮：逐字符 send('ai:chunk') 流式返回文字 */
});
```

**只替换「模型」这一段**，页面侧全部真实代码：AI 面板 → 工具执行 → 确认弹窗 → 写文件 → 卡片 → 撤销。

自检拆成两步（一步到底只能拍到终态）：

| 步骤 | 截图 | 断言（都是"人能看到什么"） |
|---|---|---|
| `aiPanelFlow` | `check-ui-1h-ai-flow.png` | 打开文档后**面板自己显示「正在看 这份文件」**（不用手动附）／它要动文件之前**先给我看 diff**／改完出现**改动卡片**（写明文件 + 加减行数）／点「看改动」**就地展开红绿**／按钮能收回去 |
| `aiPanelUndo` | `check-ui-1h2-ai-undone.png` | **回头还能看到**上次改动（不是一闪而过）／卡片上有「撤销」／点完**标记为已撤销**／**文件内容真的回到改之前**（不是只改界面） |

### 4.2 人眼复核（这一步抓到了真问题）

- 放大卡片逐像素确认 `+1` 是绿、`-1` 是红
- 看截图时发现**空白气泡**并修掉（断言全绿时它照样存在 —— 这正是"只靠断言测不出体验"的例子）
- 两张截图分别对应"改完当时"和"撤销后"，都能对上人的预期

## 五、踩坑

1. **Electron 主进程里 `http.createServer().listen()` 不回调**
   最初想让自检连一个本地假 OpenAI 服务（最接近真实链路），结果卡死在 `listen`：`.ui-check-boot.txt` 打点停在「3 createServer 完成，准备 listen」，150s 看门狗触发时 `lines` 还是空的（报告里连"窗口模式"都没有）。
   → 端到端打桩改到 **IPC 层**，效果等价且不碰网络。
   （顺带：看门狗从 150s 提到 240s，并让它把"最后阶段 + 启动打点"写进报告 —— 否则超时只看到一句"超时"，不知道卡在哪。）

2. **自检"一步到底"只能拍到终态** —— 撤销和未撤销必须分成两步，否则截图永远拍的是被撤销之后的样子。

3. **旧断言会随交互改版过时**：自动跟随的文件不再进 chips（改用「正在看」条），旧断言 `chips.length === 1` 就失败了。
   → 改成「跟随条有 **或** chips 有」都算通过 —— 断言要跟着**语义**走，而不是绑定某个具体元素。

4. **跨盘 `renameSync` 会静默失败**（既有的坑，这轮又踩到清理产物）：项目在 D 盘，往 C 盘 Temp 挪会 `EXDEV`，套了 `try{}catch{}` 就成了"清理成功"的假象 → 清产物一律挪到项目内 `.ui-check-trash/`。

## 六、没做的（用户明确排后）

- **内联改写**（选中 → `Ctrl+Shift+I` → 就地 diff）：用户说"这个能力可以有，但主要还是通过面板"，属于补充能力
- 选中内容直接进对话、整理动作菜单（润色 / 精简 / 扩写 / 统一术语 / 提炼要点）、整理结果另存新文件
