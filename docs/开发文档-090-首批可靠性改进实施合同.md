## A. EDIT-01：保存结果必须控制关闭和项目切换

### 场景与证据

用户在 A 项目输入，写入返回权限错误后切到 B。`viewer.js:saveTab` 返回 undefined，失败只写日志；`saveAllDirty` 不汇总；`app.js:openProject` 随后 closeAll。另一个场景是 IPC 保存等待期间继续输入，回调把 tab.content 设回旧 val 并清 dirty。

本轮函数级复现已确认：受控 Promise 保存等待期间改为新内容，成功回调后退回旧内容且 dirty=false；错误写入后 saveAllDirty 返回 undefined。详见 089 §8；真实窗口失败场景仍列入实施验收。

### 实现合同

1. 每个 tab 增加稳定 id、editRevision、savedRevision；用户编辑递增 revision，外部同步只更新相应磁盘版本。
2. 保存捕获 `{tabId, path, content, encoding, revision}`，同一文件串行执行；重复自动保存可合并到最后快照，但显式 Ctrl+S 必须能等待对应版本落盘。
3. 返回 `{ok, tabId, path, savedRevision, errorCode, error}`；Promise rejection 也归一化。成功只推进 savedRevision，**只有当前 revision 与保存 revision 一致时才清 dirty**，不能把旧内容覆盖新内存内容。
4. `saveAllDirty` 固定本次标签集合，返回 `{ok, saved, failed, stillDirty}`。切项目/关闭/移除当前项目共用结果；failed 或 stillDirty 时保留当前项目和标签，给出重试/另存入口。编辑期间无限输入不应被无限循环保存锁住。
5. pending 保存涉及重命名/移动时，路径迁移与保存队列协调；关闭 tab 后晚到回调不得更新其他标签。项目切换请求串行或用代次使旧请求失效。

### 验证与交付

使用可手动 resolve/reject 的 fs.writeFile mock，覆盖：拒绝保存、部分成功、保存后继续输入、先发后回顺序颠倒、切项目双击、重命名旧路径。测试断言内容/dirty/root/标签是否保留，不能仅 assert toast。

真实 Electron 用隔离 profile 和临时只读/失败 fixture 验证失败可见、重试保存成功、项目仍可继续切换。改 UI 时 `--check-ui` 并检查截图。提交建议 `fix(editor): 保存失败阻止关闭并保留保存期间的新输入`。

依赖：无；B 的磁盘冲突可后续加入同一合同，A 不等待 B 才修输入丢失。

## B. FS-01：文本写入服务与磁盘版本前置条件

### 场景与边界

现有 `fs:writeFile` 直接覆盖目标，UI 自身保存、AI 修改和任务 JSON 都复用它。没有写入原子性与文件版本前置条件。同步写大文本阻塞需要另行计时，不能先写成已测性能故障。

第四轮原处理器/真实临时文件确认编码格式改变、有损字符替换、覆盖外部新内容；受控部分写后EIO留下截断文件。具体六条观察与格式/版本/替换分包见[093 §2/5](./开发文档-093-文件写入与打包发布失败路径取证.md)。read须保留BOM/字节序元数据，写前检查不可表示字符；只加原子替换不能修复有损编码和外部冲突。

### 提议接口

`writeText({path, content, encoding, expectedVersion, source, requestId}) → {ok, version, bytes, errorCode}`。

- read 返回 version（规范化真实路径、stat 特征、必要时内容 hash）；expectedVersion 必填于覆盖已有用户文件，创建可要求 expectedAbsent。
- 主进程按真实目标路径排队、核对版本并编码；同目录创建随机临时文件（独占创建），写完整、flush、关闭后替换目标。
- Windows 替换语义、文件权限、被占用目标、符号链接和 junction 分开处理。不要把“先删原文件再 rename”包装成原子写；目标替换失败时保留原文件和可恢复的临时数据。
- 版本冲突返回 `VERSION_CONFLICT`，不写盘。比较/另存/显式覆盖是用户操作，不能因自动保存反复弹窗。异常自动保存先保留草稿并提示状态。
- 外部进程没有遵守本应用锁时仍存在核对到替换之间的竞态；文档必须说明检测能力的边界。需要更强保证时另行评估平台锁，不能宣称 compare/hash 让外部并发彻底安全。
- 编码在主进程同一入口处理：GBK、UTF-8 BOM、UTF-16 BOM/无 BOM、原换行符，不能擅自改现有编码策略。AI 局部改动应复用读取到的 encoding。

### 验收

注入写途中错误、rename 失败、磁盘外部更改与同名新建竞态，原文件完整或新文件完整，不出现截断；临时文件可回收，失败内容可恢复。编码矩阵按字节对拍；任务 JSON 确认损坏不被覆盖。恢复容量与清理策略须配置上限，不积攒无限正文。

影响文件：main/preload、viewer、AI 工具与任务写入调用；纯 Node 服务独立可测。先给编辑器接入并证明稳定，再逐个迁移其他模块，每项独立提交。

## D. LAUNCH-01：停止与重启的进程归属

### 已确认的路径

stopEntry 可按端口反查 PID 并直接 killTree；端口在旧进程退出后可能由其他程序接管。持久化 PID 未记录创建时间。restartEntry 无视停止失败继续 start。USB 分支同步执行，仅检查 r.error，不检查 r.status。

第三轮完整服务受控复现确认六条观察：无归属监听者被选为停止目标、无端口停止失败仍成功并删除记录、重启忽略停止失败、USB 非零退出被记为运行/停止成功，以及退出保留时身份字段丢失。全部是宿主 API 桩，没有实际杀用户进程；详细输入/输出与分包合同见 [092 §3/6](./开发文档-092-数据库事务与启动进程失败路径取证.md)。

### 设计

- 条目启动固定 `{entryId, launchId, pid, creationTime, command, cwd, startedAt}`，读回持久化状态必须验证操作系统进程身份。
- 优先停止当前真实 child 及归属可证明的子树。端口反查只是找候选，必须再核对启动归属；匹配不到时返回 `PORT_OWNED_BY_OTHER`，不能“替用户清端口”。PID/创建时间检查也可能有竞争窗口；平台可行时保留真实句柄/Job Object，先评估再决定实现。
- stop 返回 `{ok, state, ownedKilled, remainingOwned, foreignListeners}`，只有复查确认本条目结束才 state=stopped；无端口条目也要检查进程，不直接无条件成功。
- restart 只在 stop.ok 后进入 start；entryId 操作互斥，连续按钮不制造两个 shell。
- spawnSync 改异步 spawn/execFile，加超时、输出上限、取消与子树回收；USB 检查 status 非零和 stderr，不凭成功 spawn 判成功。
- running 需要可选 ready 条件，端口健康只算条件之一。启动成功仅表示 child 已创建时用 starting，不诱导用户以为服务已就绪。

### 验收

fixture 启动服务 A 后退出，再让可控服务 B 接同端口；点击停止 A，B 必须继续存活。测试旧 PID 记录、停止权限失败、无端口进程、USB 非零退出、重启停止失败、双击启动。测试脚本必须只处理自己创建的进程，不使用用户现有监听端口作为靶子。

用真实 Electron check:launch 验证，不弹窗口抢焦点。不得在日志/文案出现“已停止”但 owned 进程还在。实现时独立 commit，先修归属/结果，再做性能/就绪输出优化。

## E. AI-01：统一秘密存储与迁移

### 证据

AI/翻译配置和 DB 密码存在 localStorage；settings-store.snapshot 收集全部 myide-*，主进程写镜像，因此秘密会进入普通镜像/设置导出。这里是可见的存储路径问题，不是已证实的远程泄漏。

### 合同

1. 主进程秘密服务：`setCredential/deleteCredential/getCredentialStatus`。前端永远不暴露“读取明文密钥”公共 API；请求网络/连接 DB 时由主进程解析 credentialId。
2. vault 通过与 Electron 33 兼容的 safeStorage/操作系统能力加密；加密不可用返回明确错误或本次内存使用，不无提示写明文。[Electron safeStorage 官方 API](https://www.electronjs.org/docs/latest/api/safe-storage)
3. 迁移顺序：读取旧配置 → 写 vault → 校验成功 → 更新 credentialId → 清普通配置秘密 → 重写已存在镜像。失败保留原配置并报告，不能先删旧密钥导致用户服务失效。测试覆盖部分迁移后崩溃的幂等恢复。
4. snapshot/export 改为允许的非秘密字段，不能只靠 key 名黑名单，因为秘密藏在 JSON 值里。导出有 schemaVersion；本机 credentialId 换机不承诺可解密，导入后显示需重新配置。
5. 既有历史导出/外部备份并不因迁移自动消失；应用管理的旧镜像和备份应在明确范围内重写/清理，不删除用户任意目录。
6. 日志掩码 Authorization、连接密码；诊断只含“已配置/来源/错误码”，保留用户已有授权偏好。

### 验收

用独特的假密钥逐个检查 localStorage、镜像、导出、日志均不含明文；重启后 AI/翻译/数据库可用；修改/删除/迁移失败/加密不可用均有测试。不能仅搜索一个 key 名就宣称迁移成功，也不扫描输出用户真实秘密。

## F. DB-01/02：分两次交付数据库方言与批量事务

### 第一阶段：修 EXPLAIN

按 capability/方言分支：MySQL EXPLAIN、PostgreSQL EXPLAIN、SQLite EXPLAIN QUERY PLAN。保留当前 SELECT 范围，不默认加 ANALYZE；后者会实际执行语句。[PostgreSQL 官方语法](https://www.postgresql.org/docs/current/sql-explain.html)

测试分两层：单元验证语句和结果映射；三种真实后端验证服务端接受与空结果列结构。数据库未配置时集成项显式 SKIP，不能把 mock 结果报成三个后端均通过。提交建议 `fix(db): 按数据库方言生成执行计划语句`。

### 第二阶段：批量写操作事务

当前 deleteRows 对 pkRows 逐条 query，后面失败会让前面写入已落库。计划新增 connection 级 `transactionState/capabilities` 和 begin/commit/rollback。

第三轮使用真实 sql.js 1.14.2 和临时 SQLite 文件已确认六条观察：部分删除落盘、affected 虚报、WITH/RETURNING 写入未持久化、事务内 export 丢失未提交修改、导入提交调用者事务。[092 §2/5](./开发文档-092-数据库事务与启动进程失败路径取证.md) 替本阶段补充结果语义和事务所有权合同；不能只补 BEGIN/COMMIT 而继续复用当前自动 export 的 query。

- 一个批量 delete/import 用同一连接执行，任一步失败 rollback；已有用户事务时用 savepoint 或明确拒绝嵌套，不能帮用户 commit 所有改动。
- affected 来自实际结果，不用输入 pkRows.length 假报成功。没有主键/非事务存储引擎提供正确限制。
- SQLite 事务期间不逐条 export 回写；COMMIT 后统一持久化，ROLLBACK 不写变更。持久化失败保留可重试状态与原磁盘文件，复用 B 的写入思想但不能把二进制库当文本。
- 写入、返回结果行、事务提交和文件持久化分别报告；WITH/RETURNING/多语句不能靠首词或结果集判断读写。先核验引擎能力，export 关闭重开后的连接配置必须复位；DB-A 持久化边界先于 DB-B 批量事务交付。
- UI 显示 pending/commit/rollback 并在断开前处理未提交事务；连接断开/网络异常根据服务端实际结果标为未知，不能自动重试非幂等写操作。
- 取消查询为单独第三阶段：requestId、后端取消/statement timeout、结果流的行/字节预算；它不阻塞批量事务缺陷先修。

验收：删第 2 条触发可控错误，前后行数/数据完全一致；成功批量 affected 精确；已有事务只回滚本批次；SQLite 重启后结果与事务一致；MySQL 非事务表不假装可回滚。参考 [DBeaver 事务模式](https://dbeaver.com/docs/dbeaver/Auto-and-Manual-Commit-Modes/)。

### 目标与依赖

保留现有工具确认与项目授权记忆，新增执行端边界。优先复用 A/B 的版本化写入、E 的秘密服务和 PROJECT-01 的 generation，不另造一套文件覆盖逻辑。

### 设计

- IPC sender 必须属于本地可信主 UI 的有效 frame；仅校验 sender 不代表插件被沙箱隔离，同 UI 插件仍属于本机受信代码。
- 通用文件 API 要保留用户显式打开项目外文件的能力；AI 工具用专门入口，绑定由主进程登记的项目/请求上下文，不把全局 fs API 的所有路径突然限制到项目根。
- 工具调用包含 `{requestId, sessionId, rootId, generation, toolCallId, expectedFileVersion}`。主进程保存上下文并验证，不能相信 renderer 传过来的 allowed=true。
- realpath 核对已有目标；新文件核对最近存在祖先及最终目录；拒绝绝对路径、UNC/驱动器逃逸、`..`、junction/符号链接越界等未授权情况。合法项目外目标通过单独明确授权处理。
- abort 变成 requestId 范围的状态机：running → cancelling → cancelled/done/failed。停止同时阻止新工具派发，迟到工具/网络响应不能写盘或替下一会话更新 UI。
- run_command 与项目授权匹配，shell 字符串黑名单不是安全边界；命令执行保留已授权 cwd/env，用超时/输出上限/进程树取消处理生命周期。拒绝重复 toolCallId 导致非幂等写重复执行。
- 文本工具协议与原生工具走同一个 validator；会话规则、README、搜索命中文本不能更新 permission 状态。

### 验收
