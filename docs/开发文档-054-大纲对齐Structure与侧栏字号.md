# 开发文档-054 · 大纲对齐 PyCharm Structure + 侧栏字号失效修复

> 用户反馈三条：① 侧栏字体调整对**某些窗口的某些字**失效；② 大纲界面要仿 PyCharm 的 Structure；
> ③ 想右键章节名「复制这个章节」，并且觉得这里原本的展开按钮不符合用户逻辑。
> 参照图：PyCharm 中文版 Structure 工具窗口（树形 + 选中蓝带 + 上下箭头列）。

## 一、侧栏字号：为什么有些字调不动

### 根因

面板本身的基准字号是跟着 `--tool-font` 走的（`#sidebar`、`#panel-git`、`#ai-panel`、`#git-log-panel`、
`#tasks-dag-body` 都写了 `font-size: var(--tool-font, 13px)`），**但面板内部大量文字把字号写死成了 px**：

```css
.git-sec-title { font-size: 11px; }   /* 状态栏 A−/A+ 只改面板基准 → 这里纹丝不动 */
.badge         { font-size: 10px; }
#commit-msg    { font-size: 12.5px; }
```

所以现象是「调了字号，面板里只有一部分字变大」——即用户说的「某些窗口的某些字失效」。

### 修法

把**工具窗口面板内部**的固定 px 字号统一改成 em（相对该面板的 `--tool-font` 基准），
换算按默认 13px 取整：`9→.69  10→.77  10.5→.81  11→.85  11.5→.88  12→.92  12.5→.96  13→1`。

共改 **89 处**，覆盖：目录树（`#tree-head` / 搜索框 / 行内图标 / 路径）、大纲、提交面板
（分节标题 / 文件行 / 徽章 / 计数 / 消息框 / 面板标题 / 预览）、Git 日志（`.gl-*`）、数据库（`.db-*`）、
任务（`.tk-*` / `#tasks-*`）。

**刻意没改**的：主编辑区（`.zoom-btn` 图片工具条、`.md-view`、编辑器字体）——那些跟随「界面字号 / 编辑器字号」，
不属于「侧栏字号」的作用域。改完特意把已经误改的 `.zoom-btn` / `.zoom-pct` 还原回 px。

### 验证（真实 Chromium）

```
PASS  字号 +3 后面板内部文字全部跟着变
      提交·分节标题 11.05→13.6 | 提交·文件行 11.96→14.72 | 提交·状态徽章 9.21→11.33 |
      提交·勾选计数 11.05→13.6 | 提交·消息框 13→16 | 提交·面板标题 11.96→14.72 |
      提交·ahead/behind 10.17→12.51 | 目录树·行 13→16 | 目录树·搜索框 11→13.54 | 目录树·图标列 10.01→12.32
PASS  放大比例符合 16/13   [ratio=1.231]
PASS  还原后回到原字号
```

10 个采样点全部跟随。改前这些点里至少 6 个（分节标题 / 徽章 / 计数 / 消息框 / ahead-behind / 图标列）是**完全不动**的。

## 二、大纲对齐 PyCharm Structure

### 参照图 → 实现对照

| PyCharm Structure | 我们的实现 |
|---|---|
| 固定宽度的箭头列，▾/▸ 只在有子层时出现 | `.ol-arrow`（宽度 `1.15em`）；叶子行保留 `.ol-pad` 占位但**不画任何符号**（旧实现画 `·`，视觉噪音） |
| 点箭头只折叠、点文本只跳转 | 箭头 `onclick` 里 `stopPropagation`；行点击 = 选中 + 跳转 |
| 选中项**整行铺满**高亮带 | `.outline-item.key-nav-sel { background: var(--bg-selected) }`（键盘导航复用同一状态；实测 `rgb(45,79,107)`） |
| 各层级**字号一致**，只靠缩进和颜色区分 | `.outline-item { font-size: 1em }`；`lv3+` 只降对比（旧实现把深层级缩到 11.5px） |
| 行高宽松、点得中 | `height: 1.9em`（13px 基准下实测 25px） |
| 缩进逐级递进 | `padding-left = (level-1) * 13 + 4`（实测文本起点 57 < 70 < 83） |

### 「原本的展开按钮不符合用户逻辑」→ 拆成两件事

原来面板顶部有一排按钮：**全展 ｜ H1 ｜ H2 ｜ H3 ｜ H4**。
它实际的作用是「**折叠编辑器里的标题节**」，但摆在一个树形大纲上，任何人都会先理解成
「按层级过滤/收起大纲」——语义与位置不匹配。

改法：

1. 顶部改成 **2 个图标按钮**（SVG，无文字）：`展开全部章节` / `收起全部章节` —— 作用于大纲树本身，符合直觉。
2. 「折叠编辑器到某个层级」这类动作**下沉到右键菜单**，带上上下文：
   `⇥ 在编辑器中折叠到此层级（H2）` / `⇤ 展开编辑器中全部标题节`。
   在具体章节上右键才有意义，也不会再被误读成大纲过滤。

顺手把「小箭头点起来费劲」也解决了：

- 箭头独占点击区（点箭头不会跳转）
- **双击任意标题行** = 折叠 / 展开它的子层（给了除小箭头之外的大目标）
- 键盘：`↑↓` 选择、`Enter` 跳转、`→` 展开（已展开则进入第一个子项）、`←` 收起（已收起则回到父级）
  —— 与文件树一致，也是 PyCharm 的树操作习惯

## 三、右键章节名 → 复制本章节

右键菜单（截图实测 6 项）：

```
📋 复制本章节（含子章节）        ← 主项
📋 只复制本节正文
📋 复制标题文本
────────────────────
▾ 折叠子级 / ▸ 展开子级          （按当前状态切换，叶子节点不出现）
⇥ 在编辑器中折叠到此层级（H2）
⇤ 展开编辑器中全部标题节
```

### 复制范围规则（关键，别想当然）

给定标题 `i`（层级 `L`，行号 `N`）：

| 模式 | 取哪些行 |
|---|---|
| `full`（默认） | `N` 起 → **下一个层级 ≤ L 的标题之前**（即含所有子章节） |
| `body` | `N` 的下一行起 → 第一个子标题之前（只本节正文） |
| `title` | 只有标题文本 |

首尾空行裁掉；`full` 以一个空行都不含的紧凑形式给到剪贴板。
实测（文档 `# 一级 / ## 二级A / ### 三级A1 / ## 二级B`）：
右键「二级 A」→ 复制得到 `## 二级 A` + `二级 A 正文。` + `### 三级 A1` + `三级 A1 正文。`（7 行），
**不含**「二级 B」也不含上一节的「一级正文」；叶子节点「三级 A1」得到的正是它自己的标题 + 正文。

复制后给 toast 反馈：`已复制「二级 A」整节（7 行）`。

## 五、踩坑（这次新踩的，都写进 skill 了）

1. **`npm test` / 命令输出莫名为空**：把输出重定向到文件再读（管道 + grep 偶发丢输出）。
2. **heredoc 传给 Python 的反斜杠会被吃掉一层**：正则 `\s` 变成 `s` → 匹配全空，
   一度怀疑「Python 读到的文件内容不一样」（绿盾），其实是我自己的转义问题。
   结论：给 Python 传脚本时**别依赖正则转义**，用纯字符串解析（`find` / `split`）更稳。
3. **改文件要按该文件自己的行尾**：仓库里 `.js`/`.css`/`tests` 是 CRLF、`scripts/*.js` 是 LF，
   断言字符串里的 `\n` 对不上就报「找不到锚点」。先探测 `'\r\n' in raw` 再拼字符串。
4. **自检不能并发跑**：`--check-ui` 会在开头写 fixture、结尾 `cleanFixtures`。
   同时跑两个实例 → 先结束的那个把文件删了 → 另一个出现「图片没解码 / 大纲 0 行 / mermaid 没渲染」这类
   **假失败**。必须等环境里没有 electron 进程再启动，且只启动一个。
5. **断言里别用 `indexOf(...) === 0` 判菜单项**：条目文案带 emoji 前缀（`📋 复制本章节…`），
   要用 `includes`。
