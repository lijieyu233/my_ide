# 开发文档-060 界面信息层整治（状态栏 / 图标 / 路径）

> 起因：用户截图圈了 5 处说「展示的很乱 不好看」，问有什么建议。逐处量过之后动手改。

## 一、先量后改：五处到底是什么问题

| # | 位置 | 改前 | 根因 |
|---|---|---|---|
| 1 | 底部状态栏 | `v0.8.5 ⌥ generation-driven · 52 处修改  50 行  行 1，列 1 (CRLF)` | ① 组间用 **4 个空格**连接 → 糊成一片；② `⎇` 字符**掉字形**（Windows 默认字体没有 → fallback 成 `⌥`）；③ 「50 行」和「行 1，列 1」两个"行"字并排；④ 版本号常驻最左占地 |
| 2 | 编辑器工具条 | `⧉ 复制路径 / ◉ 预览 / ⌖ 定位` | 同上：**字符图标掉字形**（`⌖` 渲染成了 `+`），且图标与文字挤在一起 |
| 3 | 文件路径 | `D:\document\code\ditto-takinghead-benchmark\avatars.json` | **同一条绝对路径在界面上出现三次**（树根右侧、编辑器工具条、状态栏旁），每次都被截断成半截 |
| 4 | 编辑器标签 | `ditto-realtime.service` 宽、`avatars.json` 窄 | 宽度跟着文件名走（`flex-shrink:1` + 无统一下限）→ 一排参差 |
| 5 | 顶部「全部项目」 | `▾ 14 项目` | 中文量词位置不通顺，也看不出这是"全部项目"入口 |

**共性根因只有两条**：字符图标 + 绝对路径。

## 二、改法

### 1. 图标一律换成内联 SVG（治本）

`⧉ ◉ ⌖ ⎇ ✎ ◫ { }` 这些"用字符当图标"的写法，在 Windows 默认字体下大量缺失 →
fallback 成完全不相干的符号（用户看到的 `⌥ generation-driven`、`+ 定位` 就是这么来的）。

项目里本来就有 `svg.ic` 体系（AI 面板头部按钮就是这么做的），这次把状态栏分支图标、
编辑器工具条（复制 / 预览 / 源码 / 定位 / Markdown 四模式）全部换成内联 SVG。

> 往后新增控件**不要再拿 Unicode 符号当图标** —— 那不是字体，是运气。

### 2. 状态栏重排 + 统一分隔

```
改前：v0.8.5 | ⎇ generation-driven · 52 处修改  50 行    行 1，列 1 (CRLF)    [侧栏字号][编辑字号]
改后：5:1 │ 16 行 │ ⑂ main · 18 处修改                  [侧栏 − 13 +] [编辑 − 13 +]  v0.8.5
```

- **光标位置放最左**（看得最勤的东西不该排在第 4 位），格式从 `行 1，列 1` 改 `5:1`（编辑器通行写法，顺便消掉两个"行"字相撞）
- 组间**统一细竖线** `.sb-d`（1px、透明度 55%），不再用四个空格
- 编码 / 换行符去掉方括号与括号
- 版本号移到最右（开发调试用，不该占着最左的黄金位）
- 两组字号控件一起靠右（VS Code / PyCharm 习惯：左下是状态，右侧是设置入口）

⚠ 实现上用 **DOM 构造**（`createElement` + `textContent`）而不是拼 HTML 字符串 ——
app.js 里没有转义工具，拼字符串等于给将来埋坑（这次第一版写了 `esc()` 直接 ReferenceError，是 dom 测试拦下来的）。

### 3. 路径只出现一次、且用相对路径

- **树根行**：删掉右侧那串完整路径（230px 宽的树里必然截成半截，而项目名就在同一行左边）→ 只显示项目名，完整路径仍在 `title`
- **编辑器工具条**：`tab.path` → 相对项目根的路径（如 `avatars.json`、`src/x/y.json`），完整路径仍在 `title` 与「复制路径」按钮里

### 4. 标签统一宽度 + 当前标签常驻关闭按钮

- `.tab` 从"宽度跟着文件名走"改成 `flex: 0 0 152px`（超出中段省略）→ 一排整齐
- `.tab.active .tclose` 常驻显示：想关的多半就是眼前这个，不该非得先把鼠标移上去

### 5.「14 项目」→「全部项目 + 数量徽标」

`▾ 全部项目 [14]`：文字说清这是入口，数量做成 accent 色的小徽标（不再和文字混在一起）。

## 三、验证

- `npm test` **306 项全绿**（语法 26 + git 45 + dom 235）
- `electron . --check-ui`（headless）**209 项全绿 / 0 失败**
- 自检新增/更新断言：状态栏组间有分隔线、字号控件在右侧、信息在前（光标优先）、
  「全部项目」入口显示项目数
- 截图复核：状态栏 `5:1 │ 16 行 │ ⑂ main · 18 处修改 … 侧栏 13 / 编辑 13 / v0.8.5`；
  顶栏 `▾ 全部项目 [14]`

## 四、测试被牵动的地方（改动会影响断言，别只改代码）

- 状态栏光标 `行 1，列 4` → `1:4`、`(CRLF)` → `CRLF`
- 5 处用 `.root-path` 判断"当前是哪个项目" → 改用 `App.root`（树根不再挂路径 span，
  而且大项目虚拟滚动时树根行可能压根不在可视窗口里）
- md 模式按钮按文案查找必须用**精确匹配**：`◉ 预览` → `textContent.trim() === '预览'`，
  因为 `预览` 是 `实时预览` 的子串，`includes` 会先命中「实时预览」把按钮点错
- 「全部项目」断言 `/1\d\s*项目/` → `/全部项目\s*\d+/`
