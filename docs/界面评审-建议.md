# MyIDE 界面评审与改进建议

> 评审对象：`renderer/index.html` + `renderer/styles.css`（v0.8.5，dev 分支）
> 评审依据：① 项目自身的《AI 产品 / UX / UI 一体化设计规范》；② 实现内部的一致性；③ 可读性底线
> 总体结论：骨架已经是一个"能用的专业工具"——工具窗口分组、图标规格、焦点态策略都站得住。
> 问题只剩两类：**同一件事在代码里有两套写法**（分界线、选中态、图标），以及**几个数值低于可读阈值**。
> 都是小改，但直接影响"看起来专不专业"。

---

## 一、必修（P0）

### 1. 分界线还剩 6 处用旧色，等于看不见

doc 050 用 `--border-pane`（由 `--text` 派生）替换了主分界线，但下面这些仍是 `--border: #101010`（`styles.css:8`）。
在 `#141414`–`#1e1e1e` 的底色上，`#101010` 的对比度不足 1.1:1 —— 肉眼等于没有：

| 位置 | 现象 |
|---|---|
| `styles.css:291` `#tabbar` 下边框 | 标签栏与内容区之间没有分界 |
| `styles.css:295` `.tab` 右边框 / `:300` `.tab-all` 左边框 | 相邻标签糊成一片 |
| `styles.css:161` `#tool-sidebar` / `:205` `#tool-sidebar-r` 下边框 | 侧栏收起按钮与工具按钮没有分界 |
| `styles.css:193` `#sidebar-resizer` 静息底色 | 4px 拖拽条平时完全看不到，只能靠 hover 发现 |

**建议**：结构分界线统一到 `--border-pane`；`--border` 只留给"贴边装饰"，或者直接删掉这个变量，避免以后又用错。

### 2. 选中态是硬编码蓝，不跟随主题

`styles.css:6` `--bg-selected: #2d4f6b` 是写死的蓝。
配合自定义主题（例如粉色 accent）时，界面其他地方都跟着 accent 走，只有选中行还是蓝的 —— 一眼看出"两套配色混着"。

**建议**：改成派生，和 `--border-pane` 同一套思路：

```css
--bg-selected: color-mix(in srgb, var(--accent) 34%, var(--bg));
```

### 3. 三处字色低于可读阈值

| 变量 | 现值 | 用在哪 | 实测对比度 |
|---|---|---|---|
| `--text-dim` | `#808080`（`:11`） | 状态栏 11px、非激活标签、占位符、各类 hint | 侧栏底 **4.45:1**、编辑区底 **4.25:1** → 低于 AA 的 4.5:1 |
| `--num-dim` | `#5f5f5f`（`:33`） | diff 行号 | **2.7:1** → 行号基本读不出来 |

**建议**：
- `--text-dim` → `#8c8c8c`（≈5.2:1）。它承载的是状态栏、标签、占位符，全是"看错就误操作"的地方，不该省这点亮度。
- `--num-dim` → `#707070`（≈3.7:1）；或只在"未改动行"降级，改动行行号保持正常亮度。

### 4. 图标系统只做了一半

doc 050 把工具栏 / 左侧工具条 / 目录树头换成了 16px 线性 SVG（`svg.ic`，1.4 描边），
但**数据库 / 内置浏览器 / Git 日志 / 任务 / 依赖图** 仍是 emoji + Unicode 符号混排 —— 同一个界面里并存两套图标语言，光学尺寸和基线都不一致。

最该修的一处：

- `index.html:236-241` 依赖图工具栏：`⛓`（布局）、`⛓`（关键路径）、`🤖`、`⛶`、`🧹`、`＋`
  → **`⛓` 被两个完全不同的功能复用**，而且这一排只有 title、没有可见标签，只能靠 hover 猜。

其余清单：

- `index.html:112-113` `🗑` / `🔄`（数据库连接管理与刷新）
- `index.html:184` / `:186` `☆` / `📌`（收藏 / 收藏夹）、`:198` `⟳`、`:201` `🌐`、`:195` `⚠️`
- `index.html:255-257` `⇄` / `🔄` / `✕`（Git 日志）
- `index.html:133-135` `◉` / `⟲` / `⊘`（任务面板）
- 占位符里也塞了图标：`:139` `🔍 过滤任务标题…`、`:250` `👤 作者过滤…`、`:251` `🔍 消息 / 哈希…`
  → 占位符在替代 label 职责（规范 §18：不要用 placeholder 代替 label）

**建议**：
1. 把 `svg.ic` 规格铺到所有工具面板，删除 emoji；
2. 依赖图那组拆成三个语义不同的图标（拓扑 / 关键路径 / AI），并给最高频的 1–2 项加可见短标签；
3. 过滤框的 `🔍` 改为输入框内嵌 SVG（目录树搜索 `styles.css:213-224` 已经是这个范式，直接复用）。

### 5. 状态栏是一行"连写"，信息层级为零

`app.js:319-324` 把 `版本 | 分支 | 行 | 光标 | [编码] (换行符)` 用 `'    '`（4 个空格）拼成一行纯文本。实际观感：

```
v0.8.5 ⎇ 非 Git 仓库 119 行 空 119 列，界 1
```

三个问题：
1. **4 个空格不是分隔符** —— 字段边界只能靠猜；
2. **括号混用** —— `[utf-8]` 和 `(CRLF)` 用两种符号表示两个同级属性；
3. **光标位置没有定宽** —— 数字位数变化时整行会左右抖动。

**建议**：
- 字段之间改用"静默分隔"：1px 竖线或 `·`，并给每个字段定宽；
- `行:列` 用等宽字体 + `min-width`，消灭抖动；
- `v0.8.5` 属于开发信息（规范 §9 渐进式披露 / §25 诊断不污染普通界面），建议挪到「帮助 → 关于」；最左侧这个最抢眼的位置给"当前项目名"这类用户真正在意的信息。

## 二、建议（P1，需要一点判断，不是纯改色）

### 6. 桌宠压住了状态栏右侧的交互控件

`styles.css:1371-1376` `#pet { position: fixed; right: 18px; bottom: 14px; width: 52px; height: 52px; cursor: pointer }`
状态栏高 22px，右端正是「编辑 字号 −/+」和背景透明度滑条（`index.html:305`）。
52px 的玩偶正好盖在这一排控件上，而且它自己抢点击。

`#toast-wrap`（`styles.css:1368`，`bottom: 86px`、`z-index: 300`）同理：打开 AI 面板时会盖在输入区上。

**建议**：`#pet` 的 `bottom` 抬到状态栏之上（≥ 30px），或把状态栏右端控件左移让出 60px 安全区；Toast 按当前停靠的工具窗口动态避让。

### 7. 常驻呼吸动效与本项目规范冲突

`styles.css:1374` `animation: pet-breathe 3s ease-in-out infinite`，全站 `prefers-reduced-motion` 分支 **0 处**。
而《设计规范》§28 明确把"呼吸效果 / 无意义循环动画"列为禁止项。

**建议**：玩偶保留（它是产品性格，不是噪声），但补三件事：
1. `@media (prefers-reduced-motion: reduce) { #pet { animation: none } }`；
2. 窗口失焦 / 长时间无操作时暂停动画；
3. 设置页提供"关闭玩偶动画"开关。

### 8. 窗口控制按钮不像窗口控制

`index.html:26-28` 的最小化 / 最大化 / 关闭是 `─` `□` `✕` 三个字符，套在与"打开项目"同款的描边按钮里（`padding: 2px 9px` → 命中区约 30×24）。
两个后果：① 形态上和功能按钮同权重；② `□` 的字形大小/粗细随机受字体影响。

**建议**：三个控制项换 SVG（与 `svg.ic` 同规格）、常态去掉描边、命中区放大到 46×32、贴到窗口最右缘。这是用户对 Windows 应用最本能的一处预期，性价比很高。

### 9. 右侧工具条为 1 个工具保留了 38px 常驻栏

`index.html:300-303` 右侧只有「收起右栏」+「AI 助手」两个按钮，却常驻 38px 宽的竖栏（`styles.css:198-204`）。
按规范 §9「低频操作降低视觉层级」，这里权重给高了。

**建议**：折叠进 AI 面板头部一个开关按钮，把这 38px 还给编辑区；或未打开任何右栏工具时整条不显示。

## 三、保留（不要为了"统一"改掉）

- **`svg.ic` 规格**（16px / 1.4 描边 / `currentColor`）与 **工具栏 `.tb-sep` 分组**（左侧动作 | 项目 | 右侧功能 | 窗口控制）——全站最稳的一处结构，第 1、4 条建议正是把它推到底。
- **`:focus-visible` 用 `outline-offset: -1px` 并排除编辑器与输入框**（`styles.css:41-44`）——键盘可达，又不和 CM6 光标打架。
- **`--border-pane` 由 `--text` 派生**这条思路 —— 自定义配色自动跟随，方向完全正确。
- **启动页 `.empty-card`**（图标 + 标题/副标题 + kbd 胶囊 + 唯一主按钮 + 纵向最近项目）——层级清楚，不要退回"居中大 emoji + 一排灰字"。
- **状态栏与侧栏字号分设两套**（`--ui-font-size` / `--tool-font`）—— 工具窗口和编辑区确实需要不同基准，这个拆分是对的。

## 四、验收方式

项目自带 `--check-ui` 会逐阶段截图（`check-ui-*.png`）。改完后在 `scripts/check-ui-steps.js` 的 `chrome` 分组补三条断言即可锁死：

1. 分界线色值 —— 断言 `#tabbar` 的 `border-bottom-color` 等于 `--border-pane` 计算值；
2. 选中态跟随 —— 切换 accent 后断言行选中态背景随之变化；
3. 状态栏分隔 —— 断言字段之间存在分隔元素（而非纯空格拼接）。
