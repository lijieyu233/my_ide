# 文件替换失败保全（FS-01 / FS-C）

> 2026-10-01；实施前基线 `609625e`。按090-B、093-FS-C先修复直接截断目标的失败路径，不整体关闭FS-01。

## 实施合同

1. 文本和二进制IPC共用生产文件写入模块。编码完成后才开始写盘；同目录随机临时文件以wx独占创建、循环处理短写、fsync、close后替换。任何失败禁止unlink原目标或回落直接覆盖。
2. 现有文件保留mode（POSIX还保留uid/gid）；符号链接/junction解析到真实目标，保留链接本身，替换前复查路径身份与原字节，拒绝写入期间的变化。多硬链接文件先明确拒绝替换，避免原本共享的文件突然分叉。新建在Windows用不带REPLACE_EXISTING的MoveFileExW，在POSIX用排他link提交，禁止覆盖写入期间出现的文件；不能让Windows新建依赖FAT/exFAT不支持的硬链接。
3. 失败返回稳定errorCode，清理仅限本次确实独占创建的临时文件。清理失败准确返回恢复来源，不能删除其他文件。成功返回不再留下临时正文；进程在提交前退出可能留下临时文件，按精确命名与年龄另定恢复清理合同，本包不自动删历史残留。
4. 测试用真实系统临时文件及生产模块，分阶段注入open、短写/零写、fsync、close、rename/link失败；每项比较原字节、临时文件和结果。测新建、普通替换、二进制、权限、符号链接、硬链接及提交途中外部修改。Windows实际占用/只读另做原生取证。
5. 接真实隐藏Electron窗口/IPC保存测试，保留101的失败闸门和在途输入。后台npm test；新模块进入语法、产物门槛和build.files，提交推送核对并重启MyIDE。

## 边界与后续

这包只接fs:writeFile/fs:writeBinary。任务/AI经这两条IPC的落盘得到替换保全，但它们的旧快照/撤销/事务策略尚未迁移；DB、设置及主进程其他直接写入仍逐项接入。BOM/UTF-16BE/GBK有损问题按FS-A另包修，读取到保存之间的外部修改按FS-B携带version修；本包只拒绝写入操作开始以后观察到的目标变化，不冒充跨应用compare-and-swap。

Windows使用`ReplaceFileW`（flags=0，不忽略ACL/元数据错误），通过固定版本Koffi 3.3.2调用系统API。临时正文写入前用原DACL/继承标记保护临时文件；原生替换还提供随机backup路径，1176/1177等部分提交错误保留原文件副本及待保存临时文件。普通rename不能证明这些属性保全。官方依据：[Microsoft ReplaceFileW](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-replacefilew)、[Koffi调用约定](https://koffi.dev/start)。

自定义DACL、ADS、创建时间与Windows占用/只读已纳入真实本机测试；压缩/加密/企业保护、多硬链接安全更新、POSIX扩展ACL、突然退出后的恢复清理仍需后续验收。fsync临时文件不等于突然断电后的目录持久性；提交后的响应丢失也不能保证客户端收到成功。低概率清理失败会返回cleanupError/recoveryPath，恢复浏览与容量/保留期管理尚未交付，不宣称整个FS-C合同关闭。本包没有新UI或新快捷键，不以保存测试截图宣称整个工作台视觉达标。
