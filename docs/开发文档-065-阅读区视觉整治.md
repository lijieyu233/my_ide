# 开发文档-065 · 阅读区视觉整治（正文收窄 / 流程图独立成块 / 线条与强调色减面积）

> 触发：用户贴出 Markdown 阅读界面的截图，逐条给出**纯视觉**观察：
> 区域顶得太满、大块深色面积连续、横向元素太长、边界太密、强调色覆盖范围偏大。
> 明确要求：只谈观感，不评价目录展开策略 / 工作集 / 大纲逻辑 / 交互功能。

## 一、先量，再改

观感问题最容易凭感觉调，所以先把用户截图按像素量一遍（1823×983，深红主题）：

| 量的对象 | 实测 |
|---|---|
| 编辑区宽度 | x 332 → 1823 = **1491px**，正文一行横跨整个宽度 |
| 正文列 `.md-view` | 设了 `max-width: 820px` 却**完全没生效** |
| 流程图块 | x 360 → 超出窗口右边缘；底色 `#180e13`（`--code-bg`） |
| 流程图底色 vs 正文底色 | `#180e13` vs `#2a171d`，明度差 **12 级** |
| 正文标题 | `#f2cfdb`（R−G=**34**，明显发粉） |
| 分界线 | `--border-pane: text 16%` |
| 目录名 | `accent 62% + text` |

两个根因当场就出来了：

1. **`#viewer > .md-view { max-width: none }`** —— 选择器优先级（1,1,0）高于 `.md-view`（0,1,0），
   把正文列的宽度上限**整个压掉了**。所以"设了 max-width 却一直满宽"。
2. 流程图在 Live Preview 里是 `.cm-md-mermaid::before { background: var(--code-bg) }` ——
   比正文底色暗 12 级，面积一大就是页面中间的一个黑洞。

## 二、改了什么

### 2.1 正文列收窄并居中（两种模式）

```
改前：正文满宽 1491px，一行要横扫整个窗口
改后：正文列 820px，居中，两侧各留 191px（窗口 1600 时）
```

- `.md-view`：`padding: 16px 24px` → `22px 34px 38px`，`max-width: 820px`，居中
- Live Preview：列宽上限挂在 `.cm-scroller` 上（`max-width: 876px = 820 + 两侧 28 内边距`），
  `.cm-content` 只管上下内边距

⚠ **踩了两个 flex 坑，都记进 MEMORY**：

1. **`margin: 0 auto` 在 flex 容器里会让元素变成 `fit-content`** —— `#viewer` 是 column flex，
   `.md-view` 一旦有 auto 的横向 margin，`align-self: stretch` 就失效、元素按内容宽度算。
   实测编辑区 582 时列宽只有 417，换一篇文档又变成另一个宽度。
   正解：`width: 100%` + `max-width` 给**确定宽度**，居中用 `align-self: center`。
2. **`.cm-content` 的 `flex-grow` 会把自由空间全吃掉**，auto margin 拿不到剩余空间 → 居中不生效。
   所以列宽上限挂到 `.cm-scroller`（它是 `.cm-editor` 的 cross-axis 项，`align-self` 好使）。
3. **纵向滚动条会吃掉右侧 10px** → 文字列看起来偏左（实测左 71 / 右 81）。
   `scrollbar-gutter: stable both-edges` 两侧都预留，正文才真居中。

### 2.2 流程图 = 独立内容块

```css
.mermaid-box {
  margin: 18px 0; padding: 18px 16px; border-radius: 10px;
  background: color-mix(in srgb, var(--bg-input) 52%, var(--bg));
  border: 1px solid color-mix(in srgb, var(--text) 9%, transparent);
}
```

Live Preview 的 `.cm-md-mermaid::before` 同样处理（原来是 `--code-bg`）。
底色与正文的明度差从 **12 级 → 1 级**，同时用细边 + 圆角把它标成"一个块"。

### 2.3 内边距 +20%~40%

| 项 | 改前 | 改后 |
|---|---|---|
| 正文左右 | 24px | 34px |
| 正文上/下 | 16 / 24 | 22 / 38 |
| 标题上边距 | 13px | 18px |
| h1 / h2 上边距 | 18 / 15 | 24 / 20 |
| 段落间距 | 6px | 9px |
| 流程图块上下 | 10px | 18px |

### 2.4 弱化分隔线与边框

- `--border-pane`：`text 16%` → **`11%`**（顶栏底线 / 侧栏右线 / 面板标题线）
- 标签栏底线、标签右线、操作区左线、`▾ 全部标签` 左线：`var(--border)` → `color-mix(text 8%)`
- 正文 `pre`：**去掉描边**（只留底色），圆角 6 → 8
- 正文 `hr`：`var(--border)` → `color-mix(text 10%)`
- 表格线（含 Live Preview）：`var(--border-mid)` → `color-mix(text 12%)`
- Live Preview 围栏代码块的左/右/上/下描边全部去掉

原则：**区域之间靠明度阶梯分开，线只做提示**。

### 2.5 强调色减面积

| 位置 | 改前 | 改后 |
|---|---|---|
| 正文标题（深红主题） | `--md-heading` = `text-bright 90% + accent` → `#f2cfdb` | **`#f2eef0`**（中性暖白，R−G 从 34 → 5） |
| 其余主题标题 | `text-bright 90% + accent` | `text-bright 93% + accent` |
| h3（正文 / Live 各一处） | `accent 62% + heading` | `accent 34% + heading` |
| 引用竖线 | `3px solid accent` | `2px solid color-mix(accent 55%)` |
| 目录名 `.nm-dir` | `accent 62% + text` | `accent 44% + text` |
| 当前标签上边线 | `2px solid accent` | `color-mix(accent 65%)` |

深红主题单独给 `--md-heading` 一个中性值：该主题的 `--text-bright` 本身是粉白 `#f2dce4`，
跟 accent 混出来的标题必然是粉的 —— 用户要的是"标题偏白灰，粉红只留给少量重点"。

### 2.6 背景底图再弱一档

- 默认透明度 **0.15 → 0.10**（`theme.js`）
- 内容区不透明度 80% → **88%**（`body.has-bg` 那组规则）：底图只在四周透出来，
  正文压得更实 —— "在本来就偏满的页面里，水印仍是一层视觉信息"

## 四、教训

1. **"设了某条 CSS 却没生效"要先查优先级**，不要怀疑数值。
   `#viewer > .md-view { max-width: none }` 这种"为了占满而写"的规则，会在半年后变成
   "为什么上限不起作用"的谜题。
2. **flex 上下文里的 `margin: auto` 不是"居中"的同义词** —— 它会顺带把尺寸变成 `fit-content`。
   要定宽就用 `width` + `max-width` + `align-self`。
3. **滚动条是 10px 的对称性杀手**：列居中了，但内容看着还是偏 —— `scrollbar-gutter: stable both-edges`
   才是"真居中"。
4. 断言要**量真实几何**并且**在能暴露问题的条件下量**（把 AI 助手收起来再量），
   否则"列宽 ≤ 860"在 582 宽的编辑区里永远通过，等于没测。
