# Git 历史面板卡顿优化

2026-10-17。针对 mh_admin_suite 底部 Git 历史与上方差异预览切换卡顿。

## 定位与结果

- 只读实测仓库：历史查询约795ms；提交文件列表约29ms；示例 JSON 差异计算约27ms、1667行。查询在worker内运行；本批主要修复渲染线程的同步DOM工作。
- 原先大块虽然默认折叠，仍先创建全部行和单元格，再逐行display:none；新文件/生成文件切换仍付出整份绘制成本。
- 相同1667行jsdom对比：原先约216ms/8346个DOM节点，改后约6ms/14个节点。这是同机该次测量，不代表所有文件固定耗时。
- 隐藏真实MyIDE打开示例提交a885a4c，差异绘制约1.4ms；历史355条首次显示约1092ms。50000行折叠块仅14个节点、约0.3ms构建。历史查询和首次列表加载仍有实际开销，不能把绘制时间称为完整操作时间。

## 行为

- 超过30行的块初始只建分隔行；展开时最多创建200行，继续显示按钮逐批加载，文本、原行号和顺序保留。小块保持直接展开。
- hunk身份与原快照不变，暂存/取消暂存/回退仍作用于原完整块，不把当前可见200行当作新的提交范围。
- 同一历史查询共享在途请求；结果不变时保留列表、滚动位置和已选差异文件，不再自动清空并打开第一个文件。
- 项目切换、隐藏和查询代次隔离过期结果，A→B→A期间迟到结果不能覆盖新项目。退出分支对比时仍重建普通列表。
- 搜索按OID索引查提交，避免加载更多后逐行find形成二次扫描。

## 验证入口

- tests/git-diff-render.test.js：大块折叠零代码行DOM、200行分批、最终行号无遗漏、多块顺序、折叠恢复、文本转义与原hunk操作。
- tests/git-log-refresh.test.js：并发合并、结果不变保留DOM/滚动/文件选择、项目往返与迟到请求隔离、退出分支对比。
- tests/git-log-selection.test.js：连续选择最后一项优先、文件差异竞态、缓存、隐藏后忽略迟到结果。
- scripts/check-git-history-performance.js：独立profile、隐藏生产窗口、只读真实仓库与IPC。可传 --repo=绝对目录，包含真实差异与50000行折叠检查；不修改目标仓库。
