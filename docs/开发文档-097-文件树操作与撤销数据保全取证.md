# 文件树操作与撤销数据保全取证

> 2026-10-01，第八轮持续审计；基线 `827fb33`，MyIDE 0.8.5。
> 对应 [089 总台账](./开发文档-089-全模块成熟项目对照与持续改进台账.md) 的 TREE-01，并依赖 EDIT-01/FS-01/PROJECT-01。本轮为证据和实施方案，未修改产品/测试；**现有文件操作的数据保全升P0**，10k/50k目录性能仍P1待验。

## 1. 方法、范围与安全落点

主实验使用 **Node v22.20.0 / jsdom 29.1.1 / Windows真实临时文件**。原样截取main.js的fs:mkdir/writeFile/rename/move/remove/checkExists/copy处理器，VM注册为函数表；完整eval实际tree.js和viewer.js，不复制操作或undo算法。IPC桥直接调用原处理器，目录读取/UTF-8正文读取为真实磁盘桥；Modal自动确认/提供名称，CodeEditor只提供创建/销毁/状态桩。只覆盖这些调用所用控制流，不代表真实IPC序列化、完整应用或CM6视觉验证。

F1–F11共11类观察（F1含文件、目录两个fixture），另有新目标复制/撤销正向对照C1。F3注入桥返回{error}；F11只替换当前fixture的copyFileSync为“写PART后抛EIO”，是真实目标字节变化加受控失败，不是实际ACL/磁盘故障。其他fixture直接执行实际Windows文件操作。没有更改本仓库文件树、用户文档、系统剪贴板或回收站。

补充 **Electron33.4.11内置Node20.18.3** 的原处理器/真实临时文件对照N1–N4，确认覆盖重命名、普通writeFile截断、目录合并、自动改名后的反向move行为一致。使用隔离userData、--headless/--disable-gpu/--no-sandbox；没有创建可见窗口，入口在app.ready前设置profile。不是完整Electron渲染层点击取证。

DOM脚本stdin执行，每个fixture独立jsdom并关闭；finally核对临时目录在os.tmpdir内、真实路径一致、basename前缀myide-audit097-后删除。原生对照入口/profile/report在另一独立临时目录，进程退出0、报告读取并确认无相关进程后清理。没有长期保留一次性脚本或截图。

尚未验证跨卷EXDEV、junction/符号链接、NTFS大小写特性、锁定文件、ACL/属性保全、批量中断、进程崩溃恢复或10k/50k性能；不能据此宣称这些都支持或都失败。

## 2. 当前失败行为与真实结果

| 编号 | 输入/动作 | 输出与文件结果 | 原因 |
|---|---|---|---|
| F1-file | src/a.txt=NEW，dest/a.txt=ORIGINAL；确认覆盖粘贴，再undo | 粘贴后NEW；undo后目标不存在，源仍NEW | copyInto把所有成功target记成created；paste逆操作一律remove，没有目标旧字节来源 |
| F1-dir | src/pack只有a=NEW；dest/pack有a=OLD和keep=UNSELECTED；覆盖粘贴再undo | 复制合并保留keep；undo删除整个pack，keep也不存在 | cpSync递归默认合并；顶层target不是本次完整新建，不能整目录删除作逆操作 |
| F2 | a=SOURCE、b=DESTINATION；renameItem(a,'b.txt')再undo | rename后b=SOURCE，原b字节被覆盖；undo后a=SOURCE、b不存在 | fs.renameSync允许覆盖已有文件；重命名没有冲突/备份，旧目标未进入undo |
| F3 | 正常a→b后，undo时rename桥返回{error:'EACCES-injected'} | b仍在，却toast“已撤销”；下一次“没有可撤销” | undo先pop，只await不检查结果；处理器通常resolve错误对象，catch不触发 |
| F4 | 真Viewer打开a，Tree重命名a→b再undo；继续编辑并saveTab | 磁盘恢复a，但活动tab仍指b；保存后a=A、b=EDIT，b被复活 | 正向rename同步Viewer，逆向不发路径迁移；不是复现自动保存定时器，但实际saveTab已写出错误身份 |
| F5 | 打开folder/child.txt，Tree重命名folder→renamed，再保存dirty子标签 | tab旧路径不存在；新路径CHILD不变，dirty仍true | Viewer.renamed只匹配完全相等文件路径，没有映射目录后代；本fixture保存失败而非丢dirty |
| F6 | 根已有existing.txt=ORIGINAL；右键“新建文件”输入同名，再undo | 新建把内容截为空；undo删除existing.txt | createItem用普通writeFile，未排他创建；undo当作本次新对象删除 |
| F7 | Delete删除含child.bin的folder，再undo | 确认文案承诺“Ctrl+Z可撤销”；目录已删除，undo提示没有可撤销 | fs:remove是永久rm；目录不做backup。二进制/超大文件同样不备份为C，未在单文件fixture运行 |
| F8 | 删除a=OLD；外部在原路径写EXTERNAL_NEW；undo | 最终a=OLD，外部新字节被覆盖 | 删除恢复直接writeFile，无目标缺席/版本前提 |
| F9 | 向新目标粘贴a=COPY；外部改目标为LATER_EDIT；undo | 后来的编辑一起被删除，目标不存在 | paste撤销只按路径remove，不校验操作后版本/身份 |
| F10 | 剪切src/a到已有dest/a，正向自动命名a (1).txt，再undo | 文件回到src/a (1).txt；原src/a不存在 | undo只保存oldDir，反向move沿用当前basename，丢失原始名字；再遇同名还会继续自动改名 |
| F11 | 覆盖复制中注入写PART后EIO | 目标仅PART，toast失败；undo没有条目 | 错误路径没有已修改目标/恢复来源，失败不等于无副作用；此处未证明Node真实copyFile必然按同样方式失败 |

**C1正向对照**：新目标不存在，正常复制得到COPY；undo删除这份未改副本，源仍COPY。保留该正确路径，不能将所有undo禁用或所有复制改成“永不覆盖”作为完整解决方案。

F4/F5使用完整Viewer，但CM6状态为桩，未测编辑器焦点/光标。F6通过完整Tree右键菜单“新建文件”事件，F7/F8通过Delete事件；其它通过公开操作API，不声称已经模拟真实鼠标拖放。F3/F11的注入与正常磁盘结果分开标注。

## 5. 分包实施合同

### 097-T-A：先阻止新建/覆盖/撤销无条件破坏（TREE-01，P0）

建议分“排他新建/冲突决策”和“可恢复覆盖/撤销”两个逻辑提交：

1. 新建文件用明确createOnly接口，排他打开wx；目录明确是否允许复用已有项，不能把已存在目录记为本次新建。名称/相对路径策略先明确，最终归属由主进程判断，不能只靠renderer字符串过滤。
2. rename/copy/move统一冲突策略{reject,keepBoth,replace,merge}和最终目标预览。保留用户明确选择的覆盖能力；replace/merge在恢复来源准备完成前不得修改目标。exists只用于提示，写入仍需排他/身份条件；rename无覆盖需要平台适配，单纯Node exists+rename不能保证外部进程竞态安全。无法满足时受控失败，不偷偷回到无条件覆盖。
3. 覆盖文件保存旧字节/格式/身份；目录merge逐个记录替换、新建、未触及项及目录元数据，不能只记录顶层target。准备/发布沿用093的临时写/版本/替换合同；复制失败返回partial和恢复来源。多文件/目录不承诺天然单次原子，显示已完成/失败/未执行并提供回滚结果。
4. undo按真实操作逆向恢复：新建副本仅在仍为本次对象/版本时删除；覆盖恢复旧目标；merge只逆转本次变更，保留keep；rename/move同时记录oldPath和finalPath，逆向不再自动改名。目标被外部重建或操作后被编辑，返回STALE_OPERATION/DEST_CONFLICT，先保留两份，给差异/另存/明确覆盖决定。
5. 一条journal保留projectId、operationId、items、before/after版本、recoveryRef、阶段及逐项结果。undo先peek，确认成功后才推进栈；错误对象和rejection归一化，失败可重试/导出，部分成功可精确继续，重复operationId不重复破坏。栈过期/恢复来源不可用时明确显示，不虚报成功。

验收：F1/F2/F6原字节可恢复、目录keep始终存在；F8/F9旧undo不覆盖/删除后来内容；F3失败仍有可重试记录且不报成功；F10恢复原名。保留C1与正常冲突确认/取消。检查最终字节/路径/未选内容，不以toast为唯一证据。先加这些完整行为回归，再改结构，不能只新增与实现同构的undo字段断言。

### 097-T-B：路径身份与编辑器保存队列协调（TREE-01 / EDIT-01 / PROJECT-01，P0）

每个打开文档有稳定docId，路径迁移是操作结果中的{oldPath,newPath,type,affectedDocs}；文件和目录后代按路径段/平台规范化映射，正向与撤销都发同一事件。映射同步更新Viewer/会话/最近项/AI上下文/树选择与展开，不能只修改active tab或对原字符串完全相等。

与090-A保存队列统一：操作开始固定相关doc revision与项目上下文；pending旧路径保存需要协调完成或取消，不得在磁盘move后复活旧名字。覆盖目标已有dirty标签先保留内存稿并让用户明确决定，不能暗中将其当磁盘旧版本备份。目录删除涵盖后代dirty文档；删除后标签标为源文件已删除，保存明确另存/恢复，不能无提示创建旧路径。

验收：F4 undo后活动tab指a，后续保存只写a；F5目录改名后child映射到新路径，dirty内容可正常保存。补“旧保存等待→rename→旧保存完成”、两目录/多个tab、大小写改名、路径分隔符、undo遇已打开目标、跨项目操作晚回。不确定平台别名/junction时拒绝危险操作并说明，不能全平台lowercase或startsWith当归属判定。

### 097-T-C：删除恢复与确认语义（TREE-01 / FS-01 / SESSION-01，P0）

普通删除优先提供可恢复策略：本应用明确恢复来源或系统回收站。Ctrl+Z需有实际可用的恢复来源，包含目录、二进制、原始编码/BOM，不能仅readFile文本快照。系统trashItem无恢复token：若仅能引导去回收站恢复，文案就说明该方式，别继续承诺应用Ctrl+Z。永久删除单列动作，失败不能自动降级为永久rm。

删除前去重父子/重复路径，确认受影响dirty文档与恢复范围；获取恢复来源和版本后再删除，读备份与删除之间源变化则重新决策。删除恢复对原路径要求缺席或匹配预期，冲突提供另存/差异，不覆盖外部新文件。journal和备份放独立可写位置，沿用原字节保存服务，受容量/保留期控制；备份失败或超限必须在破坏前说明可恢复性，不能事后显示“可撤销”。

预算建议起步：恢复数据总额256MiB、保留7天、最多50次近期操作，均待真实目录测量。仍在执行或待重试的操作不因栈截断静默清除唯一来源；已完成/过期项明确可清理。不要将普通备份写进被删除的目录内部。重启恢复需独立manifest校验与残留清理，不能把内存undo栈等同Local History。

验收：F7不再承诺不存在的undo；目录/二进制/大文件分别有明确恢复或永久删除提示。磁盘备份失败、回收站失败、目标重建、版本变化、锁定文件、权限不足和两项中一项失败都保全可用来源；实际回收站fixture需独立临时文件，并只清理该fixture，不触碰用户回收站。当前审计未执行回收站操作。

### 097-T-D：批量/跨卷与文件树性能（TREE-01 / PERF-01，P1）

批量操作先规范化/去重父子，返回每项结果及一个逻辑组operationId，undo一次对应用户一次操作。移动跨卷EXDEV需独立“暂存复制→校验→发布→确认后删除源”流程，失败保留源，不用无条件copy+rm代替rename。链接明确复制链接还是目标，禁止目标落到源后代或通过junction绕过；权限/锁定/长路径按能力报错。

cut状态是否在失败后保留可重试需明确；当前一次性清空本身不作为数据丢失证明。多项目undo可选全局可见journal或按项目栈，但必须展示归属，不用当前root悄悄解释旧操作。进度/取消不能在“取消”后继续提交已过期动作；已完成项仍能恢复，源/目标读写队列与外部版本检查区分。

性能保留现有懒加载、虚拟滚动、renderChain和Git未知清单兜底，先测10k/50k、大目录展开/快速切项目、watch连续事件、树选择/拖放耗时。后台异步文件IO/worker是否有必要由数据决定，不重写整棵树来修文件操作。真实Electron截图核对SVG图标、同名决策、失败/部分成功状态、键盘焦点；本轮只作方案，不宣称性能达标。

## 6. 覆盖粘贴撤销的最小复跑

仓库根将下面代码送给node stdin，使用完整Tree和原copy/remove/checkExists处理器、真实临时目标。它只复跑F1-file，不替代其它场景；当前错误行为断言在修复后应改成恢复ORIGINAL。

```js
const fs = require('fs'), path = require('path'), os = require('os');
const vm = require('vm'), assert = require('assert'), { JSDOM } = require('jsdom');
const root = fs.mkdtempSync(path.join(os.tmpdir(), 'myide-audit097-'));
let dom;
(async () => {
  try {
    const raw = fs.readFileSync('main.js', 'utf8'), handlers = {};
    const part = (name, end) => {
      const a = raw.indexOf("ipcMain.handle('" + name + "'");
      const b = raw.indexOf(end, a + 1); assert(a >= 0 && b > a);
      return raw.slice(a, b);
    };
    vm.runInNewContext(
      part('fs:copy', '// ---------- IPC：Git') +
      part('fs:remove', "ipcMain.handle('shell:showInFolder'") +
      part('fs:checkExists', '// 复制文件/目录到目标目录'),
      { fs, path, ipcMain: { handle: (k, fn) => handlers[k] = fn } });
    const source = path.join(root, 'src', 'a.txt'), dest = path.join(root, 'dest');
    const target = path.join(dest, 'a.txt');
    fs.mkdirSync(path.dirname(source)); fs.mkdirSync(dest);
    fs.writeFileSync(source, 'NEW'); fs.writeFileSync(target, 'ORIGINAL');
    dom = new JSDOM(fs.readFileSync('renderer/index.html', 'utf8'), {
      url: 'https://audit.invalid', runScripts: 'outside-only'
    });
    const w = dom.window;
    w.MI = { toast() {}, log() {} };
    w.App = { refreshGit() {}, ftIcon: () => '', dirIcon: () => '' };
    w.Modal = { stack: [], confirm: async () => true };
    const call = (k, ...args) => Promise.resolve(handlers[k]({}, ...args));
    w.myIDE = { fs: { readDir: async () => [],
      remove: p => call('fs:remove', p) },
      fsCopy: (...a) => call('fs:copy', ...a),
      checkConflict: (...a) => call('fs:checkExists', ...a),
      clip: { copyFiles: async () => {}, getFiles: async () => [] } };
    w.eval(fs.readFileSync('renderer/tree.js', 'utf8'));
    w.Tree.setRoot(root); await w.Tree.render();
    w.Tree.select(source, 'file'); await w.Tree.copySelected();
    await w.Tree.pasteTo(dest);
    assert.equal(fs.readFileSync(target, 'utf8'), 'NEW');
    await w.Tree.undo(); assert(!fs.existsSync(target));
    console.log('F1: overwritten target was deleted by undo');
  } finally {
    if (dom) dom.window.close();
    const rel = path.relative(path.resolve(os.tmpdir()), path.resolve(root));
    assert(rel && !rel.startsWith('..') && !path.isAbsolute(rel));
    assert(path.basename(root).startsWith('myide-audit097-'));
    assert.equal(fs.realpathSync(root).toLowerCase(), path.resolve(root).toLowerCase());
    fs.rmSync(root, { recursive: true, force: true });
  }
})().catch(e => { console.error(e); process.exitCode = 1; });
```

## 7. 台账、顺序和收尾
