# 开发文档-062：空间比例与信息层级重构

> 起因：用户对着 PyCharm 截图给出 8 条结构性建议，核心判断是
> **「差距不在主题高级与否，而在整体视野、空间比例和信息层级」** ——
> 「PyCharm 是中间大、周围退；你的是左中右三块平分存在感」。
> 前几轮我在调颜色和图标，这一轮按优先级动结构。

## 一、改前先量出来的账

用户在 1920 宽屏上量的（我们自己的截图是 1380×880）：

| 区域 | 改前 | PyCharm |
| --- | ---: | ---: |
| 左侧项目区 | 440px / 23% | 380px / 20% |
| 中央工作区 | 990px / **52%** | 1070px / **57%** |
| 右侧 AI 区 | 465px / 24% | 420px / 22% |
| 顶部导航 | **两套 Tab 层** | 收敛的一层 |

结论：中央被两侧挤掉，且顶栏的「项目胶囊」和下面的「文件 Tab」是同一视觉层级，
一级导航压过二级导航 —— 顶栏读起来像"功能栏"而不是"标题栏"。

## 二、八项改动

### 1」左右收窄，空间还给编辑器

新增 `App.LAYOUT` 作为**尺寸的唯一来源**：

```js
const LAYOUT = {
  sidebar: { def: 340, min: 260, max: 480 },
  ai:      { def: 380, min: 320, max: 520 },
  sideSplit: { def: 0.65, min: 0.2, max: 0.85 },
};
```

CSS 的 `#sidebar { width: 340px; min-width: 260px; max-width: 480px }` 与 `#ai-panel` 同理，
**两处必须一致**（自检里有一条断言直接比对 CSS 计算值与 `LAYOUT`）—— 否则「双击复位」会跳到另一个宽度上。

- 侧栏 280 → **340**（三个上限 480）
- AI 面板 400 → **380**（上限 520），并给 AI 面板补了**之前完全没有的** min/max 钳制
- 两条分隔线都支持**双击恢复默认宽度**
- 存储键改名 `myide-sidebar-width:v2` / `myide-ai-width:v2` ——
  沿用旧键会让老用户永远停在旧宽度上，看不到新默认值

### 2」顶部项目胶囊收成一个下拉

`renderProjectBar()` 增加 `PROJ_PILL_MAX = 3`：

- **项目 ≤ 3 个** → 仍然平铺（一键切换很方便，也不会和文件 Tab 抢戏）
- **项目 > 3 个** → 只渲染一个 `「当前项目 ▾」`，其余全部进下拉

收起态的控件**不是**「选中的 Tab」：`.proj-current` 去掉了 `.proj-btn.active` 的实心 accent 底，
换成标题栏样式（透明底 + 项目图标 + 名称 + `▾`）；`✕` 关闭按钮只在 hover 时出现
（顶栏不该常驻一个危险动作）。点它开的是**项目切换菜单**，而不是"打开当前项目"这种无意义动作。

下拉底部补了「当前项目」的两个动作（复制路径 / 在资源管理器中显示）——
收起态没有右键菜单了，这些动作要有去处。

### 3」酒红主题去饱和：红只做强调色，不做环境光

| | 改前 | 改后 |
| --- | --- | --- |
| `--bg` | `#201318` | `#212121` |
| `--bg-panel` | `#26161d` | `#171717` |
| `--bg-tabbar` | `#1c1015` | `#1a1a1a` |
| `--text` | `#d8b3c0`（粉） | `#b9b9bd` |
| `--text-bright` | `#f2dce4`（粉） | `#e6e6e8` |
| `--accent` | `#f06292` | `#d9687d`（玫瑰红，柔和一档） |
| `--bg-selected` | `#6e3a52`（实心粉块） | `#322229`（去饱和暗酒红） |

改前是「整屏泛红」：底色、文字、标题、边框、选中块全是红的 —— 层级被拉平
（每个地方都重要 = 没有地方最重要）。现在大面积底色是中性黑灰，品牌感只由 `--accent` 承载。

**顺带修掉一个真 bug**：`md-editor.js` 里 markdown 的 heading token 被硬编码成 One Dark 红
`#e06c75` —— 与主题无关，所以**所有主题下标题都是玫瑰红**，还在跟 `.cm-md-*` 的变量染色打架。
已改成 `var(--text-bright)`（strong / link / monospace 同样改用变量）。
代码 token（keyword / string / number…）保留 One Dark：那是代码配色，本就该独立于界面主题。

### 4」选中态减重：弱背景 + 2px 强调线

```css
.tree-row.selected, .outline-item.key-nav-sel {
  background: color-mix(in srgb, var(--text) 9%, transparent);
  color: var(--text-bright);
}
.tree-row.selected::before, .outline-item.key-nav-sel::before {
  content: ''; position: absolute; left: 0; width: 2px; background: var(--accent);
}
```

强调权按层级分配：**当前编辑文件（标签）最强 → 侧栏当前项（弱底 + 竖线）中等 → hover 最弱**。
改前整行铺实心 `--bg-selected`，加上顶部项目药丸、AI 当前文档高亮、编辑器标题色，
屏幕上同时有 4~5 个强焦点。

### 5」Markdown 排版收紧到工具型密度

| | 改前 | 改后 |
| --- | ---: | ---: |
| h1 | 26px | **21px** |
| h2 | 22px | **18px** |
| h3 | 18px | **15px**（并带淡玫瑰色） |
| 正文行高 | 1.7 | 1.65 |
| 标题 margin | 18/8 | 13/6（h1/h2 单独加大上边距） |
| 正文段距 | 8px | 6px |
| 编辑器内边距 | 20/28 | 16/24 |

标题不再全用同一种颜色：**h1/h2 = 正文亮色，h3 = accent 62% + 亮色混合（淡玫瑰），
链接与关键 token 才用纯 accent**。

### 6」AI 空状态压缩 + 完全折叠

- `.ai-welcome` 从 `height:100%` + 垂直居中 → **靠上 + 紧凑**；`.ai-card` 去掉边框与底色
  （原来是"一张浮在几百像素空白里的对话框"，四周全是空墙）
- 新增快捷键 `Ctrl+Shift+A` = 收起 / 展开 AI 助手（`Ctrl+8` 只管打开，不冲突）

### 7」侧栏上下分栏：项目树 + 大纲（Structure）

`#panel-project` 与 `#panel-outline` 之间加入 `#side-hsplit`：

- 「项目」工具窗口激活时 = 项目树（上，默认 65%）+ 大纲（下）
- 其它工具窗口仍**独占**侧栏（切走时分栏自动收起）
- 拖拽分隔线调整比例、**双击恢复 65%**、比例持久化
- **存的是比值不是像素** —— 拖动侧栏宽度或缩放窗口后仍按比例重算（存 px 会立刻失真）

理由：本 IDE 主要处理 Markdown 与开发文档，文件树与大纲天然是一对；
PyCharm 把 Structure 做成独立工具窗口，在这里同屏更有用。

### 8」尺寸与圆角统一

`--head-h: 30px` 由 `.panel-title` / `#tabbar` / `.ai-head` 共用（上一轮），
这一轮把**面板宽度也收进 `App.LAYOUT`**，做到"所有可拖拽尺寸只有一个来源"。

## 四、踩坑记录（这轮踩得比较多）

1. **重写自检步骤时漏了收尾还原**：新的项目栏步骤最后停在"另一个项目"上，而 AI 面板解析工具路径
   用的是「当前项目根」→ 后面 AI 流程步骤的 `replace_edit` 全报「文件不存在 _ui_outline.md」，
   4 条断言连锁失败。**步骤有副作用就必须收尾还原**，并加一条"收尾"断言自证。
2. **断言读错了元素**：主题变量定义在 `body.theme-*` 上，而断言读 `document.documentElement`
   → 永远拿到 `:root` 的默认值（`--accent` 读到默认蓝）。**主题相关的断言一律从 `body` 读**。
3. **"造探针"式断言是假通过**：我在 `body` 下临时插一个 `.md-view` 探针测标题颜色，测到中性就通过了；
   而编辑器真实渲染路径里的 h1 因为 token 硬编码 `#e06c75` 依然是玫瑰色（截图放大才看出来）。
   **视觉断言要量真实存在的元素**，不能量自己造的样本。
4. **重名**：`const L` 与步骤里已有的亮度辅助函数 `const L` 冲突（`node --check` 直接抓到）。
5. **浅色/粉色的明度阶梯本来就不单调**（tabbar 比 panel 还暗）→ 守卫升级为「四档单调递减」，
   顺手把两个主题的色阶改对了。
6. **测试里 `switchTool` 是"再点一次收起"的切换语义**，想幂等显示要用 `showTool`；
   新用例第一次写成 `switchTool('project')` → 把侧栏整块收起来，断言「项目树在」直接失败。
7. **`python -c` 里写多行 JS 补丁的引号嵌套**又坑了一次（`\\d`、三引号内含引号）——
   改用 heredoc + `python -` 的写法，稳定得多。
