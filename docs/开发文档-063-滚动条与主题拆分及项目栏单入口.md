# 开发文档-063：滚动条 / 主题拆分 / 项目栏单入口

> 起因：用户三条反馈 ——
> ① 标签栏那条滚动条不该出现；
> ② 「我的粉红主题现在不粉红了」+「把现在的这种保存为一个单独的主题」+「纯白的 md 样式很难看」；
> ③ 项目栏两个按钮功能重复。

## 一、标签栏滚动条

`#tabbar` 一直是原生 `overflow-x: auto` —— 标签一多就冒出一条灰滚动条，
**比它下面的标签本身还抢眼**（用户截图圈出来了）。

```css
#tab-scroll { overflow-x: auto; scrollbar-width: none; }
#tab-scroll::-webkit-scrollbar { display: none; }
```

配套在 `viewer.js` 里把滚动交给滚轮（鼠标在标签上上下滚 = 左右滚，IDE 惯例）：

```js
tabScroll.addEventListener('wheel', (e) => {
  if (tabScroll.scrollWidth <= tabScroll.clientWidth + 1) return;
  const d = Math.abs(e.deltaY) > Math.abs(e.deltaX) ? e.deltaY : e.deltaX;
  e.preventDefault();
  tabScroll.scrollLeft += d;
}, { passive: false });
```

「还有更多标签」的提示交给右端的 `▾ N 全部标签`（它 `position: sticky; right: 0`，
不随标签滚走）。

## 二、主题拆分：深红回退 + 新增「石墨」+ md 标题不再纯白

### 1）上一轮把「深红」改中性了，用户要的是"回退"

上一轮我把 `theme-crimson` 去饱和成中性灰 + 玫瑰红 accent，用户认这个新观感
（"把现在的这种保存为一个单独的主题"），但**他的主题本身要回退**（"我的粉红主题现在不粉红了"）。

于是：

| 主题 | 状态 |
| --- | --- |
| `theme-crimson` 深红 | **回退**成原来的酒红暖调（底色/文字/强调色全部恢复） |
| `theme-graphite` 石墨 | **新增** —— 就是上一版的中性黑灰 + 玫瑰红 accent |
| `theme-pink` 粉红 / `theme-light` 浅色 | 一并回退到原值（上一轮我把它们的色阶也改了，同属越界） |

回退时只保留一处调整：**深红主题的明度阶梯对齐**（内容 > 标签栏 > 工具窗口 > 外框），
原来它是 `bg #201318 < panel #26161d` 的倒挂。现在 `#2a171d / #221218 / #1c0f14 / #170b10`。

主题表在 `theme.js`（`ORDER` / `NAMES` / `CLS`）+ 设置页多一个 `🪨 石墨` 按钮。

### 2）「纯白的 md 样式很难看」→ 引入 `--md-heading`

上一轮为了修掉「heading token 硬编码 One Dark 红 `#e06c75`」，我把标题色改成了 `--text-bright`
—— 结果是**近纯白**。用户直接反馈难看。

现在标题有自己的变量：

```css
--md-heading: color-mix(in srgb, var(--text-bright) 90%, var(--accent));
```

「偏亮的正文色 + 一点主题色调」：深红下是暖玫瑰、石墨下是极淡的冷玫瑰、浅色主题里
`--text-bright` 本身是深色所以自动变深。`.md-view h1..h6`、CM6 的 `.cm-md-h1..h6`
和 heading token 三处统一走它；h3 仍是更强的 accent 混合（更突出的一档）。
设置页的「动态自定义」也多了 `Markdown 标题` 这一项（挂在 `FIELDS` 上自动出现）。

### 3）⚠ 关键 bug：派生变量写在 `:root` 会按 html 的默认值算死

第一版 `--md-heading` 我写在 `:root` 里，结果**石墨主题下标题色仍然用默认蓝 accent 混出来**
（量到 `color(srgb 0.836 0.866 0.889)`，绿分量 > 红分量）。

原因：自定义属性里的 `var()` 是**在声明它的那个元素上**求值的。
`--md-heading` 声明在 `:root`（html）→ 里面的 `var(--accent)` 取 html 的 `#4f9cd6`（默认蓝），
`--md-heading` 算完再被 body 继承时**已经是一个固定色**，`body.theme-graphite` 覆盖的
`--accent` 不再参与计算。

修法：把派生变量从 `:root` 挪到 `body`（和主题类同一层），它就会用 body 的 computed 值算：

```css
body {
  --border-pane: color-mix(in srgb, var(--text) 16%, transparent);
  --md-heading: color-mix(in srgb, var(--text-bright) 90%, var(--accent));
}
```

顺带把同病的 `--border-pane` 也挪了过去（它一直用 html 的 `--text` 算，换主题不跟随，
只是差值小到看不出来）。

## 三、项目栏：两个入口合成一个

上一轮加「当前项目 ▾」之后，顶栏变成两个按钮：`▾ 全部项目 14` 和 `📁 心理健康项目 ▾`
—— **两个都是"点开同一个项目菜单"**。

- 撤掉 `.proj-all`（DOM + CSS 全删，不留死样式）
- 项目控件本身就是菜单按钮：点它开「已打开 / 最近打开 / 当前项目操作」
- 空状态的「全部 N」按钮锚点改为「项目控件」（`.proj-all` 没了）
- 「打开项目」文字按钮改**图标按钮**（顶栏只剩图标 + 项目名，更像标题栏）

## 五、踩坑

1. **heredoc 传给 Python 的反斜杠又被吃掉一层**（第二次踩）：`scrollbar-width:\s*none`
   写进文件变成 `scrollbar-width://s*none`，`node --check` 立刻报错。
   **含反斜杠的补丁一律先 Write 成 `.py` 文件再执行**，比调试引号快得多。
2. **"按行切片"要数够行数**：替换 `assert_(allBtn && ...)` 那块时我按 5 行切，实际是 6 行，
   断言校验直接拦住（好在加了内容校验，否则会切掉半块代码）。
3. **断言要能解析 `color(srgb ...)`**：`color-mix` 在现代 Chromium 里算成
   `color(srgb 0.83 0.86 0.88)` 这种 0~1 表示，按字符串抓数字会得到 0.83 —— 跨度算成 0.05，
   断言全错。统一加 `parseColorRgb()`。
4. **偶发不等于是回归**：`「Git 变更」把未提交改动带进来` 挂了一次（Git 状态没在 2s 内返回），
   复跑 259 全绿。**先复跑一次再动手改**，否则容易把偶发当 bug 去"修"。
