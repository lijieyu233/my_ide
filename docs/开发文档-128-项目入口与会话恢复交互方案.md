## 4. 入口与信息结构

| 入口 | 用途与显示 |
|---|---|
| 顶部项目栏 | 保留已打开项目平铺、主动顺序和横向滚动，明确当前项目；同名时补最短可区分父路径 |
| 全部项目 | 已打开 / 固定项目 / 最近项目分区，搜索项目名和路径；支持键盘选择与管理动作 |
| 启动页 | 打开目录主动作，固定项目与最近项目列表；恢复状态、失效位置和需要处理的草稿入口 |
| 状态栏 | 当前项目/文档上下文，持久失败提示可回看；不增加一排重复项目按钮 |

名称统一：**关闭项目**仅从已开集合移除；**从最近项目移除**仅忘记历史记录；**固定项目 / 取消固定**仅改变列表置顶。它们均不删除项目目录。历史移除也不顺手删除会话或未处理草稿；草稿需要单独明确处置。

顶部项目栏顺序仍由用户拖动决定，不能每次访问都打乱。最近项目按成功激活时间降序；固定项目单独置顶，不受最近淘汰。列表可显示时间摘要和完整路径提示；路径无需写成复制按钮旁的大段技术信息。

项目条目以项目身份绑定动作，搜索或重排不能用旧数组索引操作。基础身份需处理分隔符、尾分隔和经验证的大小写规则；目录别名/junction不凭字符串猜成同一目录。遇到可能相同的路径提示已有项目，不能未经核对合并它们的设置或草稿。

## 5. 启动页与全部项目交互

首屏主动作「打开目录」，次要入口是帮助与设置；已存在的拖入目录继续可用。不先铺一排新建语言项目模板。固定项目建议首屏最多6条，最近项目最多8条可见，更多进入全部项目；历史容量建议30条，固定条目不计入淘汰，具体容量可在实施时结合真实使用量确认。

全部项目按钮点击打开搜索列表；鼠标移入可保留现有发现方式，但不得夺走正在输入的焦点。列表头部搜索输入，结果显示名称、可区分路径、当前/已打开/固定状态；菜单普通行与行尾管理动作分别可聚焦，关闭按钮不得作为嵌套在另一个按钮里的非语义span。

| 键盘 | 行为 |
|---|---|
| 输入 | 名称与路径过滤，保留稳定项目身份 |
| ↑ / ↓ | 选择可打开结果，不选标题/分隔线 |
| Enter | 打开当前选中项目；当前项目不重复恢复 |
| Escape | 关闭列表，恢复全部项目按钮焦点 |
| Tab | 进入明确管理动作，不落到隐藏关闭按钮 |
| 组合输入期间 | 不执行Enter打开、关闭或删除 |

点击失效项目不把错误解释成空目录。显示「位置不可用」，区分不存在、权限不足、离线位置和校验失败；提供重试、选择新位置、从最近项目移除。暂时离线不自动忘记记录。重新定位要用户选目录并确认项目对应关系，不能按末级名称自动替换另一同名项目。

复制路径在系统确认成功后提示；失败保留可选择的路径文本。固定和历史管理落盘失败时还原原显示状态，不能在内存成功就宣布重启可保留。

## 6. 项目切换合同

保留当前保存闸门和串行队列，新增可见状态「正在切换到B」。首先确认目标可访问，再按111处理当前未保存内容；失败或取消时保留原项目、标签、最近顺序和上次成功项目。

用户连续选择B、C时显示当前处理B、下一目标C，不交错清空标签。队列过多时可按明确规则合并尚未开始的意图；已经开始保存的操作不得因UI合并被中止成半状态。默认保持当前串行语义，不把取消等待理解为取消已经完成的磁盘保存。

目标激活与恢复阶段分别报告：目录已打开、正在恢复活动文件、可用、部分恢复失败。只有目标目录与主要界面实际激活成功，才更新最近时间和lastSuccessfulProject。Git/任务扫描等后台失败显示各自状态，不把整个目录显示成无效，也不凭扫描完成速度反复改项目身份。

关闭当前项目仍先处理保存，关闭非活动项目不切换当前编辑对象。关闭最后一个项目返回启动页，记录lastActive=null；下一次启动不能因为遗留lastFolder而偷偷重开用户刚关闭的项目。启动策略提供「恢复上次成功项目 / 显示启动页」，与项目栏已开集合分开定义。

## 7. 会话恢复与部分失败

恢复范围建议包括标签顺序、活动标签、编辑/预览模式、原文光标/选区、阅读位置、工具状态及目录展开；标签预览/固定语义沿106，布局宽度与专注状态沿121。模式与位置是不同格式的参数，不用一套scrollTop数字假装所有Office/图片/Markdown位置都可恢复。

活动标签也必须携带自身位置，并等实际编辑器/预览就绪后应用；非活动标签保持懒恢复。恢复顺序保留原标签顺序，不把active移到末尾。文件缺失或无权限时保留“无法恢复”占位并提供重试/定位/关闭，而不是自动丢条目；其余合法标签继续恢复。

坏JSON保留原件并反馈；单条坏记录记录原因并跳过，不能阻断目录展开与工具状态。恢复结果返回成功项、失败项和待加载项；“部分恢复”入口可回看详情。未处理失败记录不能被随后空会话保存悄悄覆盖。

每轮恢复绑定项目身份、会话版本和恢复代次。重试、重新定位、项目切换或关闭后，旧读盘/渲染完成不能影响新的树、工具和活动文件。保存定时器绑定发起项目，不能在root变化后把旧操作写到新项目key。旧格式路径数组兼容迁移需先校验和备份，路径迁移继续沿112更新非活动会话。

## 8. 草稿恢复需求

独立草稿记录保存编辑器正文、文档身份、路径、项目身份、编辑版本、格式信息和当时磁盘基线，不能仅保存光标或路径。位置会话与正文草稿分开维护。备份不等于保存项目文件，也不清dirty；草稿实际落盘失败必须显示，不能用设置镜像成功代替。

重启后提示「发现N份未保存草稿」，先在只读预览核对来源与时间，再恢复到缓冲区或导出副本。磁盘仍匹配原基线时也只恢复缓冲内容，由用户保存；磁盘已改变时提供草稿与磁盘比较，覆盖继续沿111明确确认。原文件不存在、路径被重建或项目已移动时，不自动向同名位置写入。

草稿存储应原子更新、校验、保留可用恢复来源，删除只能针对用户已确认处理的版本。建议容量预算沿095单独测量；达到上限先反馈和提供导出/处理入口，不自动淘汰尚未处理的唯一草稿。普通项目历史的移除不能销毁草稿。

首包仍保留当前“保存成功才切换”的行为。只有草稿持久化和恢复验收完成后，才考虑显式「保留草稿并切换」动作；不得先放开保存闸门再承诺以后补备份。系统异常退出、权限/磁盘失败和真实编辑器输入都需专门验证，不能把JSDOM会话测试当崩溃恢复证明。

## 10. 验收矩阵

1. 保留C1/C2：连续切项目恢复不交错；保存失败不清标签、不换root。选目录后取消切换也不改变上次成功项目。
2. 项目栏用户顺序与最近访问顺序分开；固定/取消固定、历史移除、关闭互不误作用，所有操作不删除磁盘目录。
3. 两个同名项目、长中文路径、路径大小写与尾分隔等价输入可辨识；邻居目录不进入当前会话。UNC、离线盘、大小写敏感目录及junction以真实Windows验证。
4. 搜索、方向键、Enter、Escape、Tab和IME一致；鼠标hover不抢输入，焦点返回仍存在的触发控件。
5. 活动/非活动标签、清空active、错误条目、缺失文件和损坏JSON分别恢复；位置与顺序保持，部分失败可回看，旧任务不影响新项目。
6. lastActive、lastSuccessfulProject、已开集合、启动策略和最近历史的重启行为一致；关闭最后项目、目录失效、权限拒绝都可解释。
7. 草稿备份/恢复用真实进程异常退出与独立测试目录，验证中文/大文本/编码行尾、磁盘冲突、同名重建、容量及写失败，恢复先进入缓冲区。
8. 多主题、窄窗口、125%/150%缩放、多个项目与长路径截图检查无遮挡；不把字符串夹具当实际几何或OS焦点验收。
