# 开发文档-061：界面整体视觉层次治理

> 起因：用户反馈「问题现在不是某个图标的原因，而是整体的视觉呈现」。
> 前几轮我一直在逐个修图标（emoji → SVG），方向偏了 —— 图标不是「乱」的来源。

## 一、先量，再改

不靠感觉。两条测量手段：

1. **像素扫描**：对整窗截图按列扫色带边界，得到「每条 chrome 带从哪到哪、什么颜色」。
2. **实测量高**：在自检里读 `getBoundingClientRect()`，把各区域的真实高度打出来。

量出来的实况（1380×880 窗口）：

| y 区间 | 区域 | 背景 |
|---|---|---|
| 0–37 | 项目栏（38px） | `#191919` |
| 38–65 | 编辑器标签栏（28px） | `#141414` |
| 66 | 标签栏下边框 | `#101010` |
| 67–97 | **编辑器工具条（31px）** | `#191919` |
| 98 | 工具条下边框 | `#101010` |
| 99– | 编辑器内容 | `#1e1e1e` |

## 二、四个结构性根因

### 1. 顶栏以下堆了 3 条 chrome 带，其中一条大半是空的

`.viewer-toolbar` 是个 `justify-content: flex-end` 的整行容器，里面只有右侧 4 个模式按钮
（实时预览 / 分屏 / 源码 / 预览），左侧 500px 全空。**一整条 31px 的横带只为摆 4 个小按钮。**

chrome 合计占 99px / 880px = **11.2%**。

### 2. 明度没有层次 —— 7 个区域里 4 个同色，分层全靠 1px 黑线

| 区域 | 改前 |
|---|---|
| 项目栏 | `#191919` |
| 左侧工具条 | `#191919` |
| 侧栏 | `#191919` |
| AI 助手 | `#191919`（走 `--bg-panel`） |
| 标签栏 | `#141414` |
| 编辑器 | `#1e1e1e` |

内容与工具窗口只差 **5 级**（`1e` vs `19`），肉眼分不出。而分隔线是 `#101010`（比所有背景都暗）
→ 观感是「一堆灰块被黑线切开」，也就是用户说的「乱」。
（对比 PyCharm Darcula：工具窗口 `#3c3f41` vs 编辑器 `#2b2b2b`，差 **17 级**。清晰感来自这道明度差，不是边框。）

### 3. 三处面板标题行不等高

| 标题行 | 改前高度 |
|---|---|
| 侧栏 `.panel-title` | 32px（`padding: 7px 12px` + `.92em`） |
| 编辑器标签栏 `#tabbar` | 28px |
| AI 助手 `.ai-head` | 30px（`padding: 6px 10px`） |

三者在同一水平线上并排，**交界处的横向底线差 2~4px**，一眼睛就能看出不齐。

### 4. 同一个按钮有两个选中指示

`.tool-btn.active` 同时有 `border-left: 2px solid var(--accent)` 和 `::after` 的右侧 accent 竖条 —— 一个按钮两条主色线。

## 三、改法

### 1. chrome 4 行 → 3 行

把编辑器工具条（模式切换 / 查看源码 / 内置浏览器）并入标签栏右端，与「定位」同组。
标签栏拆成两个兄弟节点：

```html
<div id="tabbar">
  <div id="tab-scroll"></div>   <!-- 标签横向滚动区 -->
  <div id="tab-actions"></div>  <!-- 操作区：模式切换 + 定位（不随标签滚走） -->
</div>
```

拆开的原因：整条一起横向滚动的话，文件一多模式按钮就被推出视野看不见了。

抽取 `renderTabActions()` 统一构建，**由 `renderTabs()` 一起调用**。
⚠ 必须与 `renderTabs` 同生命周期：标签栏这一片会被 `renderTabs` 清空，而「标脏点」这类路径
只调 `renderTabs` 不调 `renderView` —— 挂在 `renderView` 里会被清掉（症状：右端按钮「有时有一个有时没有」，
这个坑 060 那轮踩过一次）。模式切换后需要刷新 `active` 态，所以 `renderView` 里也重建一次。

顶栏以下 chrome 从 99px → **68px**。

### 2. 建立明度四档（分层靠明度，不靠黑线）

| 变量 | 值 | 用在哪 |
|---|---|---|
| `--bg` | `#212121` | 内容画布（编辑器 / 预览）—— 最亮 |
| `--bg-tabbar` | `#1a1a1a` | 编辑器标签栏（贴在内容上，略暗 → 选中标签用 `--bg` 能「并进」内容） |
| `--bg-panel` | `#171717` | 工具窗口（侧栏 / AI 助手 / 底部面板） |
| `--bg-title` | `#121212` | 最外层 chrome（项目栏 / 左侧工具条 / 状态栏）—— 最暗 |

内容 ↔ 工具窗口从 5 级拉到 **10 级**。

### 3. 三处标题行统一 `--head-h: 30px`

`.panel-title` / `#tabbar` / `.ai-head` 共用，并统一 `box-sizing: border-box` + `padding: 0 …`。

### 4. 清掉重复的选中指示

`.tool-btn.active` 只留左侧 accent 竖条，删掉 `::after`。

## 四、连带发现：其他主题会掉回深色（已修）

新增的 `--bg-title` 在三个主题里都没定义 → 浅色 / 粉色主题的**顶栏、工具条、状态栏会继承 `#121212`，直接变成黑条**。

已补齐：

| 主题 | `--bg-title` |
|---|---|
| `body.theme-light` | `#dedede` |
| `body.theme-pink` | `#f7d3e2` |
| `body.theme-crimson` | `#151014` |

并加了两条守卫：
- 遍历样式表，**任何定义了 `--bg-panel` 的主题必须同时定义 `--bg-title`**；
- 实测四个主题下「顶栏比侧栏暗」都成立（`默认 18/23 · light 222/236 · pink 228/243 · crimson 19/30`）。

这条比只检查变量更可靠：变量名漏掉的主题会**静默**掉回默认深色，不报错。

## 五、验证

```
npm test                                   语法 26 + git 45 + dom 237 = 308 项全绿
electron . --check-ui（headless）           223 项全绿 / 0 失败（+3 项因 headless 跳过）
```

新增断言（把「看着乱」变成可验证的量）：

| 断言 | 实测 |
|---|---|
| 编辑区没有独立的工具条行（chrome 4 行 → 3 行） | 无 ✓ |
| 侧栏标题 / 标签栏 / AI 助手标题 三行等高 | 30 / 30 / 30 |
| 明度阶梯 内容 > 标签栏 > 工具窗口 > 外框 | 33 > 26 > 23 > 18 |
| 内容 ↔ 工具窗口明度差 ≥ 8 级 | 10 级 |
| 内容比标签栏亮（选中标签能与内容连成一片） | 33 > 26 |
| 外框比工具窗口暗（最外层退到最后） | 18 < 23 |
| 每个主题都定义了 `--bg-title` | 4 个主题全有 |
| 每个主题的顶栏都比侧栏暗 | 4 个主题全过 |
| 左侧工具条选中态只有一个 accent 指示 | `::after content=none` |
| 标签栏拆成「滚动区 + 操作区」且是兄弟节点 | ✓ |

dom 侧新增用例「整体视觉：编辑区不再有独立工具条行，操作区跟着标签栏」。

## 六、踩坑记录

- **拖拽排序挂在旧容器上**：`startDrag` 里 `tabbar.insertBefore/appendChild` 没跟着换成 `tabScroll`
  （因为 `#tab-scroll` 是新建的），拖拽后标签被插进 `#tabbar` 而不是滚动区 → dom 用例
  「标签拖拽排序」直接失败。重构容器时**凡是出现容器名的地方都要一起查**。
- **`chrome` 自检步骤跑在空状态**：AI 面板当时是收起的，`.ai-head` 高度为 0，
  「三处等高」在那里必然失败。已拆成两处：`chrome` 比「侧栏标题 vs 标签栏」，
  `aiAssistant`（面板确定展开）比三处。
