## 二、错误清单

### P1 · addRemote 用 Windows 反斜杠路径 → 把 .git/config 写坏，原生 git 全线失效

- 现象：在【远程】里添加一个本地路径远程后，`.git/config` 里出现 `url = C:\Users\...\bare.git`；git config 里 `\` 是转义符，**未转义** → 原生 git 报 `fatal: bad config line 14`。
- 后果（实测 4 条全挂）：`git status` / `git push` / `git branch --set-upstream-to` / 任何原生通道（merge、rebase、冲突处理、pre-commit 钩子）全部失效，且报错是看不懂的 "bad config line 14"。
- 证据：`.ui-check-trash/git-evidence.js` 输出 —— config 第 14 行即 url 行，随后 4 条原生命令全部 `ok=false`。
- 触发条件：远程 URL 是 Windows 本地路径（`C:\...`、共享盘 `\\host\share`）。https 远程不含反斜杠，不触发。
- 归属：`git-service.js` 的 `addRemote`（isomorphic-git 写 config 时未转义反斜杠）。

### P2 · 远程状态相关的 5 处表现异常（根因：本机 git 写不进 refs/remotes，产品无兜底）

| 能力 | 实测结果 | 期望 |
|---|---|---|
| `aheadBehind` | `{fetched:false, ahead:null, behind:null}`（本地又提交一个后仍是 null） | 同步时 0/0，本地多一个时 ahead=1 |
| `listPushCommits` | `{first:true, count:2}` —— 已推送的 c1 也算进去，并误判"首次推送" | 只列未推送的 1 个 |
| `setUpstream` | `fatal: the requested upstream branch 'origin/main' does not exist` | 应能设上 |
| `unsetUpstream` | `fatal: branch 'main' has no upstream information`（上一条的级联） | — |
| `branches.upstream` | `""`（`git push -u` 成功之后仍读不到） | `origin/main` |

- 根因取证：`.ui-check-trash/git-evidence.js` ② —— `git fetch` 输出 `* [new branch] main -> origin/main`（成功），但 `.git/refs/remotes/` **目录存在却为空**、`packed-refs` 不存在、`git rev-parse origin/main` 报 `Needed a single revision`。
- 这与本机已知缺陷一致（git.exe 写不进 4 段路径 `refs/remotes/**`，rc=0 但不落地）。
- 产品侧的问题在于**没有兜底**：拿不到 remote-tracking 引用时，ahead/behind 退化成 null、推送预览退化成"全部重推"，而不是改用 `FETCH_HEAD` / `ls-remote` 之类可得信息。

### P3 · dev 分支上没有 checkout 的原生修复（用户在 dev 上切分支仍会失败）

- `typeof require('git-native').checkout === 'undefined'` → dev 上 `git-ops.js` 的 checkout 仍只有 `op`（isomorphic）→ 在 autocrlf 仓库（本仓）切换分支会报 `CheckoutConflictError`。
- 连带：`branchCreate` 缺 `-` 前缀白名单 —— 传 `-x` 时 dev 会把它当选项传给 git，弹的是 git 原始 usage 错误（不是友好提示）。
- 两条都已在 **main `fa044b9`** 修好，**未合入 dev**。

### P4 · 已知限制（非缺陷，记录备查）

- isomorphic-git 通道不支持本地路径远程：`pushRemote` / `fetchRemote` / `pullRemote(strategy:'ff')` 报 `Cannot parse remote URL`。https 远程不受影响；`pullRemote` 的 `merge` / `rebase` 走原生，本地路径也正常（已验证通过）。
- `precommitRun` 的 `results` 第一条是 hook 占位条目（`skipped:true, "没有 pre-commit 脚本（正常）"`）。"失败即停"行为本身正确（第二条没跑），是我冒烟脚本的断言把这条算漏了，**非产品问题**。

- **P1**：`addRemote` 对非 http(s) 的 URL 先把反斜杠规范成正斜杠（与原生 `git remote add` 行为一致）。
- **P2**：新增 `remoteOid(root, remote, branch, url)` —— `refs/remotes` → `.git/FETCH_HEAD` → `git ls-remote` 三级兜底；`aheadBehind` / `listPushCommits` 改用它；`ahead/behind` 先算 **merge-base** 再各自计数（修"本地领先时 behind 把整段历史数进去"）；`branches().upstream` 兜底读 config 的 `branch.<name>.remote/merge`；`setUpstream` / `unsetUpstream` 拿不到引用时直接写 / 删 config。

- **附带**：`git-native` 补导出 `runRetry` —— ssh / 本地路径远程的 push、fetch 一直抛 `N.runRetry is not a function`（以前只有 ssh 能触发那条路径，没人走到）。
