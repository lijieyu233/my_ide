# Git 大文件差异与历史导航修复

2026-11-09；基线 b4be5bf。保留现有 IDE 布局、双区差异、懒构建、状态合并刷新、普通差异请求代次与缓存。

## 大文件不是整份替换

旧实现任一侧超过 4000 行就退化成全部删除/全部新增。例如 11a76cf 的样式文件原生 Git 统计只有 +6/-0，界面会显示 +4718/-4712。这不是主要由 CRLF 引起。

新行级计算先裁剪公共首尾，再用唯一行锚点分区；重复区域才使用有界 Myers。生产预算固定为 200 万工作步、1024 编辑距离、最多 1048576 个紧凑 trace 单元（4MiB 上限）。证明两侧不相交的区域可在线性工作量下精确删除/新增；无法精确对齐的区域单独标为未决，不伪装为相等或整份替换，也不计入精确增删数。

工作区、历史和分支差异使用同一算法。顺便修复旧 hunk 组装丢失内部上下文、纯插入块上下文不正确的问题。缺少末尾换行有显式标记；末尾换行变化和未决块只读，不签发块操作快照，不能绕过原有原字节与状态一致性校验。

```sh
node tests/git-large-diff.test.js
node --expose-gc --max-old-space-size=96 tests/git-large-diff.test.js --bench=50000-small-edit
node --expose-gc --max-old-space-size=96 tests/git-large-diff.test.js --bench=4000-all-change
node tests/git-hunks.test.js
node tests/git-worker-boundary.test.js
```

一次隔离算法基准：50000 行、两处共增加 6 行约 77.78ms；4000 行全部不同约 7.46ms。两个例子都精确、未使用 Myers trace。基准的 V8 堆限制为 96MiB，进程总 RSS 约 135MiB（堆限制不是整个进程内存限制）。输出本身仍为 O(N+M) 线性内存；patience 对齐不承诺所有大段重排都得到全局最短编辑脚本。

Git worker 故障后不再回落到 Electron 主进程执行重差异运算。旧请求失败并提示核对；新的显式请求可重建 worker，但绝不自动重放可能已写入的操作。

真实回归还抓到暂存前 `ls-files --cached` 的瞬时失败：夹具基线提交未成功，会继发误报状态/Shelve 失败。该只读查询现沿用既有最多两次的重试机制；持续失败仍不开始暂存写入。测试额外隔离用户 HOME/Git 全局配置，并断言关键基线提交成功，不再把准备失败当成被测行为。

## 历史与操作连续性

- 已缓存日志 → 切项目树 → 文件「显示历史」：自动查询当前路径，不再显示旧历史或要求手动刷新。
- 分支对比的等待、失败状态始终保留重试与退出；比较请求绑定项目、模式、代次，文件差异再独立隔离 A/B 迟到响应。
- 新 HEAD 到来时，若正在读的提交仍存在，保留第二文件、详情与差异 DOM、滚动位置；原提交消失才回退。
- 作者/消息筛选用同一可见提交子集生成图与文字，保持紧凑、坐标一致，不留空白占位行。
- 上下键只作用于日志列表，不再抢编辑器、输入框、select、contenteditable 或已经处理的事件。
- 对比模式隐藏无关路径过滤提示、禁用普通历史筛选，并替换已被中断的旧详情加载提示；退出恢复普通历史控件。

验证内容包括：4718 行工作文件和历史提交均为 +6/-0；新 HEAD 保留第二文件与详情 DOM；作者筛选图文中心误差 0px；有缓存时自动查询文件历史；对比失败可重试/退出；在 A 迟到后仍显示 B 的真实双方正文，而非只检查加载标题。
