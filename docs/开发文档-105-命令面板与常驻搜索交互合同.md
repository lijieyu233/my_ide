# 命令面板与常驻搜索交互合同

> 2026-10-01；产品基线 `0f19507`。承接103的F1、I2和F3，关联089的UI-01、SEARCH-01、PROJECT-01。
> 本轮交付设计样机与实施合同，未向MyIDE加入命令面板、常驻搜索或导航历史。浏览器样机的通过项不能关闭产品缺口。
> 当前更新：快速打开前置子包见§9；A命令面板首包已接入产品，范围与实际验收见§10。B常驻搜索、C导航历史仍待实施。

## 1. 用户任务与最小交付

日常任务是“找到一个动作”“连续查看几处命中”“跳走后返回刚才的位置”。入口、结果与返回应连成一条工作流，避免把工具发现、搜索速度和位置恢复拆成互不相干的功能。

| 阶段 | 可见变化 | 用户任务验收 | 保留的边界 |
|---|---|---|---|
| A 命令面板 | 工作区有“查找命令”入口，支持中文名称/别名、键盘选择、真实快捷键与不可用原因 | 不记快捷键也能找到搜索、主题设置和文件历史；Esc回到原入口 | 复用动作和确认流程，不绕过权限；先只接少量已存在动作 |
| B 常驻搜索 | 当前项目结果按文件分组，显示路径、行号、片段和完整/部分状态 | 连续打开三处命中，查询、结果和滚动位置仍在 | 先做查找，不扩展为项目批量替换 |
| C 位置历史 | 返回/前进恢复文件与文本位置 | 从A跳到B、C，返回B，再前进C；搜索列表仍在 | 是位置历史，不冒充Ctrl+Tab标签轮换或已存在最近文件 |

A可独立上线；B接入091/100的查询归属与取消合同；C依赖Viewer统一定位入口。每版1–2项，保存/文件服务等数据保全P0继续优先。

## 2. 界面方案与取舍

本轮对比“左侧结果”与“底部结果”两个可点击方案。样例仅含README、保存约定和save.js；文件内容只读，主题设置/文件历史仅展示入口反馈，恢复删除是不可用示例。搜索延迟为演示取消而人工设置，不能作为性能测量。

推荐先用左侧：沿用现有工具切换与收起机制，查询和结果位置固定，编辑区保持连续；底部保留项目树且代码横向空间较大，但占用编辑高度。当前只是设计取舍，尚无真实用户任务对比证明哪种更快；不同时实现两种可配置停靠来扩大首包。

设计约束：

- 全局“查找命令”置于工作区入口；搜索的清空、取消、重试在搜索区，返回/前进属于位置导航。
- 每组显示相对路径与命中数；每行显示行号、上下文和匹配高亮。相同文件名必须能区分目录。
- 选中、键盘焦点、当前文件和搜索高亮分开表达；只用颜色不足以说明选中或失败。
- 宽度不足时查询、结果、文件内容重排；生产Electron应结合实际最小窗口、字体缩放与侧栏宽度验收，样机320px只证明该样例布局可重排。
- 背景、列表和弹窗使用同源主题；本轮样机遵循系统深浅色，接入产品时需使用现有主题变量。
- 工具条/列表图标按仓库线性SVG规范接入；样机使用文字按钮，不能把视觉占位误认作已实现控件。

## 3. 命令面板合同

### 3.1 共享动作描述

保留现有Shortcuts注册表与用户键位。新增共享动作描述建议：`id / label / aliases / category / isEnabled(context) / run(context)`；快捷键显示通过现有bindings按id查询，不能复制一份默认键位。不可用结果应包含可展示的原因，不能只有false。

菜单、快捷键、命令面板最终调用同一执行入口。首包可以为搜索、主题设置、文件历史提供适配器，不要求立刻迁移所有历史菜单。动作id保持稳定，中文文案不作为执行身份。

打开时捕获`projectId / documentId / revision / selection / invoker`等必要上下文；执行前再次检查项目/文件是否仍存在、动作是否可用。只读导航不需要revision写入闸门，写入/删除/执行外部命令等动作仍走既有确认和服务合同。面板只是入口，不能充当授权来源。

### 3.2 查找、选择与执行

1. 打开后输入框获得焦点；空查询显示一组常用/最近动作。首包可仅用固定分组；实现MRU时只记录成功执行的动作id。
2. 名称精确/前缀优先于包含/别名，类别与名称用于稳定排序；中文、英文别名都可查。扫描完候选再取top-K，不重复103里快速打开提前截断的错误。
3. ↑↓移动有效选择，输入改变后重算选择；无结果时Enter无效果并保留面板。不可用命令可被键盘选择以阅读原因，但不能执行。
4. 展示用户当前绑定快捷键；未绑定显示“未设置快捷键”，不能写一个看似实际生效的默认键。样机“可自定义”只是占位，生产要替换。
5. 接收动作后关闭面板；同步错误/异步失败走现有可回看状态入口，不显示成功假象。危险动作的二次确认由共享执行流程承担。

建议首包默认`Ctrl+Shift+P`，先核对现有注册与用户自定义冲突；触发事件应仅由键位系统消费一次，不能再添加一份全局监听抢占编辑器/IME。快捷键在103里是提议，不是当前产品事实。

### 3.3 焦点与辅助访问

弹窗有明确标题和dialog语义；输入/listbox/option的id、controls、active-descendant一致。打开时保存真实触发控件，关闭时回到仍存在的控件；控件已卸载时回到同工作区的稳定入口。不能仅remove弹窗后让焦点落到BODY。

Tab/Shift+Tab限制在弹窗可用控件，背景不可操作；Esc由最上层弹窗消费，不能同时关闭下层或撤销正文。中文组合输入期间Enter/↑↓/Esc不作为命令面板动作处理。实际读屏、原生菜单、Editor焦点和多弹窗叠加均需Electron验收，不能只依赖aria属性。

## 4. 常驻搜索合同

### 4.1 状态模型

视图持有`projectId / queryId / query / options / phase / resultGroups / selectedHitId / scrollAnchor / terminationReason`。新查询生成新queryId并清除旧可执行命中；旧结果可以显示为“上次结果”，但必须明确过期并禁止冒充当前查询定位。

后端结果必须带查询归属，完成时区分`complete / limit / timeout / cancelled / error`；取消请求与取消确认分开。收到另一项目或旧queryId的batch/done一律忽略。渲染节流可以合并当前批次，不能把旧批次塞进新查询。详细IPC/资源边界承接091、100，不在视图里再造扫描服务。

| 终态 | 必须显示 | 可执行行为 |
|---|---|---|
| 完整且有结果 | 条数、文件数、搜索完成 | 点击/键盘定位 |
| 完整且无结果 | 搜索完成、没有匹配；保留查询/选项 | 修改查询或作用域 |
| 达到上限 | 仅显示多少条、达到上限；不能写“搜索完成” | 缩小范围或调整上限 |
| 超时 | 未搜索完、已找到数量、重试 | 浏览已接收结果，重试生成新queryId |
| 取消 | 已取消、已找到数量 | 保留真正接收的结果，修改查询/重试 |
| 失败 | 操作/范围/原因、重试；不伪装为空结果 | 按已有权限/失败合同继续操作 |

取消不得把整个缓存语料重新过滤后宣称“已找到”；零批次取消必须显示零条。取消后迟到的完成不能重新写成“完成”。本轮样机用局部generation阻断迟到timer，生产还需真实worker/IPC停止确认。

### 4.2 命中身份与定位

命中建议包含`hitId / projectId / queryId / path / version / line / startColumn / endColumn / preview`；行号一基、列偏移单位明确，不能用片段index当源码列。非BMP字符、Tab、多次同词、CRLF和编码需要服务与编辑器一致测试。

鼠标与Enter使用同一navigateToHit。打开成功并核对文档身份后定位；文件变化导致范围失效时明确告知并重新查找，不能猜一列静默跳错。文件已删除/无权限是可回看定位失败，列表仍在。

查询输入↑↓只改变选中；Enter打开选中项，不切断当前查询。鼠标点结果后保留结果控件焦点，键盘连续浏览不掉到BODY。生产CM6的选区/滚动应在打开与布局完成后应用，真实Editor合同仍待实现与取证。

选择稳定hitId而不是数组下标；新批次排序/文件折叠时尽量保留命中和滚动锚。项目切换取消旧查询；是否按项目保存最后查询属于会话策略，首包可只在本次会话内保存。跨项目结果不能混在同一面板。

## 5. 返回/前进合同

统一`navigateTo(location, origin)`入口，记录成功导航前后的`projectId / documentId / path / viewMode / offset或selection / scrollAnchor / revision`；打开失败不入栈。历史必须有数量上限，复用已打开文档身份，不能为每条记录缓存整份正文。

正常输入/同文件滚动不逐帧入栈；搜索跳转、文件打开、标题/定义定位等明确导航才记录。连续重复位置合并；返回/前进本身不再新增历史，返回后发生新导航清空前进栈。

路径变化与删除按文件服务身份处理；过期位置不能覆盖正文，也不能绕过101保存失败的离开闸门。脏文件/保存失败阻止离开时，历史指针和当前文档保持原样。跨项目跳转需项目切换成功后才提交历史变更；首包可以限制同项目。

样机只存内存文件/行号，已经证明基本返回/前进和结果保留；未证明真实文件重命名、dirty闸门、选区映射、会话恢复或Markdown视图恢复。

## 9. 快速打开前置子包实施（2026-10-02）

基线`e7b56df`。本包解决103-Q1/Q2及快速打开自身的Q3范围，不把命令面板、常驻搜索、导航历史或通用Modal全部计为完成。

- 最近文件和搜索结果使用同一可执行列表；↑↓/Enter、鼠标点击绑定对应路径。加载完成保留刚选的最近项，损坏的最近记录不锁住面板；空结果不执行旧选择，Windows路径别名去重。已有跨项目最近文件保留全路径展示，不暗改成只显示当前项目。
- 对索引全部候选评分，只保留前30项；相同分数按路径稳定排序，扫描尾部的高分结果也参与。后端仍有5万个文件上限及原有隐藏目录过滤，触顶持续说明“可能不完整”，不承诺全磁盘索引或新的性能指标。
- 面板先出现，读取中显示状态；失效/无权限目录不再被后端静默当成空目录，返回首个原因和失败目录数。面板保留查询、展示失败并可重试；失败批次不缓存为完整列表。局部不可读目录也使本次索引失败，不能把剩余文件当作完整结果。
- 索引按项目代次归属；重复打开不叠面板，同一代次加载复用。关闭后旧请求不重绘/抢焦点，切项目清掉原面板。文件监听/同项目刷新只重建索引，保留当前查询与焦点；上一代完成不能覆盖新索引。
- 本面板提供dialog/combobox/listbox/option关系、有效active-descendant及选中状态，Tab循环、组合输入期间不执行导航/关闭、背景inert和快捷键隔离。Esc只消费栈顶；取消回原入口，入口卸载后回同项目稳定入口，打开成功且身份仍一致才回当前编辑器。Modal.hide增加可选面板清理回调，外部关闭也释放本面板监听及inert。
- 标题沿用“快速打开”，移除写死的Ctrl+P提示，不冒充用户自定义后仍有效的键位。浅色选中名称用同源主题色，当前选择有左侧标记；只有读取失败才显示重试按钮。
