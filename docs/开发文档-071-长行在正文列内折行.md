# 开发文档-071 · 长行在正文列内折行（CM6 默认不换行）

> 用户反馈：「你调低了框度 但是它没有在这个框度换行」
> 背景：065 那轮把正文列从「铺满编辑区」限到 `max-width: 820px` 并在编辑区里居中。
> 列变窄之后，长行不再是"刚好放得下"，而是**从列右边直接溢出被切掉**。

## 一、根因：两个不同的渲染器，各缺一样东西

正文有**三套**渲染路径，窄列对它们的影响不一样：

| 模式 | 渲染器 | 改前 | 根因 |
|---|---|---|---|
| Live Preview | CodeMirror 6 | 长行横向溢出、看不全 | CM6 **默认不换行**（官方设计：长行横向滚动）。全仓库搜 `lineWrapping` 零命中 |
| 源码模式 | CodeMirror 6 | 同上 | 同一个原因 |
| 静态预览 | 自己写的 md → HTML | 长段落/表格还行，**长路径整段漏出列外** | 中文能自由断行，但 `D:\a\b\c.ts` 是一个"词"；**`\` 不是断行机会点**，浏览器不在这断 |

### 1.1 CM6：必须显式开 `EditorView.lineWrapping`

```js
// renderer/md-editor.js 的 extensions 里加一行
EditorView.lineWrapping,
```

这一条同时解决 live / source 两个模式（共用同一套 extensions）。

### 1.2 静态预览：`.md-view` 补 `overflow-wrap`

自检实测：一条 130 字符的 `.ts` 路径让 `p` 溢出 **45px**，连带 `.md-view` 溢出 **11px**
（`.md-view` 有 34px 左右内边距，所以父元素的溢出值看起来对不上子元素的 45px —— 一开始就是被这个数字差带偏的）。

```css
.md-view {
  /* anywhere：只在"这个词单独一行也放不下"时才断，正常文本行长不变；
     代码块是 white-space: pre，不参与换行，仍按原样横向滚动。 */
  overflow-wrap: anywhere;
}
```

## 二、自检：先分清「真溢出」和「设计如此」

`textWrapping` 步骤（11 条断言）覆 live / source / preview 三条路径。写这一步踩了两个坑：

### 坑①把"滚动容器内部的溢出"当成了 bug

第一版直接量 `scrollWidth - clientWidth > 1` 就报溢出，结果把
`code.language-python` 的 **500px** 报了出来 —— 但它在 `pre { overflow: auto }` 里，
**横向滚动是设计如此**（代码块不该折行），它根本没有撑破布局。

改成：**从元素往上走，只要中间有 `overflow-x != visible` 的祖先，就不计入**
（= 它自己滚得掉，漏不出去）。修完是 `0 个`。

### 坑②产物截图拍到的是空状态

第一版步骤收尾 `Viewer.closeAll()`，而截图是**步骤返回之后**才拍的 ——
`check-ui-10-wrap.png` 拍到的是一张"最近项目"首页（060 轮踩过同款坑，技能里记了还是又踩一次）。

改成：**故意不关这个文档**，静态预览留在那儿，截图直接能看见长段落 / 长路径 / 宽表格都在列内；
只把 `myide-md-mode` 复位成 `live`，避免影响后面的步骤（已渲染的这个不受 localStorage 影响）。

## 五、可复用的判据

- 改正文列宽 / 加新的正文渲染路径时，**先问"它换行吗"**：CM6 要 `lineWrapping`，
  自写 HTML 要 `overflow-wrap`（中文断行不覆盖路径与 URL）。
- 量溢出必须排除滚动容器内部的溢出，否则每次都会把代码块报成 bug。
- 要截图的自检步骤，**末尾不要清场**（留一个"能看出结论"的状态），清场交给下一步或收尾。
