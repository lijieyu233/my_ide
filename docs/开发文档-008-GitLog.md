# 开发文档 008 —— PyCharm 式 Git Log

> 状态：已完成 · 对应 ROADMAP P1 增补

## 一、需求

当前 Git 面板的提交历史是纯文本列表，点击提交弹窗选文件，与 PyCharm 的 Log 差距：
1. **分支图**：看不到分支/合并结构
2. **无 HEAD 标记**：不知道当前在哪
3. **看提交详情要弹窗**：PyCharm 是点击提交 → 右侧直接显示变更文件列表 + diff

## 二、设计

### 提交列表（git 面板内）
- 左侧**分支图列**：标准列分配算法（gitk 简化版）——每提交一行图字符（`●` 当前提交、`│` 分支线、空列为空格）
- **HEAD 徽标**：当前分支最新提交右侧蓝色标记
- **过滤框**：按消息/作者/哈希子串过滤（前端内存过滤，depth 100 无压力）
- 保留：短哈希/相对时间/作者、点击选中态

### 提交详情（右侧内容区，替代弹窗）
- 点击提交 → 内容区渲染 **Commit 详情双栏**：
  - 顶部：返回按钮 + 短哈希 + 消息 + 作者/时间
  - 左侧文件变更列表（点击切换）
  - 右侧 diff（复用现有 hunk 表格，默认展示第一个文件）
- 抽取 `buildDiffTable(r)` 供整页 diff 与详情双栏共用

### 图算法（列状态机）
```
cols[] 每列等待的 commit oid
对每个提交：
  所在列 = cols.indexOf(oid) 或新开列
  行图：j===col → ●；cols[j] 非空 → │；否则空格
  更新：cols[col] = first-parent；其余 parents 若不在列中则追加新列
```
线性历史显示为单列 `●│` 直线；合并提交显示多列。

## 三、测试计划

1. 分支图：合并提交出现第二列 `│`；HEAD 行有徽标
2. 过滤框：输入消息子串 → 列表过滤
3. 点击提交 → 详情双栏出现（无弹窗），文件列表 2 项
4. 点击文件 → 右侧 diff 表格渲染
5. 返回按钮回到标签视图
