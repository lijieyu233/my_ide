# 编辑区左右与上下分屏

## 使用

- 标签栏右侧的“左右分屏”“上下分屏”图标，把文档区域分成两个编辑组。默认把另一份已打开文件放入第二组；只有一份文件时，第二组为空。
- 点击任一组后，从文件树、快速打开或顶部标签选择文件，只替换当前组。组顶部的文件下拉可选择已打开文件，悬停可看完整路径。
- 当前组标题下沿显示强调线。保存、查找、大纲、选区和AI上下文跟随当前组；两边分别保留光标、滚动、撤销历史和未保存内容。
- 拖动分隔线调整比例；双击均分。分隔线聚焦后可用方向键调整，Esc取消正在拖动的比例。比例不设置旧式20%–80%限制。
- 标签栏“合并编辑区”保留当前组。组标题的关闭按钮关闭该组、保留另一组。所有文件标签及未保存内容继续保留，不等于关闭文件。
- Markdown原“分屏”更名为“源码对照”，继续提供同一篇Markdown的源码和实时预览；可在任一编辑组中使用。

## 文档与会话边界

首版支持两个编辑组，不递归拆成四组。一个文件只有一个文档和编辑实例：选择已显示在另一组的文件会切换到那组，避免同一文件出现两份输入或保存冲突。阅读器沿用独立页面，进入书籍阅读时合并编辑区，编辑文档保留为标签。

项目会话保存分屏方向、组内文件和当前组，比例全局记忆。沿用会话原规则：未保存正文不写入会话快照，dirty文件的组位置记为空；切项目仍需经过现有未保存决策，不能靠分屏绕过。

Markdown图片相对目录、嵌入、链接、粘贴回调绑定各自EditorState上下文，异步图片/流程图只测量自己的编辑器。加载迟到、关闭、合并、外部重载、路径迁移均按原文档身份处理。

## AI接口

- `editor_state`增加`layout`，包含`orientation`（horizontal/vertical/null）、`active`与两组文件路径。
- `editor_control`增加`split_horizontal`、`split_vertical`、`unsplit`、`focus_group`；后者传`group:0`或`1`。
- 操作沿用写授权与editor_state快照；布局/组焦点变化使旧快照失效。首次空组也能读取编辑状态。
- 查找命令或设置快捷键可搜索“左右分屏”“上下分屏”“合并分屏”“切换编辑组”。默认不占用现有快捷键。
