# 启动面板识别外部运行程序

现场：平台后台的 5301 端口由另一启动面板运行的 Vite 进程监听，进程祖先为 `cmd /c "pnpm dev:platform"`，而 MyIDE 仍保存 10 月 10 日旧运行的 PID/身份。旧运行已结束，所以端口探测成功但自有进程核验失败，列表长期显示“端口有响应 · 待核验”。

本次补充只读识别：一次状态轮询共用进程快照和 TCP 监听者清单，核对端口的实际 PID、完整身份、监听者命令行中的项目路径及祖先的启动命令。祖先出生时间不得晚于子进程；PID 循环、混合监听者、缺身份、查询失败、路径前缀相似或命令不匹配都不能据此确认。

匹配成功返回 `ownership: external`、实际监听 PID 和 `processAlive: true`，清除关联旧运行的 runId。页面显示绿色状态点和“运行中 · 外部启动”，计入已确认运行数量。只读识别不登记为 MyIDE 自有进程，不覆写历史记录、不授予停止或重启权限，也不宣称输出就绪规则已验证。操作仍由原启动器管理。

验证：

- 当前真实平台后台 5301 已返回外部运行状态，旧运行记录保留。
- 启动服务测试 93 通过、0 失败，补充外部识别与拒绝误识别用例。
- 启动操作 DOM 测试 19 通过、0 失败，覆盖运行显示、轮询更新和按钮权限。
- 完整 DOM 测试 517 通过、0 失败；语法检查 81 文件通过。
- `scripts/check-launch-external.js` 在隔离用户配置的隐藏真实窗口中另起测试监听进程，验证真实系统探测、生产 IPC、页面显示及拒绝停止，共 3 项通过。已查看深红主题截图。

启动模块整套测试通过。通用 UI 检查为 460 通过、9 失败、3 跳过，剩余失败涉及 Git、H3 与 Mermaid；全量 npm 检查仍受已有 Git worker 测试失败影响，未报告为全通过。测试不停止、重启或修改用户实际业务服务。
