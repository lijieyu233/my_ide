# 文本格式与无损保存（FS-01 / FS-A）

> 2026-10-01；实施前基线7c55c4f。先修093-F1–F4：BOM/字节序、遗留编码有损保存及编辑器换行规范化。

## 实施合同

- 共享decodeText/encodeText，支持UTF-8、UTF-16LE/BE、GBK；格式对象明确encoding/bom/eol/detection，保留encoding旧字段。BOM与正文U+FEFF区分，UTF-16奇数/坏代理项、未知编码、无损往返失败稳定拒绝，禁止UTF-8兜底成功。
- legacy无格式写入保留现有可解码文件格式；显式编码转换由用户选择。GBK严格Unicode往返，不做规范化或字形“近似等价”，无法无损往返拒绝ENCODING_LOSS；原字节存在非规范映射时拒绝自动保存，保留文件，需用户显式选择Unicode格式。检测来源标明GBK推测/UTF-16启发式，不冒充所有字符集识别。
- 标签保存完整格式快照；失败不推进已保存版本。在途转换后继续输入/再改格式，旧回调不得覆盖新格式；同路径队列沿101。外部重载即使正文相同也更新格式；恢复旧标签重新读盘取得格式。
- CM6以状态字段保留原始换行，交易只转换新增换行；undo/redo保留原行尾。textarea保留原行尾序列，字符编辑不得整文件规范化。新增保存编码与重新打开入口，重新打开不得丢dirty或覆盖迟到新输入；输入法组合不触发提交，弹窗动作绑定文档身份/版本。
- 编码/换行矩阵逐字节验证，有损失败不写盘；DOM测试覆盖格式传递、转换等待与失败、重载及换行。真实隐藏Electron/IPC验证F1–F4、显式UTF-8保存emoji、重新打开与深浅截图；渲染层跑通用UI并核对既有失败，Markdown状态字段另补check-live。新模块加入语法/打包闭包。

## 范围与后续

无BOM的全中文UTF-16等探测歧义保留，并提供显式重新打开编码。严格拒绝遗留编码非规范字形是数据保全选择，后续可加原字节范围映射；不静默写问号。本包不关闭FS-B旧读取磁盘版本与TREE路径协调，也不承诺已迁移设置/DB等独立写端。UTF-8也拒绝孤立代理项，正常Unicode文本不做NFC/NFKC规范化。

## 交付与验证

- `text-format.js`统一读/写编解码；IPC仍兼容旧encoding字符串，无格式文本写入先读取目标格式，不能把既有BOM/UTF-16BE无声改成UTF-8。显式格式对象用所选编码转换；编码/往返验证全部发生在替换原文件前。GBK原始`a2e3`解码为欧元而编码回`80`的真实非规范映射也拒绝，不用近似字形或Unicode规范化放行。
- 标签保留完整textFormat，格式转换计入editRevision并固定保存快照；失败保留dirty和正文，旧回调不覆盖新格式/输入。相同正文的外部格式变化也更新，后台正文重载丢弃过期CM状态。显式选择的编码用于后续watcher重载，避免无BOM纯中文UTF-16成功保存后又被猜成GBK。外部文件主动转为其他无BOM编码仍需重新选择，自动推测不是所有字符集识别。
- `renderer/text-lines.js`在CM6状态中维护原始换行；交易保留未触及行尾、新换行采用文档主要行尾，历史逆效果用压缩行尾序列恢复undo/redo。textarea用最长前后缀保留未触及行尾；批量替换中被实际重写的行采用主要行尾，不承诺还原已删除又重新输入的原换行。
