# 与 DSH 会话双向同步（标题 / 运行中 / 中断）

用户要求（2026-11-01）：

> 1 希望这里的名称修改和 dsh 同步
> 2 希望我在 dsh 中发起的会话 在运行时 my_ide 也能识别到并加入进来
> 3 如果我在 dsh 继续中断会话 my_ide 也能识别到

## 唯一数据源：宿主的 session/list

三项需求本质是同一件事：**MyIDE 的历史列表必须以 DSH 宿主为准，而不是自己的 localStorage。**
宿主的 `session/list` 一次就给出全部所需：

```json
{"items":[{"sessionId":"myide-…","updatedAt":1793514984331,"agentAvailable":true,
  "running":true,"blank":false,"cwd":"D:\\document\\code",
  "projections":{"values":{"title":"为什么无法删除文件", …}}}]}
```

- `projections.values.title` → ① 名称
- `running` → ③ 运行中 / 已中断
- `cwd` → ② 关联到哪个项目（DSH 按 cwd 分工作区）

配套改名端点 `session/rename`。

### 两个端点的参数形态不一样（实测踩过）

| 端点 | 正确 args | 错误写法会得到 |
|---|---|---|
| `session/list` | `{_request:{}}` | `missing "_request"` |
| `session/rename` | `{request:{sessionId,title}}` | `missing "request"; unexpected "_request"` |

`dsh-native.request()` 里分别处理，测试按真实形态断言（`dsh-native.test.js`）。

## 实现

| 层 | 改动 |
|---|---|
| `dsh-native.js` | 新增 `session/list` / `session/rename` 两个分支；list 把宿主原始项归一化成 `{sessionId,title,running,blank,agentAvailable,cwd,updatedAt}`，`title:null`（空白会话）归一成空串 |
| `ai-dsh.js` | 新增 `listSessions(cfg)` / `rename(cfg,sessionId,title)`；改名校验（1–120 字符）放在这层，ACP 与 native 两条链路都挡得住 |
| `main.js` | 新增 IPC `ai:dsh-sessions` / `ai:dsh-rename` |
| `preload.js` | `dshSessions(cfg)` / `dshRename(cfg,id,title)` |
| `ai-panel.js` | 历史列表改为「宿主目录 + 本地记录」合并；改名写回宿主 |

### 渲染层的三个要点

1. **`sessionsForHist()` 以宿主为准**：标题优先取宿主 `title`，`running` 取宿主实时值。
   按 `cwd` 过滤，只收当前项目的会话（别的项目混进来会带回错误上下文）。
   宿主里没有、本地有的（离线时发的）仍列出，避免历史突然消失。
2. **改名写回宿主**：先 `dshRename` 成功，再更新本地副本；失败只提示、不改本地，
   不会出现「界面改了但 DSH 没改」的假同步。
3. **打开历史时刷新一次宿主目录**：这是「DSH 里刚发起/刚中断的会话能立刻看到」的关键。

### 刷新的坑（踩了三轮）

打开历史 → 异步拉宿主目录 → 刷新列表，这条路径上先后踩到：

1. `refreshDshCatalog()` 把 IPC 返回的 `{ok,items}` 整个当成 items 存进缓存 → 永远 0 条。
2. 缓存没有项目身份，切项目后把上一个项目的会话也列进来 → 加 `root` 并校验。
3. 刷新时调用 `renderHist()`：它第一句就是 `closeHist()`，于是**刷新自己把面板关掉**，
   表现为「点历史没反应 / 列表一直是旧的」。
   → 拆出 `renderHistRows(pop, all, running)`，刷新只重写已存在面板的行，不动面板节点。

另外 `catalogUsable()` 里用了裸 `DocumentPaths`，在 eval 作用域下会 `ReferenceError`，
改为本地 `pathKey()`。

## 验证

- `tests/dsh-native.test.js`：新增「会话目录与改名的真实端点形态」——`list` 用 `_request`、
  `rename` 用 `request` 包装、无 sessionId 的项被丢弃、`title:null` 归一成 `''`。17 通过 / 0 失败。
- `tests/ai-dsh.test.js`：新增「会话目录与改名代理宿主」——透传字段、改名落到宿主、
  空标题/超长标题在本地就拒绝且不发请求。23 通过 / 0 失败。
- `tests/ai-panel-runs.test.js`：新增「MyIDE 历史以 DSH 会话目录为准」——DSH 里发起的会话
  出现在列表、别的项目不混入、宿主 `running` 决定「运行中」标记、宿主改成 `running:false`
  后标记同步消失、改名写回宿主。58 通过 / 3 失败（那 3 条是改动前就存在的基线红灯）。
- `node tests/dom.test.js`：528 通过 / 0 失败。
- **真实 DSH 端到端**（`curl` + 本机 19387）：31 个会话 / 2 个运行中；取一个会话改名 →
  `session/list` 立刻反映新标题 → 改回原值，确认无误。

## 已知边界

- 历史列表只收录 `cwd` 等于当前项目的会话。DSH 里在别的 cwd 开的会话不会出现在当前项目，
  这是有意的（否则第二条消息会带着错误的项目上下文）。
- 「在 DSH 里中断」的判定完全依赖宿主的 `running`。宿主把中断后的会话标为 `running:false`
  （实测如此），MyIDE 随之去掉「运行中」标记；MyIDE 自己的本地状态不参与这个判断。
