## 二、拖拽引用：文件/文件夹拖进面板就进上下文

### 两类来源，一套处理

```js
// ① 项目树里拖过来：tree.js 已经在发 text/myide-path / text/myide-paths 自定义 MIME，直接复用
// ② 从系统（资源管理器 / Finder）拖文件：Electron 32+ 已移除 File.path，必须走 webUtils.getPathForFile
const fl = e.dataTransfer.files;
for (const f of fl) {
  const p = window.myIDE.fs.pathOfDroppedFile(f);   // preload 里包了 webUtils
}
```

- 文件 → 读内容进上下文；目录 → 项目内复用 `dirTreeText()`，项目外列一层路径清单（上限 300 项）
- **视觉反馈**：`dragover` 时整块高亮 + 一句「松手 → 加入上下文」（`.drop-active::after`），
  不让人猜"松手会怎样"；拖拽结束/移出立即撤掉
- **不拦截纯文本拖拽**：只接管 `Files` / `text/myide-path(s)`，避免影响用户在输入框里拖字

### preload 新增

```js
const { contextBridge, ipcRenderer, webUtils } = require('electron');
// fs 里：
pathOfDroppedFile: (file) => { try { return webUtils.getPathForFile(file) || ''; } catch { return ''; } },
```

## 三、授权记忆：确认过一次，就别再问

用户的原话是「**不然我一次次点击确认多累**」。这也是竞品的共识痛点 —— Cursor 文档里那句
"Twenty clicks later, you wonder why anyone calls it productive" 说的就是同一件事。

### 设计：借用 VS Code 的两维模型

| 维度 | 取值 |
|---|---|
| **范围** | 本次会话（内存） / 本项目（localStorage，按项目分开存） |
| **粒度** | 整类操作（写文件 / 执行命令） / 单条命令前缀（如 `git`、`npm test`） |

```js
let sessionPerm = { write: false, run: false };
const permKey = () => 'myide-ai-perms:' + ((window.App && App.root) || '');

function writeNeedsConfirm() {
  const base = permWrite();
  if (base === 'deny') return 'deny';
  if (base === 'auto') return 'no';
  if (sessionPerm.write || loadPerms().write) return 'no';   // 记住过就不再问
  return 'yes';
}
function runNeedsConfirm(cmd) {
  if (permRun() === 'deny') return 'deny';
  if (sessionPerm.run || loadPerms().run) return 'no';
  const t = String(cmd || '').trim();
  if ((loadPerms().cmds || []).some((pre) => pre && t.startsWith(pre))) return 'no';  // 命令前缀白名单
  return 'yes';
}
```

### 确认弹窗都多了一个「记住」出口

- 改文件（`confirmDiff`）：`拒绝` / **`本项目内都允许`** / `应用修改`
- 执行命令（新增 `confirmRun`）：`拒绝` / **`总是允许「git」`**（按前缀记） / `运行一次`

### 设置页：已记住的授权看得见、清得掉

否则"怎么突然不问了"会变成新的困惑。设置 → AI 助手 里列出：

```
已记住的授权（本项目）
  改文件不再询问（本项目）                      [清除]
  以「node」开头的命令不再询问                  [清除]
```

**没做**（本轮明确不做，列在第六节）：按路径 glob 的写白名单、deny 黑名单、`/yolo`、LLM 风险判定。

为了让自检能验"多轮不同动作"，把模型桩从**按轮次计数**改成**按用户这轮说什么分派**：

```js
const toolDone = last.role === 'tool' || (typeof last.content === 'string' && last.content.indexOf('<tool_results>') >= 0);
if (toolDone) { /* 收尾文本 */ }
else if (ut.indexOf('第一次改') >= 0) { /* write_file 第一版 */ }
else if (ut.indexOf('第二次改') >= 0) { /* write_file 第二版 */ }
```

否则一个步骤跑完计数器就用完了，后面的步骤没法各说各话。

## 七、踩坑

1. **Electron 33 移除了 `File.path`** —— 拖拽取真实路径必须走 `webUtils.getPathForFile(file)`，
   且要在 **preload**（同渲染进程）里调用后再暴露给页面。
2. **`jsdom` 里的 `dataTransfer` 必须自己造**：`Object.defineProperty(ev, 'dataTransfer', { value: dt })`，
   否则 drop 处理器拿不到。真实 Chromium 下同样适用（比构造 DragEvent 更可控）。
3. **改了确认弹窗的按钮 id，旧测试会连锁失败**：`run_command` 用例还在找 `#cf-yes`，
   它挂住（promise 永不 resolve）→ `busy` 不释放 → **后面所有用例的发送都被忽略**，看起来像"多个功能同时坏了"。
   改交互后要顺着把测试的按钮/文案一起改。
4. **Python 内联脚本的转义别省**：`replace(/^\\//, '')` 少了一层 → 生成出 `replace(/^\\//, '')`（正则提前结束）→ 语法错误。
   写正则里的字符类统一用 `/^[\\/]/` 这种写法，并在生成后立刻 `node --check`。
