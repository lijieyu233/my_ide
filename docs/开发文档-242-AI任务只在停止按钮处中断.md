# AI 任务只在「停止」按钮处中断

用户要求（2026-11-01）：

> 我不希望我切换会话时中断 dsh 会话，只有我点击这个（停止）按钮才会主动中断，其他我的任务操作都不中断。

一句话契约：**除了停止按钮（和确认框里的「停止本次任务」），任何界面动作都不得对原生 DSH 任务发 `session/cancel`。**

## 为什么以前会被中途掐断

侧栏有五个入口会离开当前会话 / 页面 / 项目，它们原本都写成同一种退化结构：

```js
if (!parkDshRun()) stopRun();   // 挂不起来就掐掉
```

`parkDshRun()` 里有一句 `!run.stream` 的守卫：流还没建立（刚点发送、正在连 Harness）时挂起失败，
于是掉进 `stopRun()`；`onProjectChange` 更直接写着 `if(!retained) stopRun(true)`。用户看到的现象就是
「切一下会话，跑了半天的任务没了」，而且没有任何提示说明是被自己的切换动作掐掉的。

## 现在的做法

新增 `detachRun()` 作为唯一入口，返回值只有四种，**没有一条 abort**：

| 返回值 | 含义 | 对原生任务的影响 |
|---|---|---|
| `parked` | 流已建立，整块视图搬进后台记录 | 继续跑，输出继续累计，回来/点状态条接上 |
| `released` | 流还没建立，prompt 没发到主进程 | 无（本来就没开始） |
| `stopped` | 普通 API 引擎，没有后台记录机制 | 维持原来的停止语义 |
| `none` | 本来没有在跑 | 无 |

`releaseLocalRun()` 只清本地视角（`currentRun` / `busy` / 停止按钮），不碰 `controller`、不发 abort。

替换掉的五个调用点：

| 入口 | 原来 | 现在 |
|---|---|---|
| 新建对话 `#ai-new` | `stopRun(true)` | `detachRun()` |
| 历史会话切换 `openSession` | `if(!parkDshRun()) stopRun(true)` | `detachRun()` |
| 切项目 `onProjectChange` | `if(!retained) stopRun(true)` | `detachRun()` |
| 收起面板 `syncVisible(false)` | `if(!parkDshRun()) stopRun()` | `detachRun()` |
| 切工具页 `onPageChange` | `if(parkDshRun()) … else stopRun()` | `detachRun()` |

仍然保留中断的三处：`#ai-stop` 停止按钮、原生确认框的「停止本次任务」（`ai-approval-ui` 的
`ai-approval:stop`）、AI 自己的 `ai_session_control{operation:'stop'}`。

## 两个配套修正

1. **挂起后不再撤销会话授权**：`clearSessionPermissions()` 会调主进程 `ai:clearSession` →
   `ui.cancelOwner()` + `authority.revoke()`，正在等用户确认的那一步会直接变成「确认已取消」——
   对用户来说又是一次「怎么突然停了」。改成 `releaseSessionPermissions(detachRun())`：只有
   `parked` 时才保留这次会话的临时授权，真离开才清。
2. **切到别的会话不再顺手接管旧任务**：`restoreBackgroundRun` 原有一条「同 scope 只有一条就接管」的
   兜底，用于会话 id 在挂起与恢复之间从 `null` 变成真实值的窗口。现在用户主动切到**另一个**会话时
   它也生效，新会话里会突然出现上一个任务的内容。改为只在 `!curSessionId`（还没有明确会话）时才兜底。
