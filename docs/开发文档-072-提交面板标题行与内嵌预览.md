# 开发文档-072 · 提交面板标题行（「提交」竖排）与内嵌预览的说明/出口

> 用户三条反馈（附侧栏截图）：
> ① 「提交两个字怎么竖着 好难看」
> ② 「这个预览是什么意思」
> ③ 「为什么改成在侧边栏显示了 这么小的地方怎么看」

## 一、「提交」竖排：flex 的匿名项被压到 min-content

`.panel-title` 是 `display:flex`，标题文字是个**匿名 flex 项** —— 它的 `min-width` 是 `auto`，
即 **min-content = 一个汉字的宽度**。标题行内容一超宽，浏览器就把标题压成一字一行（竖着）。

实测这一行的内容宽度：

| 部分 | 宽度 |
|---|---|
| 内边距（12px × 2） | 24 |
| 「提交」 | 24 |
| 分支 `⎇ main` | ~49 |
| `↑1 ↓34 · 65 处修改` | ~88 |
| 拉取 + 推送（图标 + 文字） | ~110 |
| 搁置 / 远程 / 刷新 / 日志（4 个图标钮） | ~112 |
| 间距 | ~29 |
| **合计** | **~436** |

侧栏默认 340px（可用 316px）—— **超出 120px**。老实现能"看起来是一行"，靠的就是压标题：
把 24px 的标题压到 ~12px，字就竖起来了。

### 修法：把仓库级操作挪到工具行

`搁置 / 远程 / 日志 / 刷新` 原本和 `拉取 / 推送` 挤在标题行里。它们本来就是**仓库级操作**，
和工具行里的 `刷新 / 回滚 / 差异 / 提交` 同层 —— 挪下去之后：

- 标题行 = 分支 + ahead/behind + 修改数 + `拉取 / 推送` ≈ **313px ≤ 316px** ✓
- 工具行 = 8 → 11 个图标（在文件列表上方，高度弹性，多一行只是少显示两行文件）

配套两条 CSS：

```css
.panel-title {
  white-space: nowrap;                    /* 标题的 min-content 抬到整词宽 —— 不再被压成竖排 */
  flex-wrap: wrap;                        /* 真放不下时整行换行，而不是裁掉/压扁 */
  min-height: var(--head-h);              /* 不换行时仍是 30px，与其他标题行底线齐平 */
  column-gap: 6px; row-gap: 2px;
}
#cd-dirty { min-width: 0; overflow: hidden; text-overflow: ellipsis; }  /* 唯一可压缩项（缓冲垫） */
```

⚠ **移动按钮的两个坑**（都踩了）：

1. **按索引取按钮的地方会全乱**：dom 测试与自检步骤用 `btnsOf()[4]`（预览）、`[6]`/`[7]`（展开/分组）
   → 新按钮**追加在工具行末尾**，不动前面的索引。
2. **按 id 点击的地方会失效**（`#cd-shelve` / `#cd-remote` 各有一处 dom 测试）→ `mk()` 增加 `id` 参数，
   挪过去的按钮保留原 id。

## 二、内嵌预览：它是什么，为什么会在侧边栏

工具行里那个**眼睛**是「内嵌预览」开关：

| 状态 | 点文件行的行为 |
|---|---|
| 关（**默认**） | 在**主编辑区**打开差异（PyCharm / VS Code 的做法） |
| 开 | 在侧栏下方那 ~200px 的小框里显示行级 diff |

`let previewOn = !!uiPrefs.preview` —— 从 `ecd4662`（首次引入）起**一直是默认关**，
所以它不是"被改成在侧边栏显示"，而是**用户自己点开过**（存在 `myide-git-ui` 里）。
问题在于：开着的时候框上没有任何文字说明，只有一个 24px 图标被染成强调色 ——
用户既没意识到它开着，也不知道它叫什么。

### 修法：说清 + 给出路

1. 预览框头加 `面板内预览` 标签（+ tooltip 写清开关状态与怎么关）
2. 预览框头加 **「在编辑区打开」** 按钮：同一个文件一键转到编辑区看整体（面板窄时的出口）
3. `.git-cp-bar .vt-btn.active` 加 tint 底 —— 24px 图标只染个色，27" 屏上等于没有状态

```
PASS  预览框上写明它是「面板内预览」          ["面板内预览"]
PASS  工具栏的眼睛按钮有可见的「开」状态      [class=vt-btn active]
PASS  预览框里有「在编辑区打开」按钮
PASS  点它 → 同一个文件在编辑区打开           [编辑区=renderer\git-panel.js]
```

## 三、自检：新增两步（32 → 34）

`commitTitleLayout` —— 怎么用 DOM 断言"两个字没竖排"：
用 `Range` 只框住标题的前两个字，**竖排会得到 2 个 rect（或一个只有 1 字宽 / 1 行高的 rect）**：

```js
const rg = document.createRange();
rg.setStart(tn, 0); rg.setEnd(tn, 2);          // 「提交」
const rs = [...rg.getClientRects()];           // 横排=1 个 rect 且宽 ≥ 20px
```

```
PASS  默认宽度下「提交」排在一行（不是竖排）        [rect 数=1 宽=24px]
PASS  标题行与标签栏等高（30px，交界底线对齐）      [30 vs 30]
PASS  默认宽度下 ahead/behind + 修改数 完整显示     ["↑1 ↓216 · 17 处修改" 需要=83px 实际=83px]
PASS  拉到最窄时「提交」仍横排                     [rect 数=1 宽=24px]
PASS  窄侧栏下标题行内容不被裁掉（换行代替溢出裁剪）[裁掉=0px 行高=42]
```

`commitTitleLayoutReset` —— 收尾（**别省**）：`togglePreview(false)` + 侧栏宽度写回"进来时的值"。
⚠ 侧栏宽度是 JS 写在 `style.width` 上的（`myide-sidebar-width:v2`），置 `''` **不等于**还原。

```
PASS  内嵌预览已关（开关不再留在 localStorage 里）    [hidden=true]
PASS  侧栏宽度已还原                                [340 vs 340]
PASS  编辑区对比视图已关
```

顺带修掉一个**一直存在的自检泄漏**：`commitPanelParity` 打开内嵌预览后（会写 `myide-git-ui`）
从来没关过，后面所有步骤量的都是"预览开着"的状态。
