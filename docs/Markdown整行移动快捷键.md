# Markdown 整行移动快捷键

2026-11-11。只新增 Markdown 编辑动作，不改变 IDE 布局或其他语言的键位。

## 使用

- `Ctrl + Shift + ↑`：整行上移。
- `Ctrl + Shift + ↓`：整行下移。
- 没有选区时移动光标所在的**物理整行**，不是软换行后的视觉小段；光标跟随，保留行内位置。
- 选中多行时整块移动，保留正向/反向选区。选区刚好结束在下一行行首时，不把那一行多算进去。
- 顶部不能再上移、底部不能再下移时不改正文、选区或 dirty。空行和末尾有/无换行均支持。
- 实时预览、源码、源码对照中的编辑框使用相同快捷键。每次移动可独立撤销，不与前后键入合并；源码对照使用 Chromium 原生编辑事务，不重置整份 textarea 内容或清空撤销栈。
- 多光标按相邻行块移动，贴顶/底的不动光标和主选区仍保留。

在「设置 → Markdown」中可修改或解绑「整行上移 / 整行下移」。动作也使用现有命令面板注册表；新增默认键不会覆盖用户已有自定义。原来的编辑器 `Alt + ↑/↓` 不删除、不重绑。

## 范围与保护

仅 Markdown 的可编辑区域处理新键位；只读、读取错误、路径操作、编码切换、失效编辑器、上层弹窗、输入法组合和快捷键捕获期间不修改文件。不劫持搜索框、AI/终端等其他输入。

实时预览表格中的单元格是独立嵌套编辑器，新动作不把它当源文件整行移动；需要移动表格的 Markdown 源行时切到源码模式。

[移动计划](../renderer/md-editor.js)基于邻接物理行的局部 changes，不重新替换整份 CM 文档；选区与正文在同一个事务中更新。混合 CRLF/CR/LF 保留原行尾**位置序列**，不将全文件转为 LF；[行尾字段](../renderer/text-lines.js)在同一个历史事务中保存恢复模式，undo/redo 不因邻行重建而改变行尾格式。
