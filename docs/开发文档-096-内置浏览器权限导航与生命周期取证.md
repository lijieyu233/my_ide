# 内置浏览器权限、导航与生命周期取证

> 2026-10-01，第七轮持续审计；基线 `bfcab1d`，MyIDE 0.8.5。
> 对应 [089 总台账](./开发文档-089-全模块成熟项目对照与持续改进台账.md) 的 BROWSER-01。本轮交付取证与方案，未修复产品/测试。权限/系统协议边界列 P0，导航、持久化与资源体验保持 P1。

## 1. 环境、方法和结论边界

真实宿主实验使用 **Electron 33.4.11 / Chromium 130.0.6723.191 / Node 20.18.3**，VM原样加载 main.js 从 `let bwView = null;` 至窗口控制IPC注释前的整段。WebContentsView、BrowserWindow、网页导航和权限查询是真实 Electron；IPC注册收集为函数表并直接调用，shell.openExternal为记录桩，宿主状态send为记录桩。关闭回调用原文件的清空引用行为。不是完整MyIDE启动或真实IPC传输覆盖。

临时 userData 在系统临时目录独立 profile，入口在 app.ready 前设置；全部窗口 show:false/skipTaskbar:true，启动带 --headless/--disable-gpu/--no-sandbox。仅访问临时 loopback HTTP fixture，不访问外部站点，不取真实位置、摄像头、屏幕、剪贴板，不发系统通知，不实际启动外部协议应用。关闭观察另加空 window-all-closed监听来保留测试进程；**MyIDE真实代码会app.quit，因此不以该观察宣称正常退出后还有残留进程**。

DOM实验使用 **Node v22.20.0 / jsdom 29.1.1**，读取实际 index.html（outside-only，不运行其脚本），完整eval browser.js。页面bridge、rAF、rect为可控桩。宿主H实验使用同一原始main段与WebContentsView桩，控制loadURL Promise顺序。没有修改用户收藏、Cookie、会话或源码；临时入口/profile/report读完清理。

本轮共4项真实宿主观察E1–E4（E0为环境）、6项DOM观察D1–D6、2项宿主受控观察H1–H2，另有权限拒绝及缩放正向对照。E1仅证明Permissions API状态，E2仅证明分派到记录桩，不证明权限实际访问、OS命令执行或可利用链。实际资源容量、可视遮挡、音视频及跨平台行为仍需补验。

## 2. 真实 Electron 观察

| 编号 | 操作 | 实际结果 | 解释与范围 |
|---|---|---|---|
| E0 | 原ensureBwView创建实例，读取webPreferences/启动参数 | sandbox=true、nodeIntegration=false、contextIsolation=true；no-sandbox启动开关=true | Node隔离配置存在，但不能用sandbox偏好值证明Chromium进程沙箱有效；官方文档明确该CLI开关禁用全部进程沙箱 |
| E1 | 新隔离profile的loopback页查询geolocation/notifications | 两者state=granted；同session安装check=false/request回调false后均denied | 产品未安装业务permission handler，默认授权状态可复现；没有调用实际定位或创建Notification。拒绝对照证明控制入口有效 |
| E2 | 测试页window.open('myide-audit:benign-fixture','_blank') | shell记录桩收到该未知协议1次 | 原window-open handler只按协议正则匹配，未限定允许列表/请求来源；返回deny只阻止新窗口，已经执行的外发不会被撤销 |
| E3 | attach后view-hide，等待2200ms | attached=false、webContents仍存活，页内40ms interval计数0→3 | 隐藏保留页面/登录态符合现有设计，但不等于停止页面任务；计数受隐藏节流，不能外推CPU/RSS或媒体状态 |
| E4 | 再attach，关闭宿主；执行mainWindow=null/bwView=null，保留测试事件循环150ms | hostDestroyed=true、guestDestroyed=false，仍可读取页计数3，缓存引用null | 清空变量不关闭独立webContents；宿主关闭清理缺口成立。真实app.quit最终退出的进程释放未做完整应用取证 |

实验最终显式close网页webContents，销毁宿主并退出0。首次直接启动时无法从GUI进程可靠收集stdout，检查存活PID后终止该夹具；改用文件报告/Start-Process等待退出。第一次文件报告在最后窗口关闭时提前退出，未得到E4；最终加空window-all-closed监听后取得完整结果。不能把未执行的早期E4算通过。

当前正常MyIDE也按仓库规定带--no-sandbox重启。本轮未改变启动参数；后续需先验证Windows实际启动/权限兼容，再决定移除该开关，不能在文档中将偏好值sandbox=true写成有效OS隔离。

## 5. 分包实施与验收

### 096-B-A：权限与协议边界（BROWSER-01，P0）

建议拆成协议策略、权限服务两个独立提交，先在主进程落实：

1. 导航入口、window-open、页面重定向/顶层导航共用URL解析/决策服务。按来源区分用户地址输入、宿主打开本地预览和网页请求；普通http/https继续可用。about:blank仅内部使用；javascript/data和未知自定义协议不外发。file仅限用户/宿主明确选择的本地打开，禁止网页借弹窗切本地文件；实际Chromium拦截也不能代替宿主政策。
2. shell调用只接受明确支持的mailto/tel等集合和有限长度合法参数；网页来源必须显示请求站点/目标并确认一次，已记忆的合法站点/协议授权复用。无法证明用户手势或请求归属时拒绝，不能伪造为用户主动打开。未知协议明确返回blocked，不调用shell；对已存在会话授权沿用用户决定。
3. 只给persist:myide-browser安装check/request处理，schema={origin,permission,decision,scope,updatedAt}；不影响IDE本地宿主页。check读取有效授权且无UI副作用；request按能力显示提示并保证callback恰好一次。页面切走/关闭/超时则拒绝旧请求，确认后再次验证frame/origin/代次。
4. 首版支持确有需要的权限类型，未知类型默认拒绝并可解释。摄像头/麦克风、屏幕共享、剪贴板、设备、通知分别定义；媒体/设备选择器按Electron安装版本能力实现，不能一个media总开关授权全部设备。iframe用真实请求来源及embeddingOrigin；HTTP非安全来源、opaque/null/service-worker来源明确处理，测试loopback例外只限开发。
5. 地址栏附近统一“站点权限”入口，列出此次/持久决定，可逐条撤回；权限清除不等于Cookie清除。Cookie/站点数据清理另有范围说明与确认，保持默认登录态复用，避免每次显示浏览器都要求重新登录。
6. 调查--no-sandbox依赖，先用隔离profile验证不带该开关的浏览/IPC/预览/打包启动。若不能启用进程隔离，记录可复现原因并给远程内容访问设明确降级方案，不显示虚假安全状态。本轮仍按现有参数重启，未擅改运行方式。

验收：E1在无授权时不能直接granted；允许一次/记忆/撤回后状态一致；跨origin、iframe、旧确认、null来源均不越界。E2/H2未知协议零shell调用，合法mailto/tel只在有效决定后一次调用；取消无副作用。保留http/https、用户本地HTML、target=_blank就地导航及后退功能。协议策略可先交付，不等待完整权限UI；严禁用启动真实系统命令作为回归验证方式。

### 096-B-B：导航与浮层归属（BROWSER-01 / PROJECT-01，P1）

每个view有viewId，每次导航有navigationId，挂载/隐藏有visibilityGeneration；主进程状态带阶段accepted/loading/committed/failed/canceled及最终URL。view-open的返回明确仅接收，不能当加载成功。旧loadURL catch必须检查代次；did-fail-load按主frame与导航归属匹配，ERR_ABORTED按取消处理，不能用“当前URL一样”代替代次。

渲染层只消费当前view/导航状态，加载新页清错误，旧失败不更新新页。requestAnimationFrame前后及focus前检查可见、浮层和代次；go、show、overlay关闭都走同一挂载决策。错误层显示时原生层是否遮挡需实际确认，必要时摘view；错误关闭后仍按当前可见状态恢复。隐藏后取消未执行的focus/bounds任务，保留缩放换算。

localhost规则先明确产品约定：现有行为补https、已有测试固定。建议支持显式http输入并在本地预览入口保留来源协议；如要修改裸localhost默认，单独迁移文案/测试，不自动忽略TLS错误或悄悄从https回退http。地址栏区分提交输入/正在导航/已提交URL，失败重试针对失败请求而非上一页currentUrl。

验收：H1+D3乱序旧错误无效；D1在已开弹窗时首次打开不attach，弹窗关闭仅挂一次；D2 hide后零focus调用；resize/zoom/multiple-overlay矩阵复测。真实隐藏Electron测加载失败、迅速A→B、重定向、hash、证书失败、back/forward以及125/150%截图。只对策略选择过的导航进行检查，不阻止普通网页正常跨站浏览。

### 096-B-C：显式关闭与隐藏预算（BROWSER-01 / PERF-01，P1）

采用created/attached/detached/disposed状态，removeChildView仅表示detached。宿主closed/新宿主替换时先解绑事件/取消导航与待权限，再close独立webContents，最后清引用；ensure检查isDestroyed，必要时重建，注册不要重复。关网页时beforeunload如何处理明确区分用户关闭与最终app退出，不能无界等待；下载/会话是否继续单列。

默认隐藏仍复用一个页面与persist session，保持登录和交互连续性。E3证明任务可继续，先测隐藏页空载、定时器、音视频、下载、WebSocket/worker；根据业务决定暂停媒体或提供“关闭网页/释放资源”动作。不要通过隐藏就destroy所有页面或清Cookie来达内存目标。服务worker/session是不同生命周期，close网页不等于删除站点后台状态。

验收：E4在保留事件循环的夹具中guest关闭；完整MyIDE退出再查本应用关联进程，不能混入其他Electron。20次显示/隐藏不新增webContents、监听或权限callback；20次打开/关闭能释放页面资源，持久登录仍可恢复。报告真实全进程RSS/CPU、媒体与网络行为，不把interval计数当性能达标证明。

### 096-B-D：收藏/历史持久化与坏数据（BROWSER-01 / SETTINGS-01，P1）

JSON逐项验证url/title/folder/ts，坏条目隔离、留原串供恢复，其余继续显示；初始化失败复位visible/可重试。saveJSON返回确认结果，add/move/rename/delete只有保存接受才更新成功提示；真实镜像写失败区分“内存已更新/未持久保存”，复用091的确认与串行写。删除文件夹跨两个key更新应有版本化单快照或明确回滚，避免一半成功。

不把权限/Cookie/秘密放进普通收藏导出；历史只保留合理URL信息，带口令/userinfo或敏感query是否保存需明确策略。默认收藏、文件夹排序、SVG图标及“收藏”现有术语保持。

验收：D4配额失败不报成功；D6坏项不阻断正常项和再次打开；两个key其中一次写失败不产生错误分组；设置镜像落盘/重启验证保留有效数据。正常收藏拖拽、重命名custom标志、50条历史限制仍通过。

## 6. 隐藏宿主的关键复跑脚本

将下段保存到 **新建系统临时目录** 的entry.js，用仓库electron执行，参数带`--repo=<仓库绝对路径> --headless --disable-gpu --no-sandbox`；同shell先清ELECTRON_RUN_AS_NODE。建议Start-Process -WindowStyle Hidden -PassThru -Wait，读取临时目录report.txt并确认退出0。这里只复跑E1/E2/E4，完整E3条件见§2；它直接调用原处理器，不代表真实IPC验收。

```js
const { app, BrowserWindow, WebContentsView, nativeTheme } = require('electron');
const fs = require('fs'), path = require('path'), vm = require('vm');
const http = require('http'), assert = require('assert');
const repo = process.argv.find(x => x.startsWith('--repo=')).slice(7);
app.setPath('userData', path.join(__dirname, 'profile'));
const log = value => fs.appendFileSync(path.join(__dirname, 'report.txt'),
  JSON.stringify(value) + '\n');
app.on('window-all-closed', () => {});
const timer = setTimeout(() => { log({ timeout: true }); app.exit(3); }, 30000);
app.whenReady().then(async () => {
  let host, wc, server, exit = 0;
  try {
    server = http.createServer((req, res) => res.end('<title>fixture</title>'));
    await new Promise(r => server.listen(0, '127.0.0.1', r));
    host = new BrowserWindow({ show: false, skipTaskbar: true });
    host.webContents.send = () => {};
    const handlers = {}, external = [];
    const raw = fs.readFileSync(path.join(repo, 'main.js'), 'utf8');
    const start = raw.indexOf('let bwView = null;');
    const end = raw.indexOf('// ---------- IPC：窗口控制', start);
    assert(start >= 0 && end > start);
    const ctx = vm.createContext({ mainWindow: host, WebContentsView, nativeTheme,
      ipcMain: { handle: (key, fn) => handlers[key] = fn },
      shell: { openExternal: u => { external.push(u); return Promise.resolve(); } }
    });
    vm.runInContext(raw.slice(start, end), ctx);
    const view = vm.runInContext('ensureBwView()', ctx); wc = view.webContents;
    await wc.loadURL('http://127.0.0.1:' + server.address().port);
    const query = () => wc.executeJavaScript(
      "navigator.permissions.query({name:'geolocation'}).then(p=>p.state)");
    log({ defaultPermission: await query() });
    wc.session.setPermissionCheckHandler(() => false);
    wc.session.setPermissionRequestHandler((w, p, cb) => cb(false));
    assert.equal(await query(), 'denied');
    wc.session.setPermissionCheckHandler(null);
    wc.session.setPermissionRequestHandler(null);
    await wc.executeJavaScript("window.open('myide-audit:benign-fixture')");
    await new Promise(r => setTimeout(r, 150)); log({ external });
    assert(external.includes('myide-audit:benign-fixture'));
    handlers['browser:view-open']({}, null);
    host.on('closed', () => vm.runInContext('mainWindow=null;bwView=null', ctx));
    const closed = new Promise(r => host.once('closed', r)); host.close();
    await closed; await new Promise(r => setTimeout(r, 150));
    log({ hostDestroyed: host.isDestroyed(), guestDestroyed: wc.isDestroyed() });
    assert(!wc.isDestroyed());
  } catch (e) { exit = 1; log({ error: String(e.stack || e) }); }
  finally {
    if (wc && !wc.isDestroyed()) wc.close();
    if (host && !host.isDestroyed()) host.destroy();
    if (server) await new Promise(r => server.close(r));
    clearTimeout(timer); app.exit(exit);
  }
});
```
