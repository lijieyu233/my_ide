# 文件右键绿盾解密

2026-11-10。局部增加项目文件树右键入口，不改 IDE 布局，不自动解密、不批量处理目录。

## 使用

1. 在本地项目树右键**单个文件**，选择「绿盾解密」。文件夹、远程文件和多选不提供该入口。
2. 有未保存的修改或编码操作时，先拒绝处理；不会自动保存或丢弃输入。
3. 主进程弹出确认框，列出文件和实际工具路径，默认取消。只有信任此工具且已获解密授权才继续。
4. 使用本机现有 `OcularDecrypt.exe`，以单独参数传递所选文件，原地处理。不会把目录作为默认目标，也不通过 shell 拼接命令。
5. 工具结束后刷新树和已打开的可靠文本标签。处理中新增的输入保留，不用迟到的磁盘正文覆盖；原先因加密读取失败的文本错误页可恢复为编辑页。

## 工具来源与结果边界

候选位置沿用已有[解密脚本](../scripts/decrypt-shield.js)，没有另行下载、安装或替换程序。本机存在的工具在检查时 **Authenticode 为 NotSigned，产品/公司版本信息为空**；不能仅凭仓库旧注释认定其发布者已经得到验证。因此确认框明确提示“未验证发布者签名”，列出路径让用户决定是否信任。

- 启动成功不等于完成。只有收到进程 `close`、退出码为 0、无退出信号，才返回“绿盾工具已完成，请以绿盾客户端状态为准”。
- 成功回执包含 `completed:true, verified:false`，**不宣称已经验证磁盘物理解密**。受信进程读到明文也不等于磁盘未加密。
- 退出码非零、信号、已启动后异常或超时明确提示结果未确认，文件可能已被处理；不会说“未修改原文件”。
- 本功能没有实现绿盾算法、不提取密钥、不用受信 Node 复制明文替代解密，也不绕过客户端权限。失败仍需按本机绿盾授权流程处理。
- 界面与单测没有执行真实工具，没有擅自选择真实用户文件验证物理解密效果。

## 文件与编辑器保护

[后端服务](../src/main/files/shield-decrypt.js)只读元数据，校验项目和文件真实路径：拒绝项目根、项目外部、目录、链接祖先、符号/硬链接、UNC、远程路径、设备名、ADS 和 `.git`。确认后再核对文件、目录身份和工具版本，变化则拒绝启动。

[主进程](../main.js)仅接受主窗口主 frame；确认前后检查当前项目与 dirty/编码状态，整个确认和执行期间持有原有 PathJobs 范围锁。相同文件禁止重复处理，写入/移动等不能借机并发。

[文件树](../renderer/tree.js)调用[编辑器原有保护](../renderer/viewer.js)等待保存队列及首次载入，处理中仍允许输入，结束重载时检查文档 revision。错误或不确定结果只更新可能变化的路径；保留新输入及冲突恢复能力，不强行覆盖。

默认 120 秒超时后只请求终止自己启动的直接子进程，并提示未确认；5 秒后若仍未关闭再提示，继续持有锁，不能因超时把仍可能写盘的文件交给下一操作。只有 `close` 才释放本轮锁。退出应用只请求终止自有子进程，不查杀绿盾客户端，不无限等待 `close` 阻塞退出。

## 验证

```sh
npm run test:shield
npm run check:shield
npm run test:files
npm run test:package
```

- 26 项后端合成测试：候选缺失、路径/链接/外部拒绝、取消零启动、确认期间变化、同文件防重、中文空格和命令字符 literal 参数、非零/信号/启动失败、超时持锁及只终止自有进程。
- IPC/预加载测试：窗口/frame 来源、项目/dirty 变化、默认取消、范围锁、不确定结果及可注销进度订阅。
- DOM 新增三项：单文件菜单范围；dirty 拒绝、错误页恢复和等待期间新输入保全；非活动分屏从错误页恢复并重新绑定可编辑的 generation scope，不要求切标签才能继续输入。
- 隐藏 Electron 使用生产文件树、Viewer、IPC 和后端，只替换外部子进程为合成对端，9 项通过。验证菜单图标、默认取消零改盘、dirty 拦截、单一 literal 路径、非零退出不假成功、frame 隔离、禁网/隐藏窗口与响应性；没有执行真实 `OcularDecrypt.exe`。

全量 DOM 仍有之前已记录的自动上下文/规则开关相关失败；`npm test` 的根目录布局断言仍受用户自有未跟踪脚本影响，不为跑绿删除用户文件。完整 UI 的既有失败单列，不宣称全套通过。
