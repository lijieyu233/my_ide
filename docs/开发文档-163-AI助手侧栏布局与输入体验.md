# AI 助手侧栏布局与输入体验

## 界面问题与处理

模型原来位于标题工具条，名称被多个操作按钮挤掉；模式、推理、连接状态和上下文提示缺少层次。输入框只有一行，却把发送、引用、命令、截图提示全部塞进 placeholder。

保留当前主题和右侧停靠方式。标题只放名称与原有工具按钮，模式与模型各占一行；推理、连接状态和重连按钮单独排列，上下文信息在配置区下方显示。320px 窄侧栏与较大界面字号下允许必要的换行，避免控件互相覆盖。

输入卡片保留两行的基础高度，文字增多时自动增长，清空后恢复。发送按钮固定在卡片右下角，引用与命令提示放在按钮左侧，Enter / Shift + Enter 提示移到卡片下方。发送与停止使用线性 SVG，同时保留原有状态文本，避免破坏既有的任务完成检测。

用户消息使用主题派生的弱强调背景，助手正文减少重复边框；工具记录统一线性图标与中文名称，保留可展开的原生 Harness 工具输出。工具身份通过 `data-tool-name` 独立保存，交互断言不依赖显示文案。

空会话的配置引导随模型配置刷新，避免配置完成后仍显示“还没配置”。没有改动 Harness 连接、会话恢复或工具执行协议。

## 取证入口

`npm run check:ai-ui` 使用独立 HOME、userData 和临时项目，隐藏生产窗口，模型和 Harness 配置响应使用夹具，不访问用户账户。

四组检查覆盖：模型控件与输入提示、多行增长与清空恢复、真实文件读取与回复续流及发送/停止图标、Harness 模型/推理/重连控件在 320 / 380 / 520px 和 16px 字号下的溢出。截图复核普通对话、输入、生成中、Harness 和浅色主题。
