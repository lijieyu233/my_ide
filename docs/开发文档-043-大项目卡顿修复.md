# 开发文档 043 —— 打开大项目卡顿修复（Git 扫描移出主线程）

> 状态：已完成 · 性能（用户反馈：打开项目即卡住）

## 一、根因

`GitPanel.refresh()` 的 statusMatrix/log 在 **Electron 主进程**执行：
5000 文件约 350ms，数万文件项目可达数秒——期间主进程被占，
所有文件 IPC（树展开/打开文件）排队，界面完全无响应（表现为"卡住"）。

## 二、修复（三层）

1. **worker_threads 隔离**：所有 git 操作转发到 `git-worker.js`（isomorphic-git 纯 JS 可 worker 化），
   主进程永不阻塞；worker 异常时自动回退主进程直跑
2. **延迟扫描**：打开项目后 800ms 再启动 Git 扫描（首屏先渲染树/恢复标签）
3. **扫描提示**：状态栏/徽标显示「⏳ Git 扫描中…」，结束后更新

### 结构
```
git-worker.js    worker 入口（op → git-service）
main.js          gitCall 调度（Worker 转发 + 回退）
app.js           setRoot 延迟 800ms 触发扫描（可配置，测试置 0）
git-panel.js     扫描状态提示
```

## 三、测试计划

1. worker 集成测试（node）：真实 Worker 跑 init/commit/status
2. dom 测试：delay 可配置（测试置 0 保持即时）；扫描提示状态
3. 全部现有测试保持通过
