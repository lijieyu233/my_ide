# DSH 会话绑定与重启恢复

用户在 DSH 桌面发现同一 MyIDE 对话在项目与 myide-detached-workspace 等多段会话间切换。后台映射键包含页面 id 和 projectContext；查看模型列表会提前创建会话；渲染层每次项目初始化清空当前选择。三个行为叠加，导致切页面和重启不断产生空会话。

## 修复

- 映射键改为 MyIDE 对话 id 与项目根目录，不包含当前页面。项目、浏览器、启动页、远程页面之间保持同一原生会话。
- 固定保存会话首次工作目录。断线后在其他页面恢复时，不用该页面临时目录重新创建原生会话，避免 DSH cwd 冲突。
- 旧四字段映射迁移为稳定映射；同一对话存在多页面记录时优先采用项目会话。原生旧会话与历史没有被合并或删除。
- 未绑定会话时查看模型只调用 modelCatalog，不创建工作区、会话或模型任务；第一次真正发送时才创建。
- Harness 保存每个项目当前选择，重启、切项目再切回和重复项目通知恢复原会话；明确新建的空草稿也保持。修正页面通知早于项目恢复、抢先生成空选择的初始化顺序。
- 当前页仍控制本轮上下文与 MyIDE 工具开放范围。离开项目后不再追加后台项目文件；同一原生会话已发送过的历史继续存在。
- 用户文本放在界面观察数据前，避免新原生会话标题总是“MyIDE 界面状态”。连接提示悬停和日志提供实际原生会话 id。

## 用户原话与工具显示顺序（2026-10-13）

用户只发送“分析这个项目”，但自动跟随的《查看AI玩家.cmd》全文被放在前面，界面状态与桥接操作说明又并入用户消息。模型因此围绕当前脚本里的 SSH 查询展开。侧栏同时只建立一个文字气泡，把跨多个工具轮次的文本回填到最初位置，最终结论出现在工具之前。

- Harness 每次只追加本次用户原话与图片，不重新发送系统提示、旧对话或旧工具记录，也不在用户原话后追加界面状态说明。当前项目仍用于原生会话的工作目录，实时编辑器与页面信息由 `ide_state` 按需读取。
- Harness 不再自动附带当前打开的文件，也不显示自动附件标签；`@`、拖拽与主动引用的资料仍可发送，以独立文本块和 JSON 边界明确标记为参考资料。文件中的命令与指令不代表本次用户请求或执行授权。
- 原生文字携带消息身份；遇到新消息或工具活动后新建文字气泡，前言、原生工具、MyIDE 工具与最终结论按实际到达顺序显示。收尾不把累计文字重新填回首个气泡。
- 本地对话保存文字和工具的有序时间线，重开对话仅重绘历史，不重放操作。停止或失败说明出现在活动之后，迟到事件不能追加文字或执行工具。
- 修复作用于后续发送和新记录；已经发送到 DSH 的旧拼接历史保持原样，不删原生历史。需要干净上下文时可主动新建对话。
