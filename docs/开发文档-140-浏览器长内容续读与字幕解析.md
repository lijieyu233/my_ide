# 浏览器长内容续读与字幕解析

## 实际问题

2026-10-13 的“总结视频内容”会话成功打开了 B 站视频信息接口、字幕接口和中文 AI 字幕 JSON。但 `browser_read` 只返回正文开头 20000 字符，滚动到页面底部再读取仍得到相同片段，最终在 8 轮上限处停止。此前第二次回答还声称“重新读取”，记录却没有新的读取调用。

本次补齐通用长内容续读、字幕结构化提取、加载等待及浏览器任务额度，不依赖 SSH 下载或扩大一次返回的模型上下文。

## 工具行为

- 首次 `browser_read({})` 建立只读快照，每段最多 20000 个 UTF-16 单位，避免从 emoji 的代理对中间分段。
- 返回 `snapshot`、`cursor`、`nextCursor`、`totalChars`、`hasMore`、`sourceLimited`、`complete`。有后续时传 `{snapshot, cursor:nextCursor}`，直到没有后续；滚动不会改变文本读取起点。
- 快照最多保留 2 Mi 个 UTF-16 单位的正文。DOM 扫描仍有节点数量/耗时预算；预算触发时标记 `sourceLimited=true`，即使读到缓存末尾也不显示完整。元素超过 100 个单独标记 `elementsTruncated`，不误判正文截断。
- 续读使用初次采集的稳定正文，不因动态网页后来插入文字而重复/遗漏。新读取、点击、填写、滚动、刷新或跳转后旧续读快照失效；失效时重新采集。光标不能跳过未返回的正文，避免直接读最后一段就声称完整。
- 缓存仅留在页面的独立 JavaScript world，不落盘。输入框值、密码、隐藏内容、iframe 内部及 Shadow DOM 仍不读取；跨页面或跨视图不复用快照。

## 字幕 JSON

独立 `pre` 文本页、或 MIME 类型为 JSON 的文档（Chromium 会添加“格式化输出”控件）可以识别 JSON。

只有 `body` 数组每项都含字符串 `content` 与合法非负 `from/to` 时间，才识别为 `subtitle-json`。格式字段、音乐字段等不进入正文，输出为：

```text
[0.08 → 2.8] 第一段字幕
[2.8 → 5.1] 第二段字幕
```

附带语言、总字幕段数、起始和结束时间；正文仍可分段续读。不合法的字幕结构保留普通 JSON，不静默丢弃异常段落；普通网页中的 JSON 示例不被当作字幕。

## 任务执行

- `browser_state({wait_ms:2000})` 最多等 2 秒加载结束，返回真实 `loading` 和失败原因；等待中取消请求会停止工具，不继续读取。
- 全部属于 `browser_*` 的轮次最多 24 轮；一旦请求普通工具或混合调用，仍受原 8 轮上限约束。上限处继续保留严格的工具调用/结果配对及一次无工具收尾，Shell/写文件批准规则没有放宽。
- 系统指引要求主动查找已有字幕；提供从 B 站视频 bvid 获取真实 aid/cid，再取得实际字幕地址的只读接口路径。接口失败、要求登录或签名校验时据实报告，不绕过权限。
- `hasMore` 时使用游标续读，不滚动后重复读取开头，不转到 SSH 下载。长字幕逐段记录时间和要点，防止历史正文压缩后只总结最后一段。
- 只在真实工具调用后说“重新读取”；字幕总结不能声称看过视频画面。提示能改善模型行为，但不能保证所有模型都主动遵循流程。

## 验证

- 浏览器专项：17 项，覆盖长正文/emoji、合法与非法续读、快照失效、短/长字幕及非字幕 JSON、源预算、加载等待和取消。
- AI 面板专项：41 项，新增浏览器 24 轮上限与混合调用不能扩大普通工具权限的断言，原第 9 轮普通工具拒绝及配对修复仍通过。
- 隐藏生产窗口：5 组通过。回环 JSON 视频信息 → 字幕信息 → 长字幕文件 → 分段读取，模型流超过 8 轮仍完整读到 1500 秒、1500 段；另验证长页面完整尾部和跳转后旧快照拒绝。沿用独立 profile，不访问用户业务服务器或使用用户模型 API；已检查暗红主题下的真实活动卡截图。
- 语法 84 个文件、完整 AI 回归及 DOM 518 项均通过。全量 `npm test` 在既有 Git worker 调度出现 EPERM，不能因此宣称全量通过。

这次验证的是实际生产工具链和模拟模型调度，未重新使用用户真实 API Key 执行那条视频总结，也未把旧的部分字幕结论当成完整结果。
