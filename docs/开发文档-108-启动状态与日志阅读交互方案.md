> 2026-10-01；提交基线 `7c55c4f`。取证始于a1adbbe，两提交之间启动面板、启动服务、preload与index没有变化；收尾工作区有其他文本格式改动，index仅增加text-lines脚本与末尾换行，原launch-panel不变，9项受控观察复跑一致。承接103启动体验建议和092进程归属合同，关联089的LAUNCH-01/02、UI-01。
> 本轮交付为UI/交互与功能方案，未修改产品或运行用户配置。受控桥没有启动进程、执行命令、访问后端或打开真实页面；界面问题尚待实施修复。

## 1. 用户任务与交付顺序

用户启动一份配置后，需要知道请求是否接收、程序是否还活着、页面是否可用；看历史日志时不应被新输出推走，失败后应有准确的继续动作。界面上的“已启动”和绿点必须与证据一致，不能只把按钮摆得更整齐。

建议四包：**A运行状态与操作反馈 → B日志阅读/查找 → C错误位置跳转与可选就绪条件 → D配置复用与运行记录**。A/B为P1，C就绪与定位按需求P1/P2，D候选P2。LAUNCH-01停止归属P0仍优先；日志阅读包可独立交付，但新“停止/重启”状态依赖092的后端结果合同。

| 方向 | 用户能看到的变化 | 省掉的操作 |
|---|---|---|
| UI设计 | 名称旁有文字状态，失败/旧数据有持续提示；命令与目录可展开查看；低频编辑/删除收进更多操作 | 不靠绿点和hover猜状态，不被一排操作挤掉配置名 |
| 交互 | 滚动向上暂停跟随，有新增输出提示；操作等待中防重复；旧请求不覆盖新结果 | 看日志不用每1.5秒重新滚回去；重复点击不制造多份未决请求 |
| 新功能 | 当前日志查找、专用复制/清空入口、文件行号跳转、同次运行记录、配置复制 | 少手工选长文本、复制路径跳文件或反复重填配置 |

## 4. A包：状态可理解、动作有终态

### 4.1 三个维度分别展示

运行phase、ready状态、ownership证据分开保存与派生；不能把端口连通同时当成三者的成功。推荐默认主状态文字：

| 证据 | 主区文字示例 | 合法继续动作 |
|---|---|---|
| 配置未运行且无操作 | 未启动/已停止 | 启动、编辑 |
| 启动请求已接受，但无终态 | 启动中 | 查看日志；取消能力须后端支持，不能用stop假装取消成功 |
| 本次进程存活，无就绪规则 | 运行中 · 未验证就绪 | 查看日志、明确打开页面；停止仍需归属可确认 |
| 配置就绪条件对本次运行成功 | 已就绪 | 打开页面、查看日志、停止 |
| 仅端口有响应，来源未确认 | 端口有响应 · 进程归属未确认 | 打开页面/核查归属；不能默认启用破坏性停止 |
| 正在停止 | 停止中 | 查看日志，等待确认；不能立即显示已停止 |
| 启动/停止失败或非零退出 | 启动失败/停止失败/异常退出 | 保留具体原因与明确重试动作，区分重试启动与重试读取日志 |
| 状态查询失败 | 状态暂不可用 · 上次确认时间 | 重试查询；旧状态标为旧数据，不改成未运行 |

颜色只辅助文字/图标，使用现有主题变量。默认只展示任务相关信息；PID、启动方式、请求身份和后端地址放详情/排错区。命令、目录、后端各有独立可展开行，长值可复制，不能一直nowrap+overflow:hidden而没有补充入口。

### 4.2 操作结果与范围

entryId在第一个await前进入pending，按钮/菜单/命令入口共用状态；所有启动来源都需要092后端互斥，前端disabled只是交互反馈。异步结果带operationId/runId；旧请求返回不能清除新pending或显示新运行成功。

仅明确`ok:true/accepted:true`可显示对应确认；undefined、ok:false无error、拒绝Promise都保留诊断，不以“没有error字段”当成功。请求接受与程序就绪分别呈现。停止结果按092的confirmedStopped/failed/remainingOwned汇总，不能用前端端口绿点决定该杀谁。

“全部启动/停止”显示目标数、成功/失败/未执行条目与逐项原因；失败后可重试失败项，不清掉运行记录。失败提示持续在该终端详情与列表标记，toast只补充通知。离开主区再回来仍能看见最近失败；重试操作成功后更新对应错误，不误清其他终端的失败。

侧栏与主区打开页面共用resolvedOpenUrl；默认采用现有显式openUrl优先、port回落规则，保持服务的协议/打开约束。无URL时显示不可用原因，不让两个入口对同配置给出相反可用性。

## 5. B包：稳定阅读、查找与复制

### 5.1 跟随策略与请求归属

view state至少包含entryId、runId、logGeneration、lastSeq/快照版本、followOutput、scrollAnchor、selection、query和logReadError。旧日志Promise仅检查entryId不够：同终端轮询、A→B→A、重启换runId都要验证代次。

用户在底部且未选择文本时跟随新增输出；向上滚动或选文字暂停跟随，显示“新增N行”和“回到最新”。该动作只恢复视图跟随，绝不暂停/恢复进程或丢弃日志。筛选/查找期间不强制跟随；清除查找后恢复先前策略，不突然跳走。

首包可以继续快照API，但必须保留阅读锚与选区，读取失败显示“日志读取失败，仍显示上次输出”和重试。800行环形截断时锚可能被移除，需要显示“更早输出已不在缓冲区”，不能跳至别处而不告知。暂停跟随不是保证无限保留历史。

后续结构化协议建议`runId / seq / timestamp / stream / text`，增量解码、跨chunk残行缓冲与空行保留由服务处理。当前stdout/stderr已混成string[]，首包不能伪造“仅stderr”筛选或精确日志时间。新增运行实例后才能把该字段作为可信来源。

### 5.2 查找与工具栏

工具栏先放查找、上一处/下一处、跟随输出/回到最新、复制全部；清空与导出放更多。查找作用域明确为“当前运行缓冲区”，不是整个日志历史或全项目。显示匹配数和无结果；支持字面查询与大小写，首包无需任意正则。

日志区域焦点时Ctrl+F触发本地日志查找，Editor焦点仍走既有编辑器查找；IME组合期间不抢Enter。按命中seq+offset定位，环形截断后使失效命中重新计算，不能按旧DOM行号错跳。Esc关闭查找回日志阅读位置，Tab能离开面板。

状态与查找摘要可用polite通知；连续日志不逐行自动读出，也不靠屏幕阅读器关闭输出来“暂停”。原生选中/复制与键盘滚动需真实焦点验收，不仅检查HTML属性。

原生选择复制保留；复制全部复制本次可见缓冲完整文本并说明是否已截断，不能叫“完整历史”。复制/导出是用户明确动作，默认不向外发送日志。清空先复用已有clearLogs服务，说明清空范围是输出、不停止程序；完成前旧请求须失效，不能清空后一份旧轮询把文本复活。

## 6. C包：错误定位与就绪条件

### 6.1 从输出回文件

首包只接有限已知格式，例如JS/编译器的path:line:column、Python回溯；格式不确定保留普通文字。输出仍按文本渲染，不能直接把日志拼为HTML。识别结果带runId/seq、解析模式、路径和一基行列，列单位明确。

相对路径基于本次实际cwd，不基于当前激活项目；跨项目点击走101保存离开闸门和105导航历史。远程/桥接输出的路径没有本地映射时展示“未配置本地路径映射”，不能跳到碰巧同名的本地文件。Windows盘符、空格/中文、URL端口和重复片段均要区分。

打开失败保留日志选中和错误；打开成功后定位对应源码，文件版本变化时明确回落。按点击动作导航，不能看见一条error就抢Editor焦点或自动打开一堆文件。先做单条定位与上下处，完整“问题面板”候选P2另排，不加入语言服务平台。

### 6.2 明确可选就绪条件

配置可选“无需验证”“端口响应”“指定输出出现”，带等待超时；首包可以用字面输出匹配。条件只观察本次runId，旧运行的800行输出不能让新启动立即就绪。服务进程退出后就绪同步失效。

端口响应只证明该地址可连，不证明进程归属；就绪失败/超时仍可能进程存活，要展示该组合，不自动杀进程或无限重启。自动打开页面另为用户可选策略，默认保留现有手动打开行为；错误定位/失败提示可显示面板但不抢输入焦点。

## 7. D包：配置复用与本次运行记录

“复制终端配置”生成新entryId，保留命令/目录/分类等可编辑字段，不复制PID/运行/日志状态，不保存后自动执行。编辑区显示最终命令/目录/后端预览，遵守现有机器级配置和字段语义；首包不引入环境变量模板语言、自动探测执行或更改配置默认位置。

运行记录建议先存有界元数据：runId、配置身份/版本、开始/结束、终态/退出原因、截断标记。查看过去运行不切换当前运行实例，不用“重新打开记录”启动命令。完整日志持久化/保留上次输出由用户选择，并有容量/期限；不把默认内存800行缓冲改成无限写盘。

命令参数可能含凭据，记录/导出需要沿用实际秘密字段策略，默认不存环境变量或完整参数快照；“保留运行记录”不等于保存所有输出。后端还没有可靠runId/退出结果前，首包只能称“本次输出”，不能显示看似完整的运行历史。
