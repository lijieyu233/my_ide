# 开发文档-069 · 侧栏取消上下分栏（项目树下面的大纲去掉）

> 用户原话：「把项目文件侧边栏 下面的大纲去掉」

## 一、撤掉的是什么

`docs/开发文档-062` 第 7 项给「项目」工具窗口加了上下分栏：

```
#sidebar
  #panel-project      ← 项目树，flex: 0 0 65%
  #side-hsplit        ← 4px 可拖拽分隔线
  #panel-outline      ← 大纲 / Structure，占剩下的 35%
```

现在整块撤掉，回到「一个工具窗口独占侧栏」：

```
#sidebar
  #panel-project      ← 项目树，占满整栏
```

## 二、没有删掉的：大纲本身

**这里刻意只撤"同屏"，不撤功能。** 大纲仍是独立工具窗口 —— 左侧工具条的图标还在，
点它独占侧栏。之所以这么做，是因为上一轮有过教训：为了"界面整洁"把顶栏项目胶囊收成一个控件，
连带砍掉了右键菜单 / 拖拽排序 / 关闭项目整套能力，用户原话是
**「你不能为了保留这个删除我的功能」**。

所以自检里专门加了反向断言，防止以后有人顺手把大纲删干净：

```
PASS  大纲仍是独立工具窗口（从左侧工具条可打开，功能没被删）
PASS  大纲独占整栏                                    [812 vs 812]
PASS  大纲有内容（当前文档的标题）                     [▾一级标题▾二级 A三级 A1二级 B]
```

## 四、一个取舍说明

**没有做"可折叠的下半区"，是直接撤掉。** 理由：

- 用户说的是"去掉"，不是"收起来"；
- 大纲本来就有独立入口（工具条图标），再给它一个"折叠态"等于同一件事两个入口 ——
  这正是前几轮反复收敛掉的模式（`全部项目` vs `当前项目 ▾`、回形针按钮 vs 自动跟随）。

如果哪天想回来，`docs/开发文档-062` 里有完整的实现记录（比例存比值不存 px、双击复位、
`applySideSplit` 的钳制逻辑），可以照搬。
