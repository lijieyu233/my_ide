# 远程服务器概览：运维台完整方案 v2

> 状态：待评审　|　编写：2026-10-28　|　范围：单机（Docker + systemd + 进程 + 端口 + 磁盘）
> 前版：[开发文档-240](开发文档-240-远程服务器概览运维台开发方案.md)（已完成执行通道与基础界面）

## 一、现在的问题

第一版把「只能看」变成了「能操作」，但**信息呈现和交互还停在原型级别**。具体表现：

| 问题 | 用户的感受 |
|---|---|
| 每行只有「名字 + 一串英文」 | 「我知道有这个服务，但获取不到更多信息」 |
| 32 个服务平铺 | 「翻不到底，找不到想要的」 |
| 不能搜索、不能排序 | 「只能从头滚」 |
| 日志是个纯文本弹窗 | 「等于把终端搬进弹窗」 |
| 5 秒轮询重建整个列表 | 滚动位置跳回顶部、菜单被关掉、正在读的日志闪烁 |
| 异常混在正常里 | 「有问题的那台要自己一行行找」 |

这份方案解决「信息有没有意义」「怎么找到它」「看到之后能做什么」「刷新别打断我」四件事。

## 二、设计原则

1. **一行要能判断**：不看详情就知道它正不正常、干什么的、占多少
2. **异常优先**：有问题的永远排最前、最显眼
3. **能找得到**：搜索、排序、筛选、折叠，四件套
4. **操作有后果预判**：按钮上能看出会发生什么
5. **刷新不打断**：增量更新，不重建 DOM

## 三、信息呈现

### 3.1 行的三层结构

```
● smart-gallery-api          ● 健康    :8080→80   已运行 7 天      [日志][重启][⋯]
  smart-gallery-api:1.4.2 · 重启 0 次
```

| 层 | 内容 | 说明 |
|---|---|---|
| 第一层 | 状态点 + 名称 + **状态徽标** + **关键指标** + 操作按钮 | 一眼判断 |
| 第二层 | 身份 + 次要指标 | 镜像/命令行/描述 + 时长/重启次数 |
| 异常时 | 左侧 3px 红色边框 + 徽标变红 | 视觉跳出来 |

### 3.2 各分类要补的字段

| 分类 | 现在 | 要补 |
|---|---|---|
| **Docker** | 名称、镜像、状态串 | **端口映射**、**运行时长（结构化）**、健康状态、重启次数 |
| **服务** | 单元名、描述 | **运行时长**、内存占用、是否开机自启（enabled） |
| **进程** | PID、CPU、内存、时长、comm | **完整命令行**、**所属 service**、过滤内核线程 |
| **端口** | 端口、进程、地址 | **所属容器**（通过端口映射反查） |
| **磁盘** | 分区、可清理项 | 可清理项的**具体大小**（已在清理前探测，改为列表中直接显示） |
| **目录** | 路径、大小 | 目录项数、最近修改时间 |

### 3.3 状态徽标规范

| 徽标 | 触发条件 | 颜色 |
|---|---|---|
| `健康` | healthy / running | 绿 |
| `未检查` | 无健康检查 | 灰 |
| `不健康` | unhealthy | 橙 |
| `异常退出` | Exited ≠ 0 | 红 |
| `已停止` | Exited = 0 | 灰 |
| `重启中` | Restarting | 蓝（动画） |

### 3.4 分类标签带结论

```
Docker 11 · 全部运行中           ← 正常
Docker 11 · ⚠ 1 个异常退出       ← 有异常，红色
服务 32 · 30 运行 / 2 停止       ← 中性
```

### 3.5 顶部告警带

资源监控下方一条，只在有异常时出现：

```
⚠ 1 个容器异常退出 · 1 个服务失败 · 磁盘 95%（剩余 3.7 GB）
```

点击任意一项直接切到该分类并自动筛「只看异常」。

## 四、列表能力

### 4.1 工具行

四分类统一：

```
[🔍 搜索名称 / 镜像 / 命令行 / 端口…]   [只看异常]   [排序 ▾]   筛出 3 / 共 32
```

| 能力 | 规则 |
|---|---|
| **搜索** | 匹配多字段，输入即筛（前端过滤，不发请求）；支持空格分词（AND） |
| **只看异常** | Docker：Exited/unhealthy/Restarting；服务：非 running；进程：CPU>80% 或内存>50%；端口：无 |
| **排序** | 见下表；每个分类各自记住 |
| **计数** | 「筛出 N / 共 M」，筛完后为 0 时给明确空态 |

### 4.2 默认排序（按用户最关心的）

| 分类 | 默认 | 可选 |
|---|---|---|
| Docker | 异常优先 → 名称 | 名称 / 状态 / 运行时长 / 镜像 |
| 服务 | 关键服务优先（docker、ssh、cron、网络类）→ 名称 | 名称 / 状态 / 内存 |
| 进程 | **CPU 倒序** | CPU / 内存 / PID / 运行时长 |
| 端口 | 端口号升序 | 端口 / 进程名 |
| 磁盘 | 占用倒序 | 占用 / 名称 |
| 目录 | 大小倒序 | 大小 / 名称 |

### 4.3 分组折叠

服务、进程按状态分组：

```
▾ 运行中 30
   ● docker.service …
▾ 已停止 2
   ● xxx.service …
```

折叠状态记在内存（同一天内切换分类不丢）。

### 4.4 键盘

| 键 | 行为 |
|---|---|
| `↑` `↓` | 移动选中行（列表获得焦点时） |
| `Enter` | 查看日志（Docker/服务）或详情（进程） |
| `/` | 聚焦搜索框 |
| `Esc` | 清空搜索 / 收起菜单 |

## 五、操作设计

### 5.1 按钮按状态给

| 对象状态 | 行内按钮 |
|---|---|
| 运行中（健康） | `日志` `重启` `⋯` |
| 运行中（unhealthy） | `日志` **`诊断`** `重启` `⋯` |
| 已停止 | `日志` `启动` `⋯`（无「重启」） |
| 进程 | `详情` `⋯`（含「结束」） |

### 5.2 「⋯」菜单带后果说明

```
⋯ ▾
  停止服务          服务中断，依赖方受影响
  重载配置          不中断连接
  查看状态          systemctl status
  复制容器名        smart-gallery-api
  在终端打开        打开交互式 shell
```

每一项右侧淡色小字说明后果，不是只有动作名。

### 5.3 确认框带上下文

重启容器时：

```
重启容器 smart-gallery-api？

影响：服务中断约 3–10 秒，正在处理的请求会失败
当前：Up 7 days (healthy) · 重启 0 次 · 端口 8080→80
最近错误：16:02:15 ERROR Failed to fetch price: timeout  ← 新增

[取消]  [重启]
```

「最近错误」在点确认前实时取 3 条（一次 `docker logs --tail 20` 过滤），让用户知道**为什么**要重启。​

### 5.4 对象特有操作

| 对象 | 特有 |
|---|---|
| Docker | 进入 shell（`docker exec -it … sh`）、查看环境变量、查看挂载卷、健康检查输出 |
| 服务 | 查看单元文件（`systemctl cat`）、依赖树（`systemctl list-dependencies`）、开机自启开关 |
| 进程 | 查看打开的文件（`lsof -p`）、环境变量、**所属 service** |
| 端口 | 反查所属容器、查该端口连接数 |
| 磁盘 | 进入目录看排行、执行清理 |
| 目录 | 展开子目录 |

## 六、日志查看器

这是最高频功能，单独设计。

### 6.1 形态

右侧滑出抽屉（不是居中弹窗），宽度 60%，可拖动改宽。

```
┌ smart-gallery-api · 最近 200 行 ─────────────── ✕ ┐
│ [跟随 ○]  [级别 全部▾]  搜 [          ]  [复制] [终端] │
├──────────────────────────────────────────────────┤
│   1  16:02:11 INFO   Started Application in 3.2s  │
│   2  16:02:12 WARN   Connection pool at 85%       │
│   3  16:02:15 ERROR  Failed to fetch price: timeout│ ← 红
│   4  16:02:16 ERROR    at PriceService.fetch       │
└──────────────────────────────────────────────────┘
```

### 6.2 能力

| 能力 | 做法 |
|---|---|
| **级别着色** | 正则识别 `ERROR\|WARN\|INFO\|DEBUG\|TRACE`（大小写无关），红/黄/灰/暗灰 |
| **级别筛选** | 下拉「只看错误」，前端过滤不重拉 |
| **搜索高亮** | 关键字过滤 + 命中高亮 |
| **行号** | 左侧淡色，便于对照 |
| **跟随** | 开 `docker logs --since <ts> -f` 或 `journalctl -f` 增量拉；手动上滚自动暂停，回到底部恢复 |
| **断点续读** | 记录最后一行时间戳，断线重连后 `--since` 续，不重复不丢 |
| **JSON 格式化** | 检测到整行是 JSON 时缩进展开（可折叠） |
| **行数控制** | 默认 200，可选 500 / 1000，上限 2000（防止刷屏） |
| **复制/导出** | 复制当前筛选结果；导出为 txt |
| **跳终端** | 一键在终端打开交互式 `-f`（跟随异常时可切） |

### 6.3 跟随的实现约束

- 单条 SSH 连接上跑 `-f` 会长期占用通道，所以用**短连接增量轮询**：每 2 秒拉一次 `--since <last>`，拿到增量就追加
- 跟随期间不重建 DOM，只 append 新行
- 超过 2000 行时裁掉最旧的，并提示「已滚动裁掉 N 行」

## 七、刷新策略（现在的硬伤）

### 7.1 问题

5 秒轮询调用 `renderOverview` 重建整个 `innerHTML`，导致：

- 滚动位置跳回顶部
- 打开的「⋯」菜单被关掉
- 正在读的日志背景闪
- 搜索框失焦

### 7.2 改法：增量更新

```
轮询拿到新数据
  → 与旧数据做 diff（按 key 比对）
  → 只更新变化的行（改文本、改状态点、改徽标）
  → 新增行才插入 DOM，删除行才移除
  → 结构没变就不碰 DOM
```

**关键：用户正在交互时暂停刷新**

| 情况 | 行为 |
|---|---|
| 鼠标悬停在列表上 | 暂停轮询，离开后恢复 |
| 菜单打开中 | 暂停 |
| 搜索框有焦点 | 暂停 |
| 日志抽屉打开 | 只更新抽屉内容，不动列表 |
| 正在执行写操作 | 暂停，等回执 |

### 7.3 更新指示

右上角显示数据新鲜度：

```
刚更新  ·  5 秒前  ·  ⏸ 已暂停（悬停中）
```

## 八、性能

| 项 | 现状 | 改法 |
|---|---|---|
| 采集超时 8 秒 | 服务多时可能超时 | 拆两段：快段（Docker/服务/端口，8s）+ 慢段（进程/目录，15s，低频） |
| 轮询频率 | 统一 5 秒 | 快段 5 秒，慢段 15 秒 |
| 大列表 DOM | 32→数百行全渲染 | 超过 100 行时虚拟滚动，或分组折叠后自然减少 |
| 输出上限 | 512KB | 保持，日志单独 2MB |

## 九、数据采集扩展

现有 `OVERVIEW_SCRIPT` 要补的段：

| 段 | 命令 | 新增字段 |
|---|---|---|
| docker 增强 | `docker ps -a --format` 加端口、创建时间 | `{{.Ports}}`、`{{.CreatedAt}}`、`{{.RunningFor}}` |
| docker 健康 | `docker inspect --format '{{.State.Health.Status}} {{.RestartCount}}'` | 健康状态、重启次数（按容器循环，限 20 个） |
| 服务增强 | `systemctl show <unit> -p ActiveEnterTimestamp,MemoryCurrent,UnitFileState` | 启动时间、内存、自启 |
| 进程增强 | `ps -eo pid,args` 取完整命令行；过滤 `[...]` 内核线程 | 命令行、是否内核线程 |
| 端口增强 | 结合 `docker ps` 的端口映射反查容器名 | 所属容器 |

**注意**：这些命令会显著增加采集时间，所以按「快慢两段」拆开（见 §8）。

沿用现有做法，全部自动化（不需要用户手工点）：

| 层次 | 方式 |
|---|---|
| 采集解析 | `tests/remote-overview.test.js` 扩充新字段断言 |
| 动作白名单 | `tests/remote-ops.test.js`（26 项注入防护，已有） |
| 命令链路 | `tests/remote-ops-e2e.test.js`（已有 17 项） |
| **真点击** | `scripts/check-remote-ops.js` 扩充：搜索筛选、排序、日志抽屉、跟随、刷新不打断 |
| 性能 | 新增：300 行列表的刷新耗时、DOM 节点数不增长 |

**真点击用例要覆盖**：
- 输入搜索 → 行数变化 → 清空恢复
- 切换排序 → 首行变化
- 只看异常 → 只剩异常项
- 打开日志抽屉 → 出现着色行
- 跟随开启 → 追加新行且滚动到底
- 悬停列表 → 轮询暂停（计数不增加）
- 刷新期间菜单不关闭

## 十二、风险

| 风险 | 对策 |
|---|---|
| 采集变慢导致概览卡顿 | 快慢分段，慢段降频 |
| `docker inspect` 循环 20 次太慢 | 限制数量，或改用 `docker ps --format` 一次拿健康 |
| 日志跟随占满通道 | 短连接增量轮询，不常驻 `-f` |
| 增量刷新实现复杂易出 bug | 先做「结构没变就不重建」的粗粒度版本，再细化 |
| 虚拟滚动引入新问题 | 优先用分组折叠减少行数，行数真超 100 再上虚拟滚动 |
