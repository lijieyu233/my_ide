# DSH 连接恢复与真实模型选项

用户反馈模型与推理被显示成“原生默认”，随后连接失败。占位文案把目录未加载误表达成选中了默认模型；旧连接发现信息、地址或授权变化时也缺少完整恢复。

## 修复

- DSH 发现与授权握手放在同一有界重试循环中，每次重读发现文件；旧地址未响应或旧授权不成立时等待新信息。错误区分未发现、宿主未运行、本机未响应和授权失败，不显示内部 ACP 回退说明。
- Windows 无权查询其他进程存活时，不直接判为 DSH 未运行；仍通过仅接受 127.0.0.1 的真实授权握手验证。
- 正常消息流意外结束、请求超时使旧连接失效；后续发送重新发现宿主并恢复会话。用户停止不关闭健康宿主连接。
- 读取模型选项会向宿主读取最新目录和会话选择，不把缓存当作连接成功。发现旧连接失效后只重试一次读取，恢复原会话，不重发聊天或工具操作。
- 侧栏显示实际模型和实际推理选项；未连接时明确禁用选项，有目录前不展示虚构默认。增加“重新连接”，保持会话，运行中禁用重连。
- DSH 欢迎页不再提示填写普通助手的服务地址。记录连接成功或失败用于定位，日志不写授权令牌。

## 换设备后的安装发现（2026-10-13）

用户在已安装并打开DSH的另一台设备上收到旧机器D盘启动器ENOENT。dsh-runtime.js原默认启动器写死为开发机路径，与设置里“留空自动使用本机安装”不符。

有效显式启动器优先；留空或旧路径失效时，依次检查环境覆盖MYIDE_DSH_PATH、运行中的DeepSeek Harness.exe、Windows安装登记、常见用户/系统安装目录和PATH。检查同一安装根的dsh.cmd、桌面exe和app.asar，不执行搜索出来的启动器。Windows查询隐藏执行，预算5秒；查询失败仍可使用目录候选。未找到时提示打开本机DSH重新连接或在设置选择启动器，不再暴露开发机ENOENT。检测结果返回实际找到的启动器，兼容迁移的旧配置而不改写配置文件。

Electron将app.asar根展示为虚拟目录，fs.access根会报ENOENT；采用stat兼容Node归档文件和Electron虚拟目录，避免Node能发现但应用内失败。未改变DSH会话、模型、权限和配置绑定。
