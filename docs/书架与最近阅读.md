# 工作区书架与最近阅读

书架是当前项目的阅读视图。使用顶部原有项目标签切换工作区；打开书架不会创建另一套项目，也不会关闭编辑器中未保存的内容。

## 使用

1. 打开已有项目或一个存放书籍的文件夹。
2. 点左侧「书架」。递归识别工作区内的 TXT、EPUB、CBZ，自动显示小说与漫画。
3. 把新书放入工作区后点「刷新书架」。无需逐本导入；PDF、Markdown、代码等不显示在书架中。
4. 点书籍开始阅读，或通过「继续阅读」回到上次章节/页码。返回工作区仍能编辑项目文档。

没有打开工作区时，书架提供「打开工作区」，不会展示其他项目的全局阅读记录。TXT 的普通文件编辑功能保留，书架打开时才进入阅读模式。

## 数据归属

| 位置 | 内容 |
| --- | --- |
| 工作区内原有 TXT / EPUB / CBZ | 书籍原文件，只读 |
| `.myide/reader/library.json` | 稳定书籍 ID、相对路径、进度、书签、上架状态和阅读偏好 |
| `.myide/reader/books/<书籍ID>/` | 为后续 AI 笔记、章节总结、分析结果约定的资料目录；本版返回此路径，不创建空总结 |

书架不限制书籍必须放在某个子目录。可以自行使用「小说」「漫画」「资料」等目录分类，原来的项目文件树继续工作。

保存使用磁盘版本校验和原子替换；重复内容不重写文件。保存失败保留内存记录并提示，可在书架点击「刷新书架」重试。项目切换和关闭窗口会等待阅读记录保存。磁盘被其他程序改动时拒绝覆盖，不自动清空重建。

书籍路径按工作区相对路径保存，因此整个目录搬到另一位置后仍保留 ID、进度和书签。单独重命名或移动一本书暂按新路径识别，旧记录保留。后续 AI 内容应绑定稳定书籍 ID，并随整个工作区备份或纳入版本管理。

## 扫描与旧数据

- 扫描只枚举目录项，不预先解包 EPUB / CBZ，也不批量解析 TXT 正文；章节数在打开书籍后取得。
- 跳过 `node_modules`、`.git`、`.myide`、`.ui-check-trash`、`dist`、`build` 和隐藏子目录，不跟随符号链接。
- 每次扫描最多检查 100000 个目录项、识别 2000 本书。达到上限或目录不可读时显示提示；已有缺失记录保留。
- 「移出书架」只隐藏条目，不删除原文件、进度或书签，可立即撤销。刷新不会自动恢复已经移出的书。
- 首次进入时，只迁入旧 `myide-reader-v1` 存储中属于当前工作区的记录，保留 ID、书签和进度；其他项目记录不混入。旧存储仍保留，工作区外临时阅读沿用它。
- 删除/暂时移走源文件后，刷新时从可见书架排除，记录保留；放回原路径后继续使用原 ID。文件内容版本改变时，阅读器沿用既有策略重置位置和书签。

## AI 接口

现有接口保持名称与授权规则，资料范围改为当前工作区：

- `reader_library`：分页查询，返回 `workspace`、书籍稳定 `id`、`relativePath`、`dataDirectory` 和阅读进度。支持 query / offset / limit（最多50）与 includeRemoved。
- `reader_library_control`：show / open / remove / restore。变更需要当前快照与授权；写入工作区成功后才报告成功，不允许任意路径导入。
- `reader_state` / `reader_read` / `reader_control`：当前阅读标签的目录、正文、翻章、偏好和书签。state 增加工作区路径、稳定 `libraryBook` 和资料目录。

工作区用于存储阅读资料，不在本版自动开放项目源码编辑权限。阅读页面沿用独立的 AI 上下文保护；AI 自动分析、笔记和总结编辑器属于后续功能，不因出现资料路径就表示已实现。

## 验证

- `npm run test:reader`：解析器、旧存储、工作区扫描、迁移、版本冲突、目录搬迁、项目隔离、书签落盘、保存重试与刷新竞态。
- `npm run check:bookshelf`：真实隐藏 Electron 窗口与 IPC，验证扫描、未保存编辑器保护、续读、移出/撤销、刷新、项目往返、AI 接口及窄布局；截图位于忽略的临时检查目录。

现有格式限制详见 [小说与漫画阅读器](小说与漫画阅读器.md)。
