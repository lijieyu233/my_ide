# Git提交审阅与历史查找交互方案

> 2026-10-01；审查时HEAD为 `c946954`，工作区另有并行的保存/删除功能修改。本文只交付设计与取证结论，没有修复Git产品代码或实施新增功能。承接[103体验总方案](./开发文档-103-UI交互与新增功能改进方案.md)的I3/GIT-01；[094](./开发文档-094-Git状态与块级操作一致性取证.md)的写入、块身份与原字节合同仍独立执行。

## 1. 用户任务与已有能力

本轮关注三个日常任务：确认本次究竟提交哪些改动；连续审阅多个文件而不看错对象；找到某次历史修改并比较版本。最先交付应是**提交范围可信、切换差异不串文件、失败后可继续**，随后增加只读比较和查找能力。不能把这些工作全部归到性能优化，也不能等待完整Git重构才做不涉及写入的体验包。

| 已有能力 | 当前入口/实现 | 本轮处理 |
|---|---|---|
| 工作区/外部暂存只读分节、目录/平铺、勾选提交、命名变更列表 | git-panel.js的fileSections/syncChecked/doCommit | 核对活动列表与派发集合一致，不新增第二套勾选语义 |
| 双栏文本diff、两区差异、块折叠、前后块导航、部分暂存/回退 | buildDiffTable/showFileDiff/makeHunkNav | 优先明确文件和比较两端、加载/失败/旧结果；块写入按094验收 |
| 提交消息草稿/历史、amend、作者/sign-off、提交前检查 | doCommit及配置入口 | 保留这些能力，补操作终态与可回看的结果，不重新列为待开发 |
| 提交图、作者/消息/哈希过滤、分支过滤、文件历史、提交文件详情、上下键导航 | git-log.js与index.html | 补筛选范围、零结果、详情错误和项目/文件请求归属 |
| 分支比较、blame、cherry-pick、冲突处理、远程管理、推送预览、搁置恢复 | Git面板/日志及现有Git测试 | 不重造相同功能；任意提交/标签比较需先核对现有菜单和服务能力 |

MyIDE的既有合同是**本次勾选集合决定提交文件**，外部暂存内容原样保留；不是直接提交整个index。成熟IDE的界面可以参考，提交语义不能照搬。R8说明UI呈现与集合维护还存在矛盾，不推翻后端既有事务测试。

## 2. 当前实现取证

使用jsdom加载完整原始index.html、git-panel.js和git-log.js，仅将myIDE、App、Tree、Viewer、MI等外部桥换成内存桩。由真实行点击/筛选事件与公开doCommit/refresh进入，未改写模块算法。所有fs配置读写和Git提交都停在桩内；没有调用真实Git写入、系统剪贴板或用户配置，也没有真实Electron截图/焦点/读屏验证。

| 编号 | 操作与实际观察 | 待改进之处 |
|---|---|---|
| R1 | status返回`isRepo:false,error:STATUS_EACCES`，面板只显示“当前目录不是Git仓库/初始化仓库”，错误文本不可见 | 状态读取失败与确认非仓库必须分开；不能引导用户在读取失败后初始化 |

## 4. A包：可信的提交范围与操作反馈

**优先级**：R8范围错误先修（P0），R1/R2与状态呈现P1。场景是“把Later留到下次，只提交当前列表里的a”；界面显示、最终快照与实际参数必须是同一个集合。

维护`eligibleFiles`：当前项目有效状态中，活动列表的可提交条目以及明确允许且可见的未跟踪/忽略条目；外部index-only和其他列表不进入。加载归属、移动文件、切活动列表、刷新消失项时立即协调checked；显示按钮前与派发前都校验。自动勾选仅作用于新增且eligible的条目，切项目不能继承同名文件选择。最后派发捕获项目根、列表ID、文件集合、草稿、amend/作者、状态版本；异步预检返回后再次校验，失效则显示需重新确认，不拿新root提交旧快照。

底部持续显示“本次提交2个文件 · 活动列表Default”；点击可查看准确路径与选中内容来源。非活动列表只读，切换为活动后按明确规则建立新选择，不能暗中保留旧列表成员。选中行用于阅读，checkbox用于提交，两者样式与文字独立。提示包括未保存编辑器内容是否进入当前快照，沿既有保存协调合同，不默认自动保存所有文件。

将提交中/本地提交成功/推送中/推送失败分开。确定提交失败保留草稿和选择；成功保留OID与本地结果，推送失败显示“本地提交已完成，推送失败”及只重试推送入口。Promise断连而结果未知时，先重新读取HEAD和工作区核对原操作，不能提供会造成重复提交的立即重做。按钮finally恢复与重入闸门共用状态，不允许另一个“提交并推送”按钮绕过pending。

**验收**：R8/C1；移动b到Later/切Later/归属加载迟到/刷新/外部index；预检中切项目、消息继续输入、两按钮连点；确定失败、IPC拒绝、本地成功但push失败。真实临时仓库确认OID包含预期树、外部index字节保留；DOM核对标题/计数/派发参数，二者不能替代。

## 5. B包：连续审阅与差异阅读

**优先级P1**。头部固定“项目 · 完整可区分路径 · 左侧来源 → 右侧来源”，区分HEAD→index、index→工作区、提交→父提交；历史合并提交保留现有第一父说明。文件名过长中段省略，可键盘复制完整路径。状态使用文字加图形，深浅主题不只靠红绿。

每次选文件立即呈现同对象loading，再进入ready/error/unchanged/binary/too-large；双区一侧失败时分别显示两区结果及失败原因，不能悄悄把失败区过滤掉。旧视图若保留以便阅读，明确显示旧对象且禁用对应写入动作。R3/R4的选择与实际差异必须一致。单次token至少包含项目generation、比较端OID/版本、提交、文件、side、requestId；切项目使所有旧token失效。

新增“上/下一个文件”和`第2/8个文件`，与已有上/下块按钮分开；允许过滤变更文件路径，空结果清楚。首包保留现有双栏和折叠，增加查找、软换行、空白字符显示；快捷键接现有注册表，不能占用编辑器或输入法键位。查询仅检索当前已加载差异并明示范围，之后再评估整组差异搜索。窄屏单栏作为下一小包，截图比对后决定自动切换阈值，不凭空写死宽度。

**新增候选**：本次审阅的“已查看”标记，按比较对象/版本记录，刷新内容变化即失效；默认不影响勾选集合，也不把“看过”当批准提交。阅读设置按项目/全局明确范围；关闭差异回到原编辑标签和位置，未保存正文不能被diff替换销毁。

**验收**：R3/R4/R7；a→b→a乱序、双区部分失败、同名路径、二进制、过大、EOF、长行、文件删除；1280/1920窗口、260/340/480侧栏、100/125/150%缩放、深浅主题真实截图。任何写入按钮仍需094旧块失效与字节对拍，显示层忽略空白不授予写入权限。

## 6. C包：历史筛选与详情恢复

**优先级P1**。顶栏显示当前项目、分支/文件范围、实际加载数量和是否截断；本地过滤显示`12/500条已加载提交匹配`，零结果提供清空条件。作者、消息/哈希保留现有入口。消息搜索是否含完整正文必须明确；若做仓库全历史查询，另接后端分页、取消与代次，不把已加载500条包装成搜完整仓库。

筛选隐藏当前项时，可清空详情，或显示“当前查看的提交不在筛选结果中”并提供回到结果；首包选择一种且验收一致。不把旧详情默默当匹配结果。图与列表需保持拓扑对应；源码当前有保留图链路的意图，本轮没有截图证明筛选后图错位。实施时决定按过滤项重建行布局或保留上下文行并标记，不能只隐藏DOM然后假设线还对齐。

详情的loading/empty/error分别呈现，读取失败提供相同提交重试和可复制错误；重试仍绑定原OID/项目，切项目取消。列表、详情、文件diff各自请求代次共用项目generation，setRoot同时重置文件模式、选中及旧请求。恢复旧项目查询可选按项目保存，不能把A的文件历史pathFilter直接带到B。

**验收**：R5/R6/R7/C2；组合作者/哈希/消息/正则、无效正则提示、全文正文命中范围、清空、截断、分页、空仓库；切分支/文件历史/项目时乱序；输入框方向键不被抢，键盘焦点与选中可辨。读屏和真实系统焦点单独验证，DOM通过不能宣称完成。

## 7. D包：有价值的新增只读比较

**优先级P2，B/C请求归属完成后独立交付**。先核对已有分支比较菜单与服务，再补缺少的任意提交/标签选择，避免重造已有分支比较。

第一小包“选择用于比较 → 与所选比较”：捕获项目和不可变OID，明确左旧/右新，可交换；列变更文件和统计，复用B包连续审阅，不checkout、不恢复文件。分支/标签名先解析OID再发起读取，解析失败保留输入并显示原因。合并基点/上游快捷比较后排，各自明确直接比较还是merge-base比较。

第二小包同文件两次历史版本比较：文件历史选两个版本，只读展示来源/路径/缺失一端；跨重命名需后端追踪能力，暂未支持时明确路径变化，不能用同名新文件代替旧文件。历史进入当前编辑位置时保留返回入口。二进制只给真实具备的预览能力，不用文本乱码充数。

**验收**：根提交、同一OID、祖先/分叉、标签移动、任一端缺失、同名不同项目、读取期间切项目、版本间删除/改名；工作树、index、HEAD检查零写入。推送预览、blame、cherry-pick、搁置仍复用现有入口。行级暂存和历史写回另立094合同，不附送无保护的“恢复到此版本”。

## 8. 排期、验证与收尾

建议A中范围修复先独立提交；B中请求归属/失败面板与C中错误/零结果可以小包并行排期，随后B阅读功能、D比较。每包1–2个用户可见变化，先做可评审布局再接真实状态；本文没有UI样机或已实施功能的证明。

本轮原模块内存取证10项断言通过。后台第一次npm test退出1，Git62/0、DOM336/1；为保存失败详情重跑并写临时日志，第二次同一session退出1：语法检查40文件通过、Git62/0、DOM342/2。第二次失败项是“删除取消和dirty保留旧磁盘版本，恢复后仍需比较”和“删除等待旧保存，提交中新输入保持且新保存不复活路径”。两次期间tests/dom.test.js等并行修改，测试数量已变化；不能推断它们属于本文，也不能宣布全套绿或稳定基线。测试链在DOM失败后停止，后面的package/files/text/paths/create/copy/delete本轮未执行。保留失败结论，不擅自修改其他工作中的产品/测试文件。
