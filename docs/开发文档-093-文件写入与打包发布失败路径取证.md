> 2026-10-01，第四轮持续审计；代码基线 `a42796a`，应用版本 0.8.5。
> 对应 [089 台账](./开发文档-089-全模块成熟项目对照与持续改进台账.md) 的 FS-01、RELEASE-01，细化 [090-B/C](./开发文档-090-首批可靠性改进实施合同.md)。仅更新取证与方案，未修复产品代码。

## 1. 取证方法与边界

文件侧从当前 main.js 原样截取 `detectEncoding`、`fs:readFile`、`fs:writeFile` 注册代码，在 Node 中注册原处理器并调用；用真实系统临时文件对比前后字节。没有启动完整主进程或调用真实渲染 UI。F6 仅替换 writeFileSync，真实截断/写入部分临时文件后注入 EIO；它证明现有处理器不保全原文件，不证明本机真的发生磁盘故障。

打包侧使用 **electron-builder 26.15.3** 的真实 Windows dir 构建，沿用 package.json 的 files，覆盖输出为系统临时目录，electronDist 指向已安装发行目录，publish=never。不覆盖用户 dist，不下载另一套 Electron、不发布版本。然后读实际 app.asar，并以真实 **Electron 33.4.11 / Node 20.18.3** 加载包内主入口。探针先设独立 userData，catch 加载异常后退出，不创建窗口。

包内入口探针使用开发目录中的 Electron 二进制与生成的 asar，**不是完整运行 portable exe 或打包 MyIDE.exe**。它能证明包内依赖缺失阻止入口加载；系统 Git、SQLite 打开、格式预览、所有生产 UI 仍需修复后的独立验收。两类证据都不覆盖突然断电后的持久性。

## 2. 文件读写六条观察（FS-01：C/R，P0）

编码 fixture 的正文为 `中文 ABC\r\n`，读取后将未修改的 content 与返回的 encoding 交给原写处理器。

| 编号 | 输入/操作 | 实际输出 | 缺口 |
|---|---|---|---|
| F1 | UTF-8 BOM 文件，无改动读写 | 返回 ok=true；原首字节 efbbbf 消失，CRLF 保留 | read 去 BOM 但未返回 hasBom，write 无法保留格式 |
| F2 | UTF-16BE BOM 文件，无改动读写 | read.encoding=utf16be；write ok=true；保存后为无 BOM UTF-8 | 写端没有 utf16be 分支，兜底悄悄转码 |
| F3 | 无 BOM UTF-16LE 文件，无改动读写 | read.encoding=utf16le；保存后新增 fffe BOM | 写端总加 BOM，读取未记录原标记状态 |
| F4 | 读 GBK 的 `中文 ABC`，追加空格与 😀 后保存 | 返回 ok=true；重读为 `中文 ABC ?` | 不可表示字符经 iconv 编码丢失，没有前置检测 |
| F5 | read initial 后，外部真实写 external newer edit，再保存 my stale edit | 返回 ok=true；磁盘只剩 my stale edit | 没有磁盘版本前置条件，覆盖外部新内容 |
| F6 | 原文件 ORIGINAL FULL DATA，写 NEW FULL CONTENT；桩写前三字节后抛 EIO | 返回 error=fixture-EIO-after-partial-write；磁盘为 NEW | 错误有返回，但原文件已截断，未恢复或保留副本 |

F1/F3 是字节格式改变，不是正文字符丢失；F2 是转码，正文仍能由 UTF-8 解码；F4/F5/F6 涉及内容保全。不能把这六条都宣传成“中文乱码”。`viewer.js` 保存原样透传 tab.encoding，读取时只有 encoding 无 BOM/版本；未修改的 UI 实际保存是否触发需单独验证，本轮只确认 IPC 处理器路径。

另有待验边界：编码探测的零字节启发式、全中文无 BOM UTF-16、非 GBK 的非 UTF-8 文件，现有“UTF-8 解码失败即 GBK”不等于识别了所有字符集；本轮没有为这些输入计入 R。writeBinary/ai:run/任务 JSON 的调用策略也需逐项迁移，不能因为统一入口改了就宣称所有调用有版本约束。

## 5. FS-01 分包实施合同

### FS-A：编解码往返和有损保护（F1–F4）

建议 read 返回 `{content, textFormat:{encoding,bom,eol}, version}`，tab 保存格式对象；encoding 区分 utf8/utf16le/utf16be/gbk，bom 独立记录。eol 对混合换行不只存一个枚举：普通编辑保留正文换行，明确转换行尾才规范化。

- 建共享 decodeText/encodeText 模块，在 main、AI 写入与编辑器保存走同一合同。BOM 与字节序独立处理，UTF-16BE 先编码 LE 再换字节对，未知编码返回 UNSUPPORTED_ENCODING，禁止 UTF-8 兜底“成功”。
- 编码前做可表示性校验，GBK 等有损编码拒绝 ENCODING_LOSS，提供改为 UTF-8 保存或另存；不先写 ? 再提示。往返检测的等价关系、Unicode 规范化和遗留字形映射需定义，不能所有 decode(encode(text)) 不相等都不加解释地拒绝。
- 无改动的读写必须字节不变；更改正文时保留原 BOM/字节序与未被编辑的换行。用户主动转码更新格式并显式保存，失败不推进 tab 的已保存状态。
- 编码检测不确定时保留原字节/检测来源，提供重新打开编码入口；不要自动把所有非 UTF-8 文件标成“已可靠识别 GBK”。格式 UI 用现有命名/内联 SVG，迁移旧 tab/session 时用明确默认兼容。

验收：有/无 BOM 的 UTF-8、UTF-16LE、UTF-16BE、GBK，中文/ASCII/空文件/CRLF/LF/混合行尾逐字节对拍；F4 不写盘且 dirty 保留，显式 UTF-8 转码可重读 emoji。检测失败/奇数 UTF-16 字节/未知编码有稳定错误。UI 若加入编码按钮需真实 headless 截图，不能只运行 Node 编解码用例。

### FS-B：版本冲突与队列（F5）

- read.version 含规范化真实路径、必要 stat 特征和原字节 hash；同尺寸/同 mtime 修改不能仅靠 size+mtime 放行。保存携带 expectedVersion，创建新文件携带 expectedAbsent。
- 主进程在同一目标队列内校验版本、编码、写临时文件、替换并返回新版本；多入口复用，不能自动保存带版本而 AI/任务写入无条件覆盖。请求绑定项目代次，但允许已有用户授权的项目外文件。
- 冲突返回 VERSION_CONFLICT，内存正文与 dirty 保留；比较、另存、显式覆盖分别操作。覆盖授权固定本次内容和观察到的磁盘版本，再次外部修改需重新比较，不能给永远有效 force=true。
- watcher reload 只辅助更新视图，不能作为写前版本检查替代；自写事件去重与外部写入按版本识别。
- Windows 大小写、junction/符号链接、硬链接、重命名迁移和外部程序不遵守应用队列分别验证。hash 检查到替换仍有竞态窗口；强一致能力若不足需说明边界，不虚报跨应用原子 compare-and-swap。

验收：F5 不写盘；同尺寸修改与伪造 mtime 也识别；Ctrl+S/自动保存/AI 同路径并发结果可解释；项目切换/移动/另存不会向旧路径补写。依赖 EDIT-01 的 revision 合同，UI 保存成功只能推进相应版本。

### FS-C：替换失败保全和恢复（F6）

同目录独占创建随机临时文件 → 编码完整写入 → flush/close → 替换目标 → 返回字节/新版本；任何中途失败，原文件与待保存内容必须仍有一个可靠来源。失败临时内容按来源/容量/时间管理，不留下无限正文。

需单独验证 Windows 被占用文件、只读/权限、磁盘不足、rename 失败、硬链接与权限属性策略；替换 inode/文件对象可能影响链接和 ACL，不能只看内容。严禁先 unlink 原文件再 rename，也不能 rename 失败后悄悄回落直接覆盖。断电持久性与完整替换是两个指标，flush 并不自动提供系统崩溃保证。

验收注入分阶段失败：打开临时文件、短写、flush、close、替换、返回前崩溃。每阶段核对原文件字节与恢复内容；重启清理可识别临时文件而不删用户文件。Node 20.18.3 是否支持拟用 flush 参数按版本验证，不拿当前 Node 26 新 API 当实现基础。先接编辑器，再逐一迁移任务/AI/设置/二进制库；SQLite 仍遵守092的事务后导出边界。

## 6. RELEASE-01 分包实施合同

## 7. 文件处理器复现代码

下面是§2的最小完整脚本，可在仓库根通过 PowerShell 单引号 here-string 管道给 node；不加载完整 main，也不写用户文件。截取依赖固定于本基线，源码边界变化应更新取证方法，不能静默复用旧片段。

```js
const fs=require('fs'),path=require('path'),os=require('os'),iconv=require('iconv-lite');
const source=fs.readFileSync('main.js','utf8');
const detect=source.slice(source.indexOf('function detectEncoding('),source.indexOf("ipcMain.handle('fs:readFile'"));
function handler(name){
  const start=source.indexOf("ipcMain.handle('"+name+"'");
  if(start<0)throw Error('Missing handler');
  return source.slice(start,source.indexOf('\n});',start)+5);
}
function load(facade=fs){
  const h=new Map();
  new Function('fs','ipcMain','require',detect+handler('fs:readFile')+handler('fs:writeFile'))(
    facade,{handle:(n,f)=>h.set(n,f)},require);
  return {read:p=>h.get('fs:readFile')({},p),write:(p,c,e)=>h.get('fs:writeFile')({},p,c,e)};
}
const api=load(),root=fs.mkdtempSync(path.join(os.tmpdir(),'myide-audit093-fs-')),out=[];
const text='中文 ABC\r\n',be=Buffer.from(text,'utf16le');be.swap16();
try{
  for(const [name,bytes] of [
    ['F1',Buffer.concat([Buffer.from([239,187,191]),Buffer.from(text)])],
    ['F2',Buffer.concat([Buffer.from([254,255]),be])],
    ['F3',Buffer.from(text,'utf16le')]
  ]){
    const p=path.join(root,name+'.txt');fs.writeFileSync(p,bytes);
    const r=api.read(p),result=api.write(p,r.content,r.encoding),after=fs.readFileSync(p);
    out.push({case:name,read:r,result,beforeHex:bytes.toString('hex'),afterHex:after.toString('hex')});
  }
  const g=path.join(root,'gbk.txt');fs.writeFileSync(g,iconv.encode('中文 ABC','gbk'));
  const gr=api.read(g);out.push({case:'F4',result:api.write(g,gr.content+' 😀',gr.encoding),after:api.read(g)});
  const p=path.join(root,'conflict.txt');fs.writeFileSync(p,'initial\n');const r=api.read(p);
  fs.writeFileSync(p,'external newer edit\n');
  out.push({case:'F5',result:api.write(p,'my stale edit\n',r.encoding),after:fs.readFileSync(p,'utf8')});
  const fail=path.join(root,'partial.txt');fs.writeFileSync(fail,'ORIGINAL FULL DATA');
  const faulty=Object.create(fs);
  faulty.writeFileSync=(p,data,enc)=>{
    const bytes=Buffer.isBuffer(data)?data:Buffer.from(data,enc),fd=fs.openSync(p,'w');
    try{fs.writeSync(fd,bytes.subarray(0,3));}finally{fs.closeSync(fd);}
    throw Object.assign(new Error('fixture-EIO-after-partial-write'),{code:'EIO'});
  };
  out.push({case:'F6',result:load(faulty).write(fail,'NEW FULL CONTENT','utf8'),after:fs.readFileSync(fail,'utf8')});
  console.log(JSON.stringify(out,null,2));
}finally{
  const abs=path.resolve(root),base=path.resolve(os.tmpdir())+path.sep;
  if(!abs.startsWith(base)||!path.basename(abs).startsWith('myide-audit093-fs-'))throw Error('Unsafe cleanup');
  fs.rmSync(abs,{recursive:true,force:true});console.log('TEMP_CLEANED '+!fs.existsSync(abs));
}
```

打包复现入口为 `require('electron-builder').build({targets:Platform.WINDOWS.createTarget('dir'),publish:'never',config:{directories:{output:临时目录},electronDist:绝对安装目录}})`；用 `@electron/asar.listPackage` 检查生产文件与 index.html 实际路径。Electron 探针先 `app.setPath('userData',隔离目录)`，try require(生成的 app.asar/main.js)，catch 记录 code/message/require stack 后 app.exit(1)，由 Node spawn（windowsHide:true）收 stdout 和 close(code)。不要直接启动未捕获异常的包，让错误弹窗占桌面；也不要以 PowerShell GUI 调用立即返回的退出码代替真实 child close。
