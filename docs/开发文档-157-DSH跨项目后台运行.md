# DSH 跨项目后台运行

项目切换只卸下侧栏视图，原生 DSH 任务继续留在原项目、原会话。每个会话使用独立主进程运行归属，B 项目发消息或停止不会替换 A 的执行账本与权限。

侧栏在离屏容器中继续累计文字、原生工具、提问和授权。完成结果保存到原项目历史；返回时搬回同一组节点，保留尚未回答的交互。后台状态入口可以返回对应项目会话。需要操作当前 MyIDE 界面的 MCP 请求等待返回原项目后执行，避免误操作另一个项目。

项目恢复之前先托管旧任务，防止恢复标签、工具布局期间的隐藏面板通知取消旧任务。用户主动停止仍发送原生取消，窗口退出仍清理各宿主。

验证：

- `tests/ai-owner-router.test.js`：并发、停止隔离、身份防篡改、预授权归属和窗口清理。
- `tests/ai-panel-runs.test.js`：57 组通过，覆盖后台输出、后台完成持久化、切回继续、待确认和 MCP 延后派发。
- `scripts/check-ai-dsh.js`：14 组通过，实际启动隔离的本机 DSH 原生服务，模型使用确定性 HTTP 夹具；A 模型请求挂起期间切 B 并完成 B 的 MCP 调用，再释放 A，验证 A 继续读原项目文件、后台完成且原生会话 ID 不变。窗口全程隐藏。
- 语法 95 个文件通过；生产依赖完整性 92 组通过。
