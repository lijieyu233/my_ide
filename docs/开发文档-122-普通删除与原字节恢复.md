# 普通删除与原字节恢复

> 2026-10-01，代码基线b3f234c；沿097-T-C，先写合同再实施。期间并行方案占用117–120，本包定稿编号122。

现有单项删除统一承诺Ctrl+Z，却只备份可解码文本；目录/二进制永久rm，文本恢复也不能保留原BOM/字节和数据流。多选一次删除拆成多个文本undo，目录后代dirty未协调。本包保持普通删除、批量删除和撤销，接入115的独立持久记录/恢复预算与原字节能力。

## 合同

- 删除准备固定项目，规范化父子/重复选择，只允许项目子项；拒绝项目根、链接别名与恢复存储自身。全部原字节/目录自身数据流、普通属性和权限备份完成并校验后才允许提交；确认等待中任何选中后代版本变化则拒绝整批开始。
- 逐项持久记录删除前/后阶段；按后代优先删除，原生句柄核对对象/默认正文/数据流，目录只在仍为原身份且已空时移除。发生中途失败保留尚未删除项与恢复来源，报告实际完成范围；不调用递归永久rm作为失败兜底。
- 恢复先父后子，原路径必须缺席，不覆盖后来创建的文件/目录。部分删除时使用仍在原位的父目录，部分恢复时使用本次恢复的父目录；每层身份/自身流/权限均核对，不能把副本放进后来替换的同名父目录。原生发布后回执丢失按持久暂存身份核对，无法证明就保留并提供导出。
- 一次多选对应一个operationId/undo；目录/二进制、GBK/UTF16/BOM及混合行尾走原字节副本，内存撤销栈不保存正文。原字节恢复与复制共用50条/256MiB预算、校验和列表；不自动过期清理唯一来源。
- 等待相关保存/读取；确认说明dirty输入仍留编辑器，需要另存或恢复磁盘后比较。删除后干净标签关闭，dirty和提交等待中新输入保留标签及旧版本，旧保存不能复活删除路径；确认/恢复归属原项目。
- 对超过本应用恢复预算或不支持的特殊属性，说明未删除，提供明确的系统回收站动作。该动作由Electron shell.trashItem执行，失败不自动永久删除；系统可能已移动部分后代，按可能变更范围核对编辑器并提示检查回收站和原路径。恢复由系统回收站完成，不承诺应用Ctrl+Z。普通原字节恢复方式仍是默认。

Windows默认流共享不能锁住其他ADS；最终枚举/删除和路径父目录外部置换窗口仍按115/FS-C边界记录。本包不宣称全文件系统CAS、多文件原子或掉电恢复。系统回收站没有应用恢复token（[Electron shell文档](https://www.electronjs.org/docs/latest/api/shell)）；验证只用独立夹具，不清用户回收站。

## 保留边界

- 删除中断时deleting项的原路径缺席只证明现在不存在；显式恢复可安全以原副本重建缺席路径，不证明外部删除的原因。日志截断/校验损坏拒绝猜测，保留来源供核对导出。
- 文件原birth/mtime验证；目录恢复后加入后代会改变目录mtime/ctime，不宣称目录全部时间戳保持原值。权限覆盖已验证普通Owner/Group/DACL；复杂SACL、加密/压缩/稀疏/离线/链接/硬链接删除仍拒绝原字节方式。
- 回收站确认绑定项目身份、递归stat集合与提交前复核；不读取全正文/ADS摘要，也不宣称stat等价于原字节CAS或最终系统调用无外部竞态。超过百万项拒绝；链接/特殊对象未验证系统回收站范围，继续拒绝。Windows回收站正向只验证普通本地NTFS文件，目录部分回收/UAC/其他文件系统/系统恢复UI未独立验收。
- 默认流共享不能封锁另一ADS与最终父路径置换；多文件删除/恢复逐项执行，不是原子事务或掉电恢复。独立AI/其他工具的永久删除通道未在本包统一迁移；跨卷/大目录性能与FS-C更完整恢复管理继续原合同。
