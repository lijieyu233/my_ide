# 开发文档 047 —— 任务列表（清单 + DAG）

> 目标：为 MyIDE 增加项目级任务管理工具窗口：以清单为主视图（增删改勾、优先级、状态分组），
> 任务之间可声明依赖（DAG），并可一键切换到依赖图视图（SVG 自绘，节点 + 箭头 + 阻塞高亮）。
> 本文档为调研 + 方案设计，是后续开发的唯一依据。

---

## 1. 背景

- 用户需求原话：「添加任务列表功能 具体我没想好 能列出要做的事情 或许用dag的形式列出来」。
- 上轮对话已对齐方向：**清单为主 + 任务间依赖声明 + 可切 DAG 图视图**。
- 现状：项目内无任何任务管理代码（搜索 task/todo/待办 无业务实现，仅 todo.md 用户手记、md 编辑器的 `- [ ]` 复选框）。

## 2. 需求定义

| # | 需求 | 说明 |
|---|------|------|
| R1 | 列出要做的事情 | 项目级任务清单：标题、备注、优先级、三态（待办/进行中/完成） |
| R2 | 任务间依赖 | 任务可声明「依赖哪些任务」，依赖未完成 → 显示**阻塞**徽章 |
| R3 | DAG 图视图 | 图形化展示依赖关系：节点=任务、箭头=依赖、按拓扑层级分层布局 |
| R4 | 持久化 | 按项目隔离存储，重开项目自动恢复（对齐 myide-tool-state:<root> 惯例） |
| R5 | 工具窗口形态 | PyCharm 式左侧停靠工具窗口（与项目/大纲/提交并列），快捷键唤起 |

**非目标（本期不做）**：子任务嵌套（依赖模型保持扁平）、多人协作、日期截止提醒、跨项目任务汇总。

## 3. 方案选型

| 方案 | 思路 | 优点 | 缺点 | 结论 |
|------|------|------|------|------|
| A. 纯清单 | 只做 TODO 列表，无依赖 | 最简单 | 用户明确提了 DAG；无依赖视图 | ✗ |
| **B. 清单 + 依赖 + 双视图（推荐）** | 清单为主视图，依赖是任务的普通属性，DAG 是同一数据的只读投影 | 编辑效率高（清单增删改最快）；依赖不强制（无依赖=普通清单，零负担）；图只是渲染层，逻辑简单 | 图上直接编辑（拖拽连线）交互复杂 | ✓ |
| C. 图优先 | 节点图为主界面，双击节点编辑 | 关系直观 | 建任务要拖节点、高频编辑效率低；布局空间占用大 | ✗ |

选 **B**，理由：
1. 「具体我没想好」——方案 B 对不确定需求最宽容：不用依赖时它就是个清单，想用依赖时随时声明；
2. 项目已有 SVG 自绘经验（git-log.js `buildGraphSvg` 提交图、db-panel ER 图），DAG 渲染零新依赖；
3. 数据模型简单（任务数组 + deps 字符串数组），localStorage 持久化与现有惯例一致。

## 4. 数据模型

```js
// localStorage key：myide-tasks:<root>（按项目隔离，对齐 myide-tool-state:<root>）
{
  version: 1,
  tasks: [
    {
      id: 't1',            // 't' + Date.now().toString(36) + 3位随机 —— 创建后不变，删除即失效
      title: '实现剪切修复', // 必填，单行
      note: '',            // 备注，多行纯文本（第二行起在清单折叠显示/编辑弹窗内编辑）
      status: 'todo',      // 'todo' | 'doing' | 'done'
      priority: 'normal',  // 'low' | 'normal' | 'high'
      deps: [],            // 依赖任务 id 数组；deps 全部 done → 可开始；存在非 done → 阻塞
      createdAt: 1690000000000,
      updatedAt: 1690000000000,
      doneAt: null         // 完成时间戳（撤销完成时清空）
    }
  ]
}
```

### 4.1 派生状态（不存储，渲染时计算）

| 派生 | 规则 |
|------|------|
| `blocked(task)` | `deps` 中存在 status !== 'done' 的任务 |
| 层级 `level(task)` | 无入度=0；否则 `max(所有前驱 level)+1`（拓扑序顺带算出，DAG 布局用） |

### 4.2 不变量（所有写操作必须维护）

1. **无环**：添加依赖 a→b 前，DFS 检查 b 是否已可达 a，可达则拒绝（toast「会造成循环依赖」）；删除任务时级联清理所有 deps 引用；
2. **deps 只引用存在的 id**（删除任务/导入数据时统一清洗）；
3. status 变 `done` 必须写 `doneAt`，变回非 done 必须清空。

| 0.8 | 依赖编辑弹窗 | 「依赖…」打开简单列表弹窗：列出其余全部任务（含状态），复选多选；保存时逐条防环校验 + 清洗自引用 |
| 0.9 | 阻塞联动 | 依赖被勾成 done → 依赖它的任务阻塞徽章数字实时减（每次数据变更全量重渲染，任务量 ≤ 数百无性能问题） |
| 0.10 | 删除级联 | 删任务 → 遍历所有 tasks 剔除 deps 中的该 id |

### P1 —— DAG 视图

| # | 功能 | 实现 |
|---|------|------|
| 1.1 | 视图切换 | 面板标题栏按钮「⇄ 清单 / 图」；视图偏好存 localStorage `myide-tasks-view`（全局，非按项目） |
| 1.2 | 布局算法 | 简化 Sugiyama 三步（纯函数 `dagLayout(tasks)`，可单测）：①Kahn 拓扑排序顺带算层级 level；②层内排序：2 轮 barycenter 扫掠减交叉；③坐标：`y = level * (nodeH + gapY)`、`x = 层内序 * (nodeW + gapX)`，容器可横向滚动 |
| 1.3 | SVG 渲染 | 节点：圆角矩形（宽 160 高 40）内两行文本（标题 + 状态图标/哈希式 id）；边：贝塞尔曲线 + 箭头（复用 git-log.js `curve()` 思路）；配色全部走 CSS 变量（四主题适配） |
| 1.4 | 状态着色 | done=绿色实心边框+半透明填充、todo=默认、doing=accent 蓝边框、high 优先=左侧红条；**阻塞链**：存在未完成依赖的边画虚线红色 |
| 1.5 | 图上交互 | 点节点 = 清单中选中同一任务（双向高亮联动）；双击 = 打开编辑弹窗；图例（状态色说明）固定右下角 |
| 1.6 | 空态 | 无任务「暂无任务，回清单添加」；无依赖「任务之间还没有依赖关系」+ 提示去清单添加 |

## 6. 架构与模块设计

```
renderer/
├── tasks.js          # 新增：Tasks IIFE 模块（全部渲染端逻辑，无主进程参与）
│   ├── state: tasks[], rootPath, view('list'|'dag')
│   ├── store: load()/save() → localStorage myide-tasks:<root>
│   ├── api:  add/rename/setStatus/setPriority/setNote/toggleDep/remove
│   │         （每个 api 内部：防环/清洗/级联 + save + render）
│   ├── render: renderList()（清单）/ renderDag()（SVG）
│   ├── dagLayout(tasks) → { nodes:[{task,x,y,level}], edges:[{from,to,blocked}], width, height }
│   │         # 纯函数（无 DOM 依赖），导出供测试：window.Tasks._dagLayout
│   └── helpers: blockedMap()（id→未完成依赖数）、cleanDeps()、wouldCycle(a,b)
├── app.js            # 改：ALL_TOOLS/SIDE_TOOLS 加 'tasks'；switchTool 天然支持
├── shortcuts.js      # 改：register('tool-tasks', { keys:['ctrl+9'], run:() => App.showTool('tasks') })
└── index.html        # 改：#tool-tasks 按钮 + #panel-tasks 面板骨架
```

- **零主进程改动**（纯 localStorage，无 IPC）：风险最小，回滚容易；将来若要任务文件化（如 .tasks.json 进 git）再迁移存储层，模块边界已留好（store 内聚）。
- 渲染策略：全量重渲染（对齐 outline.js 模式）；任务数量预期 < 200，性能无虞。
- 复用组件：#ctx-menu 右键菜单、Modal.confirm/prompt、MI.toast、CSS 变量主题体系。

```
┌─ panel-tasks（左侧停靠，SIDE_TOOLS 同款）────────────────┐
│ 任务 ☑ 3/12                    [A−][A+][⇄ 图][+]         │
├─────────────────────────────────────────────────────────┤
│ ▼ 进行中（1）                                            │
│   ● 实现 DAG 布局        ⛓1   ⇄                        │
│ ▼ 待办（3）                                              │
│   ○ 拖拽连线交互   🔴                                  │
│   ○ todo.md 互导   ⛓1                                  │
│ ▶ 已完成（2）（折叠）                                    │
├─────────────────────────────────────────────────────────┤
│ [ + 新任务，回车添加                                    ] │
└─────────────────────────────────────────────────────────┘
```

- 图标/徽章：⛓=阻塞（数字=未完成依赖数）、🔴/🔵=高/中优先级色点、○/◐/●=todo/doing/done。
- DAG 视图整面板替换列表区域，标题栏（含统计与切换按钮）保持不变。

## 9. 测试与验收标准

dom.test.js 新增（jsdom 环境可直接跑 Tasks 模块）：

1. 新建任务 → localStorage 写入、清单渲染、统计更新
2. 勾选 todo→done→todo 状态与 doneAt 往返
3. 优先级分组渲染顺序（高优先在组内置顶）
4. 添加依赖 a→b 后 b→a 被拒（环）且 toast
5. 删除被依赖任务 → 依赖方 deps 自动清洗、阻塞徽章消失
6. 阻塞数字：2 个依赖完成 1 个 → 徽章 ⛓1
7. `dagLayout` 纯函数：层级正确（依赖方层级严格大于被依赖方）、无重叠坐标、孤岛节点 level=0
8. 视图切换后数据不变（只换渲染）、刷新记忆视图偏好
9. 回归：工具窗口切换（switchTool 各面板互斥）、Ctrl+9 快捷键、既有 147 用例全绿

## 10. 风险与对策

| 风险 | 对策 |
|------|------|
| 依赖编辑交互复杂 | 依赖用独立弹窗（复选列表）而非内联，先做对再做快；图上拖拽连线放 P2 |
| 环检测漏（导入/手工改存储） | 所有读入口（load/import）跑一次 `validate(tasks)`：删无效引用 + 检环（成环时按时间序断开最新边并 toast） |
| localStorage 数据量 | 单任务 < 300 字节，千任务 < 300KB，安全；version 字段为将来迁移留门 |
| 与 todo.md 双轨混乱 | todo.md 是用户手记，互不自动同步；P2.2 互导手动触发，方向明确 |
| DAG 大图渲染卡顿 | 任务量 < 200 无虞；> 500 节点时图视图提示「任务较多，建议用清单视图」并允许渲染（SVG 万级节点才需虚拟化，远超场景） |
