# 开发文档 083 —— Markdown：实时预览与预览的对齐（排版 / 语法 / 点击）

> 用户原话：「markdown 的实时预览和预览差别非常大，实时预览根本没法看，没法编辑，样式非常差，你去修复改进」。
> 本文档记录根因（含实测数据）、修复项与验收方式。**046** 是 Obsidian 式方案的调研与设计，本文是它的落地修复。

---

## 1. 复现：用用户真实 profile 对照两种模式

取证脚本（临时，跑完已删）用**用户 profile 的副本**启动整个 app，同一份 `preview-test.md` 分别在
`live` / `preview` 下量计算样式。用户的设置：主题 `theme-crimson` + 背景图 + **编辑区字号 17px**。

| 元素 | 实时预览（修复前） | 预览（修复前） |
|------|------------------|---------------|
| 正文 | **17px**（跟随 `--editor-font-size`） | 13px（写死，字号设置完全不生效） |
| h1 / h2 | 21 / 18px | 21 / 18px |
| h3 | **15px（比正文还小）** | 15px |
| h4 | **14px（比正文还小）** | 14px |
| h5 / h6 | **12.5px（比正文还小）** | 12.5px |
| 行内代码 | **12px（比正文还小）** | 12px |
| 正文列宽 | 820px（内容满宽） | 752px（820 − 左右各 34 内边距） |
| 行高 | 1.7 | 1.65 |

**根因**：两边各写一套**绝对 px**，但只有 live 的正文跟随可调的 `--editor-font-size`。
用户把编辑区字号调到 17px 后，live 侧 h3 以下全部**比正文小**，层级整个塌掉 —— 这就是"没法看、样式非常差"。
预览侧则完全不跟随字号，同一份文档两种模式长得不一样。

其它逐项差异（同一份文档渲染结果不同）：

| # | 项 | live | preview |
|---|----|------|---------|
| 1 | `==高亮==` | 渲染成高亮 | 裸文本 `==高亮文字==` |
| 2 | `[](url)` 空文字链接 | 显示 URL | 渲染成**看不见的空链接** |
| 3 | `- [ ] 任务` | `• ☐ 任务`（多一个圆点） | `☐ 任务` |
| 4 | 图片加载失败 | 虚线占位框 + 图名 | 裂图图标 |
| 5 | 表头 | accent tint + 标题色 | 纯 `--bg-panel` + 亮白字 |

**"没法编辑"的实测根因**：表格是 `block widget`，CM6 只把点击换算成**整块的起止位置** ——
点第 3 行第 2 列也会把光标丢到表格首行（自检里「点击单元格光标精确进入该格」长期是红的：
`head=1081` 而期望落在 `[1103,1128]`）。

## 2. 修复

### 2.1 排版：一条比例尺，两边共用（核心）

- 基准字号只有一个：`--editor-font-size`。预览 `.md-view` 补上 `font-size: var(--editor-font-size, 13px)`。
- 其余尺寸**一律 em**，数值 = 13px 时代的 px ÷ 13（`h1 1.62` `h2 1.38` `h3 1.15` `h4 1.08`，
  `h5/h6` **保底 1em**：正文放大后标题不得比正文小，这是历史 bug 的根）。
- live 侧（`md-editor.js` liveTheme）同步换算：标题、行内代码 0.92em、代码块 0.96em、
  任务勾选框 0.95em、表格 0.96em、以及全部行 padding（引用/围栏/标题/分隔线）。
- 行长对齐：live 的 28px scroller 内边距移到 `.cm-content`（22/34/38 + max-width 820），
  与 `.md-view` 的内边距逐项相同；scroller 上限 876 → 820。**正文列宽两边都是 752px**。
- 行高统一 1.7；预览的 p/h/ul/pre/table 间距全部改成 em。

### 2.2 语法渲染对齐

- `plugin-loader.js` 注册 marked 内联扩展 `mdHighlight`（`==x==` → `<mark>`）。
  用扩展而不是事后正则：marked 是「扩展 → 内置规则」的顺序，反引号代码段会整段被 codespan 吃掉，
  代码块里的 `==` 不会被误染。
- 预览里空文字链接补上 href 文本（`<a>` 无文字时显示 URL）。
- 预览图片 `error` → 虚线占位框（与 live 同款 `.md-img-broken` / `.cm-md-img-broken`）。
- 预览表头改成与 live 表格 widget 同源的 accent tint + `--md-heading`。
- live 任务行：`- ` 整体隐藏，**不再补圆点**（之前是 `• ☐`，与预览对不上）。

### 2.3 点击映射：表格单元格

`TableWidget` 现在接收 `from`，`mousedown` **捕获阶段**按点击的 `td/th` 反推源码行列
（`cellOffsets()` 处理省略首尾竖线、`\|` 转义、单元格前导空格；数据行源码行号 = 行序 + 2，
即跳过错开的表头行与 `|---|` 分隔行），然后 `view.dispatch({selection})` + `view.focus()`。
必须 `preventDefault/stopPropagation` 并抢在 CM6 自己的换算之前，否则会被它按"整块起点"覆盖。

## 3. 自检（把"两边一致"变成断言）

`scripts/check-live-page.js` 新增**一致性**断言组：把 `.md-view` 渲染到屏幕外（仍有布局 → 计算样式有效），
**不切模式**即可与 live 侧逐项对比：h1–h6 / 正文 / 加粗 / 斜体 / 行内代码 / 高亮 / 引用 / 代码块 / 表头格 / 数据格
的字号（容差 0.75px）、h1–h3 字重、`.cm-content` 与 `.md-view` 的 max-width 与左右内边距、
以及「预览跟随编辑区字号」「预览渲染 `==高亮==` 为 `<mark>`」「预览空文字链接显示 URL」。
以后谁再把绝对 px 写回 liveTheme，这里立刻红。

顺带修掉几条**失效/误判**断言：

- `样式: h1 字号 26px`（早已改为 21px，长期假红）→ 改成「h1 字号 > 正文字号」+「标题层级不塌」，
  并新增跨模式一致性组。
- 行内代码/`==高亮==`/代码块行背景：装饰背景画在 `::before(z:-3)`（为了让选区可见），
  只测元素自身 `background-color` 永远是 `transparent` → 加 `bgOf()` 读 `::before`。
- 任务列表区的断言必须**单独滚过去**：视口一矮，第 45~50 行的无序列表与第 61~63 行的任务区就不再同屏，
  会量成 `count=0` 的假失败。

## 4. 自检不再抢用户桌面（重要）

`--check-live` 以前是**正常可见窗口**，一跑就在用户桌面上弹窗抢焦点。用户原话：「你把桌面占据了我怎么用」。
现在与 `--check-ui` 同款规定：

- `--check-live` **默认 headless**（`show:false` + `skipTaskbar`），截图与断言不依赖窗口可见性；
- 要肉眼看着它跑用 `--check-live-show`；
- 通用开关 `--headless`（给临时取证脚本用）。

headless 带来的两个坑（已处理）：

1. **窗口被系统按工作区压矮**（实测 880 → 728），视口外的行不在 DOM → 断言假失败。
   自检里显式 `win.setContentSize(1380, 880)`（隐藏窗口可以超出屏幕）。
2. **隐藏窗口拿不到 DOM 焦点**，CM6 的 `drawSelection` 就不画选区层/光标层。
   这类项（选区可见性 3 条、光标高度 3 条）记 **SKIP** 而不是 FAIL，
   汇总行写明「/ N 跳过（隐藏窗口下无法量焦点相关项，全量校验用 --check-live-show）」；
   可见窗口（`--check-live-show`）那次跑仍是全量真值。

## 5.5 第二轮反馈（2026-09-29 当天，用户截图）

用户又贴了两张截图，原话：「原不止这些 / 实时预览 选中 ui 覆盖的范围不对 / 这里缩进也没有 /
文字几乎全是白色 / 表格也不能像 excel 那样的表格使用」。用真实 profile（crimson + 背景图 +
17px）逐项量，坐实了其中三条：

| 症状 | 实测 | 根因 | 修复 |
|------|------|------|------|
| 缩进也没有 | 嵌套子项缩进 **live 9px** vs **预览 24px** | 源码里的 2 个空格在比例字体下只有 9px；预览是 `ul { padding-left: 1.85em }` | `IndentWidget`：按**语法树里的真实层级**把前导空白换成 1.85em × 层级 的缩进（与预览同宽），实测两边都是 24px |
| 文字几乎全是白色 | 正文 live `#e8cdd6` / 加粗 `#f2dce4` vs 预览 `#d8b3c0` | live 用 `--editor-text`、加粗再加一层 `--text-bright`；预览正文用 `--text`、加粗只改字重 | `.cm-content` 前景色改 `--text`；`oneDarkHighlight` 与 `.cm-md-strong` 都去掉加粗的额外颜色（与预览一致：加粗只变字重）；预览侧补 `li::marker` / `del` 与 live 同源 |
| 表格不能像 excel 用 | 旧 Tab 只在本行找下一个 `\|`，行尾即停；Enter 会把一行表格**劈成两行** | 只按"行"处理，且从不重排 | 按整张表处理：`tableContext` 定位行列 → Tab 换格/末格换行/末行末格**追加一行**、Shift+Tab 反向、Enter 下移一行（末行补行）；每次编辑后**按显示宽度（CJK 算 2 列）重排管道**，光标重定位到目标单元格。表格源码行改等宽字体 + 不折行 → 光标进表时是一张对齐的网格（过长横向滚动，跟 Excel 一样） |

### 5.6 「选中 UI 覆盖的范围不对」：根因找到并修掉（无需再问用户）

一开始以为这条量不了（CM6 只在聚焦时绘制选区层），后来**改从几何上算**：读
`cm6-bundle.min.js` 里绘制选区的 `RectangleMarker.forRange()`，它算整行矩形的横向边界用的是

```
left  = .cm-content 的边框盒 left  + 首个 .cm-line 的 paddingLeft
right = .cm-content 的边框盒 right − 首个 .cm-line 的 paddingRight
```

**不扣 `.cm-content` 自己的左右 padding**（实测只读 `.cm-line` 的）。而上一轮我为了和预览对齐，
把 34px 左右内边距写在了 `.cm-content` 上 → 选区色块比正文列**左右各宽 34px**。用真实 profile 实测：

| | 正文列 | 选区矩形边界 |
|---|---|---|
| 修复前 | `[456..1188]` | `[422..1222]`（左右各多 34px） |
| 修复后 | `[456..1188]` | `[456..1188]`（完全重合） |
| 预览正文列 | `[456..1188]` | — |

修法：`.cm-content` 的左右内边距改 0，列宽上限与 34px 内边距挪到 **scroller**（它不在 `.cm-content`
的边框盒里，因此不进选区几何）。scroller `max-width: 820px`（= `.md-view` 的盒子宽；两者正文列
都是 752，实测左边界都是 456）。自检里同步加了断言：
「正文列宽上限与左右内边距同源（scroller vs .md-view）」+
「`.cm-content` 不吃横向内边距（否则选区色块会宽出这段）」。

> 附带发现：屏幕外渲染 `.md-view` 做对照时**不能比实际像素宽** —— live 的 scroller 带
> `scrollbar-gutter: stable both-edges`（左右各预留滚动条宽），屏幕外容器里没有滚动条，
> 会比出 20px 的假差异（132 项里那次唯一红的假失败）。所以改成比 max-width + 内边距。

新增断言（`--check-live-page.js`）：颜色逐项对比（h1–h6/正文/加粗/斜体/行内代码/高亮/引用/代码块/表头格/数据格，
归一化 `rgb()` 与 `color(srgb …)` 后比）、嵌套列表缩进量相同、正文档位同源，以及 7 条表格 Excel 式编辑
（Tab 接管 / 换格 / 竖线对齐含分隔行 / 末行末格增行 / 追加后仍对齐 / Enter 不劈裂 / 自检后文档还原）。
自检基线：**126 通过 / 0 失败 / 6 跳过（共 132 项）**。

## 5.7 对标 Obsidian：Callout（`> [!note]` 提示块）

文档 046 的 P2 清单里 Callout 一直没做。这次补上，**两种模式共用一张类型表**：

- 类型表在 `md-editor.js`（`CALLOUT_TYPES` / `CALLOUT_CLS`，25 个别名：note/info/tip/warning/danger/
  success/question/example/quote/bug/abstract/todo…），通过 `MI.calloutMeta(type)` 对预览侧开放。
  ⚠ `window.MI` 是后加载的 `plugin-loader.js` 建的 → 这里必须自己 `window.MI = window.MI || {}` 兜底，
  否则 `if (window.MI)` 永远为假、预览一个 callout 都不渲染（实测踩过）。
- **live**：`Blockquote` 首行匹配 `^\s*>\s*\[!type\][-+]?\s*(.*)$` → 整块加
  `.cm-md-callout-line` + 类型色 class（`co-*`）+ 首/末行圆角；`[!type]` 标记 replace 掉、
  用 widget 画图标；没写标题时补类型默认名（`> [!warning]` → "⚠️ Warning"）。
  左竖线与淡底色画在 `::before(z:-3)`（与表格/代码块同一套做法，保证选区可见）。
- **preview**：`marked` 只把 `> [!note]` 当普通引用 → 后处理 `blockquote` 成
  `.md-callout` 容器 + `.md-callout-title` 标题行。
  ⚠ `marked` 配了 `breaks: true`，引用块内换行是 **`<br>` 元素**而不是 `\n` —— 标题/正文必须按
  **首个 `<br>`** 切分 DOM；按字符串切换行会让标题把整段正文吞掉（实测踩过）。
- 颜色：`styles.css` 里一份 `--callout-*` 色板 + `.co-*` 变量映射，两边都用
  `var(--co-color)`；自检断言「同类型颜色两边相同」（note 实测两边都是 `rgb(68, 138, 255)`）。
- 未知类型（`> [!unknown-type]`）退回普通引用；普通引用不受影响。

自检新增 13 条 Callout 断言（live 6 条 + preview 6 条 + 跨模式同色 1 条），
`preview-test.md` 增加「九、Callout」小节作为基准。基线：**139 通过 / 0 失败 / 6 跳过（共 145 项）**。

## 6. 铁律（写在这里免得下次再踩）

1. liveTheme 里**只准写 em**，绝对值只允许出现在 1px 级细节（边框/圆角/滚动条）。
2. 两边的字号/间距/列宽/内边距必须同源，改一边就得改另一边 —— 一致性断言组会拦。
3. CM6 行内间距**只能用 padding**（heightmap 不含 margin，用 margin 会让点击坐标整体错位）。
4. block widget 的点击必须自己做映射（CM6 只知道整块起止位置）。
5. 自检脚本默认 headless；要显示窗口的跑法必须显式加 `-show` 后缀，别默认弹到用户桌面。
6. **`.cm-content` 永远不要吃横向内边距**：CM6 的整行选区矩形只按 `.cm-line` 的 padding 收缩，
   content 自己的左右 padding 会让色块比正文列宽出这一段（「选中范围不对」的根因）。
   列宽上限与左右内边距一律挂 scroller。
