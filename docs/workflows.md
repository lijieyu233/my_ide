# MyIDE 典型工作流 / Workflows

这些例子描述如何把已有模块连起来使用。AI 请求是可尝试的任务描述，不是预录的成功结果；实际执行依赖配置、授权和当前状态。

## 整理一个项目的技术资料

1. 打开本地项目目录，用搜索找到说明、接口文档和相关代码。
2. 阅读 Markdown/Office/PDF 资料；网页资料在内置浏览器中查阅，必要时选区翻译。
3. 在 AI 面板引用相关文件和当前选区，说明要整理的范围、保留的内容与目标文档。
4. 先查看方案和差异，确认范围后保存；在 Git 面板核对实际修改，独立提交。

可以这样描述任务：

> 阅读我引用的项目说明和接口文档，列出部署前需要确认的条件。先给出依据和文档结构，等我确认后更新指定文档。

输出是普通本地文件，可以继续编辑或交给其他工具。长文对照、分屏和图片操作是这个流程中的辅助功能。

## 修改代码并验证

1. 用文件树和项目搜索定位问题，查看相关 Git 差异与历史。
2. 引用错误信息、源码和预期行为，让 AI 分析原因并限制修改范围。
3. 在权限允许后修改文件；启动面板运行已配置程序，终端或命令工具执行项目检查。
4. 核对编辑器、日志和实际页面，最后检查 Git 改动再提交。

> 解释当前错误与引用代码之间的关系。先检查现有实现，再提出最小修改；运行已有检查，并告诉我验证结果和仍不确定的地方。

MyIDE 不自带每种语言的编译器或完整调试器。项目所需运行时、依赖和检查命令仍由项目提供。

## 排查程序或远程服务

1. 在启动面板检查配置、工作目录、进程、端口与日志，区分“启动了”和“已经可用”。
2. 远程服务通过 SSH/SFTP 连接；核对主机指纹、服务器身份与目标目录。
3. 让 AI 读取指定程序/会话的实际状态并解释错误。数据库问题按需连接数据库，以只读检查开始。
4. 修改前确定目标与授权；修改后重新检查服务、页面/API 和日志。

> 检查指定程序的运行状态与最近日志，说明失败发生在哪一步。先做只读诊断，涉及重启、写入或删除时说明具体目标与影响。

AI 的状态工具不能代替真实服务验收。请求受理、进程启动、端口监听和业务请求成功是不同结果。

## 连续研究与阅读

把常用网站保存成标签组，下次打开继续查阅；本地小说和漫画进入书架续读。查到的材料可以整理进项目文档，阅读页与项目页的上下文按所属页面隔离。
