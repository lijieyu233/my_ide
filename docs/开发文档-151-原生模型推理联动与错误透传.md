# 原生模型推理联动与错误透传

## 实际故障

用户给出侧栏截图：图片请求被停止、后续工具完成，但最终仅显示“原生 DSH 未完成：error”。读取对应 DSH 原生日志确认：图片已作为 image 内容入档；前两轮为用户停止，第三轮 workbuddy/deepseek-v4.1-flash 返回 INVALID_REQUEST、HTTP 400：“模型不支持该思考强度，请调整”。

不是图片丢失或字幕能力问题。模型选择器切换时写 dshReasoning 空字符串，原生模型选择删除推理值；WorkBuddy 的公开模型目录仅声明允许的强度，未公布 defaultEffort，而适配器的省略参数请求在该模型上被拒绝。同时终态错误信息位于 reason.error.message，接入层只读取 reason.message，丢掉了上游原因。

## 修复

- 切模型不再写空推理强度。新模型仍支持原值时保留，否则使用模型目录明确默认或已公布的有效值；没有合成模型目录外的强度。
- 对有明确允许强度列表的模型，只展示这些选项，不提供会清空值的“原生默认”。没有具体默认时显示实际选择；优先沿用有效原值，再用有效目录默认，其次选允许的 high 或目录第一项。
- 恢复已有原生会话时也核对推理值，修复先前已保存的空选择，不重建会话或删除历史。
- 上游明确错误值保留代码、HTTP 原因和 message；兼容嵌套 error、reason 与原生 request/error，不把失败误报完成。
- user 类型的 aborted 映射为取消；用户停止不再以泛化 error 解释。

仍不修改原生模型工具、Agent 循环或任务策略。没有自动重放原先“删除字”的项目操作。
