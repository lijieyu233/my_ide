# 排他新建与新建撤销保护

> 2026-10-01，产品基线3557000；对应097-T-A第一个逻辑子包，开发前合同。

新建文件夹目前调用recursive mkdir，同名目录会被当作新建成功，Ctrl+Z再递归删除整目录。新文件虽已由111排他发布，创建后的撤销仍按路径无条件删除，保存或外部修改后也会丢内容。本包落实排他新建和这两类撤销的数据保全；覆盖粘贴、merge、普通删除的持久恢复来源继续按097独立交付，不整体关闭TREE-01。

## 行为与边界

- 新建只接受单段名称，不隐式创建父目录；Windows设备名、路径穿越、ADS冒号、尾空格/点等由主进程拒绝。父目录必须是当前项目中的真实普通目录，链接/别名拒绝。文件和目录的创建都以系统排他原语发布，同名冲突保留原对象与内容。
- 成功保存实际路径、项目归属及本次空对象版本。只有仍为该对象且保持空白的文件/空目录才允许撤销；保存、外部替换、添加后代或数据流后拒绝，撤销记录可重试。不会递归删除新建后填入的内容。
- Windows撤销先打开带DELETE访问且不共享写入/删除的原生句柄，在句柄存活期间核对版本，最后用该句柄标记删除。不能退回“check后按路径rm”；不支持/锁定/只读等失败保留对象。不宣称跨平台实现。
- 句柄共享锁保护默认正文与删除/重命名身份，**不阻止另一个ADS数据流的写入/创建**，已用真实NTFS补测确认。最终核对拒绝已出现的额外流；流枚举与删除提交之间仍有外部新增ADS的窗口。本包不宣称所有流的原子版本比较，完整特殊流恢复继续属于FS-C/097覆盖删除恢复合同。
- 编辑器协调先等待在途保存/读取；已有dirty拒绝撤销。在操作等待期间继续输入仍保留在标签中，已移除的磁盘身份不能借旧保存复活。干净且未变化的标签在成功后关闭。切项目期间的确认不得落到新的项目，迟到成功保留原操作归属但不打开到新项目。
- 所有失败对象/rejection明确提示，先peek，成功才移除撤销记录。未能核对操作后版本仍如实报告创建成功并保留路径，不能因此回滚删除未知对象。
- 当前记录仍是既有进程内最多50条撤销栈，不是重启恢复journal；本包没有旧正文备份需要过期清理。持久恢复、待重试记录容量管理与可恢复覆盖/普通删除另包实现。

## 验收

真实临时文件覆盖同名文件/非空目录、非法名称、链接父目录、写时竞态、正常空对象撤销、后来保存/添加后代/替换对象/ADS、原生锁定、失败后重试。完整Tree/Viewer补项目切换、dirty与等待保存及撤销错误对象；隐藏隔离Electron补真实IPC和CM6新输入，不碰用户项目/剪贴板/回收站。后台npm test，并核对相关截图、打包依赖闭包，结束清理自己的临时产物、提交推送和重启。

原生依据：[CreateFileW共享模式](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-createfilew)、[SetFileInformationByHandle的DELETE访问与关闭句柄删除例子](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-setfileinformationbyhandle)、[FILE_DISPOSITION_INFO](https://learn.microsoft.com/en-us/windows/win32/api/winbase/ns-winbase-file_disposition_info)。官方说明只作为接口依据，最终支持范围以本机真实实验为准；共享句柄不等于全文件系统事务。

## 交付证据

### 已交付范围

新增path-create/file-create-win服务与专用IPC；临时空对象先记录身份再经MoveFileExW flags=0发布，已有目的拒绝，发布后被替换时保留创建事实但不给undo基线。单段名称由主进程检查，父目录必须是项目内真实目录，拒绝设备名、ADS名称、隐式父目录及junction别名。服务在既有最多4个并发worker执行，创建/撤销期间相关写入沿用路径范围锁，未改通用mkdir的递归合同。

Tree记录实际路径/项目/操作后版本；undo先peek，只在成功后消费。Viewer等待读取与旧保存，dirty先拒绝；成功关闭仍干净的原标签，等待期间新输入留在CM6与标签中，保留旧磁盘版本和保存冲突入口。未保存输入可另存，不能因为磁盘空对象已撤销而用旧保存重新创建该路径。创建确认切项目失效，已经提交的迟到成功记录归原项目，不打开到新项目。
