# 切换项目与文件短暂卡死排查

日期：2026-10-17。

## 现场与结论

用户反馈切换项目或文件后界面一段时间无法操作，之后恢复。现场主进程仍响应，渲染进程可执行脚本，没有持续高CPU或本次崩溃记录。日志存在一次打开Markdown耗时26823ms，但日志不能单独证明该次耗时全部来自读盘。

发现文件文本、版本和二进制读取IPC均同步执行磁盘操作。慢读会阻塞Electron主线程，使窗口操作和其他IPC一起排队；这是本次已复现并修复的阻塞点。当前证据不足以排除复杂文档渲染等其他卡顿来源。

## 修复

- 文本、文件版本和二进制读取改为异步磁盘操作。
- 快照仍核对规范路径、文件身份、大小、时间戳与SHA256，读盘期间目标变化拒绝返回保存基线。
- Windows采用异步callback版realpath，避免promises.realpath展开8.3路径后与现有保存基线不一致。
- 加载过程中关闭标签或切换项目后，导航安全结束；修复可选链比较null后仍访问loadPromise的异常。

## 可重复验证

运行 npm run check:file-responsiveness。脚本使用隔离profile和临时项目，隐藏窗口注入1500ms慢读，不访问用户项目或配置。

修复前，相同慢读下另一主进程IPC等待约1490ms。修复后readFile、fileVersion、readBuffer慢读期间其他IPC约0.3至2.5ms；切换文件约35至48ms，切换项目约29至33ms。检查旧响应不覆盖新文档、不复活旧项目标签，以及异步读取的版本能通过真实原子保存。

单元测试 tests/file-read.test.js 覆盖字节/版本兼容、异步等待、并发读取、文件/链接变化、缺失目标、悬空链接、大小限制和读盘故障。tests/preview-navigation.test.js 覆盖加载中清空标签与切换项目。
