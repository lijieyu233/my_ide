# Git 状态与块级操作一致性取证

> 2026-10-01，第五轮持续审计；代码基线 `3367e08`，应用版本 0.8.5。
> 对应 [089 总台账](./开发文档-089-全模块成熟项目对照与持续改进台账.md) 的 GIT-01/02。本文更新证据和实施方案，未修改产品/测试，未关闭缺陷。
> GIT-02 的**已有块级操作数据保全升为 P0**；新增行级选择仍是 P2，二者不混作一个大功能重写。

## 1. 环境、方法与边界

本轮使用真实临时仓库、原生 **Git 2.53.0.windows.1** 和仓库实际安装的 **isomorphic-git 1.41.4**，直接 require 完整 git-service.js。package.json 的版本范围不是本次实际版本，后续复现需记录安装版本。

fixture 设置本地 author、core.autocrlf/core.filemode，命令使用独立空 GIT_CONFIG_GLOBAL、GIT_CONFIG_NOSYSTEM=1、非交互模式；没有修改用户全局 Git 配置或本项目 index。clean filter 是临时 Node 大写脚本，只处理 fixture 的标准输入。所有临时目录在 finally 校验绝对路径、恢复环境并删除。

对照使用原生 status porcelain v2、diff、index blob 和按路径过滤后的 hash；关注 HEAD/index/工作区三者，不以 toast 或 status 单项当正确性证明。表内 `.M` 表示工作区修改，`MM` 表示暂存与工作区各有修改，`MD` 表示 index 修改但工作区删除。

共11类场景及1项正向对照：G9 的目录读取失败为 fs.readdirSync 受控 EACCES 注入，其余使用真实文件和 Git 对象。G11 分别执行暂存、回退两种操作。没有打开真实 Electron Git UI；尚未验证完整提交后的 HEAD、外部 index 并发、worktree、稀疏检出、所有过滤器/编码和平台模式位。

## 5. 分包实施合同

### G-A：展示版本与块身份（P0，先修G11）

影响git-service/git-ops/preload、renderer/git-panel、viewer差异渲染合同。diff返回稳定snapshot：`{snapshotId, root, generation, path, side, headOid, indexOid, worktreeVersion, attributesVersion, hunks:[{hunkId,...}]}`。EOF、路径存在/删除及mode也是内容语义，不只hash行字符串。

- UI固定展示snapshot，传snapshotId+hunkId+operationId；不能只传idx。确认弹窗固定该项目/文件/版本，换项目或换diff后失效，不能在await后重新读取全局root执行旧动作。
- 主进程持有/校验snapshot；重读必要对象、工作区字节与属性，变化返回STALE_DIFF，不暂存/回退/取消暂存，提示刷新。应用原展示块，不能用旧ordinal挑当前第N块。保留现有差异请求代次，但渲染请求代次不等于写操作前置条件。
- 同仓库index写操作排队，operationId防重复按钮/IPC重发；读取快照要验证头尾版本一致。对外部Git的并发以原生锁和写前/写后检查协作，队列只约束本应用，不能宣称阻止外部进程。
- 回退先保留可恢复内容，再走版本化文件写入；可复用093 FS-B/C，未完成该服务时先做局部版本拒绝，不能让P0等待整个文件层重构。失败不自动重试破坏性操作，也不无条件还原整份index覆盖外部暂存。

验收先重放G11：旧按钮/确认弹窗等待期间插入前块、修改原块、移动文件、切项目、外部git add、重复请求，全部无意外工作区/index变化。用户刷新后选第18行只操作第18行；工作区与index的未选修改保留。真实Electron用隔离项目验证确认等待路径，headless截图核对状态/提示，不抢桌面。

### G-B：状态结果完整性与可靠回落（G1/G6–G9）

返回`{snapshotId, backend, completeness, changed, tracked, errors}`，complete/partial/error分开。打不开目录是unknown，不是deleted；只读扫描异常可有界重试，仍失败保留最近可信视图并禁用依赖完整状态的破坏性操作，不能把空changed当干净。具体UI可保持简洁，用一条持续状态解释未完成扫描。

- 调整忽略缓存失效到矩阵遍历前，或者按规则版本缓存；本轮先修G8，再测嵌套规则/否定规则/已跟踪忽略目录，避免变成每个文件重复读取整套规则。
- 快速路径不支持的index/仓库能力，有原生Git时路由`status --porcelain=v2 -z`；解析普通/重命名/冲突/未跟踪记录，tracked由对应索引来源获取，错误逐层保留。无原生Git返回能力受限，不能把不可靠legacy当无损替代。
- G7明确legacy stat不可靠；手动完整刷新、回落与写前判断必须有可靠哈希/原生保证，不能只向未生效opts塞force=true。正常快速路径保留stat捷径和忽略剪枝；安全边界与性能结果分别证明。
- 取消无条件CRLF后置隐藏。按路径text/eol/autocrlf/clean/encoding决定仓库表示；复杂属性优先原生，纯JS能力不足说明原因。mode、符号链接、冲突stage、skip-worktree/assume-unchanged、worktree/submodule为后续矩阵，本轮未证实全支持。

验收：G1必须显示并能查看行尾差异，C1仍正确；G6有原生可用，无原生有明确能力错误且不清可信视图；G7fast/回落均检出；G8第一次刷新出现新文件；G9显示未知/错误而不虚构删除。路径含中文/空格/制表符/换行的-z解析、异常重试次数和大仓预算要独立验证。

### G-C：EOF、文件删除与属性一致性（G2–G5/G10）

先修已有块操作，随后再做G-D行级扩展。实现方案在以下两条中用fixture对拍选定：

1. 原生路径：生成仓库表示的规范diff，明确禁用外部diff/textconv的非回写展示转换；选择块形成带EOF/文件mode/删除元数据的patch，用原生check/apply --cached或等价受控index写入。不能把原始工作区UTF-8文本直接交给--cached并假设filter自动补全。
2. JS保留路径：仅支持已验证的纯文本/属性组合，hunk含双方EOF和文件存在状态，合成字节而非仅按行拼接；复杂clean/encoding/index格式路由原生或明确不可用，禁止悄悄整文件暂存代替选块。

两条都遵守G-A快照。自定义filter要定义“用户看到的提交表示”，使用受控Git属性解析/按路径过滤的原生对象对拍；过滤器失败返回错误，不能写未过滤内容。不要对已经是仓库表示的index内容重复clean：filter未必幂等。textconv通常只为展示，也不能误作clean逆变换。

删除文件与清空文件分别定义：G4应从index移除路径，用户清空仍存在文件则暂存零字节blob；不生成单独LF。EOF仅变化要能形成可选项；选中触及EOF的块采用该侧EOF，未触及时保留原状态。二进制、不可逆显示编码与mode操作不能假装普通行块。

验收比对完整字节/OID、index路径存在/mode、工作区hash、其他文件暂存状态：G2/G3末尾字节正确，G4删除路径，G10有可操作差异，G5选中内容符合filter且未选第18行不进index，C1保留。随后执行真实提交检查HEAD只含选中变更，并验证取消暂存/回退、重复块、CRLF/-text/eol/working-tree-encoding及filter失败矩阵。原生方案失败不得fallback成全文件add。

### G-D：新增行级选择（P2，依赖G-A/C）

保留原M1–M5能力。只有真实需求排期后加行级勾选：定义替换块中删除/插入的组合含义、EOF归属、空文件/整文件删除，预览最终暂存结果而不让行数变化猜用户意图。将选区映射到snapshot/hunkId里的稳定行身份，文本更新后失效或明确重映射。

验收选中行进入HEAD、未选仍在工作区、外部暂存不变；混合替换/重复文本/EOF/过滤规则可解释。不得借该扩展把当前P0错块问题延后。

## 6. 可直接重放的错块与EOF取证

在仓库根将以下Node代码通过stdin执行；全部写入系统临时目录。原始日志G11使用两个独立仓库，以下最小脚本在同一fixture先暂存，再回退，回退前将index重置到HEAD，保证两种操作的基线一致。最后核对cleanup目标，不清用户仓库。

```js
const fs=require('fs'),path=require('path'),os=require('os'),cp=require('child_process');
const G=require('./git-service'),root=fs.mkdtempSync(path.join(os.tmpdir(),'myide-audit094-repro-'));
const env={...process.env,GIT_CONFIG_GLOBAL:path.join(root,'global.cfg'),GIT_CONFIG_NOSYSTEM:'1',GIT_OPTIONAL_LOCKS:'0',GIT_TERMINAL_PROMPT:'0'};
fs.writeFileSync(env.GIT_CONFIG_GLOBAL,'');
const git=(args,input)=>cp.execFileSync('git',['-C',root,...args],{encoding:'utf8',windowsHide:true,env,input});
(async()=>{
  git(['init','-q']);git(['config','user.name','Audit']);git(['config','user.email','audit@example.invalid']);
  git(['config','core.autocrlf','false']);
  const file=path.join(root,'f.txt'),lines=Array.from({length:20},(_,i)=>'LINE'+String(i+1).padStart(2,'0'));
  fs.writeFileSync(file,lines.join('\n')+'\n');git(['add','.']);git(['commit','-qm','fixture']);
  const shown=[...lines];shown[17]='DISPLAYED-LAST';fs.writeFileSync(file,shown.join('\n')+'\n');
  const view=await G.diffUnstaged(root,'f.txt');
  shown[1]='UNSEEN-FIRST';fs.writeFileSync(file,shown.join('\n')+'\n');
  const stage=await G.stageHunk(root,'f.txt',0),index=git(['show',':f.txt']);
  git(['reset','-q','HEAD','--','f.txt']);
  const revert=await G.revertHunk(root,'f.txt',0),after=fs.readFileSync(file,'utf8').split('\n');
  console.log(JSON.stringify({displayedHunks:view.hunks.length,stage,index,revert,line2:after[1],line18:after[17]},null,2));
  fs.writeFileSync(file,'same');git(['add','f.txt']);git(['commit','-qm','eof-fixture']);
  fs.writeFileSync(file,'same\n');
  console.log(JSON.stringify({case:'G10',native:git(['diff','--no-ext-diff']),myide:await G.diffUnstaged(root,'f.txt')},null,2));
})().catch(e=>{console.error(e.stack);process.exitCode=1;}).finally(()=>{
  const abs=path.resolve(root),base=path.resolve(os.tmpdir())+path.sep;
  if(!abs.startsWith(base)||!path.basename(abs).startsWith('myide-audit094-repro-'))throw Error('Unsafe cleanup');
  fs.rmSync(abs,{recursive:true,force:true});console.log('TEMP_CLEANED '+!fs.existsSync(abs));
});
```

G1最小夹具为提交`*.txt -text`与LF文件，再仅将该文件改CRLF，对比G.status/G.diffUnstaged和原生status/diff。G5使用本地required大写filter，对比stage返回oid与`git hash-object --path=f.txt --stdin`对同一选中内容的输出。G6用真实`git update-index --index-version=4`，禁止靠改头字节伪造。G7须断言同秒/同尺寸前提，否则记场景未建立，不算通过或失败；G9须只注入fixture目录读取，不能直接封锁用户目录。
