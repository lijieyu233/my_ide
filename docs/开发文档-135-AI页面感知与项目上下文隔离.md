# AI 页面感知与项目上下文隔离

AI 请求以 `App.getPageContext()` 的即时界面状态为准。每次发送及工具续轮都注入页面 ID、名称、当前工具；项目页另外包含项目根目录和活动文件路径。远程页仅提供所选服务器的 ID、名称、地址、端口、用户名及当前会话/终端 ID、终端或文件模式，不提供密码、私钥、文件正文或终端输出。

## 页面范围

- 项目、项目侧栏大纲/搜索/Git、底部 Git 日志及收起侧栏后的编辑区继续使用项目上下文。
- 远程服务器、启动面板、数据库、内置浏览器、任务、快捷启动及无项目的欢迎页暂停项目上下文。
- AI 面板的用量栏显示当前页面；暂停时明确显示“未附带项目文件”。

离开项目页立即摘下自动跟随文件。手动引用及固定引用暂存，引用标签隐藏；回到项目页恢复显示，并重新跟随活动文件。页面版本和读取任务去重防止迟到的自动读取重新附加文件。非项目页的 `@` 仅提供主动引用的剪贴板，不枚举项目文件。

## 请求和历史

发送上下文同时过滤文件、目录、编辑器选区、打开标签和 Git 改动，并暂停项目规则。主动粘贴的图片、用户输入和主动引用的剪贴板保留。

仅过滤当前附件会留下历史文件正文。因此请求投影也移除历史用户消息的项目附件、原生及兼容文本协议的项目工具结果、历史项目工具参数。原始对话存盘保留，用户手写的对话及助手普通回复仍保留；这不是删除聊天记录或撤回已发给模型的请求。新版消息记录不含项目附件的文本，旧版带 `_text` 的附件恢复原问题。原生工具调用及结果仍按 ID 成对，防止 HTTP 400。

非项目页不向模型提供项目文件工具 schema，并拒绝兼容文本协议对 `list_files/read_file/search_files/write_file/replace_edit/run_command` 的新派发。启动及 SSH 工具继续可用，仍走原有批准流程。已经提交的操作不会因切页自动回滚。

## 验证

- `node tests/ai-panel-runs.test.js`：增加页面切换、固定引用/剪贴板保留、迟到文件读取、原生/文本历史过滤和工具打开启动页后立即同步等回归用例。
- `npm run check:ai-page`：隔离 userData 的真实隐藏 Electron 窗口，记录生产 IPC 发往模拟模型的完整请求；检查欢迎页、6 个独立页面、4 个项目侧栏入口以及旧附件和工具历史配对。不会访问用户服务器或真实模型。
- 真实窗口截图为临时产物，验证后删除；不写入用户主题、项目或会话配置。


2026-10-10 验证结果：语法检查 81 文件通过；AI 测试 151 通过（面板 39）；页面真实 IPC 4 通过；DOM 517 通过；发布资源检查 80 通过。已查看深红主题远程页截图和项目页截图。

全量 npm 测试受 Git worker 临时目录 EPERM 影响中断；通用 UI 自检 447 通过、15 失败、3 跳过，失败集中于 Git 列表/暂存/合并、H3 和 Mermaid 底色，不在本次改动的模块。没有将全量检查报告为通过。
