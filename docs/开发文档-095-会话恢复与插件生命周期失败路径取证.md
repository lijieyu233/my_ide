# 会话恢复与插件生命周期失败路径取证

> 2026-10-01，第六轮持续审计；代码基线 `122968f`，应用版本 0.8.5。
> 对应 [089 总台账](./开发文档-089-全模块成熟项目对照与持续改进台账.md) 的 SESSION-01、PROJECT-01、PLUGIN-01。本轮补充证据与实施方案，未修改产品或测试，未关闭问题，三项继续 P1。

## 1. 方法和证明范围

使用仓库实际安装的 Node v22.20.0 / jsdom 29.1.1，通过 `window.eval` 加载完整 `renderer/session.js`、`renderer/viewer.js`、`renderer/plugin-loader.js`，未复制恢复或插件加载算法。S1–S4、S6 使用真实 Viewer 控制流，CodeEditor 是仅记录 create/gotoLine 的桩；文件读取为内存桥。S5 使用完整 Session 和可控制完成时间的 Viewer 桥。P1–P4 使用完整插件加载器和合成插件，P5 使用内置 DOCX 渲染器，读取桥及解析库为桩。

共 **11 类观察及 1 项正向对照**。脚本通过 PowerShell here-string 送给 `node` 标准输入运行；没有落盘临时脚本，没有触碰用户 localStorage/profile、插件目录或真实文档。每个 fixture 使用独立 jsdom 并关闭；P1 的定时器为 Map 计数桩，不启动真实循环。

本轮 R 是受控 DOM/桥运行，**不是**真实 Electron 快速切项目、崩溃杀进程、磁盘恢复或内存测量。S1 仅证明会话序列化不含 dirty 正文，不代表已经证明应用所有退出路径都丢稿。P1 不代表当前自带 CSV 插件已产生资源泄漏；它证明现有插件加载合同不能收回插件自行创建的全局资源。P5 不证明具体 Office 库 RSS 泄漏。

## 3. 插件与格式预览观察

| 编号 | 输入与操作 | 实际结果 | 原控制流 |
|---|---|---|---|
| P1 | 合成插件 registerRenderer、window.addEventListener、setInterval；加载20次，再 loadAll=[] | 重载时渲染器仅 builtin+1；删除后用户渲染器0，但一个事件命中20次、Map内timer仍20个 | 截断 renderers 能去重注册，却没有 unload/disposer；全局资源不随数组删除释放 |
| P2 | 坏插件先注册 audit 渲染器再 throw；随后好插件注册 ok | audit()=PARTIAL；ok()=GOOD | 单插件异常隔离保住后续插件，但失败前注册未回滚；不能将“报错”视为该实例已停用 |
| P3 | 已加载 P2 后，下一次 loadAll reject(EACCES) | loadPlugins Promise resolve；旧 ok renderer 已不存在 | 先截断旧表再 await；外层 catch 不返回错误。app.js:onChanged 的 then 仍会显示“插件已热重载”（后者为调用端 C，未运行整个 App） |
| P4 | 连续发起旧A/新B两次加载，B先返回NEW，A最后返回OLD | renderFor(audit)()=OLD | 两次都在等待前截断；注册无请求代次，后返回旧版本排在最后并优先匹配 |
| P5 | 调用内置 DOCX renderer，插入再移除 wrap；之后 readBuffer 返回4字节 | renderAsync仍调用1次，body.isConnected=false | officeLoad await 后没有 disposed/generation检查；对已关闭容器继续解析。未测试真实DOCX/worker释放 |

额外 C：main.js 的 plugins watcher 每次事件直接通知；并发入口不是纯理论 API。plugins:loadAll 的读取循环被一个大 try/catch 包住，某文件读取失败可能留下部分 list；这轮没有注入宿主读取失败，不能将 P3 的 renderer 桥拒绝直接写成当前 IPC 必然 reject。

## 5. 分包实施合同

### 095-S-A：先收口恢复归属与位置（PROJECT-01 / SESSION-01）

建议一个逻辑提交，触及 App/Session/Viewer，沿用现有懒恢复：

1. 项目切换入口产生 `{projectId, canonicalRoot, generation}`；先完成旧项目保存决策，再启动新代次。所有恢复副作用在 await 后比较上下文。切换不必等所有懒标签读完，但必须取消旧恢复对树/工具/当前编辑器的写入。
2. 主进程统一路径归属服务，按路径段判定包含关系；规范化分隔符和平台大小写策略。保留原路径供显示；symlink/junction、UNC、无根临时文档策略单列，禁止全平台无条件 lowercase。旧 session key 只在确认同一项目后迁移，碰到多份旧 key 不静默覆盖。
3. `Viewer.activate/openFile` 提供“本标签加载/编辑器已就绪”的结果或 Promise。先把 active 的位置元数据放入 tab；仅在该 tab 仍是目标时恢复并消费。非活动标签继续登记不读盘；行号按当前文档范围夹取，滚动在布局就绪后恢复。
4. session schema 加 version；逐项验证 p 是非空字符串、s/l 是有限合法值。坏项跳过并汇报，其余标签、工具、树继续恢复；损坏原串留作诊断，禁止失败时立即写空会话。恢复期间抑制 renderTabs 的中间态自动保存，成功后统一保存。
5. saveNow/restore 返回 `{ok, applied, skipped, reason}`；存储异常可观测，保留旧可用版本。已存在的 settings 镜像兼容读取，但镜像失败不伪装成功。

验收：S2–S6 从失败转正确，S3-control继续通过；A慢/B快至少交错20次，旧恢复不改 B；100个懒标签只读活动文件；坏JSON、坏条目、文件缺失、quota失败各有明确结果，不覆盖原状态。真实 Windows/Electron 再测路径别名、CM6跳行/滚动、切工具和渲染过程中换项目。

### 095-S-B：草稿保险独立交付（SESSION-01，依赖090-A/B）

草稿由主进程写入 userData 独立目录，记录 schemaVersion/projectId/path/revision/baseDiskVersion/encoding/content/updatedAt。按文档串行写，先原子写快照再更新索引；不要在 renderer localStorage 放大正文。

建议起步参数：输入停止1秒落草稿、连续输入每10秒最多等待一次；单稿8MiB、总额100MiB、历史保留7天，均为待量测默认值。超限/磁盘失败明确显示“草稿备份未完成”，禁止静默剔除仍在编辑的最新 dirty 稿；历史/已保存快照可按预算清理。

正常源文件写入成功后，按 revision 确认可收回对应草稿；旧保存完成不能删除后来编辑的新稿。启动时列出可恢复稿，先比较磁盘版本，提供差异、恢复为新标签、复制或明确应用。恢复不得自动覆盖外部新版本；未知编码/大文件/二进制明确不支持。用户丢弃输入需明确清掉相应稿，关闭路径复用090-A的保存失败阻止关闭合同。

验收：独立 profile、隐藏 Electron，真正编辑后分别杀 renderer/主进程，重启能找回最后已确认快照；持续输入的最大未备份窗口符合参数；外部改盘、旧保存晚返回、写失败、恢复失败、删除/改名/路径迁移均保留可用来源。记录实际恢复 revision，不能仅看“发现草稿” toast。退出待写任务与断电 fsync 仍需单独定义保证。

### 095-P-A：插件重载按实例激活（PLUGIN-01）

建议拆成“结果/代次”与“资源/失败回滚”两个逻辑提交：

1. loadAll 返回完整读取结果或明确 per-file错误，不能把部分列表当全量删除依据。reloadId单调递增；先取代码并验证，再执行当前代次，过期结果不进入 registry。watch事件防抖并合并到单队列，运行中变化安排下一轮。
2. 每个插件有 ownerId/version/status；api.registerRenderer 返回可释放注册，并登记到该实例的暂存表。执行成功才发布；执行失败回滚该实例注册/资源，后续好插件仍可加载。读取整体失败保留上一轮可用表，返回 failed；App只对成功版本报热重载完成，部分失败汇报插件名称和原因。
3. 为插件提供 onDispose/registerDomEvent/registerInterval/registerResource 等宿主管理入口。替换/删除/失败时按实例调用，幂等且单个 disposer 抛错不阻断其他清理；异步清理设预算并报告超时。先准备候选注册，再停止旧资源并启动新实例，避免两个版本同时响应全局动作；若新激活失败，明确保留或重新激活旧版本及其失败状态。
4. 老插件返回 HTMLElement 继续适配。CSV先迁移到新注册入口作为兼容对照；未经宿主登记的旧插件全局副作用不能自动证明已释放，需标为 legacy、提示重启或要求插件迁移。不能承诺通过 new Function 回滚任意外部副作用。

验收：P1重载20次一个事件仅一次，移除后零次且宿主管理timer=0；P2失败插件不留覆盖注册，好插件仍正常；P3读失败保留旧版本且返回failed；P4只发布最新版本。另测dispose抛错/超时、重复删除、连续watch事件、同扩展优先级、老CSV兼容。真实Electron资源计数作为后续 R，不能以Map结果报告RSS达标。

### 095-P-B：预览上下文及按需 vendor（PLUGIN-01 / PERF-01）

preview 兼容 HTMLElement，也可返回 `{element, dispose}`；Viewer保存独立 previewContext，与标签/渲染代次绑定。切模式、换页、关闭、重试、插件替换时先dispose旧实例，再清DOM。提供signal与isCurrent；officeLoad await后、解析前和解析完成后都检查，避免 P5 对关闭视图继续发起解析。已开始且不可取消的库调用丢弃完成结果，仍登记最终清理，不能承诺硬中断同步解析。

格式vendor用一次Promise loader，失败清掉失败缓存允许重试；只读页面按预算缓存，dirty状态另存。DOCX的useBase64URL已避免其图片blob URL路径，保留它；对真实创建的URL、worker、媒体监听、第三方实例逐项登记，不假设各库都有destroy。大文件解析/内存预算在实测后决定是否转worker。

验收：P5关闭后读取返回不启动解析；若解析已开始，完成不改新视图，能释放所持资源。每种格式首次/再次/失败重试各测一次；20次开关真实大Office/媒体后记录全进程RSS、CPU、worker/URL计数。带独立profile且隐藏窗口，语法+DOM及相关真实UI截图检查；性能门槛沿用原大纲且先报告基线。

const fs = require('fs'), { JSDOM } = require('jsdom');
const assert = require('assert');
const source = n => fs.readFileSync('renderer/' + n + '.js', 'utf8');
const make = () => new JSDOM('', {
  url: 'https://audit.invalid', runScripts: 'outside-only'
});
(async () => {
  let d = make(), w = d.window, release;
  try {
    w.App = { root: 'A', setTool: x => w.tool = x };
    w.Tree = { setExpandedPaths: x => w.expanded = x };

      openFile: () => new Promise(r => release = r) };

      tabs: ['A/a.txt'], active: 'A/a.txt', tool: 'git', expanded: ['A']
