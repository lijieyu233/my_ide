# 大体积 HTML 只读预览

## 原因与行为

文本读取有8MiB预算。内嵌大量图片的述职HTML超过预算时，以前整个页面被拒绝；读取结果中的size也没传给标签，错误提示因此出现NaN。

超过文本预算的HTML现在直接使用隔离协议从磁盘预览，正文不复制到源码编辑器或跨IPC往返。相对CSS、图片、页面脚本与现有键盘转发继续可用，预览源不暴露IDE的preload API。工具栏显示「只读预览」及真实大小，提供「刷新预览」以重新读取磁盘；源码编辑继续沿用原预算，避免大段base64拖慢编辑器。

临时浏览意图打开这种文件时保留为独立标签，不借没有可编辑版本快照的页面替换原文档。原有小HTML仍预览当前文档内容，包含未保存修改；两种入口均保留原来的独立源、项目资源边界和释放逻辑。

普通大文本和二进制文件也正确传递大小，未知大小显示「大小未知」。

- DOM：525通过 / 0失败。新增大HTML只读打开、大小显示、不可空写、浏览槽保留旧文档，以及普通大文本不出现NaN的检查。
- `npm run test:preview`：HTML8组、映射12组、导航8组均通过；语法95个文件通过。
- `scripts/check-html-large.js`：真实隐藏Electron检查9组通过，验证脚本执行、图片/CSS、按钮交互、原文件摘要不变、刷新重读以及无法访问IDE API。
- 实际述职文件`月度述职-2026-09-11至10-11-流程进度版-v6-20261014.html`为12,304,260字节，工具栏显示11.7MB，28页述职页面正确渲染，原文件摘要保持不变。本机这次打开约350ms；属于单次本机测量。

所有自检使用独立profile，实际述职HTML只读；可选把实际HTML绝对路径作为`check-html-large.js`参数。
