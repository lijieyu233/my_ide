# 开发文档-067 · 切换文件不再闪

> 触发：用户点着左侧文件树说「这里切换文件会闪」。

## 一、两个同源的根因

两处都是**同一个错误模式：先把 DOM 清空，再去 await 异步数据** —— 中间那一帧浏览器会把
"空容器"画出来，看起来就是闪一下。

### 根因 1：左侧文件树被整体重建

```js
// renderer/tree.js —— Tree.reveal()（每次 openFile 都会调它）
select(filePath, 'file');
render();            // ← 无条件重建

// doRender()
el.innerHTML = '';   // ← 先清空
await loadDir(rootPath);        // ← 再 await …
for (const d of expanded) await loadDir(d);   // ← …一串 IPC 往返
```

切一个文件要付出：清空 → 根目录 IPC → 每个已展开目录各一次 IPC → 重新建全部行。
目录一多就是几十到几百毫秒的**空白树** —— 用户看到的"闪"。

### 根因 2：编辑区在"读盘期间"是空的

```js
// renderer/viewer.js
activate(i) → renderView()   // 此时 tab.mode 还是 null
  → viewer.innerHTML = '';
  → if (tabs[active].mode == null) return;   // ← 直接返回，容器已经空了
await loadTab(tab)           // 读盘（IPC）
  → tab.mode = 'live'
  → renderView()             // 这才画上
```

切成**已经打开过**的标签时 `mode` 已有值，是同步渲染、不闪；
切成**没打开过**的文件就必然白一段时间（文件越大越明显）。

## 二、修法

### 2.1 `reveal()`：只有"展开链真的变了"才重建

```js
let structural = false;
for (...展开目录链...) {
  if (!expanded.has(dir.path)) { await loadDir(dir.path); expanded.add(dir.path); structural = true; }
}
select(filePath, 'file');   // 高亮立刻切（applySelection 只改类名，不动结构）
if (structural) render();   // 展开链没变 → 根本不重建
```

点树里一个**同目录**的另一个文件 = 零 DOM 重建（只有一次类名切换）。

### 2.2 `doRender()`：先取数据，最后才动 DOM

```js
async function doRender() {
  // …搜索态 / 无根目录各自处理…
  await loadDir(rootPath);                 // ① 数据先齐
  for (const d of [...expanded]) await loadDir(d);
  const rows = buildRows();
  visibleRows = rows;
  el.innerHTML = '';                       // ② 到这一步才清空
  el.onscroll = null;
  for (const r of rows) el.appendChild(makeRowEl(r));
}
```

### 2.3 `renderView()`：内容没就绪就**保留旧画面**

```js
function renderView() {
  blameOn = false;
  // 内容还没加载好（mode == null）→ 什么都别动：不清空、不销毁旧编辑器
  if (active >= 0 && tabs[active] && tabs[active].mode == null) return;
  if (cmApi) { …save state…; cmApi.destroy(); cmApi = null; }
  viewer.innerHTML = '';
  …
}
```

于是切换到一个没打开过的文件时，**旧文件的内容一直留在屏幕上**，新内容读好后一次性换上去
（与 VS Code / Cursor 的行为一致），而不是先变空白再出现。

## 三、通用规律（这轮最值得记住的一条）

> **带 `await` 的重绘，一律"先把数据取齐、再换 DOM"。**
> `el.innerHTML = ''` 之后只要还有一个 `await`，中间那一帧就是空容器。
> 看到"闪"，先在代码里搜 `innerHTML = ''` 后面有没有 `await`。

配套的第二个规律：
> **能不重建就不重建。** 只改高亮、只改一个类名，就别整体重画。
> 这个项目里 `select()` → `applySelection()` 已经是这么做的（只 toggle 类名），
> `reveal()` 之前却还在无条件 `render()` —— 说明"已有轻量通道"不等于"调用方走了轻量通道"。

## 四、验证

```
npm test                240 通过 / 0 失败（新增 1 条）
electron --check-ui     277 通过 / 0 失败（+3 headless 跳过，新增 4 条）
```

「闪」没法截图证明，所以判据用 **DOM 节点身份** —— 真重建了，旧节点必然 `isConnected === false`：

```
PASS  根目录下两个 fixture 都在树里（以下断言的前提）        [root=true A=true B=true]
PASS  打开文件后树没有被重建（根行仍是同一个 DOM 节点）      [同一节点=true]
PASS  切换文件时树不重建（只换高亮，不清空重画）             [根行同节点=true 旧行仍在=true]
PASS  切换后高亮跟到新文件                                 [_ui_outline.md]
```

dom 侧同样加了一条：抓根行与两个文件行的节点引用，点完另一个文件后三个引用必须都还活着，
最后断言高亮跟到新文件（并**收尾切回 md 文件** —— 这条用例把当前文件留在 txt 上时，
后面几条按"当前是 md"写的用例会连锁失败，第一次跑就撞上了）。
