# 磁盘版本冲突与保存恢复（FS-B）

> 2026-10-01；实施前基线158f43e。沿093-F5与090-B交付，用户原有三项文档改动不纳入本包。

## 实施合同

- 读取正文与version来自同一稳定磁盘快照；version含真实目标路径、文件stat身份和原字节SHA-256，不仅比较尺寸/mtime。缺失文件携带排他新建条件，删除、同字节对象替换、链接目标变化均不能自动放行。
- 文本IPC覆盖已有文件必须携带expectedVersion，不提供永久force；在主进程同步临界段内核对、编码、原子写入、返回新version。沿107保留写途中复查。旧无条件调用不能绕过，AI/任务/项目配置等文本调用分别迁移原读取版本；二进制、DB/独立写端按原合同另行迁移。
- Viewer串行保存固定正文/格式/编辑版本，执行时承接自己上一笔成功写入的磁盘版本；失败不推进基线。watcher不在保存排队期间重载，正文相同但文件版本变化也更新。改名后的旧路径身份不能自动授权覆盖新目标。
- 冲突保留dirty和正文，自动保存不弹比较窗；标签提供持续恢复入口。比较只读，面板展示内存与磁盘全文/缺失状态；另存副本不清原dirty、不改原路径，新建排他，已有目标需明确确认本次版本。覆盖绑定查看到的磁盘版本及本次正文/路径/编辑版本，磁盘再次变化需重新比较；不隐式丢弃dirty。
- 有意义的文件/DOM/真实Electron回归覆盖同尺寸改动、mtime复原、删除/重建、链接、主进程缺版本拒绝、串行自写、确认等待期间变化、另存取消/失败/迟到新输入、自动保存/切项目闸门。渲染层后台npm test，真实check:save与通用UI截图；生产包验证加载链。

## 能力边界

应用同步IPC写段不会被另一笔应用写入穿插；外部程序不遵守此队列，最后摘要检查到原生替换仍有窗口，不能宣称跨应用原子compare-and-swap或断电持久性。硬链接拒绝沿107。任务恢复来源/容量、AI原字节undo/新建文件删除、树目录迁移/撤销、草稿恢复浏览继续按091/095/097/098推进，不以此包关闭整个FS-01。

## 交付与验收

- `file-write.readSnapshot`用前后stat/真实路径复核读取，version含目标/stat/SHA-256；缺失文件记录规范化父路径和absent。原子写入在临时文件创建前核对条件，写后重新核对本次字节才返回新基线。真实Windows大小写路径首次测试发现误拒绝，现按大小写无关路径加对象/stat/摘要核对；junction改指另一目录仍拒绝。最后检查到系统替换间的外部窗口仍存在。
- 文本IPC第四参数为`{expectedVersion: read.version}`或`{expectedAbsent:true}`；返回新version。缺条件的旧调用只允许排他创建，已有文件拒绝，不给自动force。原格式字符串/对象参数继续兼容110；旧插件覆盖需迁移第四参数。`fileVersion`给另存/导出目标提供无解码版本，超过8MB拒绝该覆盖入口。二进制IPC沿107替换保全，尚未强制旧读取版本。
- Viewer成功写入即推进磁盘基线，但只对匹配编辑版本清dirty；后续排队保存承接自己的成功基线。watcher跳过等待写入，正文相同但版本变了也推进；解码失败/二进制/过大/缺失的外部读取不能授予旧正文覆盖权。路径迁移后的旧version会安全拒绝，完整树身份/代次迁移仍待097，不静默重新读取新路径来放行dirty保存。
- 「保存冲突/保存失败」持续入口显示只读两方全文，路径/正文使用textContent。取消保留输入，Escape避开IME，Tab循环并恢复调用方焦点；动作绑定原标签/路径/编辑版本。覆盖绑定面板已读磁盘版本，不弹全局永久授权；另存副本取消/失败/迟到新输入保留原状态，已有副本目标明确确认并再次条件写入。不会清原dirty或改原路径；尚未提供一般另存后切换文档身份。
- AI write/replace在确认前固定原读取版本与格式，replace不再重新读取后为旧转换结果授权；既有文本checkpoint恢复使用写后version和原格式。新建AI文件的删除undo、原字节映射、dirty联动与请求隔离仍待098。任务按文件保存基线，坏JSON不给覆盖授权，版本失败走原本地降级；项目变更列表/提交前配置同路径串行并保留本地副本。设置导出读取目标版本并明确确认已有目标；树文本创建/删除恢复排他，恢复失败不丢撤销记录。任务加载代次/恢复浏览、Git配置schema等仍按原专项，不宣称这些模块整体关闭。
