# 连接桌面 DSH 原生会话服务

## 修正目标

用户要的是 MyIDE 侧栏使用完整 DSH 执行环境。字幕失败只是能力差异的一个例子，为每个单独任务加工具不能解决接入架构的问题。

核对本机安装包与配置后发现：ACP 是仅自动化入口，文档明确不提供 DSH 的交互提问、计划和终端呈现等界面能力。MyIDE 原先启动 acp profile，其组合只有 dsh-base 与 dsh-acp-app，默认 deepseek-official/deepseek-v4-flash。用户桌面 profile 还加载 dsh-workbuddy-connect，实际默认为 workbuddy/deepseek-v4.1-flash/high。相同安装目录并不代表同一个运行配置。

## 新链路

MyIDE 侧栏 → 本机鉴权 HTTP 连接器 → 正在运行的桌面 DSH 会话服务 → 原生 standard Agent、模型、插件、Skills 与执行循环。

反向操作链路为原生 Agent → MyIDE MCP → 当前页面/启动面板/SSH/内置浏览器/项目操作。MyIDE MCP 只增加应用能力，不替代 DSH 的通用工具与决策循环。

- 不再由产品路径启动 ACP 子进程，不以另一套配置做失败回退。ACP 注入进程分支只用于原有协议单元测试。
- 原生模型目录由正在运行的桌面宿主读取。旧 ACP 模型设置不会自动覆盖桌面默认值，用户在新连接下显式选模型后才覆盖。
- 使用 DSH workspace/create、session/create、session/prompt、session/follow、session/cancel 等原生控制面；新会话附加到 DSH 工作区，独立 DSH 可查看。
- 默认使用原生标准 Agent。原生工具失败、重试、连续步骤、上下文压缩与工具选择由 DSH 负责，不套普通助手的轮数上限。Harness 输入移除了字幕专用路线指令。
- 原生工具结果、一次性权限、交互提问由侧栏呈现；问题回答返回同一个正在等待的原生工具调用。计划/待办事件在侧栏展示，原始信息仍由 DSH 持久化。
- 明确区分完成、blocked/error、断流与取消，只有对应轮次的 completed 才报告完成。旧快照不会重新执行或混入新轮输出。
- 取消仅针对当前会话；关闭 MyIDE 断开自己的订阅和 MCP，不关闭独立 DSH 进程。
- 当前页变化仍停止旧请求。离开项目页使用分离工作区与会话，不注入后台文件。

## 连接器安装

连接器源码 dsh-native-plugin.cjs 以内容版本命名复制到用户 .dsh/myide/，向 profiles/desktop/cordis.patch.yml 添加独立配置项。保留已有 YAML 标签、插件、权限与模型；首次配置副本为 .dsh/myide/desktop-patch-before-myide.yml。已安装且内容一致时不重复写配置；更新采用新模块路径触发原生配置重载，不依赖旧模块缓存。

宿主将本机临时连接信息写入 .dsh/myide-native.json。MyIDE 仅允许 127.0.0.1 HTTP，校验 profile 与活动 PID，并通过原生 launch-token 换取授权 Cookie。连接凭据只留在主进程，不向模型、渲染层或日志输出。连接器只接受已激活、myide- 前缀的自有会话；MCP 目标也必须是本机固定路径和预期会话头。

本机实测现有桌面 DSH 在配置重载后直接提供连接器，无需杀进程。其他安装若未热加载，会明确提示打开或正常重启 DSH；不会自动终止用户 DSH。

新映射使用 dsh-native-sessions.json，旧 dsh-sessions.json 与历史 ACP 日志保留。旧 ACP 记录不伪装成原生 standard 会话，升级后应新建侧栏会话开始；同一原生会话的后续消息与重启恢复沿用真实 DSH 历史。

## 验证与边界

- 已连接实际运行的桌面宿主，只读模型目录确认 workbuddy/deepseek-v4.1-flash/high 与 standard/ptc/minimal/cordis 模式目录。
- 真实安装的原生 Web 宿主 + 隐藏 MyIDE + 确定性模型夹具 10 组通过：原生读取、未保存编辑器上下文、续聊、页面隔离、浏览器操作、错误字幕、失败恢复、原生提问、取消后续聊、读取/编辑/重新读取。原生读写实际发生在隔离文件系统，不只检查函数调用。
- 真实桌面模型额外完成隔离多步骤任务：读取订单数据、汇总、写 summary.json、重新读取并校验；实际 7 次原生工具调用，结果 A=17、B=7、grandTotal=24，模型自行发现并修正 UTF-8 BOM。验收程序另用 Node 解析确认结果正确。
- 连接器单元测试 6 组通过：URL 边界、模型保留、安装幂等与备份、工作区/MCP 绑定、错误和断流不报完成、宿主断开后重新发现且不重放命令。
- DOM 523 项、面板 46 项、资源打包 90 项、语法 92 文件通过。全套 npm test 停在 Git 测试（61 通过 / 1 失败）；隐藏通用 UI 463 通过 / 6 失败 / 3 跳过，失败为 Git hunk 与 Markdown 视觉断言，未宣称全套通过。

隔离夹具与真实模型任务证明接入及通用执行链路，不能由一次验收推出任意真实任务都会成功。当前侧栏接通原生服务及主要对话交互，不宣称已复制 DSH 的全部桌面菜单、终端视图、会话管理和所有插件界面。后续应以跨任务实测评估能力，不能以字幕专用工具的成功替代通用能力验收。
