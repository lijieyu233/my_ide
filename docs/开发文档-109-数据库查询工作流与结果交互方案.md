# 数据库查询工作流与结果交互方案

> 2026-10-01；提交基线 `ccb2d46`。承接103数据库体验建议、092事务/持久化合同，沿用089的DB-01/02与UI-01。工作区另有文本格式开发；本轮不修改这些产品文件。
> 交付为UI设计、交互与新增功能方案，未实现产品功能。原db-panel完整加载到jsdom，使用原index结构和内存桥；没有真实数据库连接、SQL写库、文件导出、Electron窗口或用户localStorage写入。

## 1. 用户任务与优先顺序

用户需要明确“在哪个库执行了什么、结果属于哪次查询、失败为什么”，然后才能放心重复使用查询或带走结果。建议 **A查询身份/状态 → B结果与消息阅读 → C历史/收藏/SQL文件复用 → D结果导出**。A/B为P1，C/D为P2候选，按每版1–2项推进；092的数据保全P0继续优先，纯阅读体验不必等待数据库服务全重构。

| 方向 | 看得见的变化 | 用户收益 |
|---|---|---|
| UI设计 | 查询区显示当前连接与执行范围；结果有名称、行数、状态；错误可回看；窄屏低频操作折入更多菜单 | 不靠侧栏和短暂toast猜结果归属，空结果也能检查列 |
| 交互 | 未决请求有反馈，迟到结果不覆盖当前查询；可固定一份结果；载入历史先看连接，不自动执行 | 连续查询能比较，切库后不把旧结果当新库数据 |
| 新功能 | 命名查询收藏、SQL文件打开/保存、当前查询结果复制/导出 | 少反复输入SQL或为了导出结果重新查整张表 |

## 3. 原模块受控观察

方法：去掉index脚本标签，加载原db-panel.js；不注入CodeEditor，走产品已有textarea回退；用公开init和原按钮处理器执行。query桥返回可控Promise，connect/tables/close为内存成功桩。断言7项观察通过，但这不证明真实CM6、IPC或数据库行为。

| 编号 | 输入/操作 | 实际观察 | 结论边界 |
|---|---|---|---|
| R1 | 发old后发new；先返回NEW再返回OLD | 两次桥调用，运行按钮保持可用；最终表格为OLD | 缺少结果代次隔离与未决操作反馈；不是实测两个后端并行执行 |
| R2 | query返回 `{ok:false,error:'near BROKEN: syntax error'}` | toast含详细原因，结果区域仅“执行失败” | 错误已有提示，但没有持续详情/定位；不声称无任何错误反馈 |
| R3 | A发查询，断开，连接B，再返回FROM_A | 状态“已连接B”，SQL结果显示FROM_A且无连接标签 | 迟到结果跨连接显示；没有证明写入了B |
| R4 | 返回columns=id/name、rows=[] | 只显示“无结果行”，没有表头 | 前端丢失已收到的列；MySQL空结果服务元数据另需真实驱动验证 |
| R5 | A执行成功后检查历史、打开原历史弹窗 | 记录仅sql/ts/ok，弹窗可载入；没有连接/耗时/行数 | 复用缺上下文；未测试真实持久化失败或敏感SQL迁移 |
| C1 | 编辑器两句SQL，只选择第二句 | 桥收到精确的`SELECT second;` | 选中执行已有，应保留；不外推到CM6/IME/多方言解析 |
| C2 | 返回NULL单元格 | 文本NULL且有db-null类 | 已有类型提示，不能当全新设计；空串/二进制/数值精度尚待验 |

静态补证：runSql和runExplain共用一个输出容器，没有requestId/connection generation；call只返回data，错误详情没有进入结果模型，桥拒绝也没有统一catch。历史注释提“Ctrl重跑”，实际onclick只载入，没有读取修饰键；方案沿实际行为，不新增隐藏自动执行。exportCsv在文件选择返回后读取可变connId/curTable，导出对象快照也要绑定；本轮未动态复现该路径。

## 5. A包：查询上下文与在途状态

查询栏显示`连接名称 · 类型 · 库/文件`与“执行选中片段/执行全文”。连接选择下拉只是选择配置，活动连接状态独立；正在连接、失败、已断开有文字，不能只用颜色。名称相同也用类型和数据库/文件区分，长路径可展开复制。

每次执行冻结`requestId / connectionId / connectionGeneration / sql / range / operation / startedAt`。连接断开/替换立即使旧代次失效；查询与EXPLAIN共用结果归属协议。当前运行入口防重复提交，pending有明确文字；切换连接可以继续但旧结果必须标出来源或移出当前输出，迟到响应只能归到自己的记录。按钮重新可用不等于操作已取消。

保留编辑器输入和上次成功结果；进行中加状态条，成功再替换可复用结果，失败进入消息区。拒绝Promise进入同一终态，详细错误可复制；不因toast消失而无法继续排查。UI显示总等待耗时必须注明口径；后端执行耗时需服务返回，不能拿前端计时冒充。

**验收**：R1/R3归属一致；运行/EXPLAIN交错；断开失败、重新连接同名配置、桥reject、切tab与隐藏面板；迟到成功/失败都不修改新连接的输出或按钮。保留C1，测试CM6与textarea两种入口。没有后端取消能力时不显示虚假的“已取消”；中止等待与查询实际终止须分别呈现。

## 6. B包：结果与消息的视觉层级

连接上下文与执行入口在编辑器上方；编辑器下方是可调高度的“结果 / 消息”，沿现有双区工具布局。结果顶部保留SQL摘要、来源连接、状态、显示行数/已获取行数/截断标记；完整总行数未知时写未知，不推导为已获取数。空结果保留列标题与0行。写入显示affected与提交状态，不能把执行成功直接写成“已经持久化”。

结果可复用，增加“固定当前结果”候选用于两次查询对比。先限制最多3份只读快照并设总字节预算；达到预算由用户选择关闭，不覆盖固定项。结果不随侧栏选择表改变标题。长值单元格有展开/复制，NULL与空字符串不同；首包不开放任意查询结果编辑，联合查询/无主键定位依赖后端身份合同。

错误消息含来源、完整原因、重试/复制。仅驱动提供可靠行列时定位SQL，缺位置只高亮来源，不按英文错误字符串猜中文行列。再运行同一SQL仍走同一执行合同；已执行写入的超时不能提供默认自动重试。

工具条主动作保留运行，EXPLAIN/历史/更多有单一名字；新列表/工具条图标用现有内联SVG体系。先保留结果网格横向滚动和列宽，窄屏合并低频项；图标模式有可见或可读标签，结果/消息切换、固定/关闭、网格复制支持键盘并保留焦点。

**验收**：R2/R4与C2，0/1/1000/1001行、长中文/空串/NULL/相同列名、二进制/大整数、深浅主题、100%/125%/150%、窄屏截图；鼠标与键盘固定/关闭后焦点明确。DOM不能证明几何和读屏，实施后跑headless check-ui并看截图。

## 7. C包：查询复用，小范围新增功能

历史升级为`版本 / 查询ID / SQL / 连接配置ID / 类型 / 库标识 / 时间 / 状态 / 耗时口径 / 行数`，继续有数量和字节上限；旧记录标“来源未知”，不猜它属于当前连接。连接删除后记录仍能查看SQL，但不自动换到同名库。历史默认仅载入编辑器；编辑器已有不同输入时，提供新查询草稿或确认替换，不把收藏点击做成自动执行。

新增“查询收藏”：名称、SQL与可选连接引用，支持改名/删除/筛选；与自动历史区分。沿项目已有“收藏”术语，不再加“书签/收藏夹”。收藏可留本机，SQL可能含业务数据，提供关闭历史/清除入口，导出连接配置时不顺带导出SQL记录或密码。

新增SQL文件复用：优先借助已有文件打开/保存基础，查询草稿明确文件路径、修改状态和目标连接；文件切换/关闭遵守101保存版本合同、文本格式支持沿110实际实施状态接入。执行固定编辑器快照，执行结束不能清掉之后输入。先一个查询草稿，不同时重造多编辑组、后台恢复和模板参数系统。

**验收**：R5旧格式迁移、同名/重命名/删除连接、历史开关、存储失败不报成功、载入不执行、未保存输入替换、SQL文件中文/编码与外部变化。光标语句执行若进入后续包，需覆盖引号内分号、注释、函数/过程和方言，不能`split(';')`。

## 8. D包：结果带走与写入边界

结果页新增复制单元格/行、导出已获取结果CSV/JSON，冻结结果ID/连接/SQL/列/行快照，显示导出范围、行数和是否截断；文件选择期间切换库/表/结果不能改目标。CSV的NULL/空串、换行/引号、编码与数值精度明确，JSON保持类型。这里导出的不是全部数据库数据，也不默认重新查询。

现有整表CSV/JSON/SQL导出保留，补目标快照和错误详情；“完整查询导出”待后端分批/取消预算定义后另包。任意SELECT结果不能默认生成可回放INSERT：目标表、列映射与不可写表达式需先有合同。导入预览、字段映射与失败清单沿092批量事务分包，不只加一个漂亮确认弹窗。

**验收**：查询快照与文件内容对拍；取消文件选择不写入；错误、权限、磁盘满保留错误；切库时导出仍用原快照；结果截断在导出前后都可知；二进制/类型策略不静默丢信息。真实临时文件与三种数据库驱动分别验证，不拿内存桥当后端验收。
