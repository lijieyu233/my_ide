# 查看优先定位与后续执行清单

更新：2026-10-04。本文是需求与执行范围，所列新增功能尚未因此交付。

## 1. 用户确认的用途

用户明确：**代码编辑不是重点，基本不会手写代码，只做查看。** MyIDE优先支持找项目、找文件、阅读代码与文档、审阅AI改动、快速启动应用及查看运行日志。

后续AI先读本文，再读[进度总览](./改进进度总览.md)和[协作分工](./改进协作分工.md)，然后进入对应详细方案。本文覆盖旧方案的优先级与实施范围；旧方案中的现状、取证和保护约束继续有效。不得因为旧文档写了P1，就自动实施多光标、缩进转换、格式化、补全或完整语言服务。

保留已有编辑能力及保存保护，不强行将整个产品改成只读。查看、查找、调整显示和定位不得悄悄改写文件；AI写入仍须遵守已有授权、版本核对和恢复规则。

## 3. 各包必须守住的交互边界

### R1：找内容后可以接着读

- 搜索结果默认留在左侧，按文件分组；点击命中打开正文，下一/上一命中无需重新搜索。继续复用已交付的布局。
- 区分文件名/路径搜索和正文搜索，显示实际搜索范围及被排除的目录；无结果、失败、取消分别反馈。
- 同名项目和文件显示可辨认路径；打开失败保留当前阅读内容，提供重试入口。
- 切项目或换查询后，旧响应不能覆盖当前结果。源码行列与预览定位无法对应时明确说明并提供源码定位，不能假跳到近似位置。

### R2：显示变化不产生文件改动

- 复用既有行号、高亮、缩放、折叠能力；只补缺失入口和已证实的配置错误。未知语言保留可读纯文本并说明支持范围。
- 软换行是视觉折行，行号仍对应源码逻辑行；切字号/换行后保留可辨认的阅读位置。选择、复制和只读查找始终可用。
- 大纲解析与正文标题规则一致；重复标题、围栏代码内的伪标题和折叠章节不能跳错。当前章节提示应随阅读更新。
- 文件/模式切换及视图恢复核对当前对象；旧建议和旧实例回调不能插入正文。修复此类正确性问题不自动扩展为新的编辑功能。

### R3：用户能审阅与恢复AI改动

- 工具执行与写入前预览明确区分；写入仍经已有main授权，展示目标路径、版本和差异。相同调用不重复执行，失败不能显示为成功。
- 变更汇总提供逐文件回看；已实施的记录与待确认预览明显区分。多文件部分成功逐项说明，不假报整批原子成功。
- 修改前保存可恢复原字节记录，包含原有格式；遇到未保存正文不得绕过缓冲直接覆盖磁盘。恢复前核对后续改动，冲突时提供比较与导出。
- 切项目、取消、关面板和服务失败后，迟到响应不能更新错误对象。已有shell命令的实际停止独立验收，不以UI停止动画证明进程已终止。

### R4—R7：完成一个日常动作

- 快速启动使用专门的测试目标和独立配置验证真实打开；程序、目录、文件、网址分别留证据。中文/空格路径及参数需逐字核对，勿改用户原有启动库。
- 专注模式有可发现的退出入口，恢复之前可见面板与宽度；键位从当前有效绑定读取，避免重复占用。
- 日志位置链接核对路径和行列；含空格、Windows盘符、相对路径、文件不存在时分别处理。未经核验的日志文字不能变成任意命令执行入口。
- Git阅读明确工作区/暂存区/提交及所选版本；查看和切换比较对象不得产生暂存、提交或改写文件。

## 4. 不进入近期实施的需求

**移出近期计划：** 多光标/矩形编辑、缩进转换、格式化预览、智能补全、完整语言服务/重构、复杂批量整理、Markdown章节拖拽重排、命名布局。131旧A包仅保留语言高亮及实例/旧建议正确性修复；旧B包仅保留显示设置；旧C/D包暂缓。定位阅读以后确有需求时，重新单独评估语言服务。

**降低优先级：** 手写草稿的完整退出/崩溃恢复、选区替换、查询历史、跨项目及重启后的位置历史、重启后误关记录、运行历史。已有保存与冲突保护继续保留；AI原字节恢复属于R3，优先级不随手写草稿一起降低。

**有实际使用再排：** 任务详情及位置引用、浏览器导航/收藏扩展、数据库查询工作流、Office导航/摘取、翻译双栏、图片旋转/连续浏览。任务筛选删除对象不一致、插件停用残留、翻译旧结果覆盖等已存在的正确性缺陷不因模块低频而取消修复。

**准备对外发布时再排：** 签名、自动更新、更多安装格式；现有包的资源完整和实际启动验收继续要求。

**目前不作为独立目标：** 任意规模必须一秒、全部特殊编码/复杂属性/链接场景全面支持。先测真实常用项目的卡顿，再按证据优化；无法安全处理的对象明确拒绝并保留原内容。

## 5. AI如何执行与交付

1. 读取仓库AGENTS.md、本文、总览、分工及本包详细方案。核对最新代码和实现记录，只认领一个可独立交付的子包；记录要改的文件，保留他人的在途修改。
2. 把所选子包写清为“具体用户操作→当前缺口→目标行为→验收点”。已有功能先复用，不把整篇历史方案当成本次全部实施范围。
3. 为UI提供实际可用入口和中文反馈。列表/工具条图标沿仓库SVG体系；显示、布局和设置需说明真实有效状态。
4. 按AGENTS.md后台跑npm test；渲染层变更完成语法/DOM检查，UI变更完成隐藏真实窗口检查并看截图。Markdown布局变更补check-live一致性检查，专项与全应用结果分开记录。
5. 使用独立userData及测试目标，清除ELECTRON_RUN_AS_NODE，测试默认隐藏、不抢焦点。无法核验的真实服务、系统输入法或读屏项标为未验，不能用模拟测试替代实际通过。
6. 每个逻辑改动只提交自己的文件，commit并push到dev，核对远端HEAD。产品代码交付按AGENTS.md重启MyIDE；遇到明确拒绝遵守限制并记录待办，不绕过。
7. 回填总览同一张表中的“已经做了什么／还没做什么／什么时候做的”；保留尚未完成项和实际功能日期。详细方案补实施范围、验证结果与限制，协作表释放占用。只写需求不标功能完成。

R8至少串行核验：打开项目→找文件→源码阅读；正文搜索→连续命中→返回；Markdown大纲→章节定位；显示调整→专注模式→恢复；AI预览→确认→差异回看→恢复；四类快速启动；日志报错→源码→返回日志；Git历史→版本比较。每条按已交付子包执行，未实现部分保留待验；源码查看、搜索、布局与版本比较前后核对文件内容未变化。
