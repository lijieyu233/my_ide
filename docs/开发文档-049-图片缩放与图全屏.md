# 开发文档 049 —— 图片缩放工具条 + mermaid 图全屏 + 项目栏样式修复

> 状态：已完成 · 体验打磨（含 2026-09-20 二次返工：滚轮语义 + 项目栏结构）

## 一、需求

1. **图片查看加放大 / 缩小按钮**：打开 PNG/JPG 等图片只能按窗口宽度看，没有缩放入口
2. **mermaid 渲染图加全屏按钮**：md 里 ` ```mermaid ` 渲染出的图被正文宽度压缩，大图看不清
3. **顶部项目栏不美观**：项目多时出现三种问题 ——
   - 挤压：按钮文字上下贴边（项目名像被切掉一截）
   - 覆盖：sticky 的「全部项目」浮在最左，滚过去的项目按钮被它压住
   - 截断：末尾按钮被切掉半截，没有任何「还能横向滚」的提示
4. **（返工）滚轮语义**：第一版把滚轮拿去缩放了 —— 那放大之后怎么上下滑动看？图也一样。
   要画布式体验：**滚轮 = 滚动/平移，Ctrl+滚轮 = 缩放**

## 二、设计

### 1. 通用缩放器 `MI.createZoomer`（renderer/plugin-loader.js）

图片与 SVG 共用一个缩放引擎，三处复用（图片查看器 / 图片全屏 / mermaid 全屏）：

```
MI.createZoomer({ stage, el, bar, initial, min, max, keys, dblclick, extra })
  → { scale, setScale, zoomBy, fit, reset, refresh, apply, destroy }
```

关键实现取舍：

| 点 | 做法 | 原因 |
|---|---|---|
| 缩放方式 | **显式像素宽高 + 滚动容器**，不用 transform | transform 不改变布局尺寸，父容器高度失效；显式尺寸可直接用滚动条/拖拽平移 |
| 居中 | 容器 `display:flex` + 子元素 `margin:auto` | `justify-content:center` 在内容溢出时会把左上角推出容器，滚动条也够不着 |
| 尺寸基准 | `el.style.boxSizing = 'content-box'` | 全局 `* { box-sizing: border-box }` 会让 1px 边框吃掉内容尺寸 → 图片被挤压 2px 且轻微变形 |
| 适应窗口 | `min(1, (stageW-slack)/natW, …)`，`slack=4` | 小图不放大（防像素化）；留余量免得「刚好放得下」时冒出滚动条 |
| **滚轮** | **纯滚轮不拦截**（交给容器原生滚动），**只有 Ctrl/⌘+滚轮才缩放** | 与画布/编辑器习惯一致（对照本项目的任务 DAG 画布：Ctrl+滚轮为锚点缩放、无修饰滚轮不劫持）。第一版把滚轮全用来缩放，等于"放大之后没法上下滑动" |
| 缩放锚点 | 以光标位置为锚（缩放前后光标下那点不动） | 滚轮缩放的手感基准 |
| 拖拽平移 | 左键：内容溢出才接管；中键：随时可拖 | 不溢出时不影响点击/选中；中键拖拽是画布类工具的习惯 |
| 尺寸未知 | 不写死像素，退回 CSS `max-width:100%`；`load` 事件后 `refresh(true)` | 图片解码完成才有 naturalWidth（jsdom 里恒为 0，也要能跑） |

### 2. 三处接入

- **图片查看器**：`MI.buildImageViewer(src, alt)` → `.img-view > .img-stage(滚动) + .img-bar(浮层工具条)`
  工具条：`－ 100% ＋ ｜ 适应 1:1 ｜ ⛶ 全屏`；双击图 = 适应 ↔ 100%
- **图片全屏 lightbox**：`MI.showImgLightbox` 复用同一套控件
- **mermaid 全屏**：`MI.showSvgFullscreen(svgEl)` 克隆 SVG 进浮层（清掉内联 max-width），
  由 `MI.attachMermaidFullscreen(container, svg)` 在两处挂载右上角「⛶」：
  - md 预览（`.mermaid-box`，plugin-loader 的 md 渲染器）
  - Live Preview（`.cm-md-mermaid`，md-editor 的 MermaidWidget）

按钮默认 `opacity:0`，容器 hover 才浮现；浮层提示文案：`滚轮滚动 · Ctrl+滚轮缩放 · 拖动平移 · Esc 关闭`。

### 3. 项目栏（renderer/index.html + styles.css + app.js）

**结构改了：把「全部项目」入口移出横向滚动容器**，不再用 sticky 浮层。

```html
<div id="project-bar-wrap">        <!-- 固定区：入口 + 间距 -->
  <button class="proj-all">▾ 14 项目</button>
  <div id="project-bar">…项目按钮（横向滚动只发生在这里）…</div>
</div>
```

- **彻底没有「覆盖」**：入口与按钮不在同一个滚动层，按钮不可能从入口底下钻过去
  （老实现的 sticky + 横向滚动 = 必然遮挡，靠留安全边距只是打补丁）
- **不再重复显示当前项目名**：入口只显示计数，高亮按钮就在旁边，同一个名字出现两遍才是上一版看着乱的原因
- **等高 + inline-flex 居中**：原来靠 `padding: 2px 10px` 撑高，中文上下被挤出边框（挤压感）
- **长名字省略号截断**：`max-width:180px + ellipsis`，不把栏撑爆
- **溢出淡出**：`scrollWidth > clientWidth` 且右侧仍有隐藏内容时挂 `.scroll-r`（mask-image），
  配合滚轮横向滚动，明确提示"后面还有项目"
- **滚动收口（关键 bug 修复）**：渲染后把当前项目按钮拉进可视区。

  ⚠ 必须用 `getBoundingClientRect()` 差值算相对位置：
  `offsetLeft` 是相对 **offsetParent（这里是 body）** 的坐标，直接和 `scrollLeft` 相减，
  会把工具栏左侧（打开项目按钮 + 入口药丸）的宽度算进去 → 滚到错误位置，当前项目反而被藏起来。
  （第一版就是这么错的：`scrollLeft` 被设成 188，当前项目被推到容器外。）

```js
const br = bar.getBoundingClientRect(), ar = act.getBoundingClientRect();
const relLeft = ar.left - br.left;
const overflowRight = relLeft + ar.width - bar.clientWidth;
if (relLeft < -1) bar.scrollLeft = Math.max(0, bar.scrollLeft + relLeft);
else if (overflowRight > 1) bar.scrollLeft += overflowRight;
```

### 自检工程化的坑（记录备查）
1. `capturePage()` 对后台/被遮挡窗口会返回**上一帧旧画面**（DOM 已变、位图不变）→ 用 CDP
   `Page.captureScreenshot { fromSurface:false }`；带 `clip` 时**必须** `fromSurface:true` 且要有超时兜底
2. **滚轮注入的符号是反的**：Chromium 内部 `WebMouseWheelEvent.deltaY` 正值 = 向上滚，
   与 DOM `WheelEvent.deltaY` 相反；`sendInputEvent` 收的是内部值 → 发送前取反
3. 合成事件（`dispatchEvent(new WheelEvent(...))`）**不会触发原生滚动/缩放**，只能验「有没有拦截」；
   真实验证必须走 `sendInputEvent`
4. **自检 profile 放系统临时目录**（`os.tmpdir()/myide-ui-check-<pid>`）：项目目录下建 Chromium profile
   会偶发 `Unable to move the cache: 拒绝访问`，甚至主进程卡死在 profile 初始化（事件循环被占住，
   连看门狗定时器都不触发）。带 PID 也避免上一次卡住的实例持有 profile 锁拖死这一次
5. 自检要有**看门狗 + 阶段标记**（`.ui-check-stage.txt` + stdout 各写一份）：卡住时能一眼看出停在哪一步
6. 「打开浮层」与「关闭浮层」拆成两步，中间截图；hover 态用 `sendInputEvent({type:'mouseMove'})` 触发
