# 长任务进度反馈（删除 / 复制 / 恢复 / 回收站）

## 问题

删一个 4078 项、109 MB 的目录，MyIDE 要先把每一项的原字节备份进恢复目录（为了能撤销），
再逐项真删。实测从建立记录到收尾 **12 分钟**，而这段时间界面**没有任何反馈**：

- 确认框一关就什么都不显示，看起来像点了没反应；
- 用户以为没生效，又点了一次删除 → 第二次被路径锁挡住，返回 `PATH_BUSY`，
  而这条提示被拼成了「删除未完成：相关路径已有操作，请等待完成」—— 读起来就是彻底失败；
- 事后只能去 `%APPDATA%\my-ide\file-operations` 翻日志才知道其实已经删完了。

## 做法

链路：worker 上报 → 主进程转发 → preload 订阅 → 右下角浮层。

| 环节 | 位置 | 说明 |
|---|---|---|
| 阶段上报 | `src/main/files/copy-journal.js` | `createService(root, native, {report})`，在扫描/备份/删除/恢复的每一项之后调 `progress(phase, done, total)` |
| 节流 | 同上 `progress()` | 阶段切换、首项、**最后一项**必发，其余按 200ms 合并 |
| 跨线程 | `src/main/files/path-worker.js` + `path-jobs.js` | worker `postMessage({progress})`；`run(op, args, onProgress)` 用 `on('message')` 分发 |
| IPC | `main.js` | `fs:path-progress`，只发给发起该次操作的渲染进程 |
| 订阅 | `preload.js` | `fs.onPathProgress(cb)` |
| 展示 | `renderer/path-progress.js` + `#sb-progress` | 右下角浮层，`pointer-events:none` |

阶段文案：`scanning 统计项目` → `backup 备份原字节` → `delete 删除` / `trash 移到回收站` /
`copy 复制` / `restore 恢复`。总数未知（还在扫描）时走不确定态动画，**不假装知道百分比**。

不给「取消」按钮：中断删除会留下「一半删了、一半还在」，比等十几分钟糟得多；
真要撤销有 Ctrl+Z 和「恢复文件操作」。

## 过程中修掉的两个真 bug

1. **`once('message')` 把进度消息当结果消费掉**
   最初实现是 `worker.on('message', 进度) + worker.once('message', 结果)`。第一条进度到达时
   `once` 注册的监听也被触发 → `run()` 直接 `resolve(undefined)`。真实后果是删除「成功」但拿不到
   `changedPaths` / `operationId`，**Ctrl+Z 的撤销记录根本不会建立**。改成单条 `on('message')`
   按 `msg.progress` 分流。

2. **节流把「最后一项」也吞掉**
   小规模操作整个跑在同一个 200ms 窗口里，所有上报被合并成一条（done=0），进度条永远停在 0%。
   现在 `done===total` 视为里程碑必发。

## 验证

- `tests/delete-journal.test.js`：新增「删除全程按阶段上报进度，总数覆盖每一项」——
  扫描阶段不谎报总数、备份/删除/恢复的末项 `done === total`、上报次数不超过项数级。20 通过 / 0 失败。
- `tests/path-jobs.test.js`：新增「进度回调穿透 worker 且只上报本操作的阶段」。
  同时覆盖上面第 1 个 bug（能拿到 `prepared.items` 与 `committed.ok` 就说明结果没被进度消息吃掉）。6 通过 / 0 失败。
- `tests/dom.test.js`：新增「长任务进度：备份/删除按阶段显示，无总数走不确定态，结束收起」，
  断言文案、计数、百分比、阶段切换、收起复位、`pointer-events:none`。528 通过 / 0 失败。
- `npm run check:js`：142 个文件通过。

### 写这个浮层踩过的坑（留给后来者）

`document` 的取法不能图省事，两轮都踩了：

1. 直接写裸 `document`：jsdom 用例里模块被 `eval` 进独立作用域后抛
   `Cannot read properties of undefined (reading 'getElementById')`。
2. 改成「加载时缓存一份 `window.document`」：用例之间页面会被重建，缓存的引用指向**旧** document，
   `getElementById` 返回 null，之后进度条再也不出现。

最终：`doc()` 每次按「当前 `window.document` → 裸 `document` → `globalThis.document`」现取，
且 `ensure()` 用 `isConnected` 校验缓存节点；取不到当前 document 时保留已有缓存而不是清空
（宁可写旧节点，也别静默不显示）。
