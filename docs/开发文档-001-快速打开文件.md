# 开发文档 001 —— Ctrl+P 快速打开文件

> 状态：已完成 · 对应 ROADMAP P0-1 · 依据《开发大纲.md》极简 + 性能原则

## 一、需求

- PyCharm 用户习惯用 "Go to File"（Ctrl+Shift+N）快速打开文件，这是日常最高频操作
- 本软件没有项目内搜索能力，打开深路径文件只能一层层点树
- 目标：全项目文件名模糊匹配，**键盘全程操作**，零鼠标

## 二、设计

### 交互（对齐 PyCharm/VS Code 习惯）
- 快捷键：`Ctrl+P`（VS Code 习惯）与 `Ctrl+Shift+N`（PyCharm 习惯）均可用
- 面板：居中弹窗，输入框自动聚焦，实时过滤
- 键盘：`↑`/`↓` 选择 · `Enter` 打开 · `Esc` 关闭
- 结果：文件名 + 灰色相对路径，最多 30 条

### 匹配算法（自研轻量评分，不引第三方依赖）
- 查询词是文件名的**连续子串** → 高分（靠前加分）
- 否则按**字符序列**允许分散匹配（如 "qk" 可匹配 QuickOpen.js）
- 文件名命中比路径命中加分
- 得分 ≤ 0 的排除

### 性能（对照大纲基线）
- 文件列表在**主进程异步递归**生成（fs.promises，不阻塞主进程）
- 渲染进程**缓存列表**：首次打开加载，Ctrl+R / 切换根目录后失效
- 上限 5 万个文件（超出截断并提示，node_modules 已排除，个人项目足够）
- 匹配为内存中线性扫描，万级文件 < 10ms

### 结构
```
main.js        fs:listAll IPC（异步递归 + 过滤 .git/node_modules/隐藏）
preload.js     window.myIDE.fs.listAll 桥接
renderer/quickopen.js   面板 + 匹配 + 键盘导航（复用 #modal-mask 容器）
shortcuts.js   Ctrl+P / Ctrl+Shift+N 绑定
```

## 三、测试计划

- dom 测试（fake fs 提供 listAll）：
