# 开发文档-064 · 项目栏恢复平铺（撤销「当前项目收成一个控件」）

> 触发：用户贴出顶栏 `📁 官方 ▾` 的截图，说「这个去掉。**你不能为了保留这个删除我的功能**」。

## 一、我上一轮做错了什么

为了压掉"顶栏那排项目胶囊和下面的文件 Tab 抢同一个视觉层级"，我做了两件事：

1. 项目 > 3 个时**不再平铺**，改成一个「当前项目 ▾」控件（显示当前项目名 + 下拉箭头）
2. 项目 ≤ 3 个时才平铺

结果是：用户有 14 个项目，**永远看不到那排按钮**。而这排按钮承载的不只是"切换项目"这一件事 ——
它同时是这些能力的唯一入口：

| 能力 | 载体 |
|---|---|
| 点一下直接切项目 | 按钮本体（`btn.onclick`） |
| 打开此项目 / 复制完整路径 / 在资源管理器中显示 | 按钮右键菜单（`oncontextmenu`） |
| 关闭某个项目 | 按钮上的 ✕ 与右键菜单里的「关闭项目」 |
| 拖拽调整项目顺序（并持久化到 localStorage） | `dragstart` / `dragover` / `dragend` |
| 新开项目自动滚入可视区 | `.proj-btn.active` 的 `getBoundingClientRect` 计算 |

也就是说，"收成一个控件"不是 UI 精简，而是**一次性删掉 5 项功能**。
用户那句话点得很准：这是**为了保留一个好看的控件，把功能砍了**。这是本末倒置。

## 二、改回来

### 2.1 恢复平铺（无条件）

`renderProjectBar()` 恢复成"每个项目一个按钮"，删掉 `PROJ_PILL_MAX` 分支与整个「当前项目 ▾」控件代码。
被删的 5 项能力全部回归：点击切换、右键菜单、✕ 关闭、拖拽排序、自动滚入可视区。

### 2.2 删掉的是「当前项目 ▾」，不是「全部项目」

两个入口的分工，这一轮明确下来：

| 入口 | 形态 | 负责 |
|---|---|---|
| `.proj-btn` × N | 项目名胶囊（平铺） | 已打开的项目，**一下点过去**；右键有完整动作 |
| `.proj-all` | 图标（叠层）+ 数量徽标 | **最近打开过但已不在列表里**的项目；完整列表入口 |

上一轮用户说过"这里两个按钮功能重复了" —— 真正重复的是**「全部项目」和「当前项目 ▾」**
（两者都只是"点开同一个项目菜单"）。撤掉的是后者。现在这两个入口**分工不同、视觉重量也不同**
（图标 vs 项目名），不会再像两个重复的项目按钮。

### 2.3 当前项目怎么标

平铺能成立的前提是"哪个是当前项目一眼看得出"，但不能用实心 accent 色块
（那正是"处处抢注意力"的来源）。改成**弱背景 + 强调色边线**：

```css
.proj-btn.active {
  background: color-mix(in srgb, var(--accent) 15%, transparent);
  color: var(--text-bright);
  border-color: color-mix(in srgb, var(--accent) 42%, var(--btn-border));
}
```

和侧栏树的选中态（弱背景 + 2px accent 左线）同一条原则：**选中要看得出来，但不要喊出来**。

### 2.4 顺手清掉一个 CSS 残留

上一轮删 `.proj-current` 的样式时，选择器列表只删了一半，留下一行悬空的

```css
.proj-btn.proj-current,

/* ---------- 侧栏上下分栏分隔线 ---------- */
#side-hsplit { height: 4px; ... }
```

即分隔线规则被挂到了 `.proj-btn.proj-current` 上。效果上无害（那个类不存在了），
但属于 CSS 里最难查的一类残留 —— 已删除。

## 四、教训

1. **"让界面更干净"不能以删功能为代价。** 一个控件的价值不等于它的像素面积。
   收掉一排按钮时，必须先把"这排按钮还承载了什么"列出来 —— 这次一列就是 5 项（含右键菜单和拖拽排序，
   它们连视觉痕迹都没有）。
2. **判据应该由用户给。** "顶栏像功能栏"是我从截图里推的观感结论，用户重的是"快速打开之前的项目"。
   这类取舍我应该先问一句，而不是直接动手。
3. 删样式时**选择器列表也要整体检查**：退掉一个类名后，容易在原地留一个悬空选择器，
   把后面那条规则的适用范围悄悄改掉。
