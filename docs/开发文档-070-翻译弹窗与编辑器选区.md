# 开发文档-070 · 翻译弹窗（居中 / 可自填）与编辑器选区

> 用户两条反馈：
> ① 「这个应该居中 且可以自己填文本 未选中文本 按快捷键也能弹出」（附翻译弹窗截图）
> ② 「当前选中非常奇怪」（附编辑器里一条 818px 的实心蓝色大块）

## 一、翻译弹窗：三条诉求，一个共同根因

`Ctrl+Alt+T` 的翻译弹窗（`renderer/translate.js` + `.tr-box`）改前有三个毛病：

| 反馈 | 改前的行为 |
|---|---|
| 应该居中 | 弹窗整体被挤偏 —— 但 `#modal-mask` 本身就是 `position:fixed; inset:0` 的居中 flex 容器 |
| 可以自己填文本 | 原文区是 `<div class="tr-src">`，**只读**，只能看选中的那段 |
| 未选中也能弹出 | `run()` 里 `if (!src) { MI.toast('请先选中文本再翻译'); return; }` —— 直接不弹 |

### 居中的根因：一个 560px 宽的"幽灵容器"

`#modal-mask` 的 HTML 里躺着一个**空的** `<div id="modal-box"></div>`，它还带着旧版 Modal 的样式
（`width: 560px; display:flex`）。`Modal.show()` 的实现是「把面板 `appendChild` 进 mask」，
于是 mask 里有两个 flex 子项：`[#modal-box 560px] [真正的弹窗]` —— 居中的是这一组，
弹窗被整体推到右边 560px 处。

`tests/dom.test.js` 里其实早有线索（「回归：Modal.show 不再依赖 #modal-box」），说明这层依赖
早就拆了，**只是那个空 div 和它的 CSS 一直没删**。已删（HTML + CSS 各一处），并加守卫：

```
PASS  弹窗在遮罩里水平居中   [偏差=0.0px]
PASS  弹窗在遮罩里垂直居中   [偏差=0.0px]
PASS  遮罩里只有弹窗一个子节点（遗留空容器已删）   [children=1]
```

> 教训：`Modal.show` 把 mask 当居中容器用，**mask 里就不该有任何常驻子节点**。
> 一个"看起来无害"的空 div，在 flex 布局里就是一个 560px 的占位。

### 另外两条

- 原文区 `div` → `textarea`（`.tr-src` 重写：可聚焦、可换行、`resize: vertical`、聚焦时 accent 边）。
  未选中文本进来就是空框 + 占位文案，光标已聚焦，直接打字 / 粘贴即可。
- `run()` 不再因为"没有选中"而 return：照常开框。底部加了「翻译」按钮和 `Ctrl+Enter` 快捷键
  （原来只有选中文本这一条触发路径，填了文本也没有办法翻）。
- 选中文本的老路径保留：预填原文 + 自动翻译，少一次点击。
- 译文区加了空态占位（`「译文会显示在这里」`）和翻译中的状态色；「复制译文」在空结果时提示而不是复制空串。
- Esc 在输入框里也能关（`box.dataset.selfEsc`），✕ 与「关闭」不变。

### 自检怎么验的

`llm:chat` 在自检里也打了桩（返回 `译:<原文>`）—— 不然没配 key 会报错并弹设置页，步骤就跑偏了。
翻译配置 `myide-translate-cfg` 加进了 main.js 的"自检收尾还原持久化键"列表。

踩坑一次：步骤结尾把弹窗关了，产物截图就只剩背景（060 轮踩过的同款坑，技能里明明记了）。
已按惯例拆成「开 / 关」两步，中间留给主进程截图。

## 二、编辑器选区：818px 的"大蓝块"

截图里那条 818px 的实心蓝块（`#2d4f6b` = `--bg-selected`）不是 bug 渲染，是**设计选择不对**：

```js
// md-editor.js
'.cm-selectionBackground, &.cm-focused .cm-selectionBackground': { backgroundColor: 'var(--bg-selected) !important' }
```

CodeMirror 画多行选区的方式是**每一行画一条**（含行尾空白，空行也是一整条）。
用一个不透明的重色去画，几行叠起来就是一大块蓝色平板 —— 和全应用
「选中态减重（弱背景 + 2px 强调线）」的设计语言完全冲突。

改成主题强调色的半透明 tint：

```js
{ backgroundColor: 'color-mix(in srgb, var(--accent) 32%, transparent) !important' }
```

顺带把走原生 `::selection` 的地方（正文预览 / AI 消息 / 输入框）也统一成同一个 tint ——
操作系统默认蓝在暗色主题里同样突兀。

```css
::selection { background: color-mix(in srgb, var(--accent) 32%, transparent); }
```

## 内置浏览器选区右键翻译（2026-10-15）

内置网页为独立的WebContentsView，宿主的DOM右键菜单无法处理其中的选区。新增 `browser-context-menu.js` 绑定网页原生context-menu事件，提供翻译选中文本、复制、编辑、全选及导航菜单。翻译只传入该次选区纯文本，通过主进程推送和preload回调进入 `Translate.run`，复用现有服务地址、模型、目标语言及自动翻译流程；未配置时打开翻译设置。密码输入不提供选区翻译。

翻译弹窗继续使用现有Modal，网页视图在遮罩显示期间临时摘下，关闭后挂回同一实例，不跳转网页、不丢登录态。新增模块纳入构建资源清单、资源缺失检查、语法检查与浏览器单测。隐藏生产窗口核验真实网页选区、原生菜单点击回调、IPC、翻译请求原文/目标语言、译文显示、配置缺失与关闭后恢复；隐藏窗口没有OS右键焦点，因此向真实context-menu入口注入网页选区参数，popup替换为接收器，测试不弹桌面菜单、不调用实际模型。


## 语言、多厂商配置与网页快捷键（2026-10-15）

翻译弹窗增加原文语言（默认自动检测）、目标语言（常用建议及自定义输入）和已保存服务选择。切换语言或服务自动重新翻译；每次请求带版本号，旧请求、旧弹窗及原文编辑后的迟到响应不会覆盖当前结果。错误响应不能复制为译文。

设置页支持多配置的新增、命名、切换、删除、独立Key/模型和连接测试；厂商预设复用AI助手现有OpenAI兼容厂商列表，填入地址和候选模型，同一厂商可添加多份。页面内切换保留编辑草稿，点击「保存全部配置」持久化并设为当前配置。原单服务格式按需无损迁移，保留原地址/Key/模型/目标语言，Key输入改为密码框。

原生网页焦点下转发翻译快捷键，默认Ctrl+Alt+T，生效键位来自Shortcuts.effectiveCombos，自定义、冲突和解绑都同步主进程。网页的选区与宿主选区独立：从网页读取普通输入框选区或DOM选区，密码字段不取值；无选区传空原文打开输入框，不拿编辑器旧选区代替。隐藏真实窗口脚本覆盖旧配置保留、多厂商保存、语言和厂商切换、默认/改绑快捷键、无选区及页面恢复，翻译请求打桩不调用真实服务。


## 厂商下拉选择直接作用于当前配置（2026-10-15）

原厂商下拉只决定新增配置的模板，选择OpenAI后当前表单仍显示DeepSeek，造成无效操作的观感。现在明确标注「当前配置的厂商」，选择后直接填入当前草稿的厂商地址、默认模型及候选模型；跨地址清空旧Key，避免凭据混发，保存后持久生效。选择自定义保留原字段并记住自定义模式；已有配置按地址识别厂商。新增配置独立另存，不再是应用厂商选择的必经步骤。隐藏窗口新增断言检查选项与字段一致、连接测试实际参数、保存前旧配置保全、保存后恢复以及自定义模式保留。


## 厂商切换保留各自Key和模型（2026-10-15）

上一节跨厂商清空当前Key的交互改为按厂商保留：当前配置内部维护providerConfigs，切换前记住该厂商的名称、地址、模型、Key，切回恢复该厂商完整草稿。保存全部配置后，关闭设置并重开仍能恢复各厂商字段；首次未配置厂商使用预设和空Key，其他厂商内容保持。自定义模式独立保留，厂商使用自定义代理地址也仍归于已选厂商。测试连接和实际翻译只取当前厂商字段，不携带其他厂商的配置集合。真实窗口核验DeepSeek/OpenAI往返、各自Key恢复、自定义地址与模型、保存重开及实际请求参数。

## 配置即时生效与设置返回（2026-10-15）

此前切换服务、厂商或编辑字段仅改页面草稿，关闭设置或切到其它分类即丢失；连接测试使用草稿，而翻译使用已保存配置，两者可能不同。现在字段输入、服务/厂商切换、新增和删除都立即保存并设为当前服务；测试连接先保存同一份配置。各厂商仍分别保留自己的 Key、模型和地址。「保存全部配置」保留为显式确认入口。

翻译弹窗进入设置时保留原文和结果，临时隐藏自身，避免两个面板占用同一 flex 容器而并排挤开。设置关闭后刷新服务列表和目标语言；配置确有变化才重新翻译，并使旧响应失效。

`tests/translate.test.js` 覆盖不点保存、关窗重开、多配置切换和旧响应隔离。`scripts/check-browser.js` 在独立用户目录的隐藏生产窗口中，使用生产 `llm:chat` 和本机 HTTP 服务实际核对请求路径、模型、Authorization、目标语言、译文和重新加载后的配置，另检查设置居中及原文保留；此用例没有替换翻译 IPC。后续原有浏览器用例仍使用翻译桩，不访问外部服务。

## 弹窗背景与统一 Esc 取消（2026-10-15）

原生网页视图暂时让位时，宿主现在以网页当前帧保留背景，避免翻译、设置、菜单弹出后网页区域变空，尤其是浏览器全屏时。网页实例继续保留；弹窗全部关闭后恢复同一个实例，不导航、不重载。画面只在浮层期间用于背景，不写入磁盘，关闭或切换工具时移除。隐藏窗口的首次截图可能为空，短暂重试获取已绘制帧，并设时间预算；主进程与渲染层分别核对显示代次，防止迟到截图隐藏已恢复的网页。地址栏建议不重新抢焦点，避免建议被 focus 事件收起。

工作台弹窗统一在捕获阶段处理 Esc，输入框、textarea、select、按钮和正文均可取消最上层。优先走已有取消/关闭按钮，确保确认与输入 Promise 正常结算；快捷键录制期间 Esc 先取消录制，输入法选词期间不关闭面板，按住 Esc 的重复事件不连带关闭下层。已有清理与焦点恢复仍由各面板负责。原生 HTML dialog 和系统文件/确认窗口沿用自己的取消机制。

隐藏生产窗口检查输入焦点矩阵、翻译→设置→确认的逐层退出、确认 false / 输入 null、改键取消、全屏背景截图、原页面表单与滚动保持，以及人为延迟截图后提前关窗的竞态。截图由真实原生网页捕获，未替换为静态测试图片。
