# 标签身份与预览固定交互方案

> 2026-10-01；产品基线 `a77ba36`，本轮viewer/shortcuts/session源码未改。承接103-U2/F2和105导航合同，关联089的EDIT-01、UI-01与SESSION-01。
> 交付为取证与后续方案，未修复生产标签页，也未实现预览标签、固定或关闭重开。工作区并行文件写入改动不属于本轮交付。

## 1. 用户任务与先后顺序

用户需要知道“正在编辑哪份文件”，浏览文件时少堆标签，常用文件保持可见，误关后能重新打开。新增预览/固定之前，应先让标签高亮、正文、保存目标与会话记录使用同一身份；只增加图标会放大现有身份漂移。

建议四包：**A身份与关闭一致性 → B同名辨识和键盘入口 → C可选预览/固定 → D关闭重开**。均P1，每版1–2项。B的路径文案可以与A并行准备；C依赖A和101保存合同，D依赖文件身份/位置恢复。不在首包加入多编辑组、自动按标签数量关闭文件或改掉现有Ctrl+Tab习惯。

### 3.1 隐藏Electron与真实CM6对拍

在独立userData中创建`show:false / skipTaskbar:true`的1100×750 BrowserWindow；原index移除自动脚本后依次加载生产CM6 bundle、code-editor.js、viewer.js。文件服务/App仍是内存桥，未用用户项目IPC。

R2和R3按同样步骤复现；拖动坐标使用真实标签getBoundingClientRect，鼠标事件仍为页面合成事件。真实CM6 dispatch输入`EDITED-A-REAL-CM6`后，active/highlight=B、CM绑定/正文=A，只有A dirty，writes=0。进程退出0，报告包含前后顺序、active、CM绑定、状态、正文与dirty身份。

这比编辑器API桩强，但仍没有验证原生鼠标最终click补发、焦点/选区绘制、DPI/读屏、真实写入路径或全应用生命周期。生产修复必须覆盖拖动释放到空白/窗口外与最后click，不能只让合成序列通过。

## 4. A包：身份、加载与批量关闭

### 4.1 同一身份贯穿视图

建议保留现有tab.id，活动状态改为activeTabId，显示顺序独立存id列表。DOM、菜单回调、保存、drag source/target、关闭队列和位置历史都按id解析，不捕获会在删除/排序后漂移的数组下标。改名只变path/label，不生成新tabId；未来多编辑组还需独立documentId，当前不因此引入双组。

必须成立：

- 重排只改变顺序，活动文档、CM实例绑定、光标/撤销、保存目标和状态栏保持原身份。
- 关闭后台标签保持活动文档；只有关闭活动标签才按确定的相邻策略选后继，无后继选前一个。首包保留相邻策略，MRU另排。
- 拖动的取消、pointercancel、Esc、窗口失焦和DOM重绘清理监听；结束后的click按id解析或明确抑制一次，不能用开始拖动时的index激活另一文件。
- dirty重绘标签、主题切换与排序同时发生时，不能遗留指向已卸载节点的dragState。
- 空工作区关闭最后标签后，焦点回稳定打开入口；后台关闭不抢Editor焦点。

当前保存快照已绑tab对象，不能为“统一身份”移除101的排队/版本检查。R3/R6中编辑回调仍写回A，因此修复应确保所有入口一致，不以切换高亮或缓存一个旧index掩盖问题。

### 4.2 加载期间的正文归属

保留旧画面避免闪白，但必须显示“正在打开B，当前仍显示A”的明确状态，或在新标签区显示加载占位。生产设计选其一，不能让B标题与可编辑A正文无提示并存。

加载结果带tabId/path/request generation；提交前检查标签仍存在、路径/代次仍匹配。读完B后只为仍有效的B更新；切到C、关闭B、预览槽换成C后的迟到结果不覆盖当前视图。若保留A编辑能力，保存/编辑指令明确绑定可见A；如果冻结输入，读完/失败后恢复焦点，不能吞IME尾段或丢用户输入。

新预览替换必须先完成候选B读取/格式校验，再提交替换A；失败仍留A并显示B失败。不能先删除A后发现B无权限。dirty、保存中、未决确认或尚未恢复的草稿永不自动替换。

### 4.3 批量关闭的集合提交

一次操作固定目标tabIds与revision，展示一份未保存列表和统一决策，避免循环closeTab同步生成多个确认。选择保存并关闭、放弃并关闭或取消；具体文案与现有Modal统一，不另写多个同义动作。

在决定前不关闭干净标签。保存逐份执行既有服务；只要任一失败、路径改变或等待中又输入，就不提交关闭集合，展示逐项结果并保留标签。先前已成功的磁盘保存保留，不能声称“所有保存已回滚”。用户可重试失败项，不能自动循环保存追赶一直输入。

放弃修改须明确作用于该次已确认版本；确认后发生新输入时再次保留并提示，不能悄悄放弃后来内容。单标签也应复核确认版本：101已经修复“确认索引误关”，并不自动证明“确认期间新输入已保护”。此分支本轮未取证，仍作为H待验。

项目切换closeAll由调用方负责保存闸门，保持101合同；它不是用户菜单的无条件强制关闭API。关闭完成后只更新一次活动身份/焦点/会话，逐文件保存结果仍逐项展示。

## 5. B包：可见辨识与键盘工作流

同名标签按最短可区分父路径显示，例如`src/readme.txt`、`docs/readme.txt`；不同项目/磁盘根无法仅靠父路径区分时再补项目/根。路径归一化和大小写语义复用文件服务，不通过label去重。最终省略后的可见标签也要检查冲突，不能计算出唯一全文后再次截成相同字符串。

唯一文件保留现有简名/中段省略。dirty、固定、预览/加载/失败各有独立标记，避免一个圆点承载多种状态；图标沿用SVG规范，右键菜单保留仓库emoji前缀惯例。

复用已有“全部打开的标签”列表，补文件/路径、当前项、dirty/固定状态与键盘过滤，不新增第二个同用途列表。文本标签与辅助名称从同一描述生成；完整路径可用键盘打开详情/复制，不能只hover查看。

采用有语义的tablist/tab/tabpanel与单一焦点入口；左右键移动标签焦点、Enter/Space激活，读盘有可见延迟时优先手动激活，避免仅浏览焦点就反复加载重文件。Tab离开标签栏进入正文；关闭按钮使用独立可访问控件，避免button嵌套button。Shift+F10打开上下文菜单，关闭后焦点落在逻辑后继或空工作区入口。

Ctrl+Tab继续按当前物理顺序，设置绑定保持；新增MRU选择可以接105命令系统，在用户明确选择后再绑定快捷键。它与105“返回/前进位置历史”分开：前者切文件，后者回文本位置。

## 6. C包：预览、保留、固定

把保留策略与dirty、savePending、loading/error、正文mode正交存储，不能建一个把所有组合塞进去的status枚举。建议`retention:preview|regular`和`pinned:boolean`；固定必然转regular，但固定不是只读、不是保存成功，也不抹dirty。

| 用户动作 | 状态转移 | 必须保持 |
|---|---|---|
| 开启预览标签后，单击新文件B | 当前工作区最多一个preview槽；安全时B替换A | A干净/无在途请求；B读取成功才提交；失败留A |
| 双击文件/标签或执行“保留标签” | preview→regular | 内容、撤销、选区和文档身份不重建 |
| 第一次用户编辑或开始明确保存 | preview→regular | 转移先于异步替换/保存，输入不能被下一次浏览顶走 |
| 执行固定/取消固定 | regular+pinned / regular+unpinned | 固定区域稳定、dirty独立；取消固定不变回preview |
| 预览关闭或新预览替换 | 仅移除干净且允许替换的槽 | 外部修改/确认/草稿版本依赖先处理，旧读取失效 |

默认保持旧习惯：未开启预览时单击仍开普通标签。开启后文件树与快速打开的行为应有一致说明；搜索结果/导航来源显式传open intent，不让任意内部openFile自动改成preview。已打开的普通/固定文件只激活，不降级为preview。

固定区域拖动有明确边界；拖到普通区域是否取消固定必须显示反馈并统一鼠标/命令行为，首包可限制跨区拖动。省略固定标签名称为小图标暂不做，仍需区分同名文件。

批量默认关闭入口明确命名为“关闭未固定标签”或“关闭其他（保留固定）”；真正“关闭全部（含固定）”须说明范围，仍走dirty决策。单独关闭固定标签是明确用户动作，可允许，不额外制造与dirty无关的反复确认。

会话只持久化regular/固定与必要位置；preview是否恢复需独立策略，首包不恢复preview。兼容旧session结构，未知新字段安全回落；草稿依旧独立保全，不能为了保存固定信息把dirty正文偷偷塞进现有会话。

## 7. D包：重新打开关闭的文件

用有界栈记录成功用户关闭的path/document identity、项目、正文视图mode、文本位置和固定状态；关闭失败/取消不入栈，预览替换和项目切换不当作用户误关记录。批量关闭可以作为一组，首包可逐个重新打开并明确顺序。

重新打开读取当前磁盘版本并复用已打开文档；改名/删除/无权限提供可回看原因。复用105位置恢复合同，位置过期时明确回落；不能重放此前明确放弃的dirty正文，也不能承诺未保存内容恢复。那属于103-F5草稿/本地历史，必须有独立来源与版本确认。

Ctrl+Shift+T已用于主题，不能照搬VS Code默认键。首包从105命令面板/标签菜单执行，可自定义键位时展示冲突；不自动迁移主题用户绑定。MRU、最近文件、关闭重开和位置历史分别有模型，不共用一个“最近”数组。
