# 081 · 提交面板三处视觉错位修复（缩进 / 对齐 / 标题重复）

> 用户拿三张截图报的：①「文件和文件夹缩进怎么一样」②「换个视角更离谱，上层的缩进还更高」
> ③「这里还重复了」。三处都是**能用数字判定**的结构问题，所以每条修复都配了断言。

## 1. 缩进：层级根本没体现出来（截图 ①）

**现象**：树形视图里，父目录 `build` 与它的子文件 `icon.png`，**复选框在同一列**（实测都在 x=44），
只有名字差 22px（因为文件行多一个徽章）。看着就像"平铺"而不是树。

**根因**：目录行与文件行各自拼列，但列组成不同：

| 行 | 列组成 | 名字相对左边距的偏移 |
|---|---|---|
| 目录行 | `caret(10)` + 复选框(13) + 名字 | 43 |
| 文件行 | 复选框(13) + 徽章(22) + 名字 | 57 |

再加上左边距公式还差 2px（目录 `8+depth*14`、文件 `10+depth*14`），结果子文件的复选框正好被"抵"回父目录那一列。

**修法**：定一条铁律 —— **只有 `depth` 决定左边距**，列结构用固定宽度的占位元素统一：

```
缩进 = 8 + depth*14        ← 目录行与文件行用同一个公式
目录行 = [缩进] caret(10) · 复选框(13) · 徽章占位(16) · 名字 …
文件行 = [缩进] caret占位(10) · 复选框(13) · 徽章(16) · 名字 …
```

于是：同层的目录名与文件名从同一个 x 起（偏移恒等于 95），子级永远比父级深一级（刚好 14px）。

⚠ 顺带踩到的一个细节：全局有 `* { box-sizing: border-box }`，所以徽章写 `min-width:16px + padding:0 3px`
的**实测总宽是 16px**，而占位写 22px 就会差 6px。现在两处都写死成确定值（`.badge { width:16px }`
与 `.badge-spacer { flex:0 0 16px }`），并在注释里互相指认 —— 改一个必须改另一个。

## 2. 平铺视图：文件名参差不齐（截图 ②）

**现象**：平铺视图每行是 `父目录/ 文件名`，父目录前缀宽度随字面变化（`build/` 29px、`plugins/` 40px），
于是后面的**文件名各自起始在不同 x**，看着就是"有的更靠右有的更靠左"。

**修法**：父目录前缀改占**固定宽列**（`flex: 0 0 72px` + 省略号），所有行的名字从同一个 x 起
（自检实测 12 行全是 x=181）。

⚠ 这里还踩了第二个坑：**顶层文件没有父目录**，如果它不画这一列，名字就会比别的行少 78px 跳到左边
（第一版自检立刻报出 `xs=181,103,181,…`）。所以"要不要保留父目录列"必须由**整份变更列表**统一决定
（`flatNeedsDirCol()`：只要有任何一个文件带目录，所有行都留这一列，顶层文件留空列）——
按"单个文件有没有父目录"决定，就还是会参差。另外平铺行也补上 caret 占位，与目录行共用同一套列宽 ——
否则同一层级的"目录名"与"文件名"会差一个 caret 列宽（那正是截图 ① 的另一种形态）。

## 3. 差异视图：文件名写了两遍（截图 ③）

**现象**：编辑区差异视图顶部一行是 `plugins/README.md  未暂存（工作区 vs 暂存区）  +12 / -8`，
紧接着又一行 `plugins/README.md  未暂存` —— 同一个文件、同一个侧别，重复。

**根因**：`renderDiffView` 画了 `.diff-head`（路径 + 侧别 + 行数），而它调用的 `buildDiffTable`
**总是**再画一个 `.diff-file-title`（M3 加侧标记时加上的）。

**修法**：`buildDiffTable(r, act, { hideTitle })` —— 只在**单文件**视图里跳过表格标题。
⚠ 不能一刀切删掉：M3 的"同一个文件已暂存 + 未暂存两块并排"必须保留各自的标题与侧标记
（否则两块看不出谁是谁），多文件堆叠同理。dom 测试里两条断言分别守着这两种情况。

## 4. 验证

- 自检新增 5 条**可量化的**断言（都在提交窗口那一步，跑的是真实渲染 + `getBoundingClientRect`）：

  | 断言 | 实测 |
  |---|---|
  | 平铺：所有文件名起始 x 一致 | `181,181,…`（12 行全相同） |
  | 树形：子文件复选框比父目录复选框右移一级 | `76 → 90`，Δ=14 |
  | 层级递进：文件名比父目录名更靠右 | `117 → 131`，Δ=14 |
  | 列结构一致：目录行/文件行的名字偏移相同 | `95`（73 行样本只有一个取值） |
  | 单文件差异：文件名只出现一次 | 重复标题 0 个 |
  | 多文件/双区仍按文件分块 | 2 块各有标题 + 侧标记 |

  最后一条"列结构一致"是关键：**不依赖真实仓库里恰好凑到两个同层的行**（我第一次就这么写，
  结果比到了两个不同 depth 的行、误报 28px —— 这类断言必须验"结构不变量"，不能靠取样）。

- `npm test` 56 + 255（+2 dom：行结构占位、单文件不重复标题 / 双区保留侧标记）
- `electron . --check-ui` **404 通过 / 0 失败**

## 5. 顺手记下的两条方法论

1. **视觉 bug 先量化再改**：这次用 Python 手解 PNG（本机没有 PIL）量出"复选框同列、名字差 22px"，
   才定位到"列组成不同"这个真因；只凭"看着没缩进"改 padding 会越改越乱。
2. **修完要有断言，且断言要验不变量**：位置类断言尽量写成"结构恒定"（偏移值唯一），
   而不是"拿两个样本比" —— 后者在真实数据里很难凑齐，还会误报。
