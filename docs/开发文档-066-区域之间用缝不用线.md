# 开发文档-066 · 区域之间用「缝」，不用「线」

> 触发：用户看过上一轮（阅读区收窄）之后给了一句很准的判断：
> 「各个区域的连接太紧凑了，一个个方块只隔一条线，所以看起来暖 / 缺乏区分。」

## 一、这句话拆开是什么问题

上一轮我把区域之间的边线**弱化**了（`--border-pane` 16% → 11%、标签线改 `text 8%`），
用户的判断是对的：线一弱，区域之间就只剩"一条线"，几块面板粘成一片。

关键差别在**"线"和"缝"读起来不是一回事**：

| | 观感 |
|---|---|
| 1px **浅色**描边（`color-mix(text 11%)`） | 像"边框"—— 区域还是紧挨着，只是被框住了 |
| 4px **深色**条（比所有区域都暗） | 像"间距"—— 区域之间真的空开了，各自成块 |

像素实测（同一处，改前 vs 改后）：

```
内容区 → 状态栏（x=700 纵向）
改前: 21 21 21 21 21 21 | 24 | 12 12 12 ...     ← 1px 亮线(0x24=36)，比两侧都亮
改后: 21 21 | 0f 0f 0f 0f | 12 12 12 ...        ← 4px 暗缝(0x0f=15)，比所有区域都暗
```

## 二、改法

新增两个变量：

```css
--seam: 4px;                                                   /* :root */
--seam-color: color-mix(in srgb, var(--bg-title) 85%, #000);    /* body（派生变量，含 var()） */
```

⚠ 缝色刻意**比最外层 chrome 再暗一档**：第一版直接用 `--bg-title`，实测与工具窗口只差 3 级，
看着仍像一条描边。压暗后与工具窗口差 **8 级**，才读得出"缝"。

四道缝（顶 / 底 / 侧栏分隔线 / AI 助手 / 两条工具条）全部改成同一来源：

| 位置 | 改前 | 改后 |
|---|---|---|
| 顶栏 ↔ 内容 | `#toolbar { border-bottom: 1px solid var(--border-pane) }` | `#main { border-top: 4px solid var(--seam-color) }` |
| 内容 ↔ 状态栏 | `#statusbar { border-top: 1px solid var(--border-pane) }` | `#main { border-bottom: 4px solid var(--seam-color) }` |
| 侧栏 ↔ 编辑区 | 侧栏 1px 描边 + 分隔线 4px `--border`（两条叠着）| 只留分隔线，宽度 `--seam`、色 `--seam-color` |
| 编辑区 ↔ AI 助手 | `1px solid var(--border)` | `4px solid var(--seam-color)` |
| 左侧工具条 | `border-right: 1px solid var(--border-pane)` | `border-right: 4px solid var(--seam-color)` |

**上下缝挂在 `#main` 自己身上**（它是 `flex: 1`），不加到 `#toolbar` / `#statusbar` 的固定高度上 ——
`height` + `border-box` 会把里面的按钮压扁。

净效果：区域之间的线条数没增加，但每一处都从"线"变成了"缝"。

## 三、验证

```
npm test                239 通过 / 0 失败
electron --check-ui     273 通过 / 0 失败（+3 项 headless 跳过）
```

新增 4 条断言（把"看起来分开"变成可验证的量）：

```
PASS  区域之间的缝 = 4px 深色条（不是 1px 浅色描边）        [上下=4px/4px 色=color(srgb 0.06 0.06 0.06)]
PASS  缝比所有区域都暗（这才读起来是"间距"）                [缝=0 最外层底=18]
PASS  四道缝同宽同色（顶/底、侧栏分隔线、AI、工具条）        [侧栏=… AI=… 工具条=…]
PASS  顶栏 / 状态栏 / 侧栏不再有浅色描边（靠缝 + 明度分层）   [statusbar=none toolbar=none sidebar=none]
```

原来的「主分界线不再是近黑」那条断言随设计一起作废（它测的是被移除的描边）。

## 四、过程中的两个事故（都值得记）

### 4.1 区间替换误删 1160 行

为了让断言口径跟上缝色，我用「找到起点字符串 → 找到终点字符串 → `s[:i] + new + s[j:]`」做替换。
终点在文件里的实际位置比预期远得多，结果**静默删掉了 1160 行**（文件 1656 → 497 行，
`projectBar` / `imageViewer` / `themeCrimsonRevert` 等 22 个自检步骤整段消失）。

`node --check` 通过、CSS 也没问题，所以看不出来；现象是自检里 **21 个步骤"注入失败"**。

**对策（已写进技能）**：区间替换一律加**跨度与行数校验** —— 替换前后行数差必须在预期范围内，
跨度超过阈值直接中止。能用精确字符串替换就不要用索引切片。

### 4.2 自检步骤污染了下一轮的起点

「正文阅读版式」那步为了让截图看得出收窄效果，把 AI 助手收了起来 —— 而 `setAiOpen`
**会把状态写进 localStorage**。于是**下一轮**自检启动时 AI 助手是关的，
`chrome` 步骤立刻报「侧栏标题 / 标签栏 / AI 助手标题 三行等高 [30 / 30 / 0]」。

**对策**：自检收尾还原的持久化状态从 2 个键扩到 5 个 —— `myide-projects` /
`myide-recent-projects` / **`myide-ai-open`** / **`myide-md-mode`** / **`myide-side-split`**。
规律：任何一步动了会写 localStorage 的开关，收尾都要还原，否则问题会在**下一次运行**才出现
（比当次失败难查得多）。

## 五、可调项

缝宽只有一个来源 `--seam`（现在 4px）。如果还想更"开"一点，把它调成 6px 即可 ——
四道缝会一起变，不需要逐个改。
