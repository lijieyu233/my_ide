# 会话历史：同项目多会话与「运行中」标识

用户反馈（2026-11-01）：

> 还有同一个项目好像不能开两个会话，这也不行。要在这里加标识，哪个会话在运行中。

## 事实：能并行，但看不见也回不去

先确认底层能力没问题。用探针跑「A 会话在跑 → 新建 → B 会话也开跑」：

```
[P] calls= 2  aborts= 0          ← 第二个会话没有中断第一个
[P] A.sid= s-57a8…  B.sid= s-4092…  same= false   ← 两个不同会话
```

`ai-owner-router` 按 `[host,'dsh',rootId,sessionId]` 分配运行归属，同项目多会话本来就是支持的。

真正的问题是**历史列表的数据源**：

`persistSession()` 只在一轮对话结束（或挂起）时写 localStorage。所以第二个会话正在跑的时候，
`loadSessions()` 里根本没有它 —— 历史下拉只有一条（甚至一条都没有），用户从历史切走之后
**没有任何入口能切回来**。表现就是「同一个项目只能开一个会话」。

## 改动

1. `sessionsForHist()`：历史列表改为「已落盘会话 + 仍在运行但尚未落盘的会话」。
   运行中的会话按其 sessionId 合并，标题取当前会话的 msgs 或后台记录里的视图；
   标 `virtual:true`，只用于展示与切回，不写回 localStorage（落盘仍由 `persistSession` 负责）。
2. `runningSessionIds()`：前台 `currentRun` + 所有 `backgroundRuns` 里 status=active 的会话。
3. 列表行三态：
   - **运行中** —— 左侧绿点（呼吸动画，`prefers-reduced-motion` 下关闭）+ 淡色底 + 右侧「运行中」文字；
   - **当前查看** —— 左侧 accent 竖线（原有）；
   - 普通历史 —— 右侧相对时间。
4. `openSession(id)` 命中后台记录时走 `restoreBackgroundRun({sessionId})`，把后台那份整块接回前台，
   而不是 replay 已落盘的旧正文 —— 后者会把后台已累积的输出丢掉。接回前先把当前前台会话挂起，
   避免它的 DOM 被顶掉。
5. `onPageChange()` 不再 `detachRun()`（上一轮只删了 stopRun 回退，没删这个）。
   侧边栏工具只是换主区视图，会话本身没变；把它搬进离屏容器再跳过恢复，
   面板就被搬空、看起来像「开了个新对话」—— 这正是用户看到的第二个现象。
   会话级迁移只在切项目时发生（`beforeProjectChange` / `onProjectChange`）。
