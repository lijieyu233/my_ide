## 1. 证据范围与参考项目

通过 Node + 仓库安装的 jsdom，以 outside-only 加载完整 `tasks.js/search.js/settings-store.js`，只替换文件/设置 IPC 桥和宿主入口。任务模块使用真实 `index.html`；搜索使用真实生成的输入框/结果 DOM，发 input/keydown 事件。不是上轮那种抽取单个函数的实验。

任务模块现有写队列捕获目标是有效设计，应保留；新证据针对读端、迁移和恢复来源。搜索/设置仍维持 P1，任务由于可写入错误项目及丢失降级数据升为 P0。

## 3. TASK-01A：上下文隔离与迁移结果（第一实施包，P0）

### 不变量

1. `root/generation` 同一对值决定一次载入和它的后续动作；A 项目结果不能更新 B 的 tasks、history、storeMode、目录缓存或状态提示。
2. 列表正在载入时不能直接拿尚未确定来源的 tasks 去保存。可暂时禁用新建/编辑，不能让一次空渲染形成已保存空数据。
3. 保存结果区分“项目文件已写入”“本地降级已写入”“全部失败”，不能以 Promise 正常 resolve/undefined 当成功。
4. 只有源数据被目标文件持久化确认后才能清迁移源。用户在迁移过程中又改过源 key 时不能删新版本。

### 接口与步骤（提案）

- `setRoot(p)` 规范化 p，增加 `generation`，清选择/历史，返回当前 load Promise；相同 root 的显式 reload 也要有独立 request token，以防同项目两次读乱序。
- `load({root, generation, requestId}) → LoadResult`。所有 await 之后、读共享状态之前先检查 token；读失败、坏 JSON、unsupportedVersion 和真正不存在分开，禁止统一空列表。
- `LoadResult` 包含 `{ok, source: 'file'|'fallback'|'empty', data, fileVersion, recoveryState, errorCode}`。只在最末应用阶段一次性更新模块状态，过期操作返回 `{obsolete:true}`。
- 迁移时固定 `{sourceKey, sourceRaw, destination, generation}`；await save 后以捕获 key 清理，不读取此时 root。仅在 destination=file 且当前源 key 字节仍等于 sourceRaw 时删除。
- `writeStore` 返回 `{ok, destination: 'file'|'fallback'|null, pathOrKey, revision, errorCode}`；写队列仍保留已实现的 target snapshot。catch 返回明确失败，不吞掉结果；本地存储 quota 失败也不能显示“已降级保存”。
- 第一步可保持旧 `{version:1,tasks}` 数据格式，先修时序和迁移；不要为了修两个确定问题先重写 DAG、历史/布局和全局应用架构。

### 实施影响和兼容

`tasks.js` 的 load/setRoot/save/writeStore 及所有创建/撤销/编辑入口需要知道 loading/保存状态。`app.js:setRoot/refreshAll` 可观察 Promise，用状态提示替代猜测完成。其他模块先不强制共享工具类，但上下文字段应与 PROJECT-01 提案一致。

已入队旧项目写入继续写旧路径是允许行为，不能因为全局 generation 更新把用户已经提交的有效保存取消。旧**读取**作废与旧**写入**保全不是同一规则。

### 验收

| 编号 | 必须注入的失败/时序 | 通过门槛 |
|---|---|---|
| TA1 | A→B→A，各请求任意顺序返回 | 只有最后上下文数据可见；不只比 root 字符串 |
| TA2 | 同项目两次 reload，旧读后回 | 最新请求获胜，选择/撤销栈不被旧读复位 |
| TA3 | 载入期间用户点新建/快捷键/撤销 | 无隐式旧数据/空数据写盘，操作状态可解释 |
| TA4 | 磁盘失败、LS 成功 | 返回 destination=fallback，LS保留并能重载 |
| TA5 | 磁盘/LS均失败 | 返回失败，内存修改保留且可导出 |
| TA6 | 迁移中切项目/源键更新 | 清理仅指向捕获源，绝不删另一项目或新 revision |
| TA7 | 旧写队列完成时已切B | 旧数据仍落A，不污染B的 storeMode/history |

建议首个提交：`fix(tasks): 隔离过期载入并按持久化结果保留迁移源`。先用完整模块桥注入回归，再在真实隐藏窗口与临时只读项目验证。原 DOM 测试 6722 附近只模拟“慢写后切项目”，不能作为“慢读乱序/迁移失败”已覆盖的证明。

## 4. TASK-01B：恢复来源与损坏文件（第二实施包，P0）

### 恢复模型

不能仅按 `updatedAt` 谁大选谁：系统时间可变，外部手工文件没有可信客户端 revision。建议使用兼容的新 envelope：

```json
{
  "version": 2,
  "datasetId": "stable-id-per-project-task-store",
  "revision": 42,
  "baseFileVersion": "hash-of-last-confirmed-file",
  "pendingFileWrite": true,
  "tasks": []
}
```

`revision` 为应用内排序，`baseFileVersion` 为最近确认文件的内容版本；本地副本只有在降级保存/迁移未确认时 pending。hash 是版本比较，不是全机器分布式锁。文件规范化与秘密排除属于另外服务。

### 载入决策

| 文件 | 降级副本 | 决策 |
|---|---|---|
| 不存在 | 无 | 新建空库，状态明确为新项目 |
| 有效 | 无或无待写入且一致 | 以确认文件为准 |
| 不存在/暂不可读 | 有效pending | 载入本地副本，标“仅保存在本机”，保留原键 |
| 有效且hash=副本base | 较新有效pending | 使用副本，尝试安全推广；确认写盘后才清pending |
| 有效且hash≠副本base | 有效pending | 保留两份，提供比较/选择；不自动按时间覆盖 |
| 损坏/未知schema | 任意 | 保留原字节，恢复/只读状态；不可自动覆写原路径 |

v1 降级数据缺 base 信息时作为恢复候选呈现，不猜“哪个一定最新”。datasetId 不一致也必须视为冲突。修复损坏文件前保全原始副本，恢复内容另存或由用户明确替换。对无法写项目的用户，本地副本仍必须能长期作为有效工作数据，并通过导出迁移。

### 存储边界与资源

恢复文件放 userData 下按项目标识分区，有保留期/总字节上限；先确认可恢复副本存在再按策略回收旧快照。无法创建备份时禁止自动覆盖损坏文件，允许另存；内存临时修改可导出。项目路径搬家如何关联旧快照单列交互，不能以一个字符串前缀猜迁移来源。

写服务若尚未按 090-B 原子化，先提供损坏只读/备份保全；恢复推广的版本检查与原子替换随后接入。只有模块可靠性证据齐全后再扩展画布虚拟化，数据保全不依赖图绘制优化。

### 验收

TB1：复现 T3，原损坏字节不变；TB2：复现 T4，新任务重载可找到；TB3：外部磁盘和LS各有新改动，二者都保留；TB4：旧v1、未来version、重复ID、环清洗分别给报告；TB5：备份目录失败不覆写；TB6：容量到上限保持最近可恢复记录；TB7：正常v1升级后任务ID/依赖/位置/估时不变。

建议第二提交：`fix(tasks): 保留损坏文件并恢复未落盘的本地任务副本`。只“把 JSON parse 放 try/catch”不能验收，现有实现已这样做且已复现覆盖。

## 5. SEARCH-01：结果集合、定位和取消（第三实施包，P1）

### 先交付定位正确性

使用 `rows = list.querySelectorAll('.qo-item')` 对结果索引操作，统计头不算结果。渲染/点击时以固定 resultIndex/resultId 取结果；`pick` 校验存在有效结果和输入状态。

清空输入、打开新搜索、关闭弹窗立即清 `results/sel`，使已有后端返回也不能重新激活旧集合。取消旧 debounce；结果失败/0项也不能保留旧数组可操作状态。

打开结果：固定项目归属与文件路径，`await Viewer.openFile(path)` 后确认仍是同一导航请求和目标活动标签，再调用 `Viewer.revealLine(line)`；一次读取未成功时不给“已定位”提示。多次点击/切项目须让旧跳行请求失效，避免A加载完成跳到B文件第77行。

### 再交付异步搜索合同

渲染请求建议 `{requestId, rootId, projectGeneration, query, options}`。main 登记真实目标目录和请求归属，按 requestId 分配可取消工作；桥通过普通可序列化数据传递，不跨 IPC 传 Web AbortController。

回复建议 `{requestId, rootId, projectGeneration, results, doneReason, scanned, skipped, elapsed}`，doneReason 为 complete/resultLimit/deadline/cancelled/error。若后续分批推送，再增加 batchNo；过期批次不覆盖当前状态。

后端取消信号在目录遍历/每次文件读取前后检查，timeout/resultLimit 遵守同一结束流程并释放登记对象。新查询/关闭/切项目发取消消息，同时渲染端立即使 token 失效。即使后端取消稍晚也不会呈现旧内容；取消不靠仅改变 CSS 隐藏。

范围/排除/大小写在该合同稳定后扩充，参考 VS Code 范围控制；默认200项保留，但达上限必须说明“未完整搜索”，并允许缩小范围。编码与文件大小略过明确统计，不能把10秒停下来报成没有匹配。

### 分拆和验收

- SC1：两结果↑↓/hover/Enter和实际打开一致；统计头有无不影响索引。
- SC2：清空输入/错误/空结果后Enter无操作。
- SC3：控制 old/new 返回顺序，最后输入获胜；项目切换使集合失效。
- SC4：读取慢文件/连续点击/打开失败，行定位只作用于对应成功标签。
- SC5：取消后后台扫描计数停止增长，登记Map回收；DOM关闭本身不足以证明后台取消。
- SC6：达到上限、超时、跳过GBK/大文件、目录拒绝访问分别显示原因；错误不冒充complete。
- SC7：真实Electron临时文件第22/77行验证光标定位；headless不依赖绘制焦点层作为唯一断言。

## 6. SETTINGS-01：确认快照、重试和正确计数（第四实施包，P1）

### 状态与合同

分别保存 `desiredSnapshot/desiredRevision/inFlight/persistedHash/persistedRevision/lastResult`。canonicalize仅包含业务配置；metadata 的 `at/count` 在真正执行写入时生成，count取业务键数，不减1。配置删除也形成新的业务快照，不能因hash只覆盖现存键的一部分而丢删除。

同一镜像文件写入串行，一次最多一个inFlight。繁忙时最新desired合并待执行；每个flush调用返回Promise，对应所要求revision被持久化或明确失败，不用“上一次lastResult”代替当前请求结果。

只有 mirrorWrite 返回 ok 后更新 persisted；失败保留待写快照并可显式重试。显式flush绕过去重失败结果；后台使用有限退避且在版本更新时更新待写内容。退避参数作为实现时可调值（例1/3/10秒，达到上限显示待重试），不是本轮已测预算。没有变化且已确认落盘时才可skip。

若部分异步结果仍可能乱序，revision过滤状态，避免过期失败覆盖最新成功；串行设计还需验证实际文件最终内容是最新配置。内存Promise确认不是断电持久化保证，主进程镜像服务的原子替换与真实错误码另测。

健康检查表示“探测时可写”，保存结果表示“本次成功”，不能用前者代替后者。pagehide/visibilitychange的flush是尽力而为；设置持久化需要每次常规操作完成，而非承诺退出瞬间异步必完成。

snapshot必须与090-E秘密迁移一致：canonicalize/de-dupe不能扩大镜像字段范围，先保持当前接口兼容，再按秘密服务迁移字段。

## 7. 公共上下文的边界（PROJECT-01）

最小公共合同 `{rootId, generation}` 可由 app 提供，但消费者还需要各自request token。A→B→A 必须比较generation，单看root相同不够；相同项目两次query/reload必须比较request token。

不要做一个“所有过期操作都取消”的全局开关：

| 操作 | 切项目后策略 |
|---|---|
| 任务/搜索读取结果 | 失效，不更新当前 UI/数据 |
| 已入队任务保存 | 继续固定目标的写入；返回只影响对应项目记录 |
| AI未执行工具写入 | 按090-G会话/授权合同停止或明确处理 |
| 全局设置镜像 | 不随项目切换作废，只随业务revision推进 |
| 编辑器待保存 | 按090-A保全输入及固定标签/路径，不能一概丢弃 |

这种共用身份合同消除重复竞态，却保留各模块领域语义。是否抽出通用helper由两次实际迁移后的重复代码决定，不先引框架。
