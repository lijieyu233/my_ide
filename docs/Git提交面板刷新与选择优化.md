# Git 提交面板刷新与选择优化

日期：2026-10-22。适用于本轮 dev 源码；已发布的旧预发布包不因源码提交自动更新。

## 用户可见行为

- 未进行版本管理的文件默认不勾选，用户可逐个或按目录/分节明确选择。
- 已跟踪修改仍沿用默认选择；用户的选择和取消跨刷新保留。消失文件与只读暂存项不混入提交。
- 顶部合并为一行：拉取及方式、推送、刷新、查看差异、更多。低频/破坏性操作仍保留带名称的菜单入口。
- 窄侧栏隐藏差异文字，保留图标、完整名称和 tooltip；不会用大块同步按钮再占一整行。
- 状态读取期间刷新按钮显示忙碌状态。提交成功后所有复选框与内部选择同步清空。
- 日常刷新只读本地远程引用；远端有无新提交以拉取/推送等实际联网操作更新。提示会说明计数来源。

## 耗时来源与处理

1. 原 syncChecked 对每个路径反复 find 全部状态，接近 O(n²)；改成一次 Map/Set 建模与线性遍历。
2. 旧 checkNodes 每次渲染只追加，不清理脱离文档的目录复选框，导致旧 DOM 被保留、后续三态更新累积；重建时清空登记表。
3. 相同状态每次都重建整棵提交树；现按实际可见数据判断是否变化，快照 ID 更新不触发重建，保留行、滚动和焦点。
4. 文件监听和保存通知并发触发扫描；同一项目/代次合并为一次尾随扫描，force 核验不降级。所有等待者在最新尾随结果应用后才返回，切项目丢弃旧归属。
5. 自动刷新会 fetch，远程引用缺失还可能回落 ls-remote；面板改用 localOnly，禁止这两类隐式联网。HEAD/上游引用不变时复用提交计数。
6. 同步按钮与工具栏反复随文件树销毁；改成稳定的顶部操作区域，保留在途操作的控件与事件。

状态、操作状态和冲突信息并行读取。未取消真实扫描、过期快照检查、未保存内容保护或错误时暂停写入的规则。

## 性能对照

同机 Node.js 24 + jsdom，600 个变更文件、20 个目录。初次渲染后，连续调用 5 次无变化 refresh；Git 返回值使用相同合成数据，刻意排除磁盘、网络和原生 Git 启动成本。

| 指标 | 修改前 | 修改后 |
| --- | --- | --- |
| 5 次无变化刷新总耗时 | 758ms | 12ms |
| 文件行身份 | 每次销毁 | 保留同一节点 |
| 8 次在途刷新通知 | 各自派发状态请求 | 一次当前扫描 + 一次尾随扫描 |

这是渲染层的定向对照，不是整个 Git 模块或任意仓库的速度保证。独立真实应用夹具的一次暖刷新约 0.9–1.3 秒，仍包含本机原生 Git 和 IPC 成本；不能把 12ms 宣传为真实仓库扫描耗时。
