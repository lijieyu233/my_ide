# Git拉取可靠性与中文操作入口

2026-10-15，用户反馈：应用中反复拉取失败，提交面板两排图标不知道怎么用。本包直接修复该入口，不把用户引导到命令行作为最终方案。

## 原因与变化

同仓库、同一远程，命令行git pull --ff-only成功且已是最新，应用GitPanel对应服务pullRemote默认ff返回“Client network socket disconnected before secure TLS connection was established”。默认拉取原本使用JS HTTP隧道下载、原生Git更新文件，两边网络实现不同。

现在没有应用专用凭据时，拉取下载和更新均使用本机Git，复用仓库／系统代理与凭据助手。禁止终端和凭据弹窗交互，失败能结算为可读结果。按当前分支实际branch.remote／branch.merge抓取指定上游，用已核验提交OID更新，避免把抓取多个分支的任意FETCH_HEAD当作目标。默认仅快进，不强制覆盖本地修改，不自动搁置或产生合并提交。

应用保存过的专用凭据／URL凭据继续走原认证链，不静默丢弃；系统凭据查询补上仓库cwd和完整URL，缓存按仓库／URL区分，保留仓库级账号和路径配置。未装本机Git时不再使用已知可能只移动引用却未更新文件的JS pull，明确提示配置Git。本包没有更换用户代理、账号或远程地址；没有验证所有私有服务器和应用专用令牌的网络兼容性。

## 使用入口

- 独立同步区域显示“拉取最新代码”“推送提交”和用途说明。默认按钮直接安全拉取；合并／变基保留在“拉取方式…”。
- 工具栏沿用SVG，每个操作增加中文名称，包括查看差异、放弃勾选改动、搁置改动、远程设置、提交历史。保留现有确认与后端保护，不增加自动丢弃操作。
- 进行中禁用重复同步；异常Promise也释放按钮。持久结果区区分已经最新、已更新和失败，提供更新目标、详细错误、重试与远程设置；URL内的凭据打码，错误按文本渲染。
- 未保存编辑先提示保存，切项目后旧结果不更新新面板；远程计数的迟到响应也核对项目代次。原“↑／↓”计数明确显示待推送／待拉取，“检查远程”不再声称文件已更新。
