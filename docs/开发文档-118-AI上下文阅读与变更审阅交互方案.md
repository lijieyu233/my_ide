## 1. 已有能力与目标任务

当前已有流式对话、模型切换、项目规则读取、文件跟随/固定、文件目录拖入、@引用（选区/打开标签/Git变更/剪贴板）、图片粘贴、上下文明细、工具结果压缩、历史会话/重命名/删除、编辑重发/重新生成、代码块复制/插入、写入确认diff、项目授权、逐处改动卡片及撤销。首次附加的文件/选区内容作为快照保存在ctxFiles；“固定”目前主要控制新对话保留，不代表自动刷新。

本轮目标任务：确认AI读的是自己刚改的内容；流式生成时能稳定回看/复制；一次改多个文件后集中审阅，分清应用/失败/取消/已撤销；从历史继续工作时仍能知道当时引用了什么。不重做整个代理引擎，不把已有能力再列为新增。

## 4. UI层级与操作流程

| 区域 | 首版展示 | 交互原则 |
|---|---|---|
| 顶部 | 当前项目/会话、模型、历史/新对话，权限保留独立入口 | 操作密度在320–520px验证；低频配置入更多菜单，核心权限/停止不能被折叠藏掉 |
| 任务状态条 | 正在生成/待确认/工具执行/正在停止/已结束，以及本轮改动数 | 文本与图标共同表达；状态依真实请求/工具终态，不用发送按钮字符推断 |
| 消息区 | 文字、可展开引用/工具详情、就地改动卡片 | 用户回看时不抢滚动，出现“有新内容/回到底部”；复制取当前可见回复正文 |
| 输入区 | 草稿、引用条、图片、发送/停止；引用详情与本次估算可打开 | 来源和内容状态可见，固定与跟随区分，截断有说明；不新增发送确认弹窗打断每次提问 |
| 审阅入口 | 本轮N文件/M处修改→文件清单→diff与反馈 | 写后审阅与写前确认分清；失败卡片不计为已修改，撤销结果真实再更新 |

任务流程：选择/刷新引用→编辑问题→发送冻结快照→生成/工具/确认状态→查看结果或审阅文件→继续提问。浏览历史请求只显示当时快照；刷新当前上下文不得改写旧请求证据。

### 118-A：上下文来源与发送快照（P1）

1. 区分“跟随最新内容”和“固定引用”。跟随来自当前Document/CM6规范读取的正文与版本，发送时更新同文件；不靠磁盘read覆盖dirty。显式文件默认在下一次发送时读取最新可靠版本，用户可选择“固定此快照”。固定保留现有跨新对话语义，但文案注明是否刷新内容，不能偷偷改变用户已固定资料。
2. 引用记录至少有contextId、kind、root/documentId、path、范围、来源（编辑缓冲/磁盘/选区/Git/剪贴板）、capturedVersion、text、截断说明和更新策略。R3选区重复添加时明确更新当前选区项；多选区引用需不同id而不是相同伪路径。路径映射沿112，特殊标签不可当磁盘路径处理。
3. 发送构造不可变requestSnapshot，接098的requestId/sessionId/rootId；回复或工具等待中切编辑器、改草稿、移除chip只影响下一次请求，不能改变在途上下文。每条user消息有“引用N项”可展开，名称/路径/行范围/来源/版本/截断与只读快照可回看。历史持久化沿30会话上限另设字节预算，同版本内容去重引用，避免在正文和附件schema中重复存一份全文；超预算/存储失败明确提示，不能称长期可恢复。
4. 下一次请求估算包括历史+新消息+此次附件+规则/系统提示，累计实际usage另列，不将粗估当精确token/费用。历史已含旧附件时避免再次在明细总数中重复计；图片明确粗估且模型能力未验证时不承诺可读图。按总字符预算截取与摘要只标真实发生的行为。
5. 读取失败/二进制/tooLarge不能显示为“空内容已附”；保留失败项并给移除/重试入口。普通发送不附加审批；如不能取得指定必需引用，明确未发送及原因，由用户修正或移除后继续。敏感来源和项目外授权遵循既有权限合同，不能为preview保存额外密钥。

验收：R1/R2/R3实际发送内容与所示来源/版本一致；真实CM6 dirty、同文件继续编辑、选区刷新、路径迁移、在途修改chip/项目切换、读取失败、总预算/图片与旧历史附件去重。C1/C2继续成立。历史回复回看不能显示现chip或静默重读新磁盘替代原快照；新schema旧会话标“引用信息未记录”，不伪造旧版本。

### 118-B：稳定阅读、复制与历史发现（P1）

消息维护自己的正文状态，chunk/done、复制、代码块操作和历史回放使用同一最终文本；R4复制不能持有气泡初始空串。流式期间复制的是当前已收到文本并注明尚未结束，工具协议块是否复制采用一致可见正文策略；用户消息正文与引用展开内容分别复制。

只在用户接近底部/主动点击“回到底部”时继续跟随；滚上去后chunk、工具卡与diff展开保持阅读锚点，显示新增内容数量。新发送可主动回到底部；收起面板后再打开恢复阅读位置，不误判为用户又要求自动跟随。失败/取消保留已生成文本与最终说明，使用098终态而不是凭“回复非空”标成功。

历史列表加当前项目标识、搜索、空匹配与明确返回；人工会话名独立于自动标题，下一轮保存保留customTitle，R6不能复原默认名。加载历史不重新执行工具；已执行记录可回看但不能伪装为本轮正在执行。键盘可打开历史/选中条目/关闭并返回输入焦点；现重命名/删除和30条上限先保留，跨项目搜索另包。

验收：R4复制得到可见正文；R5真实滚动回看不漂移、底部自动跟随仍有效；R6修改名跨回复/新对话/重启保留。历史/再生成/编辑重发/图片恢复、空回复与取消均核对；不能以复制测试通过覆盖编辑重发的全部语义。主题/缩放/长代码块/键盘与读屏分别记录。

### 118-C：工具状态与改动汇总（P1，汇总入口为新增能力）

1. 每工具按requestId/toolCallId记录待确认、执行中、成功、用户拒绝、失败、取消及部分完成；文件写成功才标已应用。R8执行错误展开显示原因/目标/可复制技术信息，用户拒绝单独呈现。不提供未有幂等保护的“一键重跑全部工具”，失败重试先按098检查执行事实。
2. 汇总按请求/文件索引现有卡片与操作记录，展示已应用/待确认/失败数及未审阅数量；点击文件打开实际diff，在320px时采用单列。标题“已应用，待审阅”说明磁盘事实，不能出现“待应用”却实际已写入。每处记录可关联到原卡片，保持写前确认与当前权限习惯。
3. “已审阅”是用户阅读标记，文件版本变化后标过期并要求重新查看；旧卡片可显示只读历史diff，与当前磁盘diff分清。批量撤销只有在098-C原字节/条件恢复、顺序依赖与项目归属真正成立后启用；失败保持记录，不能消失或统一标已撤销。
4. 单文件反馈先提供文件关联的备注草稿，集中提交到下一次用户请求；行级反馈后续接文档版本+范围映射。模型建议、已批准、实际应用、已审阅是不同状态，不能把反馈自动当新写授权。默认不将审阅标记等于Git已提交。

验收：只读工具不计改动；拒绝/磁盘失败/成功/停止前已提交各计数正确；旧请求工具不串新会话；同文件多次修改、外部编辑、路径迁移与逆序撤销保持版本保护。实际Viewer diff及定位、真实IPC停止、重启恢复按098独立补验，内存卡片数量不算持久恢复达标。

### 118-D：工作流新增候选（P2，分别评审）

| 候选 | 用户收益/最小入口 | 依赖与范围 |

| 引用日志/错误输出 | 启动失败时少复制一次日志，直接带选定片段提问 | 复用108日志选择/运行身份；只附用户指定范围，记录原进程/时间，不自动送全环境变量或整项目 |
