## 5. 各模块详细改进方案

### 5.1 编辑器与保存（EDIT-01、FS-01）

**现状**：`renderer/viewer.js:saveTab` 调 IPC 写入，成功后直接把 captured val 写回 tab 并清 dirty；`saveAllDirty` 没有失败汇总。`renderer/app.js:openProject` 在保存完成后无条件 closeAll。主进程 `fs:writeFile` 使用同步直接覆盖。

**缺口 C**：失败结果只留日志，切项目仍关闭内存标签；保存等待期间新增编辑没有版本比较。外部修改时 `reloadExternal` 跳过 dirty 标签，但写入前也没有磁盘版本前置条件（冲突造成覆盖是待复现风险 H）。

**参考与收益**：S1/S5 的连续工作和恢复思路；省掉用户追找丢失输入、反复人工备份的成本。

**步骤**：先实现每标签 revision 与保存返回合同，再让项目切换/关闭以结果为前置条件；之后引入统一文本写入服务、同目录临时文件和磁盘版本检查。GBK/UTF-16/BOM/行尾在编码层处理，不能在 UI 里各自猜测。自动保存失败应有持续但去重的状态提示。

**验收**：权限拒绝/磁盘写失败时标签、光标、dirty 保留；延迟保存期间输入新字符不会被清掉；旧任务不复活重命名旧路径；与外部编辑冲突提供比较、另存或显式覆盖。详见 090-A/B。

### 5.2 会话恢复与多项目（SESSION-01、PROJECT-01）

**现状 C**：`session.js:doSave` 排除 dirty 标签，存路径/位置；以字符串 startsWith 判断是否属于项目。`app.js:setRoot` 调 `Session.restore`/任务载入但没有等待整套恢复完成。单模块已有部分竞态防护（例如 Git 刷新），不能推断所有模块共用保护。

**方案**：引入 `{root, generation}` 项目上下文，setRoot 增加代次；每次异步读/渲染携带上下文，返回时检查代次。路径归属使用 Windows 大小写/分隔符规范化后按路径段判定，处理 `repo` 与 `repo-old`。单独在 userData 保存未保存内容、磁盘版本和 revision；正常路径会话和草稿恢复各自版本化，按容量/保留时间清理。

**验收**：A/B 项目反复快速切换，故意让 A 最后返回，B 不显示 A 的标签/任务/搜索/AI 工具结果；杀进程后草稿可找回，恢复先比较磁盘再由用户应用。借鉴 S1/S5，不需要账号同步。

### 5.3 搜索、快速打开与文件树（SEARCH-01、TREE-01）

**现状 C**：`main.js:fs:grep` 固定跳过隐藏目录、1MB 文件上限、200 结果、10s 停止；按 UTF-8 解码，与编辑器编码识别不同；超时与大文件略过缺少细分结果。`search.js:doSearch` 无请求代次；`pick` 只打开文件、toast 显示行号，没有调用 `Viewer.revealLine`。`setSel` 按含统计头的 children 索引标选中，和 results 索引错一行。文件树虚拟滚动、快速打开缓存已存在。

**方案**：先修搜索定位和行选择；返回 `{requestId, root, doneReason, scanned, skipped, results}`，后台取消并丢弃旧结果；随后提供大小写、范围、排除设置，尽量共用 Git 忽略/编码服务，未知编码可提示略过。UI 增量展示，200 是默认预算而非“全库搜完”。快速打开与内容搜索可共用文件列表元数据，但不缓存所有正文。

**验收**：慢查询 A/快查询 B 交错只呈现 B；关闭搜索后停止走查；点击/Enter 精确跳行；↑↓ 高亮与打开项一致；GBK、忽略规则、超时显示原因。树性能先测 10k/50k 和窄侧栏，拖到自身后代/同目录/同名及撤销必须保持路径正确。参考 S1。

**第二轮 R**：完整加载 search.js，已复现查询返回乱序、统计头造成选中错位、未调用跳行、跨项目使用旧集合及清空输入后的旧结果打开。具体输入/输出、修复分拆和真实IPC取消验收见091 §2/5；未验证后端扫描取消或真实可视焦点。

### 5.4 大纲（OUTLINE-01）

**现状 C**：`outline.js:parse` 使用 ATX 正则，并在任何 ```/~~~ 行翻转 inFence，没有区分围栏字符/长度；不解析 Setext 标题。折叠 key 为 `line|text`，存储 key 全局单一，标题移动后稳定性有限。

**方案**：优先消费现有 Markdown 语法树/共享标题解析器，统一 heading 范围、行号、显示文字；若暂不共享，围栏解析至少记录字符和长度。折叠状态按规范化项目/文件 key 隔离，标题标识加同名序号，更新时重映射而不是只按旧行号。

**验收**：四反引号围栏里的三反引号不应结束代码块；不同字符围栏不互相结束；Setext/重复标题/空标题/嵌套代码块与渲染匹配；改动标题前正文后折叠与选中仍可解释。不能仅凭大纲外观变好判完成。

### 5.5 Markdown 与格式预览（MD-01）

**现状**：已有 CM6 live/source、预览、表格交互、wiki/脚注等；文档 083/087 已治理样式与几何。本轮没有运行 check-live，沿用历史数值不能充当当前截图证据。

**待验证 H**：长文、异步图片尺寸变化、中文输入法组合期间切模式、表格编辑撤销是否仍稳定；复杂标题/脚注的两套解析是否漂移。

**方案**：共用可独立验证的 Markdown 语义与设计 token；先扩充矩阵（13/17/24px、深浅主题、100/125/150%缩放、长文/图片/表格、中文 IME），在真实 Electron 验证坐标、滚动锚点和撤销。保留 `liveTheme` 仅用 em 的硬规则及同源列宽/间距。大文档耗时先测，再定是否 worker 化解析；不能把全部 DOM 常驻作为“优化”。

**验收**：check-live 同源断言通过并看截图；需要焦点的项在 headless 记 SKIP，安排可用环境的单独验证；source/live/preview 切换不改正文、不丢选区。参考 S4/S11。

### 5.6 Git 提交、日志与冲突（GIT-01/02）

**现状**：原生/JS 混合路由、提交事务、Changelist、块级暂存、多方冲突工具、拉取策略、提交前检查都已实现。`git-service.js:matrixFast` 有 racy 防护，index v4/异常/空 HEAD 回落 JS；`stageHunk` 则仍通过 blob/index 合成路径。

**方案 P1**：用同一真实仓库分别执行快速、legacy 和 `git status --porcelain=v2 -z` 对拍；覆盖同尺寸同秒、index v4、worktree、符号链接、模式位、空仓库、异常文件访问、外部更改 index。手动强制刷新需明确语义，不能“吞错返回空列表”。对拍差异先查来源，再决定迁移哪条能力；不要单凭旧待办的 refresh 参数建议直接开写。

**方案 P2**：有混合提交需求后，在既有双区 diff 上加行级选择，删除/插入选择定义清楚；生成 patch 或合成 index 两种实现先做属性对照实验，验证 `.gitattributes`、全局 autocrlf、BOM 和 filter。提交前重检 index 版本，外部暂存不覆盖，失败可回滚事务。

**验收**：正常和回落状态均不漏同尺寸修改；错误不显示“无改动”；部分提交 HEAD 只含选中行、工作区原样、外部暂存原样。既有 merge/rebase continue/abort、快进落盘和 force-with-lease 回归必须保留。参考 S2/S3；新增行级能力不重写 M1–M5。

### 5.7 数据库（DB-01/02）

**现状 C**：`db-service.js:explain` 为 mysql 使用 EXPLAIN、其余统一 QUERY PLAN，因此 PostgreSQL 方言错误。`deleteRows` 循环逐条执行无事务包裹；表数据每页最多 500，但自由 SQL 查询先取完整结果。SQLite 的 exec/export 在主进程执行。连接密码在 `db-panel.js` localStorage。

**方案**：先独立修复 EXPLAIN 方言并保留“仅计划、不默认执行 ANALYZE”；随后定义后端 `begin/commit/rollback/cancel/capabilities`，批量删除/导入默认可回滚，结果标记事务状态。自由查询增加服务端超时/取消/行数与字节预算；MySQL/PG 可流式分批，SQLite 若证明阻塞则放 worker。不能只在前端截 500 行却让后端载入全部结果。提交/回滚和 pending 指示必须与同一连接事务绑定。

**验收**：三个真实后端 EXPLAIN 均成功；删除中间一条失败时整批回滚并准确报 affected；取消真的结束后端查询，连接还能正常使用；大结果内存有上限；不支持事务的表/DDL 明示能力，不能承诺全部可回滚。参考 S6/S15；090-F 详述。

### 5.8 AI 助手与翻译（AI-01/02）

**已有**：流式对话/停止、结构化与文本工具协议、replace_edit/diff、权限记忆、项目规则、会话引用；这些不是待实现项。

**缺口 C/H**：AI 配置、翻译配置和 DB 密码在渲染存储；settings snapshot 收集所有 myide-*，因此镜像/导出也会带秘密。`ai-service.js` 用单一 activeAbort；工具路径在渲染层拼接，`main.js` 通用写入/ai:run 没有对应工具级的来源与根路径授权验证。真实越界/项目切换迟到工具尚未复现，不能写成已成功攻击。

**方案**：秘密存主进程 vault，前端只有 credentialId/“已配置”状态，镜像/导出显式排除；AI/翻译/数据库共同迁移。工具调用绑定 requestId、sessionId、root、generation 与授权快照，主进程验证路径真实归属（含 junction/符号链接），读文件和项目规则视作上下文资料，不能改变权限。保持已记住授权，不每次重问；命令黑名单只是 UX 提示，不能当执行边界。

**验收**：镜像/导出/日志不含测试密钥；停止后的迟到写入不执行；A 项目授权不自动套到 B；junction 指向外部时拒绝或走明确额外授权；应用变更前核对文件版本，不覆盖刚编辑的内容。参考 S9/S12/S13，090-E/G。

### 5.9 启动面板（LAUNCH-01/02）

**现状 C**：已做 Windows 进程树停止和停止后端口复查。但 `stopEntry` 兜底会杀当前端口的所有监听 PID，未核对是否仍属于本条目；记录 PID 没有创建时间用于区分复用。`restartEntry` 不检查 stop 返回就 start。USB 启停 `spawnSync` 最长 60s、端口查找最长 8s，均在主进程调用；USB success 看 r.error 没检查非零 status。

**方案**：先加进程归属记录、复用校验与重启前置条件，再异步化系统操作。状态统一为 starting/running/stopping/stopped/failed，portReady/输出就绪只是条目可选规则，shell 存活不等于服务就绪。日志维持环形缓冲、分块编码解码，出错保留 exitCode/signal/stderr 摘要。

**验收**：端口被无关进程接管时只报占用、不杀；过期 PID 不杀；stop 失败 restart 不执行；USB 非零退出显示失败；连续点击启动只创建一个实例；执行系统命令期间编辑输入可用。参考 S7，090-D。

### 5.10 内置浏览器（BROWSER-01）

**现状 C**：已用 WebContentsView、独立 persist partition、sandbox/contextIsolation、导航/错误状态与缩放 bounds 处理；不应回退 webview。window.open 对 http/file 就地导航，其他协议交 shell；没有看到业务 permission handler。

**方案**：给浏览器 session 加按 origin/权限类型的策略和可清除记录；统一 URL 规范化，系统协议只允许实际需要的 mailto/tel 等。权限记忆有作用域，不做每次打扰。隐藏时媒体/网络/资源是否暂停先量测；宿主销毁时核对 view webContents 是否需要显式 close。下载若用户确有需要再做路径/状态/取消最小能力。

**验收**：本地测试页申请权限结果可解释；未知自定义协议不直接外发；正常 http/https 与本地 HTML 仍能用；模态弹窗、缩放、项目切换无原生视图遮挡；关闭窗口后无遗留 guest 进程。参考 S8/S12；未取证前不宣称存在泄漏。

### 5.11 任务与 DAG（TASK-01）

**现状 C**：已有 JSON 存储、写队列目标快照、依赖清洗、撤销与布局。`load()` 在 await readFile 后直接覆盖共享 tasks，没有代次校验；迁移 await save 后无条件删除 LS_KEY(root)，但 save 会在磁盘失败时写回该降级键。损坏 JSON 被解析成空任务，无显式恢复状态。

**方案**：读端也固定 root/generation，旧请求返回即丢弃；writeStore 返回明确的 fileSaved/fallbackSaved/error，只有 fileSaved 才删迁移源。损坏数据先备份并提示恢复，不能把空列表当成功再覆盖。数据 schema 版本化，清洗报告列出被移除引用/环；画布性能先测 500/2000 节点后再考虑可视区域裁剪。

**验收**：慢 A/快 B 载入不串档；只读项目的旧 localStorage 迁移失败后仍能重启恢复；磁盘和本地同时失败不报成功；坏 JSON 原字节可导出；正常队列快照、依赖环与撤销回归不退化。参考 S1/S5 的保全思想，布局优化属于 H。

**第二轮 R/P0**：读端乱序后新增任务实际写入B文件并包含A任务；迁移EACCES后降级键被删除，二次载入为空；坏JSON被新增任务覆盖；旧文件成功读取时会遮住较新降级副本。091 §3–4细化上下文、保存目的地、恢复来源和版本冲突合同。保留现有写队列目标快照，不能把读端修复误写成取消所有旧项目有效保存。

### 5.12 设置与主题（SETTINGS-01、UI-01）

**现状 C**：已有主题变量、快捷键冲突、自定义主题、镜像、自愈和健康检查。`settings-store.js:flushMirror` 在写成功前更新 lastJson；而 __meta.at 又每次变化，导致相同业务内容通常不能被有效去重。修去重时若不同时修成功确认，可能让失败快照以后被误跳过。

**方案**：业务快照先 canonicalize/hash；只有写入确认后更新 lastPersisted，失败保留 pending 并有限退避；带 schemaVersion，迁移旧数据时保留备份。设置页解释全局/项目/本次覆盖与生效来源；与 AI-01 统一秘密排除。UI 基于当前 token 做键盘/缩放/contrast 实测，不凭印象重新刷一轮颜色。玩宠提供减动画/关闭选项是否需要先核对现有设置，隐藏时 timer/animation 生命周期可量测。

**验收**：一次镜像失败后相同配置重试成功，连续无变化不重复写；损坏数据有诊断且能恢复；快捷键重定义后菜单/帮助一致；只用键盘可打开、操作和关闭弹窗并回到原焦点；100/125/150% 缩放和深浅主题无截断。参考 S10/S12。

**第二轮 R**：完整模块桥实验确认metadata时间阻碍业务去重、同毫秒显式重试复用失败、旧完成覆盖lastResult，以及1个业务键的count=0。091 §6要求确认后才推进persisted与串行写合同；相同毫秒是边界注入，不能据此宣称以后任何时间都不能重试，也不能把桥乱序等同真实磁盘已乱序。

### 5.13 插件与 Office/媒体预览（PLUGIN-01）

**现状 C**：插件注册 renderer，热重载截断旧注册表，用 new Function 运行；失败被捕获，但没有插件自己注册 timer/事件的 dispose 合同。`index.html` 同时加载 Mermaid、DOCX、XLSX、PPTX 等 vendor。

**方案**：插件实例返回/注册 disposer，统一清理 renderer、action、listener、timer、objectURL；失败可停用并显示来源/版本。插件是本机受信代码，不能把 new Function 捕异常当沙箱。先做按格式单次 Promise loader，失败可重试；preview 返回 `{element, dispose}`，标签切换/关闭配套清理。只读标签缓存/LRU 先量测，dirty 内容不可丢弃。

**验收**：热重载 20 次同一动作只执行一次；坏插件不妨碍编辑；首次打开格式才请求对应 vendor，重复打开不重复注入；大 Office/媒体关闭后 URL/worker 释放；内存结果按真实 Electron 记录。参考 S8/S11。

**验收**：故意移除运行时依赖能让打包检查失败；无源码启动打开编辑/Git/启动/SQLite；性能报告包含机器、版本、采样方法与结果。200MB/<2s/<0.5s/<1s 是原大纲目标，本轮没有证据证明已达标。参考 S14；090-C。
