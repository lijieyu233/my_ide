# Codex 原生连接与权限边界

2026-11-10。保留原有 IDE 和右侧 AI 面板，新增与普通助手、DeepSeek Harness 并列的 `Codex（原生连接）` 模式。

## 使用

1. 在官方 Codex 客户端或 CLI 完成登录，或使用自己已经配置好的原生服务配置。MyIDE 不索取、复制、代填或改写认证资料。
2. AI 面板的「模式」选择 Codex。默认查找 PATH、官方 npm 安装以及桌面版自带的版本化 CLI；没有自动发现时，在「设置 → AI 助手」选择启动器。
3. 设置中的「检查安装/测试连接」仅检查本机启动器。面板上的重新连接才建立 stdio 协议、读取脱敏登录状态和真实模型目录；不会发送模型任务或新建原生线程。
4. 在面板选择 Codex 返回的实际模型与思考强度，然后发送消息。普通助手的 API Key、DSH 模型和启动器配置保持独立。
5. 未登录时明确提示先在官方客户端登录，禁用发送。不会弹出登录浏览器、自动安装或代改全局配置。

## 原生协议，不是 API 套壳

MyIDE 启动自己拥有的 `codex app-server --stdio` 子进程，使用换行 JSON-RPC：initialize/initialized、模型目录、thread/start/resume、turn/start/interrupt。它不是附着桌面版正在运行的 app-server，也不是把 Codex 请求伪装成 DSH 请求。

本机实测 CLI 为 `0.167.0-alpha.3.2`；通过它实际生成的稳定及实验 JSON Schema 核验字段。dynamicTools 和部分审批协商属于实验协议。遇到不支持的版本明确要求更新，不回退到未经确认的字段、不静默改为另一个模型，也不新建线程替代失配历史。官方协议参考：[Codex app-server README](https://github.com/openai/codex/blob/main/codex-rs/app-server/README.md)。

初始化声明显式网关 OAuth，由 `account/gatewayOAuth/read` 安全探测；网关未就绪或接口不支持时中止，不调用 login。`account/read` 不刷新 token，返回界面前只保留账号类型与是否需要认证，不返回邮箱、账号 ID、routing 或 token。

## 会话、项目和后台

- 本地会话存储使用独立 `:codex` 命名空间；原生线程映射保存于 MyIDE userData 自有映射中，不与 DSH 映射混用。
- 首次发送才创建原生线程；后续只追加本次用户原话和显式资料，不重复历史工具调用。
- 恢复校验原生返回的线程 ID 与规范化 cwd。恢复请求不传 cwd/model 覆盖旧身份；失配持久标为不可续聊，不偷偷创建替代线程。
- 模型目录中的缓存选择不等于原生恢复已确认。界面使用服务返回的实际/待应用选择；显式改选才在下一轮应用，不拿另一项目的全局偏好覆盖已恢复的线程。
- 阅读页/书架使用独立历史与 MyIDE 自有 detached 工作目录，不使用后台项目的 cwd 或项目工具权限。
- 切项目、切会话时保留 Codex 后台运行；返回接回原视图。后台工具待返回处理，不借用当前项目执行。
- 停止只针对自己拥有的 threadId + turnId，不杀桌面 Codex、DSH 或别的会话。

**首版只管理 MyIDE 自己创建的线程映射。** 不承诺外部桌面会话目录同步、实时旁听、DSH 原生队列/插入或别的客户端审批联动，界面不展示这些不具备的能力。

## 两套权限，不能相互代授

Codex 原生命令、文件修改等仅作为原生活动展示，MyIDE 不重复执行。

- 原生线程从只读沙箱开始，审批策略固定 `on-request`、reviewer 为用户。支持命令/文件/延迟网络的单次确认；不授予 session 级或规则级长期批准。
- 网络审批展示目标 host/protocol，文件审批显示路径与补丁资料，不以之前的工具摘要替换当前审批材料。
- 整轮/会话权限 profile 扩权不在首版支持范围，明确拒绝；不能把它伪装成“仅一次允许”。秘密问题不放进普通文本问答框，提示走官方安全流程。
- MyIDE 工具通过 Codex dynamicTools 进入原有 validate/authority/可信确认流程。Codex 原生批准不授予 MyIDE 写入权限，MyIDE 的自动模式也不代替 Codex 原生审批。
- 入口仍检查主窗口主 frame、engine、项目、会话、请求代次及页面；后台、迟到、跨项目和伪造回执不能借用其它任务身份。
- Codex 原生沙箱与 MyIDE 的路径/命令策略不是同一套约束。不要认为本应用的 deny 设置会重写 Codex 的所有原生策略。

## 资源和错误处理

RPC 只扫描新片段、增量计字节数，完整帧换行后才合并解析；单帧 4MiB，等待请求数有上限。stderr 丢弃，不把潜在认证/配置日志泄漏到界面。连接/轮次/队列有界超时，身份或终态不明时拒绝自动重试；重连不自动重发旧消息。

模型切换会等待明确检查，运行期间禁用模型/推理改选。正文、思考、工具仍沿用合并重绘与紧凑活动折叠，未重做界面。

## 验证与限制

```sh
npm run test:ai
npm run check:ai-codex
npm run test:package
```

- 原生协议单测 38 项；设置 `CODEX_PROTOCOL_SCHEMA_DIR` 指向官方生成的实验 schema 目录时增加一项实际出站参数/schema 校验，共 39 项。覆盖分片预算、模型目录、首次/恢复、身份失配持久拒绝、审批/问题/工具归属、同时运行、停止、网关不自动登录，以及重试、终态回执、真实受理阶段与无活动超时。
- 实际本机 CLI 的隔离 smoke 成功：initialize → 网关只读探测 → 账号只读探测 → model/list；返回 9 个实际模型。独立测试 HOME 未登录，sessionId 为空；没有 thread/start、turn/start 或 login，没有调用收费模型。
- 隐藏 Electron 使用生产 UI、IPC、Codex 服务/RPC及 MyIDE 工具 authority，只把 app-server 子进程替换为离线合成对端。验证审批不自动通过、MyIDE 实际读文件回执、续聊保持原线程、项目切换与后台隔离、停止归属及禁网。一次测量最大 16ms 心跳间隔约 25.3ms；不是 60Hz 帧率声明或所有负载保证。
- **首版验收仅完成未登录隔离握手与离线端到端，未运行真实模型轮次。** 用户反馈无回复后补做了下面的真实最小对话；真实原生命令/文件审批仍未执行，不能将离线通过冒称它们也已实测。
- 全量 DOM 仍有既有自动上下文/规则开关相关失败，完整 UI 还有已记录的非本功能失败；根目录用户脚本导致全套布局断言失败，保留用户文件不为跑绿删除。

## “表面运行、实际无回复”的真实复查

2026-11-10，用户反馈 MyIDE 没有恢复/回复、Codex 也找不到会话。未重发原任务，未停止用户进程，未读取认证文件或改写原生配置：

- 只读查询 MyIDE 自有映射中的线程，同一 ID 的原生持久记录确实存在，`source=vscode`，保存的轮次只有 `userMessage`、没有助手正文，读回为 `interrupted`。独立查询子进程的 `notLoaded` 只说明它自己未加载该线程，不能代替原客户端的实时运行状态。没有证据将桌面不可见归因于 source 过滤，更不能把本地映射当作真实生成证明。
- 使用独立临时只读工作区和同一模型 `gpt-6.1-sol`，仅发送固定的 `CODEX_OK` 连通性请求，不调用工具。真实原生 `turn/start` 约 1.3 秒确认，之后发生 **4 次 `error` 通知，`willRetry=true`、`responseStreamDisconnected`**（约 47/63/78/95 秒），约 **116 秒**才收到助手正文并完成。
- 再经修复后的生产 Codex service 验证：首次账号只读检查返回原生 RPC `-32603`，没有发送模型轮次；重新做只读检查成功后，独立最小轮次再次出现 4 次断流重试，约 **116.2 秒**收到准确的 `CODEX_OK`，`ok=true/status=completed`。这证明实际接收与回复链路，不证明原用户任务已经恢复，也不证明上游网络问题已经修复。

修复前把“本地任务开始”提前显示为生成，漏掉 `error` 通知的 `willRetry` 与结构化错误，且只读终态 status、不读 `turn.error`。因此重试、已经失败或仅等待确认都可能看起来仍正常生成。

修复后：

1. 状态区分连接/目录核对/线程恢复/提交/原生受理/实际活动/通信重试。只收到原生 turn ID 或 `turn/started` 才显示受理；只有助手、思考或原生工具活动才显示生成，用户消息回声不算输出。
2. 重试展示安全错误分类与次数，保持同一原生轮次，**不重发用户输入、不新建替代线程**。不可重试错误、终态回执和 `turn.error` 立即收尾，RPC 明确拒绝不误锁成未知受理。
3. 65 秒无活动警示、5 分钟无活动请求中断；按匹配的原生活动重置，等待 MyIDE 工具/审批/问题时暂停，不将用户思考时间误判掉线。
4. 状态提示和 AI 状态查询提供原生 thread/turn ID、阶段、重试次数、安全错误分类与正文长度；不记录 prompt、错误原文、账户信息、token 或 stderr。
5. 隐藏生产 UI 回放同类 4 次断流：无正文时明确显示重试，输入只提交一次，恢复后正文与工具桥继续；不会靠转圈或合成回答冒充真实生成。

当前 CLI 的 `responses_websockets` / `responses_websockets_v2` 已是 removed 兼容空开关。不能凭重试时序猜测 WebSocket→HTTP 回退，也不能通过无效 flag 或静默修改 provider/auth/proxy 来冒称修好网络。

### 显式真实对话自检

默认离线自检不消费账号额度；另提供必须明确 opt-in 的真实链路检查：

```sh
npm run check:ai-codex-live -- --confirm-live-model --model=gpt-6.1-sol
```

它会使用本机原生登录态并消耗少量额度，仅发送固定一句 `CODEX_OK` 请求，使用独立临时线程、只读沙箱、拒绝工具与额外审批。没有确认参数就以提示退出，不启动 Codex。不会重放原任务、读取/改写认证或操作用户项目。报告仅包含阶段、时刻、错误类别、长度和精确回复是否匹配，不保存正文或凭据。
