## 二、底部：从「三层堆叠」到「一条线」

### 改前（截图里就是这样）

```
┌ 正在看 .env.development.local            ✕ ┐   ← 独占一整行，还带底色块
│ 📁 (打开的这个标签页) ✕   📄 (剪贴板内容) ✕ │   ← chips 换行，占 2~3 行
│ 📄 openapi-clinic.v1.json ✕                │
│ [📎]  @cont|                        [➤]    │
└────────────────────────────────────────────┘
```

具体毛病：

1. **三层堆叠**：「正在看」条 + chips + 输入框，贴着输入框堆了三层，面板底部被吃掉一大块。
2. **文案像占位符**：chip 上写的是 `（打开的 1 个标签页）`、`（剪贴板内容）` —— 全角括号 + 描述性文字，不像「内容」，像没填的字段。
3. **图标错配**：标签页那条用的是 `🗂`（目录图标），剪贴板用 `📄`（文件图标），纯按 `isDir` 布尔值挑 emoji。
4. **回形针按钮功能重复**：它做的是「把当前编辑器文件附为上下文」，但（a）面板已经**自动跟随当前文件**，（b）`@` 能引用项目内任意文件。等于同一件事有三个入口，而它是最弱的一个，还占着输入框左侧 38px。
5. **整块 chip 可点 = 移除**：想看一眼这 chip 是什么，手一滑就删了，还得重新 `@` 一次。

### 改后

```
┌ 👁 note.md ✕ │ 📄 a.md 📌 ✕ │ ✦ Git 变更 📌 ✕ ┐   ← 单行横向滚动
│ @cont|                                  [➤]   │
└───────────────────────────────────────────────┘
```

- **删掉回形针**（`#ai-file-chip`）：入口收敛到两个 —— 自动跟随 + `@`。
- **删掉「正在看」独立条**（`#ai-follow`）：「正在看」降级成 chips 里的一项（`.ai-ctx-chip.follow`，眼睛图标 + accent 描边），语义不变、占地减半。
- **chips 单行横向滚动**：`flex-wrap: nowrap` + `overflow-x: auto`，高度固定一行，再多上下文也是横着滚。
- **文案改短**：`（打开的 1 个标签页）` → `打开的标签页`；`（剪贴板内容）` → `剪贴板`；`（Git 未提交改动）` → `Git 变更`。完整路径放 `<title>` 悬停提示与上下文明细里。
- **图标换内联 SVG**（`CTX_ICON`）：眼睛 / 选区 / 标签页 / 分支 / 剪贴板 / 文件 / 目录，各自一个，不再按布尔值挑 emoji。
- **只有 ✕ 才移除**：点 chip 本体不再做任何事，杜绝误删。

> `renderFollow()` 保留为 `renderChips()` 的别名，调用点一处没改。

## 三、@ 列表 hover 没反应

CSS 里只有键盘选中的 `.ai-at-item.sel` 有底色，**没有 `:hover` 规则** —— 鼠标划过列表项毫无反馈（截图里正指着一条，看不出区别）。

```css
/* 新增 */
.ai-at-item:hover { background: color-mix(in srgb, var(--accent) 22%, transparent); }
/* 同时把键盘选中改成「淡底 + 左侧 accent 竖线」，与鼠标悬停区分开 */
.ai-at-item.sel { background: color-mix(in srgb, var(--accent) 15%, transparent); box-shadow: inset 2px 0 0 var(--accent); }
```

## 四、确认弹窗：从居中大模态到「贴底浮层」

### 4.1 其他 AI IDE 怎么展示（用户问的）

| 产品 | 改动确认的呈现 |
|---|---|
| **Cursor** | 不弹框。改动直接以 **inline diff** 出现在编辑器里（红绿行 + gutter 标记），编辑器内配 Keep / Undo；只有**终端命令**才单独确认（Allow / Allow once / Always allow this command） |
| **VS Code Copilot** | 改动进 chat 的 Working Set，点文件名在编辑器里开 diff 视图（并排），Keep / Undo；终端命令走 **allowlist + scoped approval**（Allow in this Workspace） |
| **Cline** | diff **卡片直接插在对话流里**（Auto-approve 复选框按工具粒度勾选：读文件 / 写文件 / 执行命令各一个），外加全局 YOLO 模式 |
| **Zed** | inline diff + 接受 / 拒绝按钮 |
| **Aider** | 终端里打 diff，`y/n/d` 决策 |

**共识很清楚**：*不要抢焦点的居中模态；改动就地给 diff，决策按钮贴着 diff。* 大模态的问题很实在 —— 一跳出来编辑器被整个盖住，用户没法「一边看真实文件一边决定」。

### 4.2 我们的改法

原来是 `Modal.show(box)`：560px 居中、70vh 高、纯文本 diff、三个大按钮横排。改成：

```
┌ #ai-panel 内，position:absolute; left/right:8px; bottom:8px ─┐
│ 📄 _ui_perm.md                              +1 -1   [收起] │
│ ─────────────────────────────────────────────────────────  │
│   -  第二版内容        ← 红底                                  │
│   +  第一版内容        ← 绿底                                  │
│      第二行                                                  │
│ ─────────────────────────────────────────────────────────  │
│ 本项目内都允许                          [拒绝]  [应用修改]      │
└────────────────────────────────────────────────────────────┘
```

- **挂在 `#ai-panel` 内的浮层**（`.ai-confirm`），不遮编辑器；`#modal-mask` 全程不出现。
- 头部 = 图标 + 文件名 + `+N/-M` + 「收起」；正文 = diff（**默认展开**，可折叠）；底部 = 决策。
- **「本项目内都允许」降级为左下角下划线小字** —— 它是次要动作，不该和「应用修改」抢同一视觉权重（原来三个大按钮横排，主次不分）。
- 危险命令（清空文件 / rm 类）标题与说明转红，且不提供该选项。
- `Esc` = 拒绝。
- **所有原有 id 保留**（`dw-yes` / `dw-no` / `dw-always`、`cr-yes` / `cr-no` / `cr-always`），测试与自检零成本复用。

## 五、预设权限：面板头部的「访问权限」按钮

用户的原话是「能不能预先给权限，不用每一个修改都要确认」。原来只能钻进 *设置 → AI 助手* 改下拉，改完也不知道生效没。

新增 `#ai-perm`（盾牌图标，头部第 1 个按钮）+ `.ai-perm-pop` 浮层：

```
访问权限
改文件    [每次确认][自动][禁止]
执行命令  [每次确认][自动][禁止]
选「自动」后不再逐次弹确认；但危险命令…… 始终要单独点一次。
已记住的授权（本项目）
  本项目改文件不再询问                    [清除]
  「npm」开头的命令不再询问                [清除]
  写入 docs/** 不询问                     [清除]
```

- 按钮本身带 `.on` 态：只要「自动」或「本项目改文件不再询问」生效，就高亮 —— 一眼知道当前是不是放行模式。
- `permRun` **新增 `auto` 档**（原来只有 confirm / deny）。`runNeedsConfirm` 的顺序是
  `deny → 危险命令 → 用户黑名单 → auto → 记住授权 → 问`，
  **危险命令与黑名单始终排在 auto 前面** —— 能一键放行「改文件」和「跑测试」，但不能一键放行 `rm -rf`。
- 设置页同步：命令下拉补「自动执行」；并注明「这些档位在面板顶部的访问权限按钮里也能切」。

## 六、会话跟着项目走

**问题**：`LS_SESS = 'myide-ai-sessions'` 是全局 key，切项目后对话还挂着 —— 模型会把上一个项目的文件路径当成本项目的上下文，历史会话列表也串味。

**改法**：

- key 按项目分开：`myide-ai-sessions:<项目根>`。
- 新增 `AiPanel.onProjectChange()`，由 `App.setRoot()` 调用：
  - 中断进行中的生成、关掉所有浮层（mention / 历史 / 斜杠 / 权限）、**作废未处理的确认浮层**（它指向的是上一个项目的文件）
  - 清空 `msgs` / `ctxFiles` / `pendingImages` / `usageSum` / 会话 id
  - 重置 `sessionPerm`、失效 `mentionCache` 与项目规则缓存
  - 重新跟随当前文件、重读项目规则、回到欢迎页
- 切回去时历史仍在（是「分开存」而不是「删掉」）。

### ⚠ 踩坑：`sessionPerm` 不能重新赋值

第一版写成 `sessionPerm = { write: false, run: false }`，结果 **3 个老用例回归**。

原因：`AiPanel` 的导出里 `sessionPerm` 是**对象引用**，`sessionPerm = {...}` 让模块内部指向新对象，而外部拿到的 `AiPanel.sessionPerm` 仍是旧对象 —— 于是 `/yolo` 设置的是新对象，测试读旧对象永远 false；权限用例更糟：测试写旧对象、代码读新对象，判定完全错位。

修法：**原地清空**（`sessionPerm.write = false`）。凡是导出的可变状态，都不要整体重新赋值。

## 八、补记：底部控件统一刻度（第二轮反馈「高度都不一致」）

用户放大截图指出底部控件高度参差。**先量后改**（临时在自检里加了一条测量断言，拿到真实数字再动手）：

| 元素 | 改前 | 改后 |
|---|---|---|
| 上下文 chip 高度 | 21px | **24px** |
| chip 字号 | .8em（≈10.4px） | **.88em** |
| chip 内图标 | 11px | **13px** |
| chip 里的固定按钮 | 📌 emoji（字体撑高胶囊、各平台大小不一） | **内联 SVG**（12px，与 ✕ 同为 15×15 命中区） |
| 输入框圆角 | 6px | **8px** |
| 发送按钮圆角 | 4px（`.tb-btn` 默认值） | **8px** |
| 输入框最小高 / 按钮高 | 38 / 38 | 38 / 38（本来就齐，现在用断言钉住） |

三处根因：

1. **同一元素两套规则并存**：`.ai-ctx-chip` 在旧位置是 22px 版本、文件末尾是 21px 版本，后者覆盖前者 ——
   改的时候容易只改一处、数据也对不上。已删掉旧规则，只留一处定义。
2. **三套圆角**：输入框 6 / 按钮 4 / chip 11，视觉上"各长各的"。统一到 8（chip 保持胶囊 12 = 高度一半）。
3. **emoji 撑高胶囊**：📌 由字体渲染，高度不可控。换成内联 SVG 后，chip 里的三件东西
   （类型图标 13px / 文字盒 高=字号 / 两个动作 15px）都在同一档里，居中也准了（实测偏差 0.0px）。

测量断言已升级为永久断言（`aiUi` 步骤）：

```
PASS  底部控件按同一套刻度：chip 24 / 发送按钮 38 / 输入框最小高 38   [chip=24 按钮=38 输入框 min=38px]
PASS  输入框与发送按钮圆角统一为 8px（不再一个 6 一个 4）   [输入框=8px 按钮=8px]
PASS  发送按钮与输入框底部对齐（输入框多行时按钮也不飘）   [bottom差=0]
PASS  chip 里图标与文字垂直居中（中心偏差 ≤ 1px）   [偏差=0.0px（图标 13px / chip 24px）]
```

> 方法上的教训：这类「感觉不齐」的反馈，别凭 CSS 猜。加一条打印 `getBoundingClientRect()` 的临时断言，
> 跑一次自检就有数字（这次一眼看到「chip 21 / 输入框 57 / 按钮 38」，以及 `.ai-ctx-chip` 的两套规则）。
