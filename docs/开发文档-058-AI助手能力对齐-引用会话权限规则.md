# 开发文档-058 · AI 助手能力对齐（@ 引用 / 会话操作 / 权限细化 / 项目规则）

> 背景：用户批评上一轮调研太浅、只做了两条就动手。本轮把 Cursor / Zed / VS Code Copilot /
> Cline / Continue 的能力清单系统过了一遍（清单见 `docs/开发文档-057` 第五节），然后**分四批全部实现**。

## 一、@ 引用体系（上下文补齐）

### 1. 特殊来源（`@` 菜单顶部）

文件/文件夹之外，用户高频想引用的还有四样，现在都在 `@` 菜单最前面（图标 ✨ 区分）：

| 项 | 实现 | 说明 |
|---|---|---|
| `@当前选区` | `Viewer.cm.view.state.selection` 取选区文本 | 没选中时给 toast 提示，不静默失败 |
| `@打开的标签页` | `Viewer.openTabs`（用内存里的 `content`，含未保存改动） | 总量 60k 字符封顶 |
| `@Git 变更` | `myIDE.git.status` + 逐个文件 `diffWorkdir`，用 `lineDiff` 生成紧凑 -/+ 清单 | 最多 12 个文件 × 6k 字符 |
| `@剪贴板` | 新增 IPC `clip:readText`（渲染进程读不了剪贴板） | 空剪贴板给明确提示 |

**关键设计**：特殊来源**不往输入框插 `@token`**（那是文件路径的写法，模型看到「@选区」只会困惑），
直接进上下文 chips。

### 2. 上下文预算明细

点顶部「上下文 ~xx tok」→ 弹窗列出**每一条上下文占多少**（字符数 + 估算 token + 占比条 + 来源标记
「跟随当前文件 / 拖入 / 已固定 / 不可摘」），并给一个「摘掉所有未固定的上下文」按钮。

理由：一个笼统的数字没法指导行动，用户要知道的是「谁在占地方、要不要摘掉」（VS Code Copilot 也这么做）。

### 3. 固定（pin）

chip 上加了 📌：固定过的上下文**跨「新对话」保留**（`ctxFiles.filter(f => f.auto || f.pin)`），
并且排在最前面。

### 4. 修掉一个真 bug：`@` 菜单死循环把应用卡死

```js
// 旧代码（会卡死）
const dirSet = new Set();
for (const f of files) {
  let p = f.rel;
  while ((p = p.replace(/[\\/][^\\/]*$/, ''))) dirSet.add(p);   // ← 没有分隔符时 replace 原样返回
}
```
`rel` 里没有分隔符时（**根目录下的文件，如 `package.json`**），`replace` 找不到匹配会**原样返回**，
`p` 永远非空 → 死循环。用户一打 `@` 就整个应用冻结（只要项目根目录有文件就必中）。

改成显式判「还有没有分隔符」：

```js
for (;;) {
  const i1 = rel.indexOf('/');
  const i2 = rel.indexOf(SEP);                    // SEP = String.fromCharCode(92)
  const cut = i1 < 0 ? i2 : (i2 < 0 ? i1 : Math.min(i1, i2));
  if (cut < 0) break;
  rel = rel.slice(0, cut);
  if (!rel) break;
  dirSet.add(rel);
}
```

> 这个 bug 是写测试时发现的：新用例一跑就**挂住不返回**（不是失败，是进程被卡住），
> 用探针（往文件里 append 打点）定位到「打完 `@` 之后」就没有下一步了。

## 二、会话与输出

| 能力 | 实现 |
|---|---|
| **斜杠命令** | 输入框打 `/` 弹菜单（复用 `@` 补全的弹窗样式，少一套 CSS）：`/精简 /扩写 /润色 /纠错 /统一术语 /提炼要点 /转表格` 填指令；`/生成提交信息 /压缩上下文 /yolo` 直接执行。内容整理类命令**有选区就自动带上选区**（用户说「精简」多半指他选中的那段） |
| **编辑已发消息并重发** | 用户消息悬停出现「✎ 编辑并重发」：正文回输入框、这条之后的对话丢弃（改动卡片保留 —— 文件确实改了，撤销入口不能丢） |
| **重新生成** | 只在**最后一条**助手回复上挂「⟳ 重新生成」（中间那些重生成没意义，到处挂只会误点）；回退到 `lastUserAt + 1` 再续流 |
| **历史会话** | 每轮结束自动存（localStorage，上限 30 条，标题取第一条用户发言）；顶栏 🕘 打开：点击载入、✎ 重命名、✕ 删除；载入时 `replayMsgs()` 重放对话 |
| **代码块一键插入** | 回复里每个代码块悬停出现「复制 / 插入到编辑器」，插入走 CM6 `dispatch`（有选区则替换），纯文本模式回退 textarea |
| **贴图片** | 输入框 Ctrl+V 贴图 → 缩略图待发送 → 下一条消息以多模态格式发出（`[{type:'text'}, {type:'image_url'}]`，OpenAI 兼容）；>4MB 拒绝（又贵又慢） |

配套：`msgChars()` 让 token 估算兼容数组内容（图片按 ≈800 tok 折算）。

## 三、权限细化

对齐 VS Code「范围 × 粒度」与 Cursor「deny 优先于 allow」：

| 机制 | 规则 |
|---|---|
| **写白名单（按路径）** | 设置页填 `docs/**`、`*.md` 之类（简化 glob，支持 `**`/`*`）。命中才免确认 —— 避免「一处放心 = 全项目放行」 |
| **命令黑名单（内置 + 自定义）** | 内置破坏性命令：`rm/rmdir/del/erase/format/dd/taskkill/reg/...` + `git clean`/`git reset --hard`/`git push --force`/`git branch -D`…；按 `;` `&` `|` 拆段看首个词（`npm run x && rm -rf y` 也认）；**黑名单优先于一切放行** |
| **危险命令的确认弹窗** | 红色提示 + 按钮写「仍然执行」，且**不提供「总是允许」**（只能逐次点） |
| **删除保护** | 把已有内容清空（写入结果为空 + 原文件非空）= 删内容：即便白名单/记住授权/`auto` 放行了写入，**仍要单独确认一次**，确认框标红、不给「以后都允许」 |
| **`/yolo`** | 本次对话内写文件/跑命令都不再询问（内存级，关面板或开新对话即恢复），**但不豁免上面的黑名单与删除保护** |

顺带：设置页能看见并逐条清除「已记住的授权」，路径白名单也列出来（否则用户不知道哪些路径被放行了）。

## 四、工程化

- **项目规则文件**：支持 `.myide/ai-rules.md`（本项目专用）/ `AGENTS.md` / `CLAUDE.md` / `.cursorrules`，
  取第一个非空的注入系统提示（顺序：内置规则 → 项目规则 → 用户自定义设定）。
  换项目自动重读；**写入规则文件本身会让缓存失效**（否则要切项目才生效）。
- **生成提交信息**（`/生成提交信息`）：读工作区改动 + 逐文件 diff 作为上下文，自动发问。
  不需要 `run_command` 权限，走的是已有的 `git.status` / `diffWorkdir`。
- **编辑器右键交给 AI**：右键菜单加「✨ 解释选中内容 / ✏️ 修正选中内容 / 🔧 改进选中内容 /
  📄 整理这个文件」——把选中内容作为上下文并**把指令填好**（不直接发，用户可以改措辞）。

## 六、踩坑（本轮新增，环境相关）

1. **`@` 菜单的死循环**（见第一节 4）—— 表现为「测试挂住不返回」，不是失败。定位靠**探针**：
   往一个文件 append 打点，看最后停在哪；`console.log` 不可靠（管道输出在进程被卡住时不会 flush）。
2. **锚点必须按文件自身行尾拼**（本仓库 CRLF/LF 混用）：本轮因此浪费了好几次替换失败，
   最后统一用 `rep()` 助手尝试 CRLF 与 LF 两种拼法。
3. **给 Python 传多行锚点别用 `python -c "..."`**：shell 会吃掉一层转义。写成 `.py` 文件再执行。
4. **自检步骤之间会互相污染**：前面的步骤把 `permRun` 设成 `deny`、点过「本项目内都允许」，
   会让后面的权限断言得出错误结论。**每个步骤开头自带配置**（并把记忆的授权先清掉）。
5. 断言要验「人的可见结果」：本轮把「没弹窗」改成附上**末条回复 + 末条用户消息 + 规则判定值**，
   一眼看出是「没弹窗」还是「弹的是另一个窗」。
